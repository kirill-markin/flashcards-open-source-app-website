## Claude கோப்பகம் வழியாக இணையுங்கள்

[Claude கோப்பகத்தில் Nibomo](https://claude.ai/directory/nibomo) ஐத் திறந்து, அதை இணைத்து, உங்கள் Nibomo கணக்கில் உள்நுழைந்து, அணுகலை அங்கீகரியுங்கள். Nibomo ஒரு Community இணைப்பானாகப் பட்டியலிடப்பட்டுள்ளது.

Claude Code க்கு, அதே Claude சந்தாக் கணக்கைப் பயன்படுத்தி, இணைத்த பிறகு `/mcp` ஐச் சரிபாருங்கள். API விசை மூலமோ மூன்றாம் தரப்பு வழங்குநர் மூலமோ உள்நுழைந்தால் உங்கள் claude.ai இணைப்பான்கள் தானாக ஏற்றப்படுவதில்லை.

Claude Code ஐ நேரடியாகவும் உள்ளமைக்கலாம். கீழே உள்ள கட்டளையை இயக்கி, பின்னர் Claude Code இல் `/mcp` ஐத் திறந்து உலாவி அங்கீகாரத்தை முடியுங்கள்:

```bash
claude mcp add --transport http nibomo https://mcp.nibomo.com/mcp
```

[Claude Code MCP ஆவணங்கள்](https://code.claude.com/docs/en/mcp#use-mcp-servers-from-claudeai).

## கண்ணோட்டம்

MCP கிளையண்டுகளும் AI முகவர்களும் மீள்பயிற்சிக்கு உரிய உங்கள் அட்டைகளைப் படிக்கவும், ஒரு நேரத்தில் ஒரு கேள்வி என உங்களுடன் அவற்றை மீள்பயிற்சி செய்யவும், உங்களுக்காக அட்டைகளையும் அட்டைத் தொகுப்புகளையும் உருவாக்கவும் திருத்தவும் முடியும் வகையில், Nibomo ஒரு தொலைநிலை MCP (Model Context Protocol) சேவையகத்தை இயக்குகிறது.

முகவர்கள் இரண்டு வழிகளில் இணையலாம்: இந்த MCP சேவையகம் வழியாக (Claude அல்லது Cursor போன்ற MCP கிளையண்டுகளுக்குச் சிறந்தது), அல்லது CLI முகவர்களுக்கான [Agents API கண்டறிதல் URL](/docs/api/) வழியாக. இரண்டும் ஒரே பயனர் வாரியான தரவு இடைமுகத்தை அடைகின்றன; இந்தப் பக்கம் MCP சேவையகத்தை விவரிக்கிறது.

இங்கே இணையுங்கள்:

```text
https://mcp.nibomo.com/mcp
```

தரவுப் பரிமாற்ற முறை (transport) Streamable HTTP. பணியிடக் கண்டறிதல், அட்டைகளையும் அட்டைத் தொகுப்புகளையும் படித்தல், எழுதுதல், குறிப்பு வழிகாட்டிகள், மீள்பயிற்சிகள், கணக்குப் பயன்பாடு ஆகியவற்றுக்காகச் சேவையகம் எட்டுக் கருவிகளை வழங்குகிறது.

## உங்கள் கிளையண்டில் இதை எப்படிச் சேர்ப்பது

பெரும்பாலான கிளையண்டுகள் தொலைநிலை MCP சேவையகத்தைத் தனிப்பயன் இணைப்பானாகச் சேர்க்கின்றன:

1. உங்கள் கிளையண்டின் இணைப்பான் அல்லது MCP சேவையக அமைப்புகளைத் திறங்கள்.
2. ஒரு தனிப்பயன் இணைப்பானைச் சேர்த்து, சேவையக URL `https://mcp.nibomo.com/mcp` ஐ ஒட்டுங்கள்.
3. ஊடாடும் கிளையண்டுகளில், கேட்கப்படும்போது உலாவியில் அங்கீகரியுங்கள். சேவையகம் Dynamic Client Registration உடன் OAuth 2.1 ஐப் பயன்படுத்துகிறது, எனவே ஒட்ட வேண்டிய கிளையண்ட் ரகசியமோ முன்கூட்டியே பதிவு செய்ய வேண்டிய செயலியோ இல்லை.
4. திரையில்லா அல்லது CLI பயன்பாட்டுக்கு, உலாவி ஓட்டத்துக்குப் பதிலாக உங்கள் முகவர் API விசையுடன் `Authorization: Bearer fca_…` தலைப்பை அமையுங்கள்.

அங்கீகரித்த பிறகு, ஒரு பணியிடத்தைத் தேர்வு செய்ய `list_workspaces` ஐ ஒருமுறை அழைத்து, பின்னர் படிப்பதற்கு `sql_query` ஐயும், அட்டைகளையும் அட்டைத் தொகுப்புகளையும் எழுதுவதற்கு `sql_execute` ஐயும் பயன்படுத்துங்கள். மீள்பயிற்சி செய்ய, `next_review_card`, பின்னர் `reveal_answer`, பின்னர் `submit_review` ஐ அழையுங்கள்.

## கருவிகள்

சேவையகம் எட்டுக் கருவிகளை வழங்குகிறது. எந்தக் கருவியும் பாதுகாப்பான செயல்பாடுகளையும் அழிக்கக்கூடிய செயல்பாடுகளையும் ஒருபோதும் கலக்காதபடி, படிக்கும் செயல்பாடுகளும் எழுதும் செயல்பாடுகளும் வேண்டுமென்றே பிரிக்கப்பட்டுள்ளன.

- `get_usage_limits` — கணக்குத் திட்டம், வரம்புகள், நடப்பு மாத AI பயன்பாடு ஆகியவற்றைக் கண்டிப்பாகப் படிக்க மட்டும் தருகிறது; அது அட்டைகளைப் படிப்பதோ மாற்றுவதோ இல்லை.
- `sql_query` — உங்கள் அட்டைகள், அட்டைத் தொகுப்புகளுக்குக் கண்டிப்பாகப் படிக்க மட்டுமான அணுகல் (`SHOW TABLES`, `DESCRIBE`, `SHOW COLUMNS`, `SELECT`).
- `sql_execute` — உங்கள் அட்டைகள், அட்டைத் தொகுப்புகளுக்கு எழுதும் அணுகல் (`INSERT`, `UPDATE`, `DELETE`); அனைத்தும் ஒன்றாக நிறைவேறும் அல்லது எதுவுமே நிறைவேறாத (atomic) ஒரே தொகுதியாக.
- `list_workspaces` — நீங்கள் அணுகக்கூடிய பணியிடங்களின் கண்டிப்பாகப் படிக்க மட்டுமான பட்டியல்; ஒவ்வொரு பணியிடத்துக்கும் அதன் `workspaceId`, பெயர், செயலில் உள்ள அட்டைகளின் எண்ணிக்கை, கடைசிச் செயல்பாடு, அது நீங்கள் தற்போது தேர்ந்தெடுத்துள்ள இயல்புப் பணியிடமா என்பது ஆகியவை தரப்படுகின்றன. SQL, மீள்பயிற்சிக் கருவிகளின் விருப்பத்தேர்வான `workspaceId` அளவுருவுக்கு, இந்தப் பட்டியலில் வந்த ஒரு `workspaceId` ஐப் பயன்படுத்துங்கள்.
- `get_guide` — ஒரு தலைப்புக்கான கண்டிப்பாகப் படிக்க மட்டுமான குறிப்பு வழிகாட்டி: `sql_dialect`, `card_authoring`, `bulk_authoring` அல்லது `review_flow`. அது எந்தப் பணியிடத் தரவையும் படிப்பதில்லை.
- `next_review_card` — கண்டிப்பாகப் படிக்க மட்டும்: செயலிகளில் உள்ள அதே வரிசை ஒழுங்கில், மீள்பயிற்சி செய்ய வேண்டிய அடுத்த அட்டையின் முன்புறத்தை மட்டும் தருகிறது. விருப்பத்தேர்வான `tags` அல்லது `deckId` வரிசையைச் சுருக்குகிறது.
- `reveal_answer` — கண்டிப்பாகப் படிக்க மட்டும்: கற்பவர் ஓர் அட்டையின் முன்புறத்துக்குப் பதிலளிக்க முயன்ற பிறகு, அதன் பின்புறத்தைத் தருகிறது.
- `submit_review` — `Again`, `Hard`, `Good` அல்லது `Easy` என்ற ஒரு மதிப்பீட்டைப் பதிவு செய்து, அட்டையின் FSRS அட்டவணையை முன்னகர்த்துகிறது.

SQL இடைமுகம் வேண்டுமென்றே வரம்புக்குட்படுத்தப்பட்ட மொழிவழக்கு, முழுமையான PostgreSQL அல்ல. இந்த ஆவணங்கள் ஆதரிக்கப்படும் மொழிவழக்கை மட்டுமே விவரிக்கின்றன; இவை PostgreSQL இணக்கத்தன்மைக்கான குறிப்பு அல்ல. கூற்றுகள் `workspace`, `cards`, `decks`, `review_events` வளங்களை மட்டுமே அணுக முடியும், ஒவ்வொரு கூற்றும் உங்கள் சொந்தப் பணியிடத்துக்குள் அடங்கும், படித்தல், எழுதுதல் இரண்டுக்கும் ஒரு கூற்றுக்கு அதிகபட்சம் `100` வரிசைகள்.

## மீள்பயிற்சிகள்

மீள்பயிற்சிக் கருவிகள் மூலம் ஒரு முகவர் கற்பவரிடம் ஒவ்வொன்றாக அட்டைகளைக் கேட்டு, ஒவ்வொரு மதிப்பீட்டையும் அட்டையின் FSRS அட்டவணையில் சேமிக்க முடியும்:

1. `next_review_card` ஒரு `cardId` ஐயும் `frontText` ஐயும் தருகிறது, அல்லது மீள்பயிற்சிக்கு உரியது எதுவும் இல்லையென்றால் `card: null` ஐத் தருகிறது.
2. கற்பவர் பதிலளித்த பிறகு, `reveal_answer` அந்த அட்டையின் `backText` ஐத் தருகிறது.
3. `submit_review` கருவி `cardId`, கிளையண்ட் உருவாக்கிய `reviewId` UUID, ஒரு `rating`, கற்பவரின் IANA `reviewedTimeZone` ஆகியவற்றை ஏற்கிறது. சேவையகம் மீள்பயிற்சி நேரத்தைப் பதிந்து, அட்டையின் புதிய அட்டவணையைத் தருகிறது.

முடிவு உறுதியாகத் தெரியாத சமர்ப்பிப்பை அதே `reviewId` உடன் மீண்டும் அனுப்புங்கள்; அது ஒருபோதும் இரண்டாவது மீள்பயிற்சியைப் பதிவு செய்யாது. ஒரு சமர்ப்பிப்புக்குப் பின்வரும் பதில்களும் வரலாம்:

- `409 REVIEW_EVENT_CONFLICT` — மீள்பயிற்சி ஏற்கனவே பதிவு செய்யப்பட்டுவிட்டது; பிழை விவரங்கள் அட்டையின் தற்போதைய அட்டவணையைக் கொண்டுள்ளன.
- `409 REVIEW_ID_CARD_MISMATCH` — அந்த `reviewId` ஏற்கனவே வேறொரு அட்டையின் மீள்பயிற்சியைக் குறிக்கிறது, எனவே எதுவும் சேமிக்கப்படவில்லை; புதிய `reviewId` உடன் மீண்டும் சமர்ப்பியுங்கள்.
- `409 REVIEW_STALE` — அட்டையில் சேமிக்கப்பட்ட மீள்பயிற்சி நேரம் தற்போதைய சேவையக நேரத்துக்குச் சமமாகவோ அதற்குப் பின்னதாகவோ உள்ளது; வேறோர் அட்டையை மீள்பயிற்சி செய்யுங்கள்.

மீள்பயிற்சிகள் `submit_review` மூலம் மட்டுமே பதிவு செய்யப்படுகின்றன: SQL ஆல் `review_events` ஐயோ FSRS திட்டமிடல் நிலையையோ எழுத முடியாது. முழுமையான மீள்பயிற்சி, மதிப்பீட்டு விதிகளுக்கு `review_flow` தலைப்புடன் `get_guide` ஐ அழையுங்கள்.

## அட்டை ஒப்பந்தம்

ஒவ்வோர் அட்டையும் ஒரே ஒப்பந்தத்தைப் பின்பற்றுகிறது, கருவிகள் அதைச் சார்ந்துள்ளன:

- `front_text` ஒரு கேள்வி அல்லது மீள்பயிற்சித் தூண்டல் மட்டுமே; அது ஒருபோதும் பதிலைக் கொண்டிருக்காது.
- `back_text` பதிலைக் கொண்டுள்ளது, தேவைப்பட்டால் ஒரு நடைமுறை எடுத்துக்காட்டுடன்.

`sql_execute` மூலம் அட்டைகளை உருவாக்கும் முகவர்கள் இந்த ஒப்பந்தத்தைப் பின்பற்றுகின்றன, எனவே அவை உருவாக்கும் அட்டைகள் உடனடியாக இடைவெளி மீள்பயிற்சிக்குத் தயாராக இருக்கும்.

## அங்கீகாரம்

இரண்டு அங்கீகார வழிகள் ஒரே பயனர் வாரியான தரவு இடைமுகத்தை அடைகின்றன.

### OAuth 2.1 (ஊடாடும் இணைப்பான் கிளையண்டுகள்)

சேவையகம் PKCE, Dynamic Client Registration ஆகியவற்றுடன் authorization-code ஓட்டத்தைச் செயல்படுத்துகிறது. MCP URL ஐத் தனிப்பயன் இணைப்பானாகச் சேர்த்து உலாவியில் அங்கீகரியுங்கள்; கிளையண்ட் ரகசியம் எதுவும் முன்கூட்டியே பகிரப்படுவதில்லை. கண்டறிதல் தரநிலை முறையைப் பின்பற்றுகிறது:

- பாதுகாக்கப்பட்ட வள மெட்டாடேட்டா: `https://mcp.nibomo.com/.well-known/oauth-protected-resource`
- அங்கீகாரச் சேவையக மெட்டாடேட்டா: `https://auth.flashcards-open-source-app.com/.well-known/oauth-authorization-server`

### API விசை (திரையில்லா, CLI)

[API குறிப்பு](/docs/api/) இல் ஆவணப்படுத்தப்பட்ட மின்னஞ்சல் OTP உள்நுழைவு ஓட்டம் மூலம் நீண்ட காலம் செல்லுபடியாகும் `fca_` முகவர் API விசையைப் பெற்று, அதை Bearer டோக்கனாக அனுப்புங்கள்:

```text
Authorization: Bearer fca_ABCDEFGH_0123456789ABCDEFGHJKMNPQRS
```

REST முகவர் இடைமுகம் ஏற்கும் அதே விசை இது; இதற்கு உலாவியோ OAuth சுற்றுப் பயணமோ தேவையில்லை.

இரண்டு வழிகளுக்குமான அதிகாரப்பூர்வ, இயந்திரம் படிக்கக்கூடிய விளக்கம் `https://api.nibomo.com/v1/` இல் உள்ள கண்டறிதல் உள்ளடக்கம் (`/v1/agent` இல் அதன் நகல் உள்ளது).

## பாதுகாப்பும் வரம்பும்

SQL கருவிகளை அங்கீகரிப்பது பாதுகாப்பானது, ஏனெனில் இந்த இடைமுகம் தன்னிச்சையான தரவுத்தள அணுகல் அல்ல; அது பாகுபடுத்தியால் கட்டுப்படுத்தப்படும், வரம்புக்குட்பட்ட ஒரு மொழிவழக்கு:

- **மூடிய கூற்று அனுமதிப் பட்டியல்**: `sql_query` `SHOW TABLES`, `DESCRIBE`, `SHOW COLUMNS`, `SELECT` ஆகியவற்றை மட்டுமே ஏற்கிறது; `sql_execute` `INSERT`, `UPDATE`, `DELETE` ஆகியவற்றை மட்டுமே ஏற்கிறது. வேறு எதுவும் பாகுபடுத்தும் நேரத்திலேயே நிராகரிக்கப்படும்.
- **வரம்புக்குட்பட்ட வளங்கள்**: கூற்றுகள் `workspace`, `cards`, `decks`, `review_events` ஆகியவற்றை மட்டுமே தொட முடியும்.
- **பணியிட வாரியான வரம்பு**: ஒவ்வொரு SQL கூற்றும் மீள்பயிற்சியும் நீங்கள் அணுகக்கூடிய ஒரே பணியிடத்துக்குள் அடங்கும்; அது நீங்கள் கொடுக்கும் `workspaceId` அல்லது நீங்கள் தேர்ந்தெடுத்த இயல்புப் பணியிடம். மற்ற பணியிடங்களின் தரவை அணுக முடியாது.
- **கண்டிப்பான அளவுருக்கள்**: ஒவ்வொரு கருவியும் அறியப்படாத அளவுருவை நிராகரிக்கிறது, எனவே எழுத்துப்பிழையுடன் உள்ள `workspaceId` உங்கள் இயல்புப் பணியிடத்தில் இயங்குவதற்குப் பதிலாகத் தோல்வியடையும்.
- **உச்ச வரம்புகள்**: ஒரு கூற்றுக்கு அதிகபட்சம் `100` வரிசைகள், ஒரு தொகுதிக்கு அதிகபட்சம் `50` கூற்றுகள், முடிவுக்குத் தோராயமாக `12k` டோக்கன்கள் வரம்பு. மாற்றத் தொகுதிகள் அனைத்தும் ஒன்றாக அல்லது எதுவுமே இல்லாமல் (atomic) பயன்படுத்தப்படுகின்றன.
- **படித்தல்/எழுதுதல் பிரிவு**: `get_usage_limits`, `sql_query`, `list_workspaces`, `get_guide`, `next_review_card`, `reveal_answer` ஆகியவை கண்டிப்பாகப் படிக்க மட்டுமானவை (`readOnlyHint`); அவை ஒருபோதும் தரவைச் சரிசெய்வதில்லை, திட்டமிடலை மீண்டும் கணக்கிடுவதில்லை, அட்டையின் நிலையை மாற்றுவதில்லை. `sql_execute`, `submit_review` மட்டுமே எழுதும் கருவிகள் (`destructiveHint`): `sql_execute` அட்டைகளையும் அட்டைத் தொகுப்புகளையும் எழுதுகிறது, `submit_review` ஒரு மீள்பயிற்சியைப் பதிவு செய்து அதன் அட்டையின் அட்டவணையை முன்னகர்த்துகிறது.

முழு அடுக்கும் — செயலி, பின்தளம், உள்கட்டமைப்பு — திறந்த மூலமானது, அதை [சொந்தமாக இயக்கலாம்](/docs/self-hosting/); எனவே அதே இணைப்பானை உங்கள் சொந்தப் பயன்படுத்தலிலும் இயக்கலாம்.
