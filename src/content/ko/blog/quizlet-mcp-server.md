2026년 9월 12일 기준, Quizlet의 공개 문서에는 MCP 서버나 개발자가 별도 승인 없이 사용할 수 있는 공개 API가 안내되어 있지 않습니다. Claude, Codex 또는 다른 MCP 클라이언트에 붙여 넣을 Quizlet MCP URL을 찾고 있었다면, 현재 Quizlet 문서에는 공개된 설정 방법이 없습니다.

Quizlet은 ChatGPT에서 공식 앱을 제공합니다. ChatGPT 대화를 새로운 Quizlet 세트로 만들 수 있지만, 이 특정 작업 흐름이 재사용 가능한 Quizlet MCP 서버는 아닙니다. 에이전트가 기존 카드에 반복해서 접근해야 한다면, 직접 만든 세트에서 텍스트를 내보내고 원본을 보관한 다음, 옮길 내용을 검토하고 에이전트의 읽기와 쓰기를 명시적으로 지원하는 플래시카드 시스템을 사용하는 것이 현실적인 방법입니다.

**사실 확인일:** 2026년 9월 12일.

> **이해관계 공개:** 저는 Kirill Markin이며 Nibomo를 개발하고 있습니다. 아래에서는 Nibomo의 MCP 서버와 Agent API를 대안으로 소개합니다. Nibomo는 Quizlet 계정에 연결하거나 Quizlet URL로 콘텐츠를 가져올 수 없습니다.

## ChatGPT 앱, 내보내기, MCP는 각각 용도가 다릅니다

[Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro)은 AI 애플리케이션을 외부 시스템에 연결하는 개방형 표준입니다. MCP 서버는 보통 호환 클라이언트가 접속할 수 있는 정해진 엔드포인트와 호출 가능한 도구 목록을 제공합니다.

Quizlet의 [공식 ChatGPT 발표](https://quizlet.com/blog/quizlet-comes-to-chat-gpt)에서 설명하는 방식은 다릅니다. ChatGPT에 Quizlet 앱을 설치하고, 프롬프트를 `@Quizlet`으로 시작한 뒤, ChatGPT 안에서 생성된 플래시카드를 미리 봅니다. 그런 다음 Quizlet에서 세트를 열어 원하는 대로 수정하고 학습합니다.

이 방식은 “이 ChatGPT 대화를 Quizlet 세트로 만들기”에 유용합니다. 하지만 해당 발표는 범용 Quizlet MCP 엔드포인트를 공개하지 않으며, Claude나 Codex에 Quizlet 라이브러리 접근 권한을 부여하거나 재사용 가능한 개발자 인증 정보를 제공하지도 않습니다.

이는 Quizlet의 비공개 또는 내부 인프라에 관해 어떤 주장도 하는 것이 아닙니다. Quizlet이 공개 문서를 통해 이용할 수 있도록 안내하는 인터페이스만을 설명합니다. 개발자가 접근할 수 있는 범위는 [2026년 Quizlet에 공개 API가 있을까?](/ko/blog/quizlet-api/)에서 더 폭넓게 다룹니다.

차이를 정리하면 다음과 같습니다.

| 실제로 하고 싶은 일 | 현재 공식적으로 지원되는 가장 적합한 방법 | 예상할 수 있는 결과 |
| --- | --- | --- |
| ChatGPT 대화에서 새 Quizlet 세트 만들기 | Quizlet 공식 ChatGPT 앱 | ChatGPT 안의 특정 `@Quizlet` 작업 흐름을 거친 뒤 Quizlet에서 편집하고 학습 |
| 직접 만든 세트의 용어와 정의 옮기기 | Quizlet 웹사이트의 내보내기 | 보관하고 확인해야 하는 일회성 텍스트 사본 |
| Claude, Codex 또는 다른 에이전트가 플래시카드를 반복해서 읽거나 수정하게 하기 | MCP 서버 또는 에이전트 API의 사용법을 문서로 공개한 플래시카드 시스템 | Quizlet이 아니라 데이터를 옮긴 대상 워크스페이스에 인증 후 접근 |
| Quizlet 계정 데이터를 사용하는 소프트웨어 개발하기 | 공식 개발자 문서 또는 승인된 파트너 경로가 나올 때까지 기다리기 | 현재 공개 문서에는 별도 승인 없이 사용할 수 있는 Quizlet API나 MCP의 명세가 없음 |

Quizlet ChatGPT 앱은 정해진 방식으로 새 세트를 만드는 데 쓰입니다. 내보내기는 한정된 분량의 데이터를 옮기는 데 쓰입니다. MCP는 도구를 명시적으로 공개한 시스템에 반복해서 접근하는 역할을 합니다. 서로 대체할 수 있는 기능이 아닙니다.

## 지원되는 방법 중 가장 간단한 경로를 선택하세요

공식 ChatGPT 앱으로 이미 작업을 해결할 수 있다면 그대로 사용하세요. 대화 하나에서 Quizlet 세트 하나를 만들기 위해 다른 시스템까지 추가할 이유는 없습니다.

백업이나 일회성 이동만 필요하다면 Quizlet의 내보내기를 사용하세요. 에이전트가 내일 다시 접속해서 덱을 찾고, 카드를 추가하고, 수정해야 한다면 데이터를 옮길 대상 시스템에 문서화된 읽기·쓰기 인터페이스가 필요합니다. Quizlet이 이런 인터페이스를 공개하기 전까지는 이 반복 작업 흐름을 Quizlet 계정에 직접 연결하는 공식 지원 방식으로 구현할 수 없습니다.

Quizlet 데이터를 중심으로 맞춤형 소프트웨어를 개발하더라도 같은 경계를 지켜야 합니다. 브라우저 요청, 오래된 래퍼, 누군가 역공학으로 만든 연동 기능은 최신 개발자 문서를 대신할 수 없습니다.

## 직접 만든 세트는 되돌릴 수 있도록 내보내세요

Quizlet의 [공식 내보내기 안내](https://help.quizlet.com/hc/en-us/articles/360034345672-Exporting-your-sets)에 따르면 세트 제작자만 내보내기를 할 수 있으며, 웹사이트에서만 가능합니다. 경로는 **더 보기 → 내보내기 → 텍스트 복사**입니다. 내보내기에는 용어와 정의가 포함됩니다. Quizlet은 이미지를 내보낼 수 없으며, 복사한 세트도 내보내기 대상이 아니라고 안내합니다.

직접 만든 세트를 신중하게 옮기는 절차는 간단합니다.

1. Quizlet 웹사이트에서 내보낸 결과를 일반 텍스트 파일에 붙여 넣습니다.
2. 구분자, 줄바꿈, 문구를 바꾸기 전에 수정하지 않은 UTF-8 사본을 저장합니다.
3. 내보낸 원본이 아니라 복제한 파일을 편집합니다.
4. 처음, 중간, 끝에서 일부 항목을 골라 확인하고, 여러 줄로 된 정의와 비라틴 문자도 확인합니다.
5. 작업용 사본을 가져오거나 첨부하고, 카드 몇 장의 앞면과 뒷면을 미리 확인한 다음 저장합니다.
6. 옮긴 덱을 직접 열어 보고 제대로 작동하는지 확인할 때까지 Quizlet 세트와 원본 파일을 보관합니다.

구분자, CSV, 파일에 관한 전체 확인 사항은 [2026년 Quizlet 세트 내보내기 방법](/ko/blog/how-to-export-quizlet-sets-and-turn-them-into-fsrs-flashcards/)에 정리되어 있습니다. 놓치기 쉬운 중요한 제한이 있습니다. 내보내기로 옮겨지는 것은 카드 텍스트이며, Quizlet의 이미지, 폴더, 학습 기록, 숙련도 상태, 복습 일정은 포함되지 않습니다.

그래서 옮기는 과정에서 문제가 생기면 되돌릴 수 있도록 해 두는 것이 중요합니다. 여러 줄로 된 정의가 카드 두 장으로 나뉘거나 구분자 때문에 필드가 밀리더라도 원본 파일이 있으면 정확한 내용을 대조할 수 있습니다.

## 내보낸 뒤 Claude와 Codex에서 사용할 수 있는 방법

Nibomo는 다음 주소에 원격 MCP 엔드포인트를 공개하고 있습니다.

`https://mcp.nibomo.com/mcp`

> [Claude에 연결](https://claude.ai/directory/nibomo) · [문서](/ko/docs/mcp-connector/)

[MCP 커넥터 문서](/ko/docs/mcp-connector/)에는 아래에서 별도로 설명하는 `get_usage_limits`를 포함해 도구 8개가 정의되어 있습니다. `list_workspaces`, 읽기용 `sql_query`, 쓰기용 `sql_execute`, 참고 가이드용 `get_guide`, 그리고 복습용 `next_review_card`, `reveal_answer`, `submit_review`가 있습니다. 대화형 MCP 클라이언트에서는 OAuth로 접근을 승인할 수 있습니다. 터미널 에이전트는 대신 [Agent API 문서](/ko/docs/api/)에서 시작해 공개된 HTTP 절차를 사용할 수 있습니다.

`get_usage_limits` — 계정 요금제, 한도, 당월 AI 사용량을 확인하는 읽기 전용 도구입니다. 카드를 읽거나 변경하지 않습니다.

이 기능이 있다고 해서 Nibomo가 Quizlet 커넥터가 되는 것은 아닙니다. 지원되는 작업 흐름은 다음과 같습니다.

1. 직접 만든 Quizlet 세트에서 텍스트를 내보냅니다.
2. 원본 파일을 보관하고 작업용 사본을 점검합니다.
3. 각 필드에 맞게 매핑된 카드를 검토한 뒤 Nibomo에 저장합니다.
4. 이후 읽기와 쓰기를 위해 생성된 Nibomo 워크스페이스를 호환 클라이언트에 연결합니다.

Claude의 커넥터 설정 단계는 [MCP로 Nibomo를 Claude에 연결하는 방법](/blog/how-to-connect-flashcards-to-claude-with-mcp/)에서 확인할 수 있습니다. Codex와 다른 에이전트는 각 환경에서 지원하는, 문서화된 MCP 또는 Agent API 경로를 사용할 수 있습니다.

Nibomo는 Quizlet URL을 읽거나, Quizlet 계정을 그대로 복제하거나, 이후의 Quizlet 변경 사항을 동기화하거나, 내보내기에 빠진 이미지와 학습 기록을 복구할 수 없습니다. 사용자가 선택해서 가져온 자료로 Nibomo 자체 카드를 만들고 복습 일정도 새로 설정합니다.

에이전트 접근 외에도 이런 전환이 가치가 있을지 고민된다면 [오픈 소스 Quizlet 대안 비교](/blog/quizlet-alternative/)를 참고하세요.

## 권한은 작업에 필요한 범위 안으로 좁히세요

공개된 명세가 있으면 연동 과정에서 추측해야 할 부분은 줄어듭니다. 하지만 모든 MCP 동작이 안전해지는 것은 아닙니다. OAuth는 연결을 인증합니다. AI가 생성한 카드의 정확성을 보장하거나, 반환된 카드 데이터가 플래시카드 서비스 밖으로 나가지 않도록 막거나, 수정 내용이 사용자의 의도와 맞는지 판단하지는 않습니다.

Nibomo는 읽기 작업과 쓰기 도구를 구분합니다. 카드와 덱에 데이터를 쓰는 도구는 `sql_execute`, 복습 결과를 기록하는 도구는 `submit_review`입니다. 다만 OAuth 인증 정보는 여전히 커넥터의 전체 기능 범위를 포괄하므로 도구 차단과 승인 방식은 클라이언트에 따라 달라집니다. 민감하지 않은 데이터가 담긴 작은 워크스페이스부터 시작하세요. 에이전트가 작업에 필요한 데이터만 읽게 하고, 클라이언트가 지원한다면 쓰기는 호출마다 승인하도록 설정하세요. 변경을 수락하기 전에 워크스페이스와 제안된 변경 내용을 확인하세요.

AI 클라이언트의 데이터 보관 및 처리 약관을 확인하기 전에는 비공개 학습 자료를 연결하지 마세요. 처음 옮길 때는 간단한 원칙이면 충분합니다. 내보낸 원본을 보관하고, 카드 몇 장을 미리 보고, 제한된 범위의 쓰기 작업을 승인한 뒤, 다음 작업을 하기 전에 대상 앱에서 결과를 확인하세요.

## 비공개 브라우저 트래픽을 API로 취급하지 마세요

브라우저 개발자 도구에서 보이는 요청이 공개 Quizlet API인 것은 아닙니다. 비공개 엔드포인트는 세션 쿠키, 내부 형식, 예고 없이 바뀌는 동작에 의존할 수 있습니다. 자동화된 사용은 [Quizlet 서비스 약관](https://quizlet.com/tos)과 해당 자료에 대해 보유한 권한도 준수해야 합니다.

이 글에서는 스크래핑 방법이나 역공학으로 알아낸 엔드포인트를 제공하지 않습니다. 공식 ChatGPT 앱이 작업에 맞으면 사용하세요. 직접 만든 세트를 한 번 옮겨야 한다면 내보내기를 이용하세요. 에이전트가 반복해서 읽고 써야 한다면 검토한 콘텐츠를 해당 인터페이스를 공개하는 시스템으로 옮기세요. Quizlet이 새로운 기능을 문서로 안내하기 전까지 Quizlet 쪽 작업은 수동으로 유지하세요.
