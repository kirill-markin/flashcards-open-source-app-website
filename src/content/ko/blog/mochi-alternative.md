Mochi는 일반적인 앞면·뒷면 입력 양식 대신 Markdown 문서에서 시작합니다. 하이픈 세 개로 된 줄을 추가하면 문서에 복습할 수 있는 면이 생깁니다. 그대로 노트로 두거나, 다른 카드와 연결하거나, 보관 처리해 복습 대기열에서는 빼고 검색으로만 찾을 수도 있습니다.

이 작은 구분선만 봐도 **Mochi 플래시카드**가 누구에게 맞는지 알 수 있습니다. 로컬 우선 앱 하나에서 노트와 간격 반복을 함께 쓰고 싶은 사람에게 잘 맞습니다. 특히 Markdown, 백링크, 기억남(Remembered)·잊어버림(Forgot) 중 하나를 고르는 단순한 복습 방식이 편하다면 그렇습니다. 반면 여러 카드 변형의 자동 생성, 사용자 지정 HTML/CSS, JavaScript, 애드온, 세밀한 스케줄러 설정에 의존하는 기존 Anki 사용자에게는 매력이 덜합니다.

기기 하나만 쓴다면 무료 요금제는 체험판 이상의 역할을 합니다. 가입할 필요가 없고, Mochi는 무제한 오프라인 사용을 문서에 명시합니다. 다만 기기 간 동기화는 **월 US$5인 Pro 요금제**에 포함됩니다. Anki 사용자에게 더 큰 비용은 이전 과정에서 잃는 것들입니다. Mochi는 Anki 패키지와 복습 기록을 가져올 수 있지만 모든 템플릿, 스타일, 스크립트, 스케줄러 설정, 애드온 동작까지 보존하지는 못합니다.

> **이해관계 공개:** 저는 Kirill Markin이며 [Nibomo](/ko/)를 만들고 있습니다. 이 글은 출처를 확인하고 실제 사용 흐름을 살펴본 리뷰입니다. 제가 제품을 직접 테스트했다는 뜻은 아닙니다. 제휴 링크는 없습니다. 주된 비교 대상은 Mochi와 Anki이고, 제 제품은 글 끝부분에서 명확히 구분한 대안으로만 소개합니다.

**사실 확인일:** 2026년 9월 7일. 당시 확인할 수 있었던 최신 [Mochi 릴리스](https://mochi.cards/changelog/)는 2026년 8월 10일에 나온 버전 26.8.2였습니다. 가격과 앱 스토어 정보는 바뀔 수 있습니다.

## 빠르게 고르려면

- Markdown 노트와 카드를 함께 쓰고, 기기 하나에서 계정 없이 오프라인으로 공부하며, 백링크와 두 가지 선택지만 있는 복습 방식을 원한다면 **Mochi를 고르세요**.
- 검증된 노트 유형, HTML/CSS 템플릿, 애드온, 무료 호스팅 동기화, 네 가지 복습 평가, 더 세밀한 FSRS 설정이 필요하다면 **Anki를 고르세요**.
- 이미 꾸준히 복습하고 있고 Mochi가 해결해 줄 구체적인 사용상의 문제를 말할 수 없다면 **아직 옮기지 마세요**. 새로운 인터페이스만으로는 수년간 쌓인 일정 데이터와 직접 만든 카드를 위험에 노출할 이유가 부족합니다.
- Anki에 오랫동안 자료를 쌓아 왔다면 **이전하기 전에 시험하세요**. Mochi는 `.apkg` 파일을 지원하고 복습 기록도 가져올 수 있지만, HTML을 Markdown으로 변환하고 CSS와 JavaScript를 제거합니다.

## Mochi와 Anki 한눈에 비교하기

| 판단 기준 | Mochi | Anki |
|---|---|---|
| 잘 맞는 사용자 | 복습 카드 곁에 노트를 두고 싶은 연결형 노트·Markdown 사용자 | 검증되어 있고 설정을 세밀하게 조정할 수 있는 플래시카드 시스템을 원하는 학습자 |
| 카드 만들기 | Markdown 문서에 `---`를 넣으면 여러 면이 생김. 필드와 템플릿도 지원 | 노트에 필드를 저장하고 HTML/CSS 템플릿으로 카드를 하나 이상 생성 |
| 복습 흐름 | 새 카드는 먼저 학습 단계를 거치고, 학습한 카드는 잊어버림(Forgot) / 기억남(Remembered)으로 평가 | 다시(Again) / 어려움(Hard) / 알맞음(Good) / 쉬움(Easy)으로 평가 |
| 복습 일정 | Mochi 자체 알고리즘이 기본값이며 FSRS는 선택 사항 | FSRS 또는 기존 SM-2 사용. FSRS 조정 도구가 더 다양함 |
| 무료 사용 | 가입 없이 무제한 오프라인 사용 | 데스크톱 앱과 AnkiWeb 동기화 무료. 공식 iOS 앱은 유료 |
| 기기 간 동기화 | Pro, 월 US$5 | AnkiWeb을 통해 무료 |
| 플랫폼 | 웹, macOS, Windows, Linux, iOS, Android | Windows, macOS, Linux, AnkiWeb, 공식 AnkiMobile, 독립 개발 앱 AnkiDroid |
| 이동 가능한 파일 형식 | 자체 `.mochi`, Markdown, CSV 내보내기 | 자체 `.colpkg`와 `.apkg`, 탭으로 구분한 텍스트 |
| 데이터와 호스팅의 범위 | 로컬 우선. 핵심 앱은 오픈 소스로 소개되지 않으며, 공식 지원되는 직접 호스팅 동기화 서비스에 대한 문서가 없음 | 주 저장소는 AGPL 라이선스. 공식 문서에 직접 호스팅하는 동기화 서버가 안내되어 있음 |

실질적인 차이는 **노트 중심의 단순함과 컬렉션 전체를 제어하는 기능**에 있습니다.

## Mochi 인터페이스의 중심에 있는 것

카드 하나를 만드는 과정부터 따라가면 Mochi 인터페이스를 이해하기 쉽습니다.

모든 카드는 덱에 속합니다. **새 카드(New Card)**를 누르면 고정된 질문·답변 칸 대신 Markdown 편집 공간이 열립니다. 카드 하나에 제목, 목록, 코드, 이미지, 구조화된 필드, 링크를 담을 수 있습니다. 블록 사이에 `---`를 넣으면 복습할 면이 두 개 이상 생깁니다. `[[double brackets]]`처럼 이중 대괄호로 다른 카드를 참조하면 Mochi가 백링크를 자동으로 만듭니다. 공식 [카드 개요](https://mochi.cards/docs/cards/)에는 자리표시자를 통해 구조화된 필드 값을 표시하는 템플릿도 설명되어 있습니다.

카드를 별개의 시스템으로 나누지 않고 두 가지 용도로 쓸 수 있습니다.

- 복습 카드는 여러 면을 활용하고 간격 반복 학습에 들어갑니다.
- 참고용 노트는 같은 덱에 둔 채 보관 처리할 수 있습니다. 내용, 태그, 링크, 기록을 지우지 않으면서 새 카드와 복습 예정 카드 대기열에서 제외합니다.

[덱 보기](https://mochi.cards/docs/decks/custom-views/)는 필터, 정렬, 레이아웃의 조합을 저장한 것입니다. 평소에는 격자로 둘러보고, 특정 태그, 복습 예정 상태, 낮은 기억 유지율, 최근 복습 여부를 기준으로 별도의 보기를 만들 수 있습니다. Mochi에서는 보기를 집중 학습 세션으로 전환할 수도 있으며, 이때 평소 복습 일정이나 기록은 바뀌지 않습니다. 단순히 인터페이스가 ‘깔끔하다’는 말보다 구체적인 장점입니다. 같은 덱을 노트 모음, 필터를 적용한 데이터베이스, 학습 대기열로 쓸 수 있습니다.

[매일 복습](https://mochi.cards/docs/getting-started/reviewing-cards/)은 두 단계로 진행됩니다. **새 카드(New cards)** 단계에서는 카드를 복습 일정에 추가하거나, 다시(Again)를 골라 잠시 후 다시 봅니다. 학습을 마친 카드의 복습 차례가 되면 다음 면을 열고 **잊어버림(Forgot)** 또는 **기억남(Remembered)**을 선택합니다. 잊어버린 경우 Mochi는 학습 진행 상황을 초기화하기 전에 재복습 대기열에 넣습니다. 복습할 때 선택할 항목을 의도적으로 줄인 방식입니다.

## Mochi는 무료인가요? 오프라인으로 무엇을 할 수 있나요?

무료로 쓸 수 있지만, ‘무료’와 ‘오프라인’의 범위는 실행 환경에 따라 다릅니다. [Mochi 요금 안내](https://mochi.cards/)에는 다음과 같이 나옵니다.

- **무료(Free):** 기간 제한 없이 US$0. 가입할 필요가 없고 오프라인으로 무제한 사용할 수 있습니다.
- **Pro:** 월 US$5. 기기 간 동기화, 덱 게시, 동적 필드, AI 연동, 이메일 지원이 추가됩니다.

Mochi는 macOS, Windows, Linux, iOS, Android, 웹에서 실행됩니다. [다운로드 및 설치 안내](https://mochi.cards/docs/getting-started/download-and-install/)를 보면 실제 사용 범위가 드러납니다.

| 사용 환경 | 무료·오프라인 사용의 범위 |
|---|---|
| 설치한 데스크톱 또는 모바일 앱 | 계정 없이 오프라인으로 사용할 수 있습니다. 데이터가 기기에 저장되므로, 설치한 앱 하나만으로 무료 학습 환경을 완성할 수 있습니다. |
| Pro 없이 사용하는 웹 앱 | 콘텐츠는 브라우저의 오프라인 저장소에 보관됩니다. Mochi는 브라우저가 예고 없이 이 데이터를 지울 수 있다고 경고합니다. |
| 여러 기기에서 같은 컬렉션 사용 | 설치한 각 앱은 오프라인으로 작동하지만, 기기 간 자동 동기화는 Pro 기능입니다. |

오프라인 사용과 동기화는 별개의 기능입니다. 다운로드한 앱에서 카드를 만들거나 복습하기만 한다면 Pro가 필요하지 않습니다. 같은 컬렉션의 최신 상태가 노트북에서 휴대전화로 자동으로 이어져야 한다면 Pro가 필요합니다. 무료 요금제의 중요한 데이터는 기기, 특히 브라우저 저장소에만 남겨 두지 말고 자체 형식으로 백업하세요.

오프라인 동작이 선택의 기준이라면 [Anki는 오프라인에서도 작동하나요?](/blog/does-anki-work-offline/)에서 기기별 사용 방식을 확인하고, 더 폭넓게 다룬 [오프라인 플래시카드 앱 안내](/blog/best-offline-flashcards-app/)와 비교해 보세요.

## Mochi를 고를 진짜 이유는 Markdown 플래시카드입니다

Mochi의 실질적인 장점은 Markdown이 관리할 원본 자료의 형태를 바꾼다는 점입니다.

Mochi 카드는 텍스트 자체로 읽을 수 있습니다. 같은 문서에 짧은 설명, 코드 블록, 관련 개념으로 연결되는 링크, 복습할 면 사이의 구분선을 담을 수 있습니다. 반복되는 구조가 중요하다면 필드와 템플릿도 사용할 수 있습니다. 템플릿을 적용하면 Mochi는 템플릿의 Markdown에 있는 자리표시자에 필드 값을 넣어 화면에 표시합니다. 카드 자체의 Markdown은 삭제하지 않되 화면에 표시할 때는 사용하지 않습니다.

Anki는 다른 모델에서 출발합니다. 노트에 필드를 저장하고, [카드 템플릿](https://docs.ankiweb.net/templates/intro.html)이 어떤 필드를 보여 줄지, 어떤 카드를 만들지 결정합니다. 템플릿은 HTML을 쓰고 스타일은 CSS로 지정합니다. 따라서 단어 노트 하나로 뜻을 알아보는 카드와 단어를 직접 떠올리는 카드를 만들면서 원본 데이터는 한곳에 유지할 수 있습니다.

이 구조 덕분에 Anki는 조건부 레이아웃, 카드 변형 생성, 답 직접 입력, 사용자 지정 스타일, 애드온으로 확장하는 학습 방식에서 더 많은 것을 할 수 있습니다. 동시에 Anki가 Markdown을 기본으로 지원하는 플래시카드 앱은 아니라는 뜻이기도 합니다. Anki에서 Markdown을 중심으로 쓰려면 변환 과정이나 애드온이 추가로 필요합니다.

실제 선택 기준은 간단합니다. 카드로 바꿀 수 있는 노트를 원하는지, 여러 카드를 생성하는 구조화된 노트 유형을 원하는지입니다. Mochi는 전자에, Anki는 후자에 맞춰져 있습니다.

## Mochi의 간격 반복도 FSRS를 지원합니다

Mochi에는 FSRS가 없다는 비교 글은 오래된 정보입니다. Mochi는 2025년에 FSRS 미리보기 기능을 추가했고, 이후에도 스케줄러 관련 수정을 이어 왔습니다. 그래도 [기본값은 여전히 Mochi 자체 알고리즘](https://mochi.cards/docs/reviewing/fsrs/)입니다.

기본 알고리즘은 매번 기억했는지 잊어버렸는지에 따라 고정된 배율로 복습 간격을 바꿉니다. 복습 설정(Review Settings)에서 FSRS로 전환하면 기존에 학습한 카드가 기록을 잃지 않고 FSRS로 옮겨갑니다. 목표 기억 유지율을 설정하고, 사용자 지정 매개변수를 입력하고, 나중에 원래 알고리즘으로 돌아갈 수도 있습니다.

Mochi는 어느 스케줄러를 써도 두 가지 평가를 유지합니다.

- **잊어버림(Forgot)**은 FSRS의 다시(Again)에 대응합니다.
- **기억남(Remembered)**은 FSRS의 알맞음(Good)에 대응합니다.

Mochi 문서에 따르면 두 가지 선택지만 있는 평가 방식은 FSRS와 함께 작동하지만, 어려움(Hard)과 쉬움(Easy)이 제공할 정보 일부를 잃습니다. 최적화한 사용자 지정 매개변수를 넣을 수는 있지만 내장 최적화 도구는 없습니다. 개인별 매개변수를 만들려면 외부 FSRS 최적화 도구와 Mochi 복습 기록이 필요합니다.

[Anki의 FSRS 설정](https://docs.ankiweb.net/deck-options.html#fsrs)은 더 많은 기능을 제공합니다. 목표 기억 유지율과 매개변수를 프리셋에 연결할 수 있고, 내장 최적화 도구로 복습 기록에 맞춰 매개변수를 조정할 수 있습니다. 시뮬레이터는 설정별 복습 횟수나 학습 시간을 분 단위로 추정합니다. Anki는 다시(Again), 어려움(Hard), 알맞음(Good), 쉬움(Easy)의 네 가지 결과도 기록합니다.

추가 버튼은 일관되게 사용할 때만 도움이 됩니다. Anki 설명서에서 어려움(Hard)은 기억해 내는 데 성공했다는 뜻입니다. 답을 잊었는데 어려움을 누르면 FSRS에 잘못된 정보를 전달해 복습 간격이 너무 길어질 수 있습니다.

기억했는지 잊어버렸는지만 판단하는 편이 복습하기 편하다면 Mochi의 두 단계 평가 방식을 고르세요. 평가 정보를 더 세밀하게 남기고 최적화 도구, 기억 유지율 설정, 프리셋, 학습량 시뮬레이터를 쓸 계획이라면 Anki를 고르세요. 앱보다 스케줄러 자체가 궁금하다면 [FSRS와 SM-2 비교](/blog/fsrs-vs-sm-2/)를 읽어 보세요.

## Mochi와 Anki는 비용이 드는 지점이 다릅니다

컴퓨터 한 대로 공부한다면 두 앱 모두 비용 없이 쓸 수 있습니다. 기기가 늘어나면 서로 다른 부분에서 비용이 생깁니다.

Mochi는 Pro 동기화에 **월 US$5**를 받으며, 덱 게시, 동적 필드, AI 연동, 지원을 함께 제공합니다. Anki 데스크톱 앱은 무료이고, [Anki 공식 사이트](https://apps.ankiweb.net/)는 AnkiWeb 동기화도 무료라고 안내합니다. AnkiMobile은 유료인 공식 iPhone·iPad 앱입니다. AnkiDroid는 독립적으로 개발하는 무료 Android 클라이언트입니다.

따라서 어느 쪽이 더 저렴한지는 사용하는 기기에 달려 있습니다.

- 컴퓨터 한 대라면 둘 다 무료로 쓸 수 있습니다.
- 데스크톱이나 Android 기기를 여러 대 쓴다면 Anki의 무료 호스팅 동기화 덕분에 구독료를 피할 수 있습니다.
- iPhone이나 iPad에서는 Anki 앱을 한 번 구매해야 합니다. Mochi의 기기 간 동기화에는 정기 결제하는 Pro 요금제가 필요합니다.
- 이미 덱 게시, 동적 필드, AI 연동을 원하는 Mochi 사용자라면 동기화 하나에만 돈을 내는 것이 아니라 여러 기능을 함께 이용하는 비용으로 볼 수 있습니다.

iOS에서의 정확한 총비용을 비교하기 전에는 해당 지역 App Store를 확인하세요. 이 리뷰에서는 시장에 따라 달라질 수 있는 앱 스토어 가격을 고정된 금액으로 제시하지 않습니다.

## Mochi 호스팅과 로컬 우선 사용은 다릅니다

흔히 다음 세 표현을 같은 의미로 섞어 씁니다.

- **로컬 우선**은 작업 중인 데이터 사본이 기기에 있고, 클라우드 서비스 없이도 앱을 계속 쓸 수 있다는 뜻입니다.
- **오픈 소스**는 소스 코드를 살펴보고 수정할 수 있는 라이선스로 코드가 공개되어 있다는 뜻입니다.
- **직접 호스팅**은 해당 서비스를 자신의 인프라에서 실행할 수 있도록 제품이 지원하며, 그 방법을 문서로 안내한다는 뜻입니다.

Mochi는 로컬 우선 동작을 문서에 명확히 설명합니다. 핵심 앱을 오픈 소스로 소개하지는 않습니다. 공식 사이트 하단의 ‘오픈 소스(Open source)’ 링크는 핵심 앱이 아닌 [연동 도구 모음](https://github.com/mochi-cards/open-source)으로 연결됩니다. 공식 사이트에는 Pro 동기화를 대체하는 공식 지원 직접 호스팅 방법도 안내되어 있지 않습니다.

자체 서버를 쓰려고 **Mochi 호스팅**을 검색했다면 이 범위를 알아야 합니다. 로컬 데이터와 자체 형식의 백업은 보관할 수 있지만, 문서에 안내된 기기 간 연결 방식은 Mochi Pro입니다. 로컬 우선은 데이터를 관리하는 데 도움이 되지만 직접 호스팅을 뜻하지는 않습니다.

Anki의 주 저장소는 일부 구성 요소에 명시된 예외를 제외하고 [AGPL 버전 3 이상 라이선스](https://github.com/ankitects/anki/blob/main/LICENSE)를 따릅니다. 공식 설명서에는 고급 사용자를 위한 [직접 호스팅 동기화 서버](https://docs.ankiweb.net/sync-server.html)도 안내되어 있습니다. 이 서버는 호환 클라이언트에서 AnkiWeb 동기화를 대체합니다. AnkiWeb 웹사이트 자체를 직접 호스팅하는 것은 아닙니다. Anki는 운영자가 명령줄, 네트워크, 방화벽, 프로토콜, 업데이트 문제를 처리할 수 있다고 전제합니다.

## Anki 가져오기에서 유지되는 것과 바뀌는 것

Mochi의 [가져오기 문서](https://mochi.cards/docs/import-and-export/importing/)는 복습 기록을 포함한 Anki `.apkg` 파일을 지원한다고 안내합니다. 하지만 가져오기에 성공했다고 같은 방식으로 작동하는 것은 아닙니다.

가져오는 동안 Mochi는 HTML을 Markdown으로 변환하고 CSS와 JavaScript를 제거합니다. 서로 다른 두 카드 모델 사이의 형식 변환입니다. 단순한 앞면·뒷면 자료가 가장 수월합니다. 스타일, 템플릿 로직, 답을 직접 입력하는 기능, JavaScript에 의존하는 카드는 가져온 뒤 확인해야 합니다.

복습 기록도 내보낼 때 명시적으로 선택해야 합니다. Anki의 [내보내기 설명서](https://docs.ankiweb.net/exporting.html)에 따르면 **일정 정보 포함(Include Scheduling Information)** 옵션이 패키지에 복습 기록을 넣을지 결정합니다. 이 옵션을 끄면 `.apkg`에 애초에 들어 있지 않은 기록을 Mochi가 복구할 수는 없습니다.

기록을 가져왔더라도 이후 복습 예정일이 같을 것이라고 기대하지 마세요. 두 앱은 스케줄러, 평가, 목표 기억 유지율, 매개변수, 학습 단계, 덱 설정이 서로 다를 수 있습니다. 보존된 복습 이벤트는 새 스케줄러의 근거 자료가 될 뿐, 두 시스템을 같게 만들지는 않습니다.

## 자체 형식 백업과 옮기기 쉬운 텍스트는 역할이 다릅니다

무엇이든 옮기기 전에 원래 시스템을 복원할 수 있는 백업을 남기세요. 읽을 수 있는 내보내기 파일이 유용하더라도 항상 복원에 쓸 수 있는 것은 아닙니다.

Mochi의 [백업 안내](https://mochi.cards/docs/getting-started/backing-up/)에는 자체 데이터를 보존하는 두 가지 방법이 나옵니다.

- 사용자 디렉터리 전체를 복사하면 콘텐츠, 복습 기록, 첨부 파일, 앱 설정, 로그인 상태가 보존됩니다.
- `.mochi`로 내보내면 덱, 카드, 템플릿과 필드, 첨부 파일, 태그와 메타데이터, 복습 기록, 카드 순서, 덱 구조가 보존됩니다.

Mochi의 [Markdown 및 CSV 내보내기](https://mochi.cards/docs/import-and-export/exporting/)는 데이터를 다른 곳으로 옮기기 위한 형식입니다. Markdown은 카드마다 파일 하나를 만들고 하위 덱은 폴더로 만들지만, 복습 기록, 카드 순서, 템플릿은 빠집니다. 메타데이터 태그도 Markdown 본문에 들어 있지 않으면 빠집니다. CSV는 템플릿 필드나 화면에 렌더링된 앞면·뒷면을 내보낼 수 있지만 복습 기록과 템플릿은 보존하지 않습니다. 메타데이터 태그도 콘텐츠 안에 들어 있지 않으면 보존하지 않습니다.

Anki도 비슷한 구분이 있습니다.

- `.colpkg`는 복습 일정과 함께 컬렉션 전체를 내보내며 미디어도 포함할 수 있습니다. 가져오면 대상 Anki 컬렉션의 카드가 교체됩니다.
- `.apkg`는 덱 하나와 그 하위 덱을 내보냅니다. 일정 정보, 프리셋, 미디어를 포함할지 선택할 수 있습니다.
- 일반 텍스트로 내보낸 노트는 탭으로 구분한 필드를 사용하며 HTML 서식이 안에 들어 있습니다. 수정 가능한 콘텐츠를 보존하지만 컬렉션의 전체 동작까지 보존하지는 않습니다.

Mochi에서 Anki로 돌아갈 때는 보통 CSV를 씁니다. Anki는 [텍스트 열을 노트 필드에 연결](https://docs.ankiweb.net/importing/text-files.html)할 수 있지만, 이 파일을 통해 Mochi의 링크, 여러 면의 동작, 템플릿, 복습 기록이 동등한 Anki 객체로 바뀌지는 않습니다. Anki로 옮긴 사본이 제대로 보이더라도 `.mochi` 내보내기 파일을 보관하세요.

## 대표 덱으로 이전과 복귀를 시험하세요

이전 대화상자는 파일을 받아들였다는 것만 보여 줍니다. 실제 컬렉션이 여전히 제대로 작동하는지, 쓸 만한 콘텐츠를 다시 가져올 수 있는지까지 증명하지는 않습니다. 평소 쓰는 Anki 프로필은 그대로 둔 채 양방향을 시험하세요.

1. **Anki 전체를 백업하세요.** 미디어를 포함한 `.colpkg`로 내보내고 작업 중인 프로필 밖에 보관하세요.
2. **백업이 열리는지 확인하세요.** 비어 있는 임시 Anki 프로필을 만들고 거기에 `.colpkg`를 가져오세요. 컬렉션 패키지를 가져오면 대상 컬렉션이 교체되므로 임시 프로필을 쓰는 것이 중요합니다.
3. **그 임시 프로필 안에서 대표 덱을 만드세요.** 카드별로 확인할 수 있을 만큼 작게 만들되, 평소 의존하는 기능을 넣으세요. 기본 카드와 역방향 카드, 빈칸 채우기, 사용자 지정 템플릿, CSS, JavaScript, 이미지, 오디오, 수식, 태그, 중첩 덱, 복습 기록을 포함하세요.
4. **그 덱을 `.apkg`로 내보내세요.** 필요하다면 일정 정보, 프리셋, 미디어를 포함하세요. 이 옵션은 데이터를 Anki 패키지에 넣는 것이지, Mochi가 모든 설정을 재현한다고 보장하는 것은 아닙니다.
5. **새 Mochi 덱으로 가져오세요.** 평소 쓰는 Anki 프로필과 복습 예정 대기열은 바꾸지 마세요.
6. **복습하기 전에 확인하세요.** 콘텐츠, 서식, 필드, 미디어, 태그, 덱 구조, 기록을 비교하세요. HTML, CSS, JavaScript, 자동 생성되는 카드 변형에 의존하던 부분은 특히 주의해서 살펴보세요.
7. **스케줄러를 의식적으로 선택하세요.** Mochi는 자체 알고리즘으로 시작합니다. 시험 후에도 FSRS를 쓸 생각인 경우에만 켜세요.
8. **평소처럼 일주일 동안 사본을 복습하세요.** Markdown 편집 과정, 새 카드 단계, 기억남·잊어버림 판단, 오프라인 동작을 평가하세요. 동기화 요금을 냈다면 실제로 들고 다니는 기기에서 동기화도 평가하세요.
9. **돌아오는 과정도 시험하세요.** Mochi 시험용 덱을 자체 백업용 `.mochi`와 Anki용 CSV로 각각 내보내세요. 재사용할 필드가 중요하다면 필드 값 CSV를 쓰고, 눈에 보이는 앞면·뒷면 콘텐츠가 주로 필요하다면 렌더링된 면의 CSV를 쓰세요. 그 CSV를 또 다른 빈 Anki 프로필에 가져오고, 열을 적절한 노트 유형에 연결하세요.
10. **감수하기로 한 손실을 모두 적으세요.** Mochi로 옮기는 과정과 Anki로 돌아오는 과정을 따로 확인하세요. 정확한 스타일, 여러 면의 동작, 애드온 동작, 자동 생성되는 카드 변형, 복습 평가, 기록, 이후 복습 예정일이 비교표에서 생각했던 것보다 일상 사용에서 더 중요할 수 있습니다.

CSV로 돌아오는 것은 콘텐츠 이전이며 Mochi 전체 복원이 아닙니다. 복습 기록과 템플릿은 담기지 않고, 메타데이터 태그도 콘텐츠 안에 들어 있지 않으면 담기지 않습니다. Mochi가 처음에 꼽았던 문제를 해결하지 못한다면 시험용 덱을 지우고 원래 Anki 프로필을 계속 쓰세요. 해결해 준다면 실제 덱을 하나씩 옮기고, 평소 복습 주기를 여러 번 거칠 때까지 Anki `.colpkg`와 Mochi `.mochi` 백업을 보관하세요.

## Mochi 플래시카드는 누구에게 맞을까요?

다음과 같다면 Mochi가 잘 맞습니다.

- 이미 Markdown으로 글을 쓰고 생각을 정리합니다.
- 노트와 복습 카드를 서로 연결된 한 작업 공간에 두고 싶습니다.
- 네 가지 평가 대신 기억남·잊어버림 중 하나만 고르고 싶습니다.
- 기기 하나에서의 오프라인 사용만으로 무료 학습 환경이 충분하거나, Pro 동기화에 월 US$5를 낼 가치가 있습니다.
- 새 컬렉션이거나 구성이 단순해서 Anki에서 변환할 때 위험이 작습니다.

다음과 같다면 Anki를 유지하세요.

- 노트 유형 하나에서 생성되는 여러 종류의 카드가 학습에 중요합니다.
- HTML/CSS 템플릿, JavaScript, 애드온, 공유 덱이 학습 시스템의 일부입니다.
- Markdown 작성보다 무료 기기 간 동기화가 중요합니다.
- Anki의 FSRS 최적화 도구, 프리셋 설정, 네 가지 평가, 학습량 시뮬레이터가 필요합니다.
- 수년간의 복습 데이터와 맞춤 동작이 이미 잘 작동하고 있습니다.

가장 적절한 Mochi 대안은 두 선택지가 모두 맞지 않는 이유에 따라 달라집니다. 구성이 단순한 새 컬렉션을 만든다면 [Nibomo의 기능](/ko/features/)도 살펴볼 만합니다. Nibomo는 FSRS 복습, 오프라인 학습과 동기화, 카드·태그·미디어 이동, 에이전트 접근, 문서로 안내된 직접 호스팅 방법을 제공합니다. 제가 만드는 제품이지만, 한계도 알아야 합니다. Mochi의 서로 연결된 Markdown 노트 모음이나 Anki의 검증된 템플릿·애드온 시스템을 대체하지는 않습니다. [시작 안내](/docs/getting-started/)에는 현재의 호스팅 서비스, 모바일, 에이전트, 직접 호스팅 사용 방법이 나옵니다.

## 최종 판단

Mochi는 단순히 Anki의 인터페이스를 더 예쁘게 만든 앱이 아닙니다. 핵심은 Markdown 노트, 서로 연결된 지식 기록, 간격 반복 카드가 하나로 합쳐질 수 있다는 생각입니다. 무료 요금제로 계정 없이 오프라인 작업을 할 수 있고, Pro는 기기 간 동기화를 비롯한 호스팅 기능을 더합니다.

Markdown 중심의 새 컬렉션을 시작하는 학습자에게는 합리적인 선택입니다. 대표 덱 시험에서 Markdown을 바로 작성하는 방식과 두 단계 복습 평가가 실제 불편을 줄여 준다는 점이 확인된다면 Anki에서 옮길 가치도 있습니다.

이미 Anki에 자료를 쌓아 온 사용자라면 옮길 이유를 더 분명히 확인해야 합니다. 컬렉션을 백업하고, 맞춤 동작이 가장 많은 카드를 시험하세요. 포기해야 할 서식, 템플릿, 스케줄러, 생태계 기능을 감수할 만큼 Mochi가 매주 반복하는 학습 과정을 개선해 주지 않는다면 Anki를 유지하세요.
