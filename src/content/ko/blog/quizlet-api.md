2026년 8월 18일 기준으로 Quizlet은 개발자가 직접 등록해 사용할 수 있는 공개 개발자 API나 공개 개발자 포털을 문서화하고 있지 않습니다. 독립 개발자가 앱을 등록하고 Quizlet API 키를 발급받아, 문서에 명시된 엔드포인트로 플래시카드 데이터를 읽거나 쓰는 공식 경로는 현재 없습니다.

이는 Quizlet의 공개 문서를 확인한 결과이며, 내부 시스템에 관한 주장은 아닙니다. Quizlet에는 제품 간 연동과 파트너 연동이 분명히 있습니다. 현재 제공되는 ChatGPT 앱과 Google Classroom 부가기능이 그 예입니다. 하지만 어느 쪽도 다른 애플리케이션에 범용 Quizlet 개발자 API를 제공하지는 않습니다.

**사실 확인:** 2026년 8월 18일.

> **이해관계 공개:** 저는 Kirill Markin이며, 아래에서 대안으로 소개하는 Agent API와 MCP 서버를 제공하는 Nibomo를 개발하고 있습니다. Nibomo는 Quizlet과 호환되지 않으며, Quizlet 세트를 자동으로 가져오지 않습니다.

## 간단한 답: 직접 등록해 이용하는 Quizlet API는 문서화되어 있지 않습니다

Quizlet 자체를 자동화하려고 “Quizlet에 API가 있나요?”를 검색했다면, 현재로서는 **개발자가 직접 등록해 이용할 수 있는 공개 API는 문서화되어 있지 않다**고 답할 수 있습니다.

몇몇 공식 기능은 겉으로 보면 API와 비슷해 보일 수 있습니다. 하지만 각각 더 제한된 작업을 위한 기능입니다.

| 필요한 작업 | 지원되는 방법 | 적합한 용도 | 제공하지 않는 것 |
|---|---|---|---|
| 직접 만든 세트의 텍스트 옮기기 | [Quizlet 웹사이트 내보내기](https://help.quizlet.com/hc/en-us/articles/360034345672-Exporting-your-sets) | 용어와 정의를 한 번 복사하기 | 이미지, 복사한 세트의 내보내기, 학습 기록, API 접근 권한 |
| 웹사이트나 LMS 페이지에 공개 세트 표시하기 | [Quizlet 임베드](https://help.quizlet.com/hc/en-us/articles/360032935851-Embedding-sets) | 페이지 안에 Quizlet 브랜드가 표시되는 학습 활동 넣기 | 구조화된 카드 데이터, 읽기·쓰기 권한 |
| ChatGPT 대화를 Quizlet 세트로 만들기 | [ChatGPT의 Quizlet 앱](https://quizlet.com/blog/quizlet-comes-to-chat-gpt) | `@Quizlet`을 통해 세트를 만들고 미리 보기 | 자체 앱에서 쓸 인증 정보나 엔드포인트 |
| Google Classroom에서 Quizlet 과제 배정하기 | [Quizlet Google Classroom 부가기능](https://quizlet.com/blog/quizlet-google-classroom-add-on) | Classroom에서 활동을 찾고, 배정하고, 추적하기 | 자체 교육 소프트웨어를 위한 범용 API |
| 자체 Quizlet 연동 개발하기 | 현재 직접 등록해 이용하는 경로는 문서화되어 있지 않음 | 특정 파트너와의 협약은 있을 수 있음 | 공개 등록 절차, API 키, 문서화된 카드 데이터 규약 |
| 자신의 플래시카드 워크스페이스 자동화하기 | [Nibomo Agent API](/ko/docs/api/) 또는 [MCP 커넥터](/ko/docs/mcp-connector/) | 워크스페이스 범위 안에서 카드와 덱을 반복적으로 읽고 쓰기 | Quizlet 호환, Quizlet 자동 가져오기 |

구분은 간단합니다. 자신의 카드 텍스트를 한 번 복사하려면 내보내기를 사용합니다. 다른 페이지에 Quizlet을 표시하려면 임베드를 사용합니다. 특정 제품과의 연동은 해당 제품에서 정해진 절차로만 이용할 수 있습니다. 소프트웨어가 카드를 반복적으로 만들고, 읽고, 수정하려면 문서화된 읽기·쓰기 API가 필요합니다.

## 내보내기, 임베드, 파트너 연동은 공개 API가 아닙니다

공개 API는 외부 개발자에게 명확한 규약을 제공합니다. 문서, 인증 방식, 지원되는 작업, 사용 규칙, 인증 정보를 발급받는 방법이 있어야 합니다. 현재 Quizlet이 공개한 기능 중에는 개발자가 직접 이용을 시작할 수 있도록 이 모든 것을 제공하는 기능이 없습니다.

Quizlet의 **내보내기**는 수동으로 데이터를 옮기는 기능입니다. 세트 작성자는 웹사이트에서 용어와 정의의 구분 방식을 정하고, **텍스트 복사(Copy text)**를 선택한 다음, 결과를 다른 곳에 붙여넣을 수 있습니다. Quizlet은 이미지를 내보낼 수 없고, 복사한 세트는 내보낼 수 없으며, 이 기능은 웹사이트에서만 사용할 수 있다고 안내합니다. 내용을 꼼꼼히 확인하며 한 번 옮길 때는 쓸 만합니다. 하지만 소프트웨어가 두 시스템을 계속 동기화할 수는 없습니다.

**임베드**는 화면에 표시하는 기능이며, 데이터 접근 기능이 아닙니다. Quizlet은 공개 세트를 짝 맞추기(Match), 학습하기(Learn), 테스트(Test), 플래시카드(Flashcards), 받아쓰기(Spell) 모드로 표시하는 HTML을 복사할 수 있게 해 줍니다. 삽입된 활동에는 Quizlet 로고가 유지되고, 학습자는 Quizlet의 인터페이스를 사용합니다. 애플리케이션이 그 세트를 수정 가능한 카드 레코드로 전달받는 것은 아닙니다.

**특정 제품과의 연동**은 합의된 범위와 사용 절차에 따라 제공됩니다. Quizlet은 모든 개발자에게 동일한 인터페이스를 제공하지 않고도 ChatGPT나 Google Classroom과 연동할 수 있습니다. 이런 출시 소식은 해당 연동이 존재한다는 근거입니다. 누구나 사용할 수 있는 Quizlet 공개 API가 있다는 근거는 아닙니다.

같은 이유로 오래된 래퍼 라이브러리나 브라우저 개발자 도구에 보이는 요청을 지원되는 Quizlet API로 볼 수는 없습니다. 공개 문서와 안정적인 개발자 규약이 빠져 있기 때문입니다.

## 작업에 맞는 방법을 선택하세요

### 한 번 백업하거나 옮길 때는 내보내기를 사용하세요

직접 만든 세트에는 Quizlet의 공식 내보내기 절차를 사용하세요. 이 절차는 **텍스트 복사(Copy text)**로 끝나므로, 구분자를 정리하거나 필드를 대응시키기 전에 처음 붙여넣은 사본을 그대로 보관하세요. 용어와 정의를 보존하는 것이지, 복원 가능한 덱 패키지를 내려받는 것은 아닙니다. 이미지와 학습 기록은 옮겨지지 않습니다.

실제 작업에 필요한 체크리스트는 [2026년 Quizlet 학습 세트 내보내기](/ko/blog/how-to-export-quizlet-sets-and-turn-them-into-fsrs-flashcards/)에서 확인할 수 있습니다. 원본과 작업용 사본, UTF-8, 탭, 여러 줄로 된 정의를 다루며, 카드 내용을 옮기는 것과 복습 일정 상태를 옮기는 것의 차이도 설명합니다.

내보내기는 한 차례 데이터를 옮기는 작업에 적합합니다. 소프트웨어로 매일 카드를 만들거나, 동기화하거나, 반복적으로 수정하는 작업에는 맞지 않습니다.

### 화면에 보여주려면 공식 임베드를 사용하세요

학습자가 수업 웹사이트나 LMS 페이지에서 공개 Quizlet 세트를 공부하게 하려면, Quizlet 웹사이트에서 제공하는 임베드 코드를 사용하세요. 활동을 고르고 **HTML 복사(Copy HTML)**를 선택한 뒤, 결과를 페이지에 추가하면 됩니다. 학습자는 상호작용할 수 있는 Quizlet 활동을 이용하지만, 이를 삽입한 사이트는 원시 카드 데이터를 받지 않습니다.

교사에게는 이것만으로 충분한 경우가 많습니다. 이를 API라고 부르면 필요한 작업을 실제보다 복잡하게 설명하게 됩니다.

### ChatGPT나 Google Classroom에서는 해당 공식 연동을 사용하세요

Quizlet의 2026년 3월 10일 ChatGPT 발표는 구체적인 사용 절차를 설명합니다. Quizlet 앱을 연결하고, `@Quizlet`으로 프롬프트를 시작하고, ChatGPT에서 생성된 세트를 미리 본 다음, Quizlet에서 열어 자신에게 맞게 수정하고 공부합니다. 해당 대화를 바탕으로 Quizlet 세트를 만드는 공식 지원 방식입니다. 봇, 스크립트, 웹사이트에서 재사용할 수 있는 Quizlet API 인증 정보를 발급해 주지는 않습니다.

Quizlet의 2026년 6월 30일 Google Classroom 발표도 마찬가지로 구체적입니다. 이 부가기능을 통해 교육자는 연습 문제, 플래시카드, 게임 등의 활동을 찾아 배정하고, Classroom 안에서 참여도와 진행 상황을 추적할 수 있습니다. Quizlet에 따르면 Google Workspace for Education Plus가 필요하며, 교육자는 IT 관리자에게 사용 권한이나 부가기능 제공을 요청해야 할 수 있습니다.

이런 공식 연동 중 하나가 이미 목적에 맞는다면 사용하세요. 자체 애플리케이션을 개발해야 한다면 어느 연동도 일반 개발자를 위한 API 접근을 대신할 수 없습니다.

### 반복적인 자동화에는 문서화된 읽기·쓰기 인터페이스를 선택하세요

지속적인 자동화에서는 소프트웨어가 같은 일을 여러 번 안정적으로 수행해야 합니다. 노트에서 카드를 만들거나, 덱 목록을 조회하거나, 답을 수정하거나, 장기간 워크스페이스를 관리하는 작업이 여기에 해당합니다. 클립보드 내보내기로는 이런 작업을 위한 규약을 제공할 수 없습니다.

안전한 방법은 외부 소프트웨어의 인증 방식과 지원하는 읽기·쓰기 작업을 명확히 공개하는 플래시카드 시스템을 사용하는 것입니다. 자동화할 작업에는 Quizlet API 대안을 선택하고, Quizlet의 공식 기능으로 할 수 있는 학습 작업에는 Quizlet을 계속 사용할 수 있습니다.

## 대안인 Nibomo API가 실제로 제공하는 것

Nibomo는 사용자별로 접근 범위가 제한된 데이터를 두 가지 경로로 제공합니다. 두 경로에서 접근할 수 있는 데이터는 같습니다.

- [외부 Agent API](/ko/docs/api/)의 시작점은 `GET https://api.nibomo.com/v1/`입니다. 이 시작점의 디스커버리 응답은 에이전트에게 이메일 OTP 로그인, API 키 생성, 워크스페이스 선택 절차를 안내합니다. 읽기에는 SQL 형식의 쿼리 경로를 사용하고, 쓰기에는 별도의 실행 경로를 사용합니다.
- [원격 MCP 서버](/ko/docs/mcp-connector/)는 `https://mcp.nibomo.com/mcp`에서 사용할 수 있습니다. MCP 클라이언트에는 도구 8개가 제공됩니다. `list_workspaces`, `sql_query`, `sql_execute`, `get_guide`와 복습 도구인 `next_review_card`, `reveal_answer`, `submit_review`가 있습니다.

`get_usage_limits`는 계정 요금제, 한도, 현재 월간 AI 사용량을 조회하는 읽기 전용 도구입니다. 카드를 읽거나 변경하지 않습니다.

두 경로 모두 선택한 워크스페이스 안에서만 데이터를 읽고 쓸 수 있습니다. 공개된 리소스는 `workspace`, `cards`, `decks`, `review_events`이며, 결과는 SQL 문당 최대 100행입니다. SQL 형식의 인터페이스는 지원하는 문법이 제한되어 있으며, PostgreSQL을 그대로 사용할 수 있는 인터페이스가 아닙니다. OpenAPI 스키마는 없으므로, OpenAPI 스키마에서 자동 생성한 클라이언트를 사용하는 작업에는 다른 인터페이스가 필요합니다.

개발자나 AI 에이전트는 이를 사용해 자신이 소유한 플래시카드를 자동화할 수 있습니다. Quizlet URL을 읽거나, Quizlet 계정을 복제하거나, 문서화되지 않은 Quizlet 클라이언트로 동작할 수는 없습니다. Quizlet 자동 가져오기 기능은 없습니다. 데이터를 옮기려면 먼저 직접 만든 세트의 용어와 정의를 내보내고, 텍스트를 확인한 뒤, 대상 시스템의 카드 필드에 대응시키세요. 대상 시스템은 자체 학습 상태를 만들며, Quizlet 기록은 옮겨지지 않습니다.

API 접근 외의 제품 차이는 [오픈 소스 Quizlet 대안 비교](/blog/quizlet-alternative/)에서 확인하세요.

## 비공개 브라우저 요청은 안전한 지름길이 아닙니다

Quizlet의 웹 인터페이스는 다른 현대 웹 애플리케이션처럼 네트워크 요청을 보냅니다. 그 요청 중 하나를 발견했다고 해서 프로그램에서 사용할 수 있는 지원되는 엔드포인트가 되는 것은 아닙니다.

비공개 브라우저 엔드포인트는 세션 쿠키, 내부 형식, 악용 방지 장치, 현재 인터페이스를 전제로 한 동작에 의존할 수 있습니다. 공개 버전 관리나 이전 안내 없이 바뀔 수도 있습니다. 더 직접적인 문제는, 2026년 5월 28일에 마지막으로 개정된 [Quizlet 이용약관](https://quizlet.com/tos)이 스크래핑과 그 밖의 자동화된 추출, 허가받지 않은 서비스 자동 이용을 금지한다는 점입니다.

개인 스크립트조차 이런 방식에 의존하면 불안정하고 위험합니다. 제품이라면 더욱 그렇습니다. 여기서는 추측한 엔드포인트나 리버스 엔지니어링 절차를 제공하지 않겠습니다.

직접 만든 세트를 한 번 옮겨야 한다면 내보내기를 사용하세요. 학습자가 다른 페이지에서 공개 세트를 이용해야 한다면 임베드를 사용하세요. ChatGPT나 Google Classroom에서 해당 작업을 하려면 그 제품을 위한 공식 연동을 사용하세요. 반복적으로 읽고 쓰려면 자동화 규약을 문서화한 소프트웨어를 선택하거나, Quizlet이 그런 규약을 공개할 때까지 Quizlet에서 하는 부분은 수동으로 처리하세요.

## API 제공 여부가 바뀌었는지 확인하는 방법

이 글의 사실 확인일 이후 Quizlet이 개발자 프로그램을 시작할 수도 있습니다. 확인할 근거는 누가 등록할 수 있는지, 인증이 어떻게 작동하는지, 어떤 카드 작업을 지원하는지, 어떤 사용 규칙이 적용되는지를 설명하는 공식 개발자 포털이나 문서입니다.

또 다른 서드파티 래퍼가 나와도 답은 바뀌지 않습니다. 새로운 파트너 연동도 마찬가지입니다. Quizlet이 개발자가 직접 등록해 API를 이용하는 방법을 문서화하기 전까지는 현재 Quizlet API를 사용할 수 있다는 주장을 신중하게 판단하고, 실제 작업에 맞는 지원되는 방법을 선택하세요.
