2026年9月12日現在、Quizletの公開ドキュメントには、MCPサーバーも、セルフサービスで使える開発者向け公開APIも記載されていません。Claude、Codex、その他のMCPクライアントに貼り付ける「Quizlet MCP」のURLを探しても、Quizletが公式に案内する設定方法は今のところありません。

Quizletには、ChatGPT向けの公式アプリがあります。ChatGPTの会話から新しいQuizletセットを作れますが、これは用途を限定したフローであり、再利用できるQuizlet MCPサーバーではありません。既存のカードへエージェントから継続的にアクセスしたいなら、現実的な手順は、自分で作ったセットのテキストをエクスポートし、未編集の原本を残して移行内容を確認したうえで、エージェントによる読み書きを明示的にサポートするフラッシュカードシステムを使うことです。

**事実確認日：** 2026年9月12日。

> **開示事項：** 私はKirill Markinで、Flashcards Open Source Appを開発しています。以下では、そのMCPサーバーとAgent APIを代替手段として紹介します。FlashcardsからQuizletアカウントへ接続したり、QuizletのURLをインポートしたりすることはできません。

## ChatGPTアプリ、エクスポート、MCPはそれぞれ用途が違う

[Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro)は、AIアプリケーションを外部システムに接続するためのオープン標準です。通常、MCPサーバーは、対応クライアントから接続できる決まったエンドポイントと、呼び出し可能なツールを提供します。

Quizletの[ChatGPT公式アプリに関する発表](https://quizlet.com/blog/quizlet-comes-to-chat-gpt)で説明されている仕組みは、これとは別です。ChatGPTにQuizletアプリをインストールし、プロンプトの先頭に`@Quizlet`を付けます。生成されたフラッシュカードをChatGPT内でプレビューしたあと、そのセットをQuizletで開いて自分向けに調整し、学習します。

「ChatGPTの会話からQuizletセットを作る」という用途には便利です。ただし、この発表では、汎用のQuizlet MCPエンドポイントも、ClaudeやCodexから自分のQuizletライブラリへアクセスする方法も、開発者が再利用できる認証情報も公開されていません。

ここで扱っているのは、Quizletが公開ドキュメントで提供しているインターフェースだけです。Quizletの非公開または社内向けインフラについて判断するものではありません。開発者向けアクセス全体の線引きは、[Quizletに公開APIはある？ 2026年の現状と安全な代替手段](/blog/quizlet-api/)で説明しています。

違いを整理すると、次のようになります。

| 実際にやりたいこと | 今使える正式な方法 | 期待できること |
| --- | --- | --- |
| ChatGPTの会話から新しいQuizletセットを作る | QuizletのChatGPT公式アプリ | ChatGPT内の`@Quizlet`専用フローを使い、その後Quizletで編集・学習する |
| 自分で作ったセットから用語と定義を移す | Quizletウェブサイトのエクスポート | 保存して内容を確認できる、一度きりのテキストコピー |
| ClaudeやCodexなどのエージェントからフラッシュカードを繰り返し読み書きする | MCPサーバーまたはAgent APIがドキュメント化されたフラッシュカードシステム | Quizletではなく、移行先のワークスペースへ認証付きでアクセスする |
| Quizletアカウントのデータを使ってソフトウェアを作る | 公式の開発者向けドキュメント、または許可されたパートナー向け手段が提供されるのを待つ | 現在、セルフサービスで使えるQuizlet APIやMCPの公開仕様はない |

QuizletのChatGPTアプリが担うのは、決められた1つの作成フローです。エクスポートは一度きりの移行、MCPはツールを明示的に公開しているシステムへの継続的なアクセスに使います。この3つは互いに置き換えられるものではありません。

## 正式に使える最短ルートを選ぶ

ChatGPT公式アプリが目的に合うなら、それを使ってください。1つの会話から1つのQuizletセットを作るだけなら、わざわざ別のシステムを挟む必要はありません。

バックアップや一度きりの移行が目的なら、Quizletのエクスポートを使います。翌日またエージェントを使ってデッキを探し、カードを追加・修正したいなら、移行先にドキュメント化された読み書き用インターフェースが必要です。Quizletがそうしたインターフェースを公開するまでは、この継続的な処理をQuizletアカウントへの正式な直接接続として実現することはできません。

Quizletのデータを前提にした独自ソフトウェアでも、線引きは同じです。ブラウザで見つけたリクエストや古いラッパー、誰かがリバースエンジニアリングした連携は、現在の開発者向けドキュメントの代わりにはなりません。

## 自分で作ったセットは、やり直せる形でエクスポートする

Quizletの[公式エクスポート手順](https://help.quizlet.com/hc/en-us/articles/360034345672-Exporting-your-sets)によると、セットをエクスポートできるのは作成者本人だけで、この機能はウェブサイトでしか使えません。手順は**More → Export → Copy text**です。用語と定義は含まれますが、画像はエクスポートできず、コピーしたセットも対象外です。

自分で作ったセットなら、慎重に進めても手順はシンプルです。

1. Quizletのウェブサイトからエクスポートし、結果をプレーンテキストファイルに貼り付ける。
2. 区切り文字、改行、文面を変更する前に、未編集のUTF-8コピーを保存する。
3. 未編集の原本には触れず、複製した作業用ファイルを編集する。
4. 冒頭、中ほど、末尾のサンプルに加え、複数行の定義とラテン文字以外の文字も確認する。
5. 作業用ファイルをインポートまたは添付し、表面と裏面を数枚プレビューしてからカードを保存する。
6. 移行先のデッキを実際に開いて動作を確認できるまで、Quizletセットと未編集の原本を残す。

区切り文字、CSV、ファイルの詳しいチェック項目は、[Quizletのセットをエクスポートする方法【2026年版】](/blog/how-to-export-quizlet-sets-and-turn-them-into-fsrs-flashcards/)にまとめています。ただし、ひとつ見落としやすい制約があります。エクスポートで移せるのはカードのテキストだけで、Quizletの画像、フォルダ、学習履歴、習熟状況、スケジュール情報は移りません。

移行をやり直せる形にしておくのは、そのためです。複数行の定義が2枚のカードに分かれたり、区切り文字の位置でフィールドがずれたりしても、未編集のファイルがあれば元の内容と照合できます。

## エクスポート後にClaudeとCodexで使えるもの

Flashcards Open Source AppのリモートMCPエンドポイントは、次のとおりです。

`https://mcp.flashcards-open-source-app.com/mcp`

[MCPコネクターのドキュメント](/docs/mcp-connector/)では、`list_workspaces`、読み取り用の`sql_query`、書き込み用の`sql_execute`という3つのツールを定義しています。対話型MCPクライアントではOAuthで認証できます。ターミナルで動くエージェントは、代わりに[Agent APIのドキュメント](/docs/api/)から始め、公開されているHTTPフローを利用できます。

この仕組みを使っても、FlashcardsがQuizletコネクターになるわけではありません。正式に対応している手順は次のとおりです。

1. 自分で作ったQuizletセットからテキストをエクスポートする。
2. 未編集の原本を残し、作業用コピーを確認する。
3. 移行先の形式に対応付けたカードを確認してから、Flashcardsに保存する。
4. 作成したFlashcardsワークスペースを対応クライアントへ接続し、以後の読み書きに使う。

Claudeでの接続手順は、[FlashcardsをMCPでClaudeに接続する方法](/blog/how-to-connect-flashcards-to-claude-with-mcp/)で説明しています。Codexやその他のエージェントは、それぞれの環境が対応している、ドキュメント化されたMCPまたはAgent APIの経路を利用できます。

Flashcardsは、QuizletのURLを読み取ったり、Quizletアカウントをミラーリングしたり、Quizlet側で後から加えた変更を同期したりすることはできません。エクスポートに含まれない画像や学習履歴も復元できません。自分で移した内容をもとに独自のカードを作成し、新しいスケジュール状態を設定します。

エージェント連携以外の違いも含めて移行する価値があるか検討するなら、[オープンソースのQuizlet代替アプリ比較](/blog/quizlet-alternative/)を参照してください。

## 権限の範囲は作業に必要な最小限に絞る

公開仕様があれば、連携時に推測すべきことは減ります。ただし、MCPの操作がすべて安全になるわけではありません。OAuthは接続を認証するだけです。AIが作ったカードの正確さを保証したり、取得したカードデータをフラッシュカードサービス内に閉じ込めたり、編集が自分の意図に沿うかを判断したりはしません。

Flashcardsでは、読み取り操作と書き込みツールの`sql_execute`を分けています。ただし、OAuth認証情報の対象はコネクター全体に及ぶため、ツールをブロックできるか、どの操作で承認を求めるかはクライアント次第です。まずは機密情報を含まない小さなワークスペースから始めてください。エージェントが読み取るデータを作業に必要な範囲だけに絞り、クライアントが対応している場合は、書き込みを1回ごとの承認にします。承認前に、対象のワークスペースと提案された変更を確認してください。

AIクライアントがデータを保持する期間や、データの取り扱い条件を確認するまでは、非公開の学習資料を接続しないでください。詳しい脅威モデルは、[フラッシュカードでMCPを安全に使える？](/blog/is-mcp-safe-for-flashcards/)で説明しています。最初の移行では、未編集のエクスポートを残し、カードを数枚プレビューし、範囲を絞った書き込みだけを承認すれば十分です。次へ進む前に、移行先のアプリで結果を確認してください。

## ブラウザ内の非公開通信をAPI代わりにしない

ブラウザの開発者ツールで見えるリクエストも、Quizletの公開APIではありません。非公開のエンドポイントは、セッションクッキーや内部形式、予告なく変わる動作に依存している可能性があります。自動利用は、[Quizletの利用規約](https://quizlet.com/tos)と、その教材に対して自分が持つ権限の両方に従う必要があります。

この記事では、スクレイピングの手順やリバースエンジニアリングされたエンドポイントを紹介しません。ChatGPT公式アプリが目的に合うなら、それを使ってください。自分で作ったセットを一度だけ移すなら、エクスポートを使います。エージェントから繰り返し読み書きする必要があるなら、確認済みの内容を、そのインターフェースを公開しているシステムへ移してください。Quizletが新しい方法をドキュメント化するまでは、Quizlet側の操作は手作業で続けましょう。
