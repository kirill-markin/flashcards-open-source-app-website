Ankiでは、新規カードの位置が10のカードでも、位置が60のカードより後に出ることがあります。親デッキを選んで学習するとき、収集順が**デッキ順（Deck）**、並べ替え順が**収集した順（Order gathered）**だと、位置10のカードがある子デッキに進む前に、先に回る子デッキからカードを集め終えることがあるためです。ブラウザーで作成日順に並べ替えても、学習時のキューは変わりません。

Ankiは新規カードの出題順を2段階で決めます。まず**収集**で、今日の上限に収まるようにカードを選びます。次に**並べ替え**で、集めたカードの出題順を決めます。出るはずのカードが選ばれていないのか、選ばれたカードが予想と違う順で出ているのか。まずはそこを切り分けましょう。

対象はデスクトップ版Ankiの通常デッキです。以下の6枚の例は、2026年10月6日に確認した公式マニュアルと公開版をもとに、この記事用に紙の上で計算したものです。実機での検証は行っていません。[Anki 26.09.3](https://github.com/ankitects/anki/releases/tag/26.09.3)

## 出したい順番に合わせて設定を選ぶ

学習時にクリックするデッキの**オプション（Options）**を開き、**表示順序（Display Order）**を確認します。親デッキから学習を始めると、子デッキのカードも含め、そのセッション全体に親デッキの表示順序が適用されます。

| 出したい順番 | 新規カードの収集順（New Card Gather Order） | 新規カードの並べ替え順（New Card Sort Order） |
| --- | --- | --- |
| 選んだデッキとその配下をまとめて、新規カードの位置が小さい順に出す | 位置の昇順（Ascending position） | 収集した順 |
| 子デッキ名のアルファベット順を優先し、各子デッキ内では位置が小さい順に出す | デッキ順 | 収集した順 |
| 選ぶカードはそのままで、出題順だけをシャッフルする | 目的に合った収集順 | ランダム（Random） |

この組み合わせは、Anki公式マニュアルの定義に沿っています。**位置の昇順**で使うのは、保存されている新規カードの位置です。カードを追加するときの挿入順や、あとから手動で位置を変更する操作によって値が変わるため、作成日順になるとは限りません。[収集順の説明（英語）](https://docs.ankiweb.net/manual/deck-options#new-card-gather-order)・[並べ替え順の説明（英語）](https://docs.ankiweb.net/manual/deck-options#new-card-sort-order)

表示順序はプリセットに保存されます。変更する前に、そのデッキに割り当てられているプリセットと、同じプリセットを使うほかのデッキを確認しましょう。1日の上限には**このデッキ（This deck）**や**今日のみ（Today only）**の上書きを使えます。表示順序はプリセットで共有されるので、このデッキだけ変えたい場合は先にプリセットを分けます。[デッキ専用のプリセットを用意する手順（英語）](/blog/anki-deck-options-presets/)

## どの4枚が選ばれるかを追ってみる

通常の親デッキ `OrderLab` に子デッキが2つあり、カードは次の6枚だけだとします。どれも別々の**基本（Basic）**ノートから作られ、各ノートにカードは1枚だけあります。6枚ともカードタイプ番号は同じで、同じノートから作られた兄弟カードはありません。

| カード | デッキ | 保存されている新規カードの位置 |
| --- | --- | --- |
| A | OrderLab::01 First | 20 |
| B | OrderLab::01 First | 40 |
| C | OrderLab::01 First | 60 |
| D | OrderLab::02 Second | 10 |
| E | OrderLab::02 Second | 30 |
| F | OrderLab::02 Second | 50 |

6枚とも新規カードで、一時非表示（buried）や学習停止（suspended）のカードはなく、フィルターデッキにも入っていないとします。開始時点ではほかのカードも、学習中のカードの繰り返し出題も、復習もありません。今日の学習はまだ始めていません。`OrderLab` に上位デッキはなく、適用される復習上限には新規カード6枚すべてを出せる余裕があります。

学習するデッキとして **OrderLab** を選びます。実際に適用される新規カードの上限は **4** 枚です。Firstの上限は **3** 枚、Secondは **2** 枚で、一時的な上書きはありません。どちらの比較でも、並べ替え順は**収集した順**にします。どちらも手を加えていない同じコレクションを出発点とし、比較の合間にカードに回答せず、紙の上で順序を追います。

収集順を**デッキ順**にした場合の流れはこうです。

1. デッキ名のアルファベット順で、Ankiは `02 Second` より先に `01 First` を処理します。
2. 位置が小さい順に **A、B、C** を集めます。Firstから3枚入ったので、親デッキの残り枠は1枚です。
3. Secondから **D** を集めると、親デッキの上限である4枚に達します。

新規カードが初めて出る順番は **A → B → C → D** と予想できます。EとFは収集されません。

**位置の昇順**で収集する場合、2つの子デッキを通した候補の順番は **D → A → E → B → F → C** です。先頭の4枚はSecondから2枚、Firstから2枚で、合計4枚。どの上限にも収まるので、収集はそこで止まります。

予想される初回の出題順は **D → A → E → B** です。CとFは収集されません。公開版のAnkiは、カードを取り込むたびに、そのデッキと親デッキの上限を適用します。[収集処理の実装](https://github.com/ankitects/anki/blob/26.09.3/rslib/src/scheduler/queue/builder/gathering.rs)

Secondの上限が2枚でも、2枚分の枠が確保されるわけではありません。デッキ順ではFirstが4枠のうち3枠を先に使うため、Secondから入るのは1枚です。位置の昇順で両方から2枚ずつ入るのは、この例の位置関係によるものです。別のコレクションでも均等に選ばれるとは限りません。

## 6枚すべてを収集して、出題順だけを比べる

次は、6枚すべてが入る条件で計算します。親デッキの上限を **6** 枚、Firstを **3** 枚、Secondを **3** 枚に設定します。並べ替え順は**収集した順**のままです。

| 収集順 | 上限（親デッキ / First / Second） | 予想される初回の出題順 |
| --- | --- | --- |
| デッキ順 | 6 / 3 / 3 | A → B → C → D → E → F |
| 位置の昇順 | 6 / 3 / 3 | D → A → E → B → F → C |

どちらも6枚すべてを選ぶので、違いは出題順だけです。Secondの上限を2枚に据え置いて親デッキだけ6枚にすると、収集されるのは5枚で、Fは入りません。上限を変えたのは動作を比べるための計算上の条件です。実際に1日の新規カードの上限を引き上げることは勧めていません。

## 並べ替えで収集から外れたカードは追加できない

上限を元の **4 / 3 / 2** に戻し、**新規カードの並べ替え順**だけを**ランダム**に変えます。

| 収集順 | シャッフルの対象になるカード | 並べ替えでは追加できないカード |
| --- | --- | --- |
| デッキ順 | A、B、C、D | E、F |
| 位置の昇順 | D、A、E、B | C、F |

シャッフルで変わるのは出題順です。選ばれたカードの顔ぶれは変わらず、この表からシャッフル後の具体的な順番を予測することはできません。公開版のAnkiが並べ替えるのは、すでに収集したカードです。[並べ替え処理の実装](https://github.com/ankitects/anki/blob/26.09.3/rslib/src/scheduler/queue/builder/sorting.rs)

**カードタイプ順、同じタイプ内では収集した順（Card type, then order gathered）**も、収集済みのカードに適用されます。この例では基本ノートから作られた6枚のカードのタイプ番号がすべて同じなので、収集したときの順序が保たれます。

並べ替えだけを見る別の例として、テンプレートが複数あるノートから作られた4枚が、すでに **W（タイプ2）、X（タイプ1）、Y（タイプ2）、Z（タイプ1）** の順に収集されているとします。カードタイプ順で並べると **X → Z → W → Y** になります。タイプ1が先に来て、同じタイプ内では収集時の順序が保たれます。この例の出発点は収集後です。一時非表示の設定に応じてどの兄弟カードが収集されるかは、この例からは分かりません。

タイプ番号は、ノートタイプ内でのカードテンプレートの位置を表します。「見て分かるか」を問うカードか、「答えを自分で思い出せるか」を問うカードかは、テンプレート次第です。カードタイプ順で順方向の問題がすべて先に出るかどうかは、実際の問題を見て確認しましょう。

## 位置を変える前にブラウザーで確認する

**ブラウザー（Browse）**を開き、**カード（Cards）**モードに切り替えて、対象のデッキとその配下を検索します。この例で使う検索式は次のとおりです。

```text
deck:OrderLab is:new
```

列見出しのメニューから、**問題（Question）**、**カード（Card）**、**デッキ（Deck）**、**期限（Due）**、**作成日（Created）**を表示します。新規カードの**期限**に表示されるのはキュー内の位置で、**作成日**はノートが作成された日時です。**並べ替えフィールド（Sort Field）**には、並べ替え用に指定されたノートフィールドの値が表示されます。列見出しで並べ替えると表の表示順だけが変わり、保存された位置や学習時の収集順の設定はそのままです。[ブラウザーの列の説明（英語）](https://docs.ankiweb.net/manual/browsing#columns)

`is:new` の検索結果には、学習停止中や一時非表示の新規カードも含まれることがあります。該当するカードの**期限**の値は括弧付きで表示されます。次の検索式を使うと、それらに加えて、現在フィルターデッキに入っているカードも除外できます。

```text
deck:OrderLab is:new -is:suspended -is:buried -deck:filtered
```

デッキ名に空白がある場合は、`deck:"My Deck"` のように名前を引用符で囲みます。[カードの状態で検索する方法（英語）](https://docs.ankiweb.net/manual/searching#card-state)・[デッキ名で検索する方法（英語）](https://docs.ankiweb.net/manual/searching#tags-decks-cards-and-notes)

この検索で絞り込めるのは、あくまで候補です。上限や兄弟カードの自動一時非表示によって、今日のキューに入るカードはさらに減ることがあります。[一時非表示と学習停止の違い（英語）](/blog/anki-bury-vs-suspend/)

保存されている位置が意図どおりなら、そのままで大丈夫です。変更が必要なら、元の位置を控え、対象の新規カードを少数だけ選んで**カード → 位置を変更（Cards → Reposition）**を使います。実行前にダイアログを確認してください。**既存カードの位置をずらす（Shift position of existing cards）**をオンにすると、選択していないカードでも、位置の値が大きいものは動くことがあります。オフの場合は新しい位置が既存の位置と重なることがあり、同じ位置のカードがどちらから出るかは、その値だけでは分かりません。[位置を変更する操作の説明（英語）](https://docs.ankiweb.net/manual/browsing#cards)

収集順や並べ替え順を変えるために、学習や復習の履歴を消す必要はありません。確認するのは新規カードの位置と表示順序です。

## 学習時に選ぶデッキと、今日の残り枠を確認する

最初の例で `OrderLab::02 Second` を直接選ぶと、候補はD、E、Fに限られます。上限が2枚で、収集順が**位置の昇順**、並べ替え順が**収集した順**なら、予想される出題順は **D → E** です。上位デッキの上限が適用される場合でも、親デッキには4枚分の枠が残っているので、この2枚を出せます。親デッキを選んでデッキ順で収集し、上限を **4 / 3 / 2** にした場合は、**A → B → C → D** です。

OrderLabから学習を始めると、そのセッションの表示順序にはOrderLabの設定が使われます。学習時に選んだデッキが表示順序と全体の上限を決め、該当する子デッキの上限も適用されます。子デッキを直接選んだときに上位デッキの上限も適用するかは、**上位デッキから上限を適用（Limits start from top）**で決まります。[子デッキのルール（英語）](https://docs.ankiweb.net/manual/deck-options#subdecks)・[上位デッキの上限を適用する設定（英語）](https://docs.ankiweb.net/manual/deck-options#limits-start-from-top)

復習の上限も確認しましょう。既定では、復習上限によって新規カードの枚数も制限されます。**新規カードに復習上限を適用しない（New cards ignore review limit）**をオンにすると、この制限が外れます。この設定と**上位デッキから上限を適用**は、どちらもコレクション全体に適用されます。新規カードの上限から今日の残り枚数を見積もる前に、両方の設定を控えておきましょう。[公開版の1日の上限設定画面の実装](https://github.com/ankitects/anki/blob/26.09.3/ts/routes/deck-options/DailyLimits.svelte)

問題を確認するだけなら、ブラウザーの**プレビュー（Preview）**で、カードに回答せずに確認できます。次の通常の学習セッションでは、以下を記録してみてください。

| 記録すること | 確認できること |
| --- | --- |
| 学習時にクリックしたデッキと、そのプリセット、収集順、並べ替え順 | どの表示順序がセッションに適用されるか |
| 出ると予想したカードと、保存されている位置 | ずれているのは、選ばれるカードか出題順か |
| 新規カードと復習の上限、デッキ別・今日のみの上書き、今日すでに学習した分 | 今日の枠がどれだけ残っているか |
| 上位デッキの上限と、コレクション全体に適用される2つの上限設定 | ほかにどの上限がかかるか |
| 一時非表示や学習停止のカード、フィルターデッキ内のカード、兄弟カード | 候補に見えても出題されない可能性があるのはどれか |
| 新規カードが初めて出た順番。学習中の繰り返し出題とは分けて記録する | 新規カードが予想どおりの順番で初めて出たか |

新規カードに回答したあと、学習中のカードがセッションの途中で繰り返し出ることがあります。**新規カードと復習カードの順序（New/Review Order）**では、新規カードを復習カードの前に出すか、後に出すか、混ぜて出すかを決めます。新規カードの収集順と並べ替え順には、それぞれの設定が引き続き使われます。公開版のAnkiは、新規カードを並べ替えたあとに、これらの種類のカードを組み合わせます。[キューを組み立てる処理の実装](https://github.com/ankitects/anki/blob/26.09.3/rslib/src/scheduler/queue/builder/mod.rs)

収集されると予想したカードと、各カードが初めて出る順番が実際の出題と合えば、確認は完了です。まだ食い違う場合は、原因を絞り込めるように、カードの位置、設定、学習時に選んだデッキ、Ankiのバージョン、実際の出題順、関係するアドオンを控えておきましょう。

特定のテーマを追加で練習したい場合は、フィルターデッキを使う別の手順があります。[フィルターデッキで追加練習する方法（英語）](/blog/anki-filtered-decks-without-rescheduling/)
