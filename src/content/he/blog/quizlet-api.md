נכון ל-18 באוגוסט 2026, Quizlet אינו מפרסם תיעוד של API ציבורי שפתוח למפתחים לשימוש עצמאי, וגם לא פורטל ציבורי למפתחים. למפתח עצמאי אין כיום דרך רשמית לרשום אפליקציה, לקבל מפתח API של Quizlet ולהשתמש בנקודות קצה מתועדות לקריאה או לכתיבה של נתוני כרטיסיות.

הממצא הזה מתייחס לתיעוד הציבורי של Quizlet, ולא למערכות הפנימיות שלו. ל-Quizlet בהחלט יש שילובים עם מוצרים ושותפים. האפליקציה שלו ב-ChatGPT והתוסף ל-Google Classroom הם שתי דוגמאות עדכניות. אף אחד מהם אינו פותח בפני אפליקציות אחרות API כללי למפתחים של Quizlet.

**העובדות נבדקו:** ב-18 באוגוסט 2026.

> **גילוי נאות:** אני קיריל מרקין, ואני מפתח את Nibomo, שה-API לסוכנים ושרת ה-MCP שלה מופיעים בהמשך כחלופות. Nibomo אינה תואמת ל-Quizlet ואינה מייבאת ערכות מ-Quizlet באופן אוטומטי.

## התשובה הקצרה: אין API מתועד של Quizlet שפתוח לשימוש עצמאי

אם חיפשתם ״האם ל-Quizlet יש API?״ כדי לבצע אוטומציה בתוך Quizlet עצמו, התשובה המעשית כיום היא ש**אין API ציבורי מתועד שפתוח לשימוש עצמאי**.

כמה מהתכונות הרשמיות עשויות להיראות כמו ממשקי API למי שאינו מכיר אותן. בפועל, הן נותנות מענה למשימות ממוקדות יותר:

| מה אתם צריכים | הדרך הנתמכת | למה היא מתאימה | מה היא אינה מספקת |
|---|---|---|---|
| להעביר טקסט מערכה שיצרתם | [ייצוא באתר של Quizlet](https://help.quizlet.com/hc/en-us/articles/360034345672-Exporting-your-sets) | עותק חד-פעמי של מונחים והגדרות | תמונות, ייצוא של ערכה שהועתקה, היסטוריית לימוד או גישה ל-API |

ההבחנה פשוטה: להעתקה חד-פעמית של טקסט הכרטיסיות שלכם צריך ייצוא. להצגת Quizlet בעמוד אחר צריך הטמעה. שילוב ייעודי פועל רק בתוך תהליך העבודה של אותו מוצר. תוכנה שיוצרת, קוראת ועורכת כרטיסיות שוב ושוב צריכה API מתועד לקריאה ולכתיבה.

## ייצוא, הטמעה וגישה לשותפים אינם API ציבורי

API ציבורי נותן למפתחים חיצוניים מפרט ברור שאפשר להסתמך עליו: תיעוד, אימות, פעולות נתמכות, כללי שימוש ודרך לקבל פרטי גישה. אף אחת מהאפשרויות ש-Quizlet מציע כיום לציבור אינה מספקת מסלול מלא כזה לשימוש עצמאי.

**הייצוא** של Quizlet הוא העברה ידנית. יוצר הערכה יכול להשתמש באתר כדי לסדר את המונחים וההגדרות, לבחור **העתקת טקסט (Copy text)** ולהדביק את התוצאה במקום אחר. לפי Quizlet, אי אפשר לייצא תמונות או ערכות שהועתקו, והתכונה זמינה רק באתר. זה מתאים להעברה חד-פעמית וזהירה. זה אינו מאפשר לתוכנה לשמור על סנכרון בין שתי מערכות.

**הטמעה** מאפשרת להציג תוכן, ולא לגשת לנתונים. Quizlet מאפשר להעתיק קוד HTML לערכה ציבורית במצב התאמה (Match), למידה (Learn), מבחן (Test), כרטיסיות (Flashcards) או איות (Spell). הפעילות המוטמעת שומרת על הלוגו של Quizlet, והלומדים משתמשים בממשק שלו. האפליקציה שלכם אינה מקבלת את הערכה כרשומות של כרטיסיות שאפשר לערוך.

**שילוב ייעודי** פועל לפי תהליך עבודה שהוסכם עם מוצר מסוים. Quizlet יכול להשתלב עם ChatGPT או Google Classroom בלי להציע את אותו ממשק לכל מפתח. ההשקות האלה מוכיחות שהשילובים האלה קיימים; הן אינן מוכיחות שמאחוריהם יש API ציבורי של Quizlet שפתוח לשימוש כללי.

מאותה סיבה, ספריית עטיפה ישנה או בקשה שרואים בכלי המפתחים של הדפדפן אינן API נתמך של Quizlet. מה שחסר הוא תיעוד ציבורי ומפרט יציב שמפתחים יכולים להסתמך עליו.

## בחרו את הדרך שמתאימה למשימה

### לגיבוי חד-פעמי או להעברה, השתמשו בייצוא

השתמשו בתהליך הייצוא הרשמי של Quizlet עבור ערכה שיצרתם. מכיוון שהתהליך מסתיים ב-**העתקת טקסט (Copy text)**, שמרו ללא שינוי את העותק הראשון שהדבקתם, לפני שתסדרו את המפרידים או תמפו את השדות. אתם שומרים מונחים והגדרות, ולא מורידים קובץ שמאפשר לשחזר חפיסה שלמה. התמונות והיסטוריית הלימוד נשארות ב-Quizlet.

רשימת הבדיקה המעשית נמצאת במאמר [איך לייצא ערכות מ-Quizlet ב-2026](/he/blog/how-to-export-quizlet-sets-and-turn-them-into-fsrs-flashcards/). הוא מסביר איך לעבוד עם עותק גולמי ועותק עבודה, UTF-8, טאבים והגדרות מרובות שורות, ומה ההבדל בין העברת תוכן הכרטיסיות להעברת נתוני התזמון.

ייצוא מתאים להעברה חד-פעמית. הוא אינו מתאים ליצירה יומיומית, לסנכרון או לעריכות חוזרות באמצעות תוכנה.

### להצגת פעילות, השתמשו בהטמעה הרשמית

אם הלומדים צריכים לתרגל עם ערכת Quizlet ציבורית דרך אתר הכיתה או עמוד במערכת לניהול למידה, השתמשו בקוד ההטמעה ש-Quizlet מספק באתר שלו. בחרו את הפעילות, לחצו על **העתקת HTML (Copy HTML)** והוסיפו את הקוד לעמוד. הלומדים מקבלים פעילות אינטראקטיבית של Quizlet; האתר המארח אינו מקבל את נתוני הכרטיסיות הגולמיים.

לעיתים קרובות זה כל מה שמורה צריך. לקרוא לזה API רק גורם לדרישה להישמע מורכבת יותר ממה שהיא.

### עבור ChatGPT או Google Classroom, השתמשו בשילוב הייעודי

ההכרזה של Quizlet על השילוב עם ChatGPT מ-10 במרץ 2026 מתארת תהליך מוגדר: מחברים את האפליקציה של Quizlet, מתחילים הנחיה ב-`@Quizlet`, רואים ב-ChatGPT תצוגה מקדימה של הערכה שנוצרה, ואז פותחים אותה ב-Quizlet כדי להתאים אותה לצרכים שלכם וללמוד. זו דרך נתמכת ליצור ערכת Quizlet מתוך אותה שיחה. היא אינה מספקת פרטי גישה ל-API של Quizlet שאפשר להשתמש בהם בבוט, בסקריפט או באתר שלכם.

גם ההכרזה של Quizlet על Google Classroom מ-30 ביוני 2026 מתארת תהליך מוגדר. התוסף מאפשר לאנשי הוראה למצוא ולהקצות פעילויות, ובהן שאלות תרגול, כרטיסיות ומשחקים, ואז לעקוב אחר השתתפות והתקדמות בתוך תהליך העבודה של Classroom. לפי Quizlet, נדרש Google Workspace for Education Plus; ייתכן שאנשי ההוראה יצטרכו שמנהל ה-IT שלהם ייתן הרשאה או יתקין עבורם את התוסף.

אם אחד התהליכים האלה כבר מתאים למטרה שלכם, השתמשו בו. אם אתם צריכים אפליקציה משלכם, אף אחד מהשילובים אינו תחליף לגישה ציבורית למפתחים.

### לאוטומציה חוזרת, בחרו ממשק מתועד לקריאה ולכתיבה

אוטומציה מתמשכת דורשת שהתוכנה שלכם תוכל לבצע את אותן פעולות באופן אמין שוב ושוב: ליצור כרטיסיות מהערות, להציג רשימת חפיסות, לעדכן תשובות או לנהל סביבת עבודה לאורך זמן. ייצוא ללוח ההעתקה אינו מספק ממשק שאפשר להסתמך עליו לצורך זה.

הדרך הבטוחה היא להשתמש במערכת כרטיסיות שמפרסמת במפורש כיצד תוכנות חיצוניות מזדהות ואילו פעולות קריאה וכתיבה היא תומכת בהן. ייתכן שלצורך האוטומציה תבחרו חלופה ל-API של Quizlet, ותמשיכו להשתמש ב-Quizlet למשימות הלימוד שנתמכות במוצר הזמין לציבור.

## מה חלופת ה-API של Nibomo מספקת בפועל

Nibomo מפרסמת שתי דרכי גישה לאותו ממשק מוגבל לנתוני המשתמש:

- [ה-API החיצוני לסוכנים](/he/docs/api/) מתחיל ב-`GET https://api.nibomo.com/v1/`. התשובה הראשונית מנחה את הסוכן להתחבר באמצעות קוד חד-פעמי באימייל, ליצור מפתח API ולבחור סביבת עבודה. הקריאה נעשית בנתיב שאילתות בסגנון SQL; הכתיבה נעשית בנתיב ביצוע נפרד.
- [שרת ה-MCP המרוחק](/he/docs/mcp-connector/) זמין בכתובת `https://mcp.nibomo.com/mcp`. לקוחות MCP מקבלים שמונה כלים: `list_workspaces`, `sql_query`, `sql_execute`, `get_guide`, וכלי החזרות `next_review_card`, `reveal_answer` ו-`submit_review`.

`get_usage_limits` — כלי לקריאה בלבד של תוכנית המינוי בחשבון, המגבלות והשימוש בבינה מלאכותית בחודש הנוכחי; הוא אינו קורא או משנה כרטיסיות.

בשתי דרכי הגישה, הפעולות מוגבלות לסביבת העבודה שנבחרה. המשאבים המתועדים הם `workspace`, `cards`, `decks` ו-`review_events`, והתוצאות מוגבלות ל-100 שורות לפקודה. הממשק בסגנון SQL תומך בניב מוגבל של SQL ואינו נותן גישה ישירה ל-PostgreSQL. אין סכמת OpenAPI, ולכן תהליכים שתלויים בלקוחות שנוצרים אוטומטית מסכמת OpenAPI יצטרכו ממשק אחר.

זה יכול לעזור למפתח או לסוכן בינה מלאכותית לבצע אוטומציה בכרטיסיות שבבעלותם. הממשק אינו יכול לקרוא תוכן מכתובת Quizlet, ליצור עותק מסונכרן של חשבון Quizlet או לשמש כלקוח לא מתועד של Quizlet. אין כלי לייבוא אוטומטי מ-Quizlet. להעברה, ייצאו תחילה את המונחים וההגדרות מהערכה שלכם, בדקו את הטקסט ואז מפו אותו לשדות הכרטיסיות במערכת היעד. מערכת היעד יוצרת נתוני לימוד משלה; ההיסטוריה של Quizlet אינה עוברת אליה.

להבדלים בין המוצרים מעבר לגישה ל-API, ראו את [ההשוואה לחלופת Quizlet בקוד פתוח](/blog/quizlet-alternative/).

## בקשות פרטיות של הדפדפן אינן קיצור דרך בטוח

הממשק באתר של Quizlet שולח בקשות רשת, כמו כל יישום אינטרנט מודרני. מציאת אחת הבקשות האלה אינה הופכת אותה לנקודת קצה נתמכת עבור התוכנית שלכם.

נקודות קצה פרטיות שהדפדפן פונה אליהן עשויות להיות תלויות בעוגיות סשן, בפורמטים פנימיים, במנגנונים למניעת שימוש לרעה ובהנחות שקשורות לממשק הנוכחי. הן יכולות להשתנות בלי ניהול גרסאות ציבורי או הנחיות למעבר. מעבר לכך, [תנאי השירות של Quizlet](https://quizlet.com/tos), שעודכנו לאחרונה ב-28 במאי 2026, אוסרים איסוף נתונים בסריקה (scraping) וחילוץ אוטומטי אחר, וכן שימוש אוטומטי לא מורשה בשירות.

זה בסיס לא יציב ומסוכן אפילו לסקריפט אישי, ובוודאי למוצר. לא אספק כאן נקודות קצה שניחשתי או הוראות להנדסה לאחור.

עבור ערכה שלכם, השתמשו בייצוא כשצריך העברה חד-פעמית. הטמיעו ערכה ציבורית כשהלומדים צריכים אותה בעמוד אחר. השתמשו בשילוב הייעודי עם ChatGPT או Google Classroom עבור התהליכים האלה בדיוק. לקריאה ולכתיבה חוזרות, בחרו תוכנה עם ממשק מתועד לאוטומציה — או המשיכו לבצע את הפעולות ב-Quizlet ידנית עד ש-Quizlet יפרסם ממשק כזה.

## איך לזהות שינוי במצב

Quizlet עשוי להשיק תוכנית למפתחים אחרי תאריך בדיקת העובדות של המאמר. הסימן שצריך לחפש הוא פורטל רשמי למפתחים או תיעוד שמסביר מי יכול להירשם, איך האימות עובד, אילו פעולות בכרטיסיות נתמכות ומהם כללי השימוש.

ספריית עטיפה נוספת של צד שלישי לא תשנה את התשובה. גם שותפות עם מוצר נוסף לא תשנה אותה. עד ש-Quizlet יפרסם תיעוד לגישה עצמאית של מפתחים, התייחסו בזהירות לטענות על API עדכני של Quizlet ובחרו בדרך הנתמכת שמתאימה למשימה בפועל.
