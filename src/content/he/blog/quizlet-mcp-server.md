נכון ל-12 בספטמבר 2026, בתיעוד הציבורי של Quizlet לא מופיעים שרת MCP או API ציבורי למפתחים הזמין בשירות עצמי. אם חיפשתם כתובת MCP של Quizlet כדי להדביק אותה ב-Claude, ב-Codex או בלקוח MCP אחר, אין כיום בתיעוד של Quizlet הוראות ציבוריות להגדרת חיבור כזה.

ל-Quizlet יש אפליקציה רשמית ב-ChatGPT. היא יכולה להפוך שיחה ב-ChatGPT לערכה חדשה ב-Quizlet, אבל תהליך העבודה הייעודי הזה אינו שרת MCP של Quizlet לשימוש חוזר. אם אתם זקוקים לגישה חוזרת של סוכן לכרטיסיות קיימות, הדרך המעשית היא לייצא טקסט מערכה שיצרתם, לשמור עותק גולמי, לבדוק את ההעברה ולהשתמש במערכת כרטיסיות שתומכת במפורש בקריאה ובכתיבה באמצעות סוכנים.

**העובדות נבדקו:** 12 בספטמבר 2026.

> **גילוי נאות:** אני Kirill Markin, ואני מפתח את Nibomo, ששרת ה-MCP וה-Agent API שלה מוצגים בהמשך כחלופות. Nibomo אינה יכולה להתחבר לחשבון Quizlet או לייבא כתובת URL של Quizlet.

## האפליקציה ב-ChatGPT, הייצוא ו-MCP מיועדים למשימות שונות

[Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro) הוא תקן פתוח לחיבור יישומי בינה מלאכותית למערכות חיצוניות. שרת MCP מספק בדרך כלל ללקוחות תואמים נקודת קצה ידועה ואוסף מוגדר של כלים שהם יכולים להפעיל.

[ההכרזה הרשמית של Quizlet על האפליקציה ב-ChatGPT](https://quizlet.com/blog/quizlet-comes-to-chat-gpt) מתארת תהליך אחר. מתקינים את אפליקציית Quizlet ב-ChatGPT, מתחילים הנחיה ב-`@Quizlet`, צופים בתצוגה מקדימה של הכרטיסיות שנוצרו בתוך ChatGPT, ואז פותחים את הערכה ב-Quizlet כדי להתאים אותה לצורכיכם וללמוד בעזרתה.

זה שימושי כשהמשימה היא ״להפוך את השיחה הזאת ב-ChatGPT לערכה ב-Quizlet״. ההכרזה אינה מפרסמת נקודת קצה כללית של Quizlet ב-MCP, אינה נותנת ל-Claude או ל-Codex גישה לספריית Quizlet שלכם ואינה מציעה פרטי הזדהות למפתחים לשימוש חוזר.

אין בכך שום קביעה לגבי התשתית הפרטית או הפנימית של Quizlet. הדברים מתארים רק את הממשק ש-Quizlet מעמידה לרשות הציבור בתיעוד שלה. גבולות הגישה למפתחים בהקשר הרחב יותר מוסברים במאמר [האם ל-Quizlet יש API ציבורי ב-2026?](/he/blog/quizlet-api/).

אפליקציית Quizlet ב-ChatGPT מטפלת בתהליך יצירה אחד. ייצוא מטפל בהעברה מוגדרת וחד-פעמית. MCP מטפל בגישה חוזרת למערכת שחושפת כלים במכוון. הם אינם תחליפים זה לזה.

## בחרו בדרך הנתמכת הקצרה ביותר

אם האפליקציה הרשמית ב-ChatGPT כבר מתאימה למשימה, השתמשו בה. אין סיבה להוסיף מערכת שנייה רק כדי ליצור ערכה אחת ב-Quizlet משיחה אחת.

אם אתם צריכים רק גיבוי או העברה חד-פעמית, השתמשו בייצוא של Quizlet. אם אתם צריכים שסוכן יחזור מחר, ימצא חפיסה, יוסיף כרטיסיות ויתקן אותן, נדרש ממשק קריאה וכתיבה מתועד בצד של מערכת היעד. עד ש-Quizlet תפרסם ממשק כזה, תהליך העבודה החוזר הזה אינו יכול להתבסס על חיבור ישיר ונתמך לחשבון Quizlet שלכם.

גם כשמפתחים תוכנה מותאמת שנבנית במיוחד סביב נתוני Quizlet, יש לעצור באותו גבול. בקשה שנשלחת מהדפדפן, ספריית מעטפת ישנה או אינטגרציה שמישהו פיתח בהנדסה לאחור אינם תחליף לתיעוד עדכני למפתחים.

## שמרו על אפשרות לחזור לאחור בייצוא של ערכה שיצרתם

לפי [הוראות הייצוא הרשמיות של Quizlet](https://help.quizlet.com/hc/en-us/articles/360034345672-Exporting-your-sets), רק יוצר הערכה יכול לייצא אותה, ורק דרך האתר. התהליך הוא **עוד (More) ← ייצוא (Export) ← העתקת טקסט (Copy text)**. הייצוא כולל מונחים והגדרות; Quizlet מציינת שאי אפשר לייצא תמונות ושערכות שהועתקו אינן ניתנות לייצוא.

כדי להעביר בזהירות ערכה שיצרתם, מספיקים כמה צעדים:

1. השתמשו בייצוא דרך האתר של Quizlet והדביקו את התוצאה בקובץ טקסט פשוט.
2. שמרו עותק UTF-8 ללא שינויים לפני שתשנו מפרידים, מעברי שורה או ניסוחים.
3. ערכו עותק נוסף, ולא את קובץ הייצוא הגולמי.
4. בדקו דגימה מההתחלה, מהאמצע ומהסוף, וגם הגדרות שמתפרסות על כמה שורות ותווים שאינם לטיניים.
5. ייבאו או צרפו את עותק העבודה, צפו בתצוגה מקדימה של הצד הקדמי והאחורי של כמה כרטיסיות, ורק אז שמרו את הכרטיסיות.
6. שמרו את ערכת Quizlet ואת הקובץ הגולמי עד שתפתחו את חפיסת היעד ותבדקו אותה.

הבדיקות המלאות למפרידים, ל-CSV ולקבצים מופיעות במאמר [איך לייצא ערכות Quizlet ב-2026](/he/blog/how-to-export-quizlet-sets-and-turn-them-into-fsrs-flashcards/). קל לפספס את המגבלה החשובה: הייצוא מעביר את טקסט הכרטיסיות, ולא את התמונות, התיקיות, היסטוריית הלמידה, מצב השליטה בחומר או תזמון החזרות של Quizlet.

לכן חשוב לשמור על האפשרות לחזור לאחור. אם הגדרה בת כמה שורות הופכת לשתי כרטיסיות או שמפריד מזיז את השדות, הקובץ הגולמי מספק לכם עותק מקור שלא שונה לצורך השוואה.

## במה Claude ו-Codex יכולים להשתמש אחרי הייצוא

Nibomo מפרסמת נקודת קצה מרוחקת של MCP בכתובת:

`https://mcp.nibomo.com/mcp`

> [חיבור ל-Claude](https://claude.ai/directory/nibomo) · [תיעוד](/he/docs/mcp-connector/)

[תיעוד מחבר ה-MCP](/he/docs/mcp-connector/) שלה מגדיר שמונה כלים בסך הכול: `list_workspaces`, ‏`sql_query` לקריאה, `sql_execute` לכתיבה, `get_guide` למדריכי עזר, וכן `next_review_card`, ‏`reveal_answer` ו-`submit_review` לחזרות. לקוחות MCP אינטראקטיביים יכולים לאשר גישה באמצעות OAuth. סוכנים שפועלים במסוף יכולים במקום זאת להיעזר תחילה ב[תיעוד ה-Agent API](/he/docs/api/) ולהשתמש בתהליך ה-HTTP שפורסם.

`get_usage_limits` — הכלי השמיני מספק מידע לקריאה בלבד על תוכנית המנוי של החשבון, המגבלות והשימוש החודשי הנוכחי בבינה מלאכותית; הכלי אינו קורא או משנה כרטיסיות.

זה לא הופך את Nibomo למחבר ל-Quizlet. תהליך העבודה הנתמך הוא:

1. לייצא טקסט מערכה ב-Quizlet שיצרתם בעצמכם;
2. לשמור את הקובץ הגולמי ולבדוק עותק עבודה;
3. לבדוק את הכרטיסיות לאחר מיפוי השדות, לפני ששומרים אותן ב-Nibomo;
4. לחבר את סביבת העבודה שנוצרה ב-Nibomo ללקוח תואם לצורך קריאה וכתיבה בהמשך.

עבור Claude, שלבי החיבור מופיעים במאמר [איך לחבר את Nibomo ל-Claude באמצעות MCP](/blog/how-to-connect-flashcards-to-claude-with-mcp/). Codex וסוכנים אחרים יכולים להשתמש במסלול המתועד של MCP או של Agent API, בהתאם לתמיכה בסביבה שלהם.

Nibomo אינה יכולה לקרוא כתובת URL של Quizlet, ליצור עותק מראה של חשבון Quizlet, לסנכרן שינויים מאוחרים יותר ב-Quizlet או לשחזר תמונות והיסטוריית למידה שלא נכללו בייצוא. היא יוצרת כרטיסיות משלה ומצב תזמון חדש מתוך החומר שאתם בוחרים להעביר.

אם אתם שוקלים אם היתרונות מצדיקים את המעבר גם בלי קשר לגישה של סוכנים, ראו את [ההשוואה לחלופת Quizlet בקוד פתוח](/blog/quizlet-alternative/).

## צמצמו את ההרשאות להיקף שנדרש למשימה

מפרט ממשק ציבורי חוסך חלק מהניחושים בחיבור בין מערכות, אבל אינו הופך כל פעולת MCP לבטוחה. OAuth מאמת את החיבור. הוא אינו מבטיח שכרטיסייה שנוצרה באמצעות בינה מלאכותית תהיה נכונה או שנתוני הכרטיסיות המוחזרים יישארו בתוך שירות הכרטיסיות, ואינו קובע אם עריכה תואמת את כוונתכם.

Nibomo מפרידה בין פעולות קריאה לכלי הכתיבה שלה: `sql_execute` לכרטיסיות ולחפיסות, ו-`submit_review` לחזרות. פרטי ההרשאה של OAuth עדיין חלים על כלל הממשק של המחבר, ולכן חסימת כלים ואופן בקשת האישורים תלויים בלקוח. התחילו מסביבת עבודה קטנה ללא מידע רגיש. אפשרו לסוכן לקרוא רק את הנתונים הנחוצים למשימה, השאירו דרישה לאישור נפרד לכל פעולת כתיבה כשהלקוח תומך בכך, ובדקו את סביבת העבודה ואת השינוי המוצע לפני שתאשרו אותו.

אל תחברו חומר לימוד פרטי לפני שבדקתם את התנאים של לקוח הבינה המלאכותית בנוגע לשמירת נתונים ולטיפול בהם. מודל האיומים המפורט מופיע במאמר [האם MCP בטוח לכרטיסיות לימוד?](/blog/is-mcp-safe-for-flashcards/). להעברה ראשונה מספיק כלל פשוט: שמרו את הייצוא הגולמי, צפו בתצוגה מקדימה של כמה כרטיסיות, אשרו פעולת כתיבה מצומצמת ובדקו את התוצאה באפליקציית היעד לפני שתמשיכו.

## אל תהפכו תעבורת דפדפן פרטית ל-API

בקשה שמופיעה בכלי המפתחים של הדפדפן אינה API ציבורי של Quizlet. נקודות קצה פרטיות עשויות להיות תלויות בעוגיות של סשן ההתחברות, בפורמטים פנימיים ובהתנהגות שמשתנה ללא הודעה מוקדמת. כל שימוש אוטומטי חייב גם לעמוד ב[תנאי השימוש של Quizlet](https://quizlet.com/tos) ובהרשאות שיש לכם לחומר.

המאמר הזה אינו מספק הוראות לאיסוף נתונים אוטומטי או נקודות קצה שהתגלו בהנדסה לאחור. אם האפליקציה הרשמית ב-ChatGPT מתאימה למשימה, השתמשו בה. אם יצרתם את הערכה ואתם צריכים העברה חד-פעמית, ייצאו אותה. אם אתם צריכים קריאה וכתיבה חוזרות של סוכן, העבירו תוכן שבדקתם למערכת שמפרסמת ממשק כזה, והשאירו את הפעולות בצד של Quizlet ידניות כל עוד Quizlet אינה מתעדת אפשרות חדשה.
