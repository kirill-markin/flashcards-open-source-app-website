## Σύνδεση μέσω του καταλόγου του Claude

Ανοίξτε το [Nibomo στον κατάλογο του Claude](https://claude.ai/directory/nibomo), συνδέστε το, συνδεθείτε στον λογαριασμό σας στο Nibomo και εγκρίνετε την πρόσβαση. Το Nibomo εμφανίζεται ως Community connector.

Στο Claude Code, χρησιμοποιήστε τον ίδιο λογαριασμό συνδρομής Claude και ελέγξτε το `/mcp` μετά τη σύνδεση. Αν έχετε συνδεθεί στο Claude Code με κλειδί API ή μέσω τρίτου παρόχου, οι connectors σας από το claude.ai δεν φορτώνονται αυτόματα.

Μπορείτε επίσης να ρυθμίσετε απευθείας το Claude Code. Εκτελέστε την παρακάτω εντολή, στη συνέχεια ανοίξτε το `/mcp` στο Claude Code και ολοκληρώστε την εξουσιοδότηση στο πρόγραμμα περιήγησης:

```bash
claude mcp add --transport http nibomo https://mcp.nibomo.com/mcp
```

[Τεκμηρίωση MCP του Claude Code](https://code.claude.com/docs/en/mcp#use-mcp-servers-from-claudeai).

## Επισκόπηση

Το Nibomo λειτουργεί έναν απομακρυσμένο διακομιστή MCP (Model Context Protocol), ώστε τα προγράμματα-πελάτες MCP και
οι πράκτορες AI να μπορούν να διαβάζουν τις κάρτες σας που είναι προς επανάληψη, να τις επαναλαμβάνουν μαζί σας μία ερώτηση κάθε φορά
και να δημιουργούν ή να επεξεργάζονται κάρτες και τράπουλες για εσάς.

Οι πράκτορες μπορούν να συνδεθούν με δύο τρόπους: μέσω αυτού του διακομιστή MCP (η καλύτερη επιλογή για προγράμματα-πελάτες MCP όπως
το Claude ή το Cursor) ή μέσω του [URL ανακάλυψης του Agents API](/docs/api/) για πράκτορες
CLI. Και οι δύο φτάνουν στην ίδια επιφάνεια δεδομένων ανά χρήστη· αυτή η σελίδα καλύπτει τον διακομιστή MCP.

Συνδεθείτε σε αυτόν στη διεύθυνση:

```text
https://mcp.nibomo.com/mcp
```

Η μεταφορά γίνεται μέσω Streamable HTTP. Ο διακομιστής παρέχει οκτώ εργαλεία για ανακάλυψη χώρων εργασίας, αναγνώσεις και εγγραφές καρτών και τραπουλών, οδηγούς αναφοράς, επαναλήψεις και χρήση του λογαριασμού.

## Πώς να τον προσθέσετε στο πρόγραμμα-πελάτη σας

Τα περισσότερα προγράμματα-πελάτες προσθέτουν έναν απομακρυσμένο διακομιστή MCP ως προσαρμοσμένο connector:

1. Ανοίξτε τις ρυθμίσεις connectors ή διακομιστών MCP του προγράμματος-πελάτη σας.
2. Προσθέστε έναν προσαρμοσμένο connector και επικολλήστε το URL του διακομιστή `https://mcp.nibomo.com/mcp`.
3. Στα διαδραστικά προγράμματα-πελάτες, εγκρίνετε την εξουσιοδότηση στο πρόγραμμα περιήγησης όταν σας ζητηθεί. Ο διακομιστής
   χρησιμοποιεί OAuth 2.1 με Dynamic Client Registration, οπότε δεν υπάρχει client secret
   για επικόλληση ούτε εφαρμογή που πρέπει να καταχωρίσετε πρώτα.
4. Για χρήση χωρίς γραφικό περιβάλλον ή από CLI, ορίστε μια κεφαλίδα `Authorization: Bearer fca_…` με το
   κλειδί API του πράκτορά σας αντί για τη ροή του προγράμματος περιήγησης.

Μετά την εξουσιοδότηση, καλέστε μία φορά το `list_workspaces` για να επιλέξετε χώρο εργασίας και στη συνέχεια χρησιμοποιήστε
το `sql_query` για αναγνώσεις και το `sql_execute` για εγγραφές καρτών και τραπουλών. Για επανάληψη, καλέστε
το `next_review_card`, μετά το `reveal_answer` και μετά το `submit_review`.

## Εργαλεία

Ο διακομιστής παρέχει οκτώ εργαλεία. Οι αναγνώσεις και οι εγγραφές είναι σκόπιμα διαχωρισμένες, ώστε ένα
εργαλείο να μην αναμειγνύει ποτέ ασφαλείς και καταστροφικές λειτουργίες.

- `get_usage_limits` — αυστηρά μόνο για ανάγνωση: το πακέτο του λογαριασμού, τα όρια και η τρέχουσα μηνιαία χρήση AI· δεν διαβάζει ούτε αλλάζει κάρτες.
- `sql_query` — πρόσβαση αυστηρά μόνο για ανάγνωση στις κάρτες και στις τράπουλές σας (`SHOW TABLES`,
  `DESCRIBE`, `SHOW COLUMNS`, `SELECT`).
- `sql_execute` — πρόσβαση εγγραφής στις κάρτες και στις τράπουλές σας (`INSERT`, `UPDATE`,
  `DELETE`) ως ατομική δέσμη.
- `list_workspaces` — λίστα, αυστηρά μόνο για ανάγνωση, των χώρων εργασίας στους οποίους έχετε πρόσβαση,
  ο καθένας με το
  `workspaceId`, το όνομα, τον αριθμό ενεργών καρτών, την τελευταία δραστηριότητα και αν είναι ο
  προεπιλεγμένος χώρος εργασίας που έχετε επιλέξει αυτή τη στιγμή. Χρησιμοποιήστε ένα `workspaceId` που επιστρέφεται για το προαιρετικό
  όρισμα `workspaceId` των εργαλείων SQL και επανάληψης.
- `get_guide` — οδηγός αναφοράς, αυστηρά μόνο για ανάγνωση, για ένα θέμα: `sql_dialect`,
  `card_authoring`, `bulk_authoring` ή `review_flow`. Δεν διαβάζει δεδομένα χώρου εργασίας.
- `next_review_card` — αυστηρά μόνο για ανάγνωση: επιστρέφει την επόμενη κάρτα προς επανάληψη, μόνο την
  μπροστινή όψη, με την ίδια σειρά ουράς όπως στις εφαρμογές. Τα προαιρετικά `tags` ή `deckId` περιορίζουν
  την ουρά.
- `reveal_answer` — αυστηρά μόνο για ανάγνωση: επιστρέφει την πίσω όψη μιας κάρτας αφού ο
  μαθητής έχει επιχειρήσει να απαντήσει στην μπροστινή όψη.
- `submit_review` — καταγράφει μία αξιολόγηση `Again`, `Hard`, `Good` ή `Easy` και
  προχωρά το χρονοδιάγραμμα FSRS της κάρτας.

Η επιφάνεια SQL είναι μια σκόπιμα περιορισμένη διάλεκτος και δεν είναι πλήρης PostgreSQL.
Αυτή η τεκμηρίωση καλύπτει μόνο την υποστηριζόμενη διάλεκτο και δεν αποτελεί αναφορά
συμβατότητας με την PostgreSQL. Οι εντολές μπορούν να απευθύνονται μόνο στους πόρους `workspace`, `cards`, `decks` και
`review_events`, κάθε εντολή περιορίζεται στον δικό σας χώρο εργασίας και
οι αναγνώσεις και οι εγγραφές έχουν όριο `100` γραμμές ανά εντολή.

## Επαναλήψεις

Τα εργαλεία επανάληψης επιτρέπουν σε έναν πράκτορα να εξετάζει τον μαθητή σε μία κάρτα κάθε φορά και να αποθηκεύει κάθε
αξιολόγηση στο χρονοδιάγραμμα FSRS της κάρτας:

1. Το `next_review_card` επιστρέφει ένα `cardId` και `frontText`, ή `card: null` όταν
   δεν υπάρχει τίποτα προς επανάληψη.
2. Αφού απαντήσει ο μαθητής, το `reveal_answer` επιστρέφει το `backText` της κάρτας.
3. Το `submit_review` δέχεται το `cardId`, ένα UUID `reviewId` που δημιουργείται από το πρόγραμμα-πελάτη, ένα
   `rating` και τη ζώνη ώρας IANA του μαθητή στο `reviewedTimeZone`. Ο διακομιστής καταγράφει την
   ώρα της επανάληψης και επιστρέφει το νέο χρονοδιάγραμμα της κάρτας.

Αν δεν είστε βέβαιοι ότι μια υποβολή καταγράφηκε, δοκιμάστε ξανά με το ίδιο `reviewId`· δεν καταγράφεται ποτέ δεύτερη
επανάληψη. Μια υποβολή μπορεί επίσης να επιστρέψει:

- `409 REVIEW_EVENT_CONFLICT` — η επανάληψη έχει ήδη καταγραφεί και οι λεπτομέρειες
  του σφάλματος περιέχουν το τρέχον χρονοδιάγραμμα της κάρτας.
- `409 REVIEW_ID_CARD_MISMATCH` — το `reviewId` αντιστοιχεί ήδη σε επανάληψη
  άλλης κάρτας, οπότε δεν αποθηκεύτηκε τίποτα· υποβάλετε ξανά με νέο `reviewId`.
- `409 REVIEW_STALE` — ο αποθηκευμένος χρόνος επανάληψης της κάρτας είναι ίσος ή μεταγενέστερος της τρέχουσας
  ώρας του διακομιστή· επαναλάβετε άλλη κάρτα.

Οι επαναλήψεις καταγράφονται μόνο μέσω του `submit_review`: η SQL δεν μπορεί να γράψει στο
`review_events` ούτε στην κατάσταση προγραμματισμού του FSRS. Καλέστε το `get_guide` με θέμα
`review_flow` για τους πλήρεις κανόνες επανάληψης και αξιολόγησης.

## Συμβόλαιο κάρτας

Κάθε κάρτα ακολουθεί ένα ενιαίο συμβόλαιο, και τα εργαλεία βασίζονται σε αυτό:

- Το `front_text` είναι μόνο μια ερώτηση ή ένα ερέθισμα για επανάληψη και δεν περιέχει ποτέ την απάντηση.
- Το `back_text` περιέχει την απάντηση, προαιρετικά με ένα συγκεκριμένο παράδειγμα.

Οι πράκτορες που δημιουργούν κάρτες μέσω του `sql_execute` ακολουθούν αυτό το συμβόλαιο, οπότε οι
κάρτες που φτιάχνουν είναι αμέσως έτοιμες για επανάληψη σε διαστήματα.

## Ταυτοποίηση

Δύο διαδρομές εξουσιοδότησης φτάνουν στην ίδια επιφάνεια δεδομένων ανά χρήστη.

### OAuth 2.1 (διαδραστικά προγράμματα-πελάτες με connectors)

Ο διακομιστής υλοποιεί τη ροή authorization code με PKCE και Dynamic Client
Registration. Προσθέστε το URL του MCP ως προσαρμοσμένο connector και εγκρίνετε την εξουσιοδότηση στο πρόγραμμα περιήγησης·
δεν απαιτείται client secret κοινοποιημένο εκ των προτέρων. Η ανακάλυψη είναι η τυπική:

- Μεταδεδομένα προστατευόμενου πόρου:
  `https://mcp.nibomo.com/.well-known/oauth-protected-resource`
- Μεταδεδομένα διακομιστή εξουσιοδότησης:
  `https://auth.flashcards-open-source-app.com/.well-known/oauth-authorization-server`

### Κλειδί API (χωρίς γραφικό περιβάλλον και CLI)

Αποκτήστε ένα μακροχρόνιο κλειδί API πράκτορα `fca_` μέσω της ροής σύνδεσης με OTP μέσω email
που τεκμηριώνεται στην [αναφορά API](/docs/api/) και στη συνέχεια στείλτε το ως Bearer token:

```text
Authorization: Bearer fca_ABCDEFGH_0123456789ABCDEFGHJKMNPQRS
```

Είναι το ίδιο κλειδί που δέχεται η επιφάνεια REST για πράκτορες και δεν χρειάζεται πρόγραμμα περιήγησης ούτε
κύκλο OAuth.

Η επίσημη περιγραφή και των δύο διαδρομών σε μορφή αναγνώσιμη από μηχανές είναι το περιεχόμενο ανακάλυψης
στο `https://api.nibomo.com/v1/` (με αντίγραφο στο `/v1/agent`).

## Ασφάλεια και εύρος πρόσβασης

Μπορείτε να εγκρίνετε με ασφάλεια τα εργαλεία SQL, επειδή η επιφάνεια είναι μια περιορισμένη
διάλεκτος που επιβάλλεται από τον συντακτικό αναλυτή και όχι αυθαίρετη πρόσβαση στη βάση δεδομένων:

- **Κλειστή λίστα επιτρεπόμενων εντολών**: το `sql_query` δέχεται μόνο `SHOW TABLES`,
  `DESCRIBE`, `SHOW COLUMNS` και `SELECT`· το `sql_execute` δέχεται μόνο `INSERT`,
  `UPDATE` και `DELETE`. Οτιδήποτε άλλο απορρίπτεται κατά τη συντακτική ανάλυση.
- **Περιορισμένοι πόροι**: οι εντολές μπορούν να αγγίζουν μόνο τα `workspace`, `cards`, `decks`
  και `review_events`.
- **Περιορισμός ανά χώρο εργασίας**: κάθε εντολή SQL και κάθε επανάληψη περιορίζεται σε έναν
  χώρο εργασίας στον οποίο έχετε πρόσβαση, είτε σε αυτόν που ορίζει το `workspaceId` που περνάτε είτε στον
  προεπιλεγμένο χώρο εργασίας που έχετε επιλέξει, χωρίς πρόσβαση σε δεδομένα άλλων μισθωτών.
- **Αυστηρά ορίσματα**: κάθε εργαλείο απορρίπτει άγνωστο όρισμα, οπότε ένα ανορθόγραφο
  `workspaceId` αποτυγχάνει αντί να εκτελεστεί στον προεπιλεγμένο χώρο εργασίας σας.
- **Όρια**: έως `100` γραμμές ανά εντολή, έως `50` εντολές ανά δέσμη και
  όριο αποτελέσματος περίπου `12k` tokens. Οι δέσμες τροποποιήσεων εφαρμόζονται ατομικά.
- **Διαχωρισμός ανάγνωσης/εγγραφής**: τα `get_usage_limits`, `sql_query`, `list_workspaces`, `get_guide`,
  `next_review_card` και `reveal_answer` είναι αυστηρά μόνο για ανάγνωση (`readOnlyHint`)
  και ποτέ δεν επιδιορθώνουν δεδομένα, δεν επαναϋπολογίζουν τον προγραμματισμό και δεν αλλάζουν την κατάσταση των καρτών.
  Τα `sql_execute` και `submit_review` είναι τα μόνα εργαλεία εγγραφής (`destructiveHint`):
  το `sql_execute` γράφει κάρτες και τράπουλες και το `submit_review` καταγράφει μια επανάληψη και
  προχωρά το χρονοδιάγραμμα της κάρτας της.

Ολόκληρη η στοίβα — εφαρμογή, backend και υποδομή — είναι ανοιχτού κώδικα και μπορείτε να τη
[φιλοξενήσετε μόνοι σας](/docs/self-hosting/), ώστε να χρησιμοποιείτε τον ίδιο connector με τη
δική σας εγκατάσταση.
