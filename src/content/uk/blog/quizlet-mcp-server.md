Станом на 12 вересня 2026 року в публічній документації Quizlet не описано MCP-сервера або загальнодоступного API для розробників із самостійним підключенням. Якщо ви шукали URL MCP-сервера Quizlet, щоб вставити його в Claude, Codex чи інший MCP-клієнт, наразі в документації Quizlet немає публічних інструкцій із такого підключення.

Quizlet має офіційний застосунок у ChatGPT. Він може перетворити розмову в ChatGPT на новий набір Quizlet, але цей конкретний сценарій не надає універсального MCP-сервера Quizlet для повторних підключень. Якщо вам потрібен регулярний доступ агента до наявних карток, практичний шлях — експортувати текст зі створеного вами набору, зберегти вихідну копію, перевірити перенесення й використовувати систему навчальних карток, яка явно підтримує читання та запис через агентів.

**Факти перевірено:** 12 вересня 2026 року.

> **Про мою зацікавленість:** Я Kirill Markin, розробник Nibomo. Нижче MCP-сервер і Agent API цього сервісу наведено як альтернативи. Nibomo не може підключитися до облікового запису Quizlet або імпортувати набір за URL Quizlet.

## Застосунок у ChatGPT, експорт і MCP розв’язують різні завдання

[Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro) — це відкритий стандарт для підключення ШІ-застосунків до зовнішніх систем. Зазвичай MCP-сервер надає сумісним клієнтам відому кінцеву точку й визначений набір інструментів, які вони можуть викликати.

В [офіційному анонсі Quizlet для ChatGPT](https://quizlet.com/blog/quizlet-comes-to-chat-gpt) описано інший підхід. Ви встановлюєте застосунок Quizlet у ChatGPT, починаєте запит із `@Quizlet`, переглядаєте згенеровані навчальні картки в ChatGPT, а потім відкриваєте набір у Quizlet, щоб налаштувати його під себе й навчатися.

Це корисно для завдання «перетворити цю розмову в ChatGPT на набір Quizlet». В анонсі не опубліковано універсальної точки доступу до MCP-сервера Quizlet, не надано Claude чи Codex доступу до вашої бібліотеки Quizlet і не запропоновано облікових даних розробника для багаторазового використання.

Це нічого не говорить про приватну чи внутрішню інфраструктуру Quizlet. Ідеться лише про інтерфейс, який Quizlet надає у своїй публічній документації. Ширші межі доступу для розробників розглянуто в статті [«Чи має Quizlet публічний API у 2026 році?»](/uk/blog/quizlet-api/).

Ось чітке розмежування:

| Що вам насправді потрібно | Найкращий підтримуваний шлях наразі | Чого очікувати |
| --- | --- | --- |
| Створити новий набір Quizlet із розмови в ChatGPT | Офіційний застосунок Quizlet у ChatGPT | Конкретний сценарій із `@Quizlet` у ChatGPT, після якого редагування та навчання відбуваються в Quizlet |
| Перенести терміни й визначення зі створеного вами набору | Експорт на сайті Quizlet | Одноразова текстова копія, яку ви зберігаєте й перевіряєте |
| Дати Claude, Codex чи іншому агенту змогу регулярно читати або редагувати навчальні картки | Система навчальних карток із задокументованим MCP-сервером або API для агентів | Автентифікований доступ до робочого простору цільової системи, а не до Quizlet |
| Створювати програмне забезпечення для роботи з даними облікового запису Quizlet | Дочекатися офіційної документації для розробників або отримати доступ через уповноваженого партнера | Наразі не задокументовано публічного інтерфейсу Quizlet API або MCP із самостійним підключенням |

Застосунок Quizlet у ChatGPT підтримує один сценарій створення набору. Експорт дає змогу виконати разове перенесення. MCP забезпечує повторюваний доступ до системи, яка цілеспрямовано відкриває інструменти. Вони не взаємозамінні.

## Оберіть найкоротший підтримуваний шлях

Якщо офіційний застосунок у ChatGPT уже підходить для завдання, скористайтеся ним. Немає сенсу додавати другу систему лише заради створення одного набору Quizlet з однієї розмови.

Якщо вам потрібна тільки резервна копія або одноразове перенесення, скористайтеся експортом Quizlet. Якщо агент має повернутися завтра, знайти колоду, додати картки й виправити їх, у цільовій системі потрібен задокументований інтерфейс читання та запису. Доки Quizlet його не опублікує, такий регулярний сценарій не може бути підтримуваним прямим підключенням до вашого облікового запису Quizlet.

Для власного програмного забезпечення, створеного саме для роботи з даними Quizlet, діє та сама межа. Запит із браузера, стара бібліотека-обгортка чи інтеграція, яку хтось створив шляхом зворотного проєктування, не замінюють актуальної документації для розробників.

## Переносьте власний набір так, щоб можна було повернутися до оригіналу

В [офіційній інструкції Quizlet з експорту](https://help.quizlet.com/hc/en-us/articles/360034345672-Exporting-your-sets) зазначено, що експортувати набір може лише його автор і тільки на сайті. Послідовність дій: **Більше → Експорт → Копіювати текст**. Експорт містить терміни й визначення; за інформацією Quizlet, зображення експортувати не можна, а скопійовані набори не підлягають експорту.

Щоб обережно перенести створений вами набір, достатньо кількох кроків:

1. Скористайтеся експортом на сайті Quizlet і вставте результат у звичайний текстовий файл.
2. Збережіть незмінену копію в UTF-8, перш ніж змінювати роздільники, переноси рядків або формулювання.
3. Редагуйте дублікат, а не вихідний експорт.
4. Перевірте кілька записів із початку, середини й кінця, а також багаторядкові визначення та символи нелатинських абеток.
5. Імпортуйте або прикріпіть робочу копію, перегляньте лицьовий і зворотний бік кількох карток і лише потім збережіть їх.
6. Зберігайте набір Quizlet і вихідний файл, доки не відкриєте й не перевірите колоду в цільовій системі.

Повний опис перевірок роздільників, CSV і файлів є в статті [«Як експортувати набори Quizlet у 2026 році»](/uk/blog/how-to-export-quizlet-sets-and-turn-them-into-fsrs-flashcards/). Важливе обмеження легко пропустити: експорт переносить текст карток, але не зображення, папки, історію навчання, рівень засвоєння чи розклад повторень із Quizlet.

Саме тому важливо мати змогу повернутися до вихідних даних під час перенесення. Якщо багаторядкове визначення перетвориться на дві картки або роздільник змістить поля, вихідний файл дасть вам незмінений зразок для порівняння.

## Що можуть використовувати Claude і Codex після експорту

Nibomo публікує точку доступу до віддаленого MCP-сервера за адресою:

`https://mcp.nibomo.com/mcp`

> [Підключити до Claude](https://claude.ai/directory/nibomo) · [Документація](/uk/docs/mcp-connector/)

У [документації MCP-конектора](/uk/docs/mcp-connector/) визначено вісім інструментів: `list_workspaces`, `sql_query` для читання, `sql_execute` для запису, `get_guide` для довідкових посібників, а також `next_review_card`, `reveal_answer` і `submit_review` для повторень. Інтерактивні MCP-клієнти можуть проходити авторизацію через OAuth. Агенти в терміналі натомість можуть почати з [документації Agent API](/uk/docs/api/) і використовувати опубліковану послідовність HTTP-запитів.

`get_usage_limits` — інструмент виключно для читання даних про тарифний план облікового запису, ліміти та поточний обсяг використання ШІ за місяць; він не читає й не змінює картки.

Це не перетворює Nibomo на конектор до Quizlet. Підтримуваний сценарій такий:

1. експортуйте текст із набору Quizlet, автором якого ви є;
2. збережіть вихідний файл і перевірте робочу копію;
3. перевірте картки після зіставлення полів, перш ніж зберігати їх у Nibomo;
4. підключіть отриманий робочий простір Nibomo до сумісного клієнта для подальшого читання та запису.

Кроки підключення для Claude наведено в статті [«Як підключити Nibomo до Claude через MCP»](/blog/how-to-connect-flashcards-to-claude-with-mcp/). Codex та інші агенти можуть використовувати задокументований шлях через MCP або Agent API, який підтримує їхнє середовище.

Nibomo не може прочитати вміст за URL Quizlet, створити дзеркальну копію облікового запису Quizlet, синхронізувати подальші зміни в Quizlet або відновити зображення та історію навчання, яких немає в експорті. На основі матеріалу, який ви вирішили перенести, Nibomo створює власні картки й формує для них новий розклад повторень.

Якщо ви вирішуєте, чи варто йти на такий компроміс з огляду на інші можливості, крім доступу для агентів, перегляньте [порівняння з альтернативою Quizlet із відкритим кодом](/blog/quizlet-alternative/).

## Не надавайте ширших дозволів, ніж потребує завдання

Публічно описаний інтерфейс зменшує кількість здогадок під час інтеграції, але не робить кожну дію через MCP безпечною. OAuth автентифікує підключення. Він не гарантує правильності картки, згенерованої ШІ, не утримує повернуті дані карток у межах сервісу навчальних карток і не визначає, чи відповідає редагування вашому задуму.

Nibomo відокремлює операції читання від інструментів запису: `sql_execute` для карток і колод, `submit_review` для повторень. Облікові дані OAuth усе одно охоплюють увесь інтерфейс конектора, тому блокування інструментів і порядок підтвердження дій залежать від клієнта. Почніть із невеликого робочого простору без конфіденційних даних. Дозволяйте агенту читати лише потрібні для завдання дані, вимагайте окремого підтвердження кожного виклику інструмента запису, якщо клієнт це підтримує, і перевіряйте робочий простір та запропоновану зміну, перш ніж її приймати.

Не підключайте приватні навчальні матеріали, доки не перевірите умови зберігання й обробки даних у ШІ-клієнті. Докладну модель загроз наведено в статті [«Чи безпечний MCP для навчальних карток?»](/blog/is-mcp-safe-for-flashcards/). Для першого перенесення достатньо простого правила: збережіть вихідний експорт, перегляньте кілька карток, підтвердьте лише чітко обмежену операцію запису і перевірте результат у цільовому застосунку, перш ніж продовжувати.

## Не перетворюйте приватний трафік браузера на API

Запит, видимий в інструментах розробника браузера, не є публічним API Quizlet. Приватні кінцеві точки можуть залежати від сеансових cookie, внутрішніх форматів і поведінки, яка змінюється без попередження. Будь-яке автоматизоване використання також має відповідати [Умовам використання Quizlet](https://quizlet.com/tos) і правам доступу, які ви маєте на ці матеріали.

У цій статті немає інструкцій зі скрейпінгу або кінцевих точок, знайдених шляхом зворотного проєктування. Якщо офіційний застосунок у ChatGPT підходить для завдання, скористайтеся ним. Якщо ви створили набір і потребуєте одноразового перенесення, експортуйте його. Якщо вам потрібне регулярне читання та запис через агентів, перенесіть перевірений вміст у систему, яка публікує такий інтерфейс, а роботу на боці Quizlet залиште ручною, доки Quizlet не задокументує щось нове.
