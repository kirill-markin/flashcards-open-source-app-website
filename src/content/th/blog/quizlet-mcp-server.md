ณ วันที่ 12 กันยายน 2026 เอกสารสาธารณะของ Quizlet ไม่ได้ระบุว่ามีเซิร์ฟเวอร์ MCP หรือ API สาธารณะสำหรับนักพัฒนาที่สมัครใช้งานได้ด้วยตนเอง หากคุณกำลังค้นหา URL ของ Quizlet MCP เพื่อนำไปวางใน Claude, Codex หรือไคลเอนต์ MCP อื่น ๆ ขณะนี้เอกสารของ Quizlet ยังไม่มีวิธีตั้งค่าที่เปิดให้บุคคลทั่วไปใช้งาน

Quizlet มีแอปอย่างเป็นทางการใน ChatGPT ซึ่งเปลี่ยนบทสนทนาใน ChatGPT ให้เป็นชุดบัตรคำใหม่ใน Quizlet ได้ แต่ขั้นตอนการทำงานเฉพาะนี้ไม่ใช่เซิร์ฟเวอร์ Quizlet MCP ที่นำกลับมาเรียกใช้ได้ซ้ำ ๆ หากคุณต้องการให้เอเจนต์เข้าถึงบัตรคำที่มีอยู่เป็นประจำ แนวทางที่ทำได้จริงคือส่งออกข้อความจากชุดที่คุณสร้าง เก็บสำเนาต้นฉบับไว้ ตรวจสอบข้อมูลที่ย้าย แล้วใช้ระบบบัตรคำที่ระบุชัดเจนว่ารองรับการอ่านและเขียนข้อมูลโดยเอเจนต์

**ตรวจสอบข้อเท็จจริงเมื่อ:** 12 กันยายน 2026

> **การเปิดเผยข้อมูล:** ผมคือ Kirill Markin ผู้พัฒนา Nibomo ซึ่งมีเซิร์ฟเวอร์ MCP และ Agent API ที่กล่าวถึงเป็นทางเลือกด้านล่าง Nibomo ไม่สามารถเชื่อมต่อกับบัญชี Quizlet หรือนำเข้าจาก URL ของ Quizlet ได้

## แอปใน ChatGPT การส่งออก และ MCP ตอบโจทย์คนละอย่าง

[Model Context Protocol](https://modelcontextprotocol.io/docs/getting-started/intro) เป็นมาตรฐานเปิดสำหรับเชื่อมต่อแอปพลิเคชัน AI กับระบบภายนอก โดยทั่วไป เซิร์ฟเวอร์ MCP จะมีเอนด์พอยต์ที่ระบุไว้และชุดเครื่องมือที่กำหนดชัดเจนให้ไคลเอนต์ที่รองรับเรียกใช้ได้

[ประกาศอย่างเป็นทางการของ Quizlet เกี่ยวกับ ChatGPT](https://quizlet.com/blog/quizlet-comes-to-chat-gpt) อธิบายการใช้งานอีกรูปแบบหนึ่ง คุณติดตั้งแอป Quizlet ใน ChatGPT เริ่มพรอมป์ต์ด้วย `@Quizlet` ดูตัวอย่างบัตรคำที่สร้างขึ้นภายใน ChatGPT แล้วเปิดชุดนั้นใน Quizlet เพื่อปรับแต่งและใช้ทบทวน

วิธีนี้มีประโยชน์เมื่องานที่ต้องการคือ “เปลี่ยนบทสนทนาใน ChatGPT นี้ให้เป็นชุดบัตรคำใน Quizlet” แต่ประกาศดังกล่าวไม่ได้เผยแพร่เอนด์พอยต์ Quizlet MCP สำหรับใช้งานทั่วไป ไม่ได้ให้ Claude หรือ Codex เข้าถึงคลังบัตรคำใน Quizlet ของคุณ และไม่ได้ให้ข้อมูลรับรองสำหรับนักพัฒนาที่นำไปใช้ซ้ำได้

ข้อความนี้ไม่ได้บ่งบอกอะไรเกี่ยวกับโครงสร้างพื้นฐานส่วนตัวหรือระบบภายในของ Quizlet แต่กล่าวถึงเฉพาะช่องทางเชื่อมต่อที่ Quizlet เปิดให้ใช้งานตามเอกสารสาธารณะเท่านั้น ส่วนขอบเขตการเข้าถึงสำหรับนักพัฒนาในภาพรวมอธิบายไว้ใน [Quizlet มี API สาธารณะในปี 2026 หรือไม่?](/th/blog/quizlet-api/)

แยกความต่างให้ชัดเจนได้ดังนี้:

| สิ่งที่คุณต้องการจริง ๆ | ช่องทางที่มีการรองรับและตรงกับงานที่สุดในปัจจุบัน | สิ่งที่จะได้รับ |
| --- | --- | --- |
| สร้างชุดบัตรคำใหม่ใน Quizlet จากบทสนทนาใน ChatGPT | แอป ChatGPT อย่างเป็นทางการของ Quizlet | ขั้นตอน `@Quizlet` ภายใน ChatGPT แล้วไปแก้ไขและทบทวนต่อใน Quizlet |
| ย้ายคำศัพท์และคำจำกัดความจากชุดที่คุณสร้าง | การส่งออกผ่านเว็บไซต์ Quizlet | สำเนาข้อความสำหรับย้ายข้อมูลครั้งเดียว ซึ่งคุณเก็บรักษาและตรวจสอบได้ |
| ให้ Claude, Codex หรือเอเจนต์อื่นอ่านหรือแก้ไขบัตรคำได้ซ้ำ ๆ | ระบบบัตรคำที่มีเอกสารเซิร์ฟเวอร์ MCP หรือ API สำหรับเอเจนต์ | การเข้าถึงเวิร์กสเปซปลายทางที่ผ่านการยืนยันตัวตน ไม่ใช่การเข้าถึง Quizlet |
| สร้างซอฟต์แวร์ที่ใช้ข้อมูลบัญชี Quizlet | รอเอกสารสำหรับนักพัฒนาอย่างเป็นทางการหรือช่องทางพาร์ตเนอร์ที่ได้รับอนุญาต | ขณะนี้ยังไม่มีเอกสารระบุรูปแบบการเชื่อมต่อ API หรือ MCP สาธารณะของ Quizlet ที่เปิดให้เริ่มใช้งานได้ด้วยตนเอง |

แอป Quizlet ใน ChatGPT รองรับขั้นตอนการสร้างชุดบัตรคำรูปแบบหนึ่ง การส่งออกรองรับการย้ายข้อมูลให้เสร็จเป็นครั้ง ๆ ส่วน MCP รองรับการเข้าถึงระบบซ้ำ ๆ เมื่อระบบนั้นเปิดเครื่องมือให้เรียกใช้อย่างชัดเจน ทั้งสามอย่างใช้แทนกันไม่ได้

## เลือกเส้นทางที่สั้นที่สุดซึ่งมีการรองรับ

หากแอป ChatGPT อย่างเป็นทางการตอบโจทย์อยู่แล้ว ก็ใช้แอปนั้นได้เลย ไม่มีเหตุผลที่จะเพิ่มระบบที่สองเพียงเพื่อสร้างชุดบัตรคำใน Quizlet หนึ่งชุดจากบทสนทนาหนึ่งครั้ง

หากคุณต้องการเพียงสำรองข้อมูลหรือย้ายครั้งเดียว ให้ใช้การส่งออกของ Quizlet แต่หากต้องการให้เอเจนต์กลับมาพรุ่งนี้ ค้นหาสำรับ เพิ่มบัตรคำ และแก้ไขบัตรคำ คุณต้องมีช่องทางอ่านและเขียนข้อมูลที่มีเอกสารรองรับในระบบปลายทาง ตราบใดที่ Quizlet ยังไม่เผยแพร่ช่องทางดังกล่าว ขั้นตอนที่ทำซ้ำเป็นประจำนี้ก็ยังไม่สามารถเป็นการเชื่อมต่อโดยตรงกับบัญชี Quizlet ที่มีการรองรับอย่างเป็นทางการได้

ซอฟต์แวร์ที่สร้างขึ้นโดยเฉพาะเพื่อใช้ข้อมูล Quizlet ก็ต้องหยุดอยู่ที่ขอบเขตเดียวกัน คำขอจากเบราว์เซอร์ ไลบรารีที่ห่อหุ้มการเรียกใช้งานรุ่นเก่า หรือการเชื่อมต่อที่ใครบางคนสร้างจากการทำวิศวกรรมย้อนกลับ ไม่สามารถใช้แทนเอกสารสำหรับนักพัฒนาฉบับปัจจุบันได้

## ย้ายข้อมูลจากชุดที่คุณสร้างโดยให้ย้อนกลับได้

[คำแนะนำการส่งออกอย่างเป็นทางการของ Quizlet](https://help.quizlet.com/hc/en-us/articles/360034345672-Exporting-your-sets) ระบุว่าเฉพาะผู้สร้างเท่านั้นที่ส่งออกชุดได้ และทำได้บนเว็บไซต์เท่านั้น ขั้นตอนคือ **เพิ่มเติม (More) → ส่งออก (Export) → คัดลอกข้อความ (Copy text)** ข้อมูลที่ได้มีคำศัพท์และคำจำกัดความ โดย Quizlet ระบุว่าไม่สามารถส่งออกรูปภาพได้ และชุดที่คัดลอกมาจะส่งออกไม่ได้

สำหรับชุดที่คุณสร้าง การย้ายอย่างรอบคอบมีขั้นตอนไม่มาก:

1. ใช้การส่งออกบนเว็บไซต์ Quizlet แล้ววางผลลัพธ์ลงในไฟล์ข้อความธรรมดา
2. บันทึกสำเนา UTF-8 ที่ยังไม่ได้แก้ไขไว้ ก่อนเปลี่ยนตัวคั่น การขึ้นบรรทัดใหม่ หรือถ้อยคำ
3. แก้ไขสำเนาอีกชุด แทนการแก้ไฟล์ส่งออกต้นฉบับ
4. สุ่มตรวจข้อมูลช่วงต้น กลาง และท้าย รวมถึงคำจำกัดความที่มีหลายบรรทัดและอักขระที่ไม่ใช่อักษรละติน
5. นำเข้าหรือแนบสำเนาที่ใช้ทำงาน ดูตัวอย่างด้านหน้าและด้านหลังของบัตรคำสักสองสามใบ แล้วจึงบันทึกบัตรคำ
6. เก็บชุดใน Quizlet และไฟล์ต้นฉบับไว้จนกว่าจะเปิดและทดลองใช้สำรับปลายทางแล้ว

รายละเอียดการตรวจตัวคั่น CSV และไฟล์ทั้งหมดอยู่ใน [วิธีส่งออกชุดบัตรคำ Quizlet ในปี 2026](/th/blog/how-to-export-quizlet-sets-and-turn-them-into-fsrs-flashcards/) ข้อจำกัดสำคัญที่มองข้ามได้ง่ายคือ การส่งออกย้ายเฉพาะข้อความบนบัตรคำ ไม่ได้ย้ายรูปภาพ โฟลเดอร์ ประวัติการเรียน ระดับความชำนาญ หรือกำหนดการทบทวนจาก Quizlet

ด้วยเหตุนี้ การย้ายข้อมูลโดยยังย้อนกลับไปใช้ต้นฉบับได้จึงสำคัญ หากคำจำกัดความหลายบรรทัดกลายเป็นบัตรคำสองใบ หรือตัวคั่นทำให้ข้อมูลเลื่อนไปอยู่ผิดช่อง ไฟล์ต้นฉบับจะเป็นข้อมูลอ้างอิงที่ยังไม่ถูกแก้ไข

## Claude และ Codex ใช้อะไรได้บ้างหลังส่งออก

Nibomo เปิดให้เชื่อมต่อเซิร์ฟเวอร์ MCP ระยะไกลผ่านเอนด์พอยต์นี้:

`https://mcp.nibomo.com/mcp`

> [เชื่อมต่อกับ Claude](https://claude.ai/directory/nibomo) · [เอกสาร](/th/docs/mcp-connector/)

[เอกสารตัวเชื่อมต่อ MCP](/th/docs/mcp-connector/) ของ Nibomo ระบุเครื่องมือทั้งหมดแปดรายการ ได้แก่ `list_workspaces`, `sql_query` สำหรับอ่านข้อมูล, `sql_execute` สำหรับเขียนข้อมูล, `get_guide` สำหรับอ่านคู่มืออ้างอิง รวมถึง `next_review_card`, `reveal_answer` และ `submit_review` สำหรับทบทวนบัตรคำ ไคลเอนต์ MCP แบบโต้ตอบสามารถให้ผู้ใช้อนุญาตการเข้าถึงผ่าน OAuth ได้ ส่วนเอเจนต์ในเทอร์มินัลสามารถเริ่มจาก [เอกสาร Agent API](/th/docs/api/) และใช้ขั้นตอนผ่าน HTTP ที่เผยแพร่ไว้แทน

`get_usage_limits` — ใช้สำหรับอ่านข้อมูลแพ็กเกจของบัญชี ขีดจำกัด และปริมาณการใช้งาน AI ในเดือนปัจจุบันเท่านั้น โดยไม่อ่านหรือเปลี่ยนแปลงบัตรคำ

สิ่งนี้ไม่ได้ทำให้ Nibomo กลายเป็นตัวเชื่อมต่อ Quizlet ขั้นตอนที่รองรับคือ:

1. ส่งออกข้อความจากชุด Quizlet ที่คุณเป็นผู้สร้าง
2. เก็บไฟล์ต้นฉบับและตรวจสำเนาที่ใช้ทำงาน
3. ตรวจสอบบัตรคำหลังจับคู่ข้อมูลกับช่องปลายทางแล้ว ก่อนบันทึกใน Nibomo และ
4. เชื่อมต่อเวิร์กสเปซ Nibomo ที่ได้กับไคลเอนต์ที่รองรับ เพื่ออ่านและเขียนข้อมูลในครั้งต่อ ๆ ไป

สำหรับ Claude ดูขั้นตอนเชื่อมต่อได้ใน [วิธีเชื่อมต่อ Nibomo กับ Claude ผ่าน MCP](/blog/how-to-connect-flashcards-to-claude-with-mcp/) ส่วน Codex และเอเจนต์อื่นสามารถใช้ช่องทาง MCP หรือ Agent API ที่มีเอกสารรองรับและใช้ได้ในสภาพแวดล้อมของตน

Nibomo ไม่สามารถอ่าน URL ของ Quizlet ทำสำเนาบัญชี Quizlet ให้ตรงกับต้นทาง ซิงค์การเปลี่ยนแปลงใน Quizlet ภายหลัง หรือกู้คืนรูปภาพและประวัติการเรียนที่ไม่ได้รวมอยู่ในการส่งออกได้ ระบบจะสร้างบัตรคำของตนเองและสถานะการจัดตารางทบทวนใหม่จากเนื้อหาที่คุณเลือกนำเข้ามา

หากคุณกำลังชั่งน้ำหนักว่าข้อดีข้อเสียของการย้ายนี้คุ้มค่าหรือไม่ นอกเหนือจากเรื่องการเข้าถึงโดยเอเจนต์ อ่านได้ใน [การเปรียบเทียบทางเลือกโอเพนซอร์สแทน Quizlet](/blog/quizlet-alternative/)

## จำกัดสิทธิ์ให้แคบกว่าขอบเขตงาน

ข้อกำหนดทางเทคนิคสำหรับการเชื่อมต่อที่เผยแพร่ต่อสาธารณะช่วยลดการคาดเดาบางส่วนในการเชื่อมระบบ แต่ไม่ได้ทำให้ทุกการกระทำผ่าน MCP ปลอดภัย OAuth ใช้ยืนยันตัวตนในการเชื่อมต่อ ไม่ได้รับประกันว่าบัตรคำที่ AI สร้างจะถูกต้อง ไม่ได้จำกัดให้ข้อมูลบัตรคำที่ส่งกลับอยู่เฉพาะภายในบริการบัตรคำ และไม่ได้ตัดสินว่าการแก้ไขตรงตามเจตนาของคุณหรือไม่

Nibomo แยกการอ่านข้อมูลออกจากเครื่องมือเขียนข้อมูล ได้แก่ `sql_execute` สำหรับบัตรคำและสำรับ และ `submit_review` สำหรับการทบทวน อย่างไรก็ตาม ข้อมูลรับรอง OAuth ยังครอบคลุมช่องทางการทำงานทั้งหมดของตัวเชื่อมต่อ ดังนั้นการบล็อกเครื่องมือและวิธีขออนุมัติการทำงานจึงขึ้นอยู่กับไคลเอนต์ เริ่มจากเวิร์กสเปซขนาดเล็กที่ไม่มีข้อมูลอ่อนไหว ให้เอเจนต์อ่านเฉพาะข้อมูลที่จำเป็นต่องาน ตั้งให้ต้องอนุมัติการเขียนข้อมูลทุกครั้งหากไคลเอนต์รองรับ และตรวจสอบเวิร์กสเปซกับการเปลี่ยนแปลงที่เสนอก่อนยอมรับ

อย่าเชื่อมต่อเนื้อหาการเรียนส่วนตัวจนกว่าจะตรวจสอบเงื่อนไขการเก็บรักษาและจัดการข้อมูลของไคลเอนต์ AI แล้ว สำหรับการย้ายครั้งแรก ใช้กฎง่าย ๆ ก็พอ: เก็บไฟล์ส่งออกต้นฉบับ ดูตัวอย่างบัตรคำสักสองสามใบ อนุมัติการเขียนข้อมูลในขอบเขตจำกัด แล้วตรวจผลลัพธ์ในแอปปลายทางก่อนทำต่อ

## อย่าเปลี่ยนการรับส่งข้อมูลภายในของเบราว์เซอร์ให้กลายเป็น API

คำขอที่มองเห็นในเครื่องมือสำหรับนักพัฒนาของเบราว์เซอร์ไม่ใช่ API สาธารณะของ Quizlet เอนด์พอยต์ส่วนตัวอาจพึ่งพาคุกกี้เซสชัน รูปแบบข้อมูลภายใน และพฤติกรรมที่เปลี่ยนได้โดยไม่แจ้งล่วงหน้า การใช้งานแบบอัตโนมัติใด ๆ ยังต้องเป็นไปตาม [ข้อกำหนดการใช้บริการของ Quizlet](https://quizlet.com/tos) และสิทธิ์ที่คุณมีต่อเนื้อหานั้นด้วย

บทความนี้ไม่มีคำแนะนำในการดึงข้อมูลจากหน้าเว็บ (scraping)หรือเอนด์พอยต์ที่ได้จากการทำวิศวกรรมย้อนกลับ หากแอป ChatGPT อย่างเป็นทางการตอบโจทย์ ก็ใช้แอปนั้น หากคุณเป็นผู้สร้างชุดและต้องการย้ายครั้งเดียว ให้ส่งออกชุดนั้น หากต้องการให้เอเจนต์อ่านและเขียนข้อมูลเป็นประจำ ให้ย้ายเนื้อหาที่ตรวจสอบแล้วไปยังระบบที่เผยแพร่ช่องทางดังกล่าว แล้วจัดการฝั่ง Quizlet ด้วยตนเองต่อไป เว้นแต่ Quizlet จะเผยแพร่เอกสารเกี่ยวกับช่องทางใหม่
