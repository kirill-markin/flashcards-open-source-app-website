Ankiમાંથી ઇમ્પોર્ટ કોઈ ભૂલ વિના પૂરો થઈ શકે, છતાં તમારો ડેક ઉપયોગી બનાવતી બાબત જ ખોવાઈ શકે. લખાણ આવી જાય અને કાર્ડ પણ ખૂલે. પણ પછી ધ્યાન પડે કે CSS ગાયબ છે, ઑડિયોનું ફીલ્ડ ખાલી છે, દરેક કાર્ડ નવું ગણાય છે અથવા એક નોટમાંથી હવે અપેક્ષિત દિશાનાં કાર્ડ બનતાં નથી.

Ankiના વિકલ્પો સરખાવતી વખતે આ જ મોંઘો પડતો ભાગ છે. વધુ સરળ એડિટર કે સસ્તો પ્લાન એપ બદલતાં પહેલાં સહેલાઈથી દેખાય છે. ટેમ્પ્લેટનું વર્તન, રિવ્યૂનો ઇતિહાસ, રિવ્યૂની નિયત તારીખો, ઍડ-ઑન્સ, ઑફલાઇન મીડિયા અને ફરી બહાર નીકળવાનો રસ્તો ઘણી વાર નુકસાન થયા પછી સમજાય છે.

આ સરખામણીમાં પહેલાં એ જ તપાસીએ છીએ કે શું જળવાય છે અને શું ગુમાય છે. અહીં Anki જેવી સાત એપ્સની વાત છે: દરેક તમારા હાલના સંગ્રહમાંથી શું લઈ શકે છે, ઇમ્પોર્ટ પછી શું બદલાય છે અને ક્યારે Anki સાથે રહેવું વધુ સુરક્ષિત છે.

> **લેખકનો સંબંધ:** હું Kirill Markin છું અને નીચેના ઉત્પાદનોમાંથી એક, [Nibomo](https://nibomo.com/), બનાવું છું. તેના ઓપન સોર્સ, સેલ્ફ-હોસ્ટિંગ અને એજન્ટ સાથેના વર્કફ્લોને કારણે મેં તેને સામેલ કર્યું છે. તેને અહીં પહેલેથી જ શ્રેષ્ઠ વિકલ્પ ગણ્યું નથી: તેમાં સીધું `.apkg` ઇમ્પોર્ટ કરવાની સુવિધા નથી, Ankiમાંથી સ્થળાંતરમાં માહિતી ગુમાય છે અને સેલ્ફ-હોસ્ટેડ સ્ટૅક ચલાવવું ખરેખર ઇન્ફ્રાસ્ટ્રક્ચર સંભાળવાનું કામ છે.

**તથ્યોની ચકાસણી:** 28 ઑગસ્ટ, 2026. કિંમતો તે દિવસે ઉપલબ્ધ જાહેર અમેરિકન અથવા દર્શાવેલી સ્થાનિક કિંમતો છે. કર, પ્રદેશ, શિક્ષણ માટેની ઑફરો અને એપ સ્ટોરના બિલિંગથી રકમ બદલાઈ શકે છે.

## કંઈ પણ ખસેડતાં પહેલાં ટૂંકો જવાબ

સામાન્ય રીતે Anki સાથે જ રહો. બીજી એપ વારંવાર નડતી એવી સમસ્યા દૂર કરતી હોય કે જેના માટે સ્થળાંતર કરવું યોગ્ય લાગે, ત્યારે જ બદલો.

ત્રણ ઉત્પાદનો શીખવાના ડેટા સાથે Anki પૅકેજ સ્વીકારે છે, પરંતુ દરેક શું જાળવવાની ખાતરી આપે છે તેની મર્યાદા જુદી છે:

- **Mnemosyne** તેના દસ્તાવેજોમાં કસ્ટમ કાર્ડ પ્રકારો અને શીખવાના ડેટા સાથે સંપૂર્ણ Anki ઇમ્પોર્ટનો સપોર્ટ જણાવે છે. પરંપરાગત સ્થાનિક, ઓપન સોર્સ ડેસ્કટૉપ વર્કફ્લો માટે અહીં તે સૌથી નજીકનો વિકલ્પ છે, જોકે તેની નેટિવ iOS એપ નથી.
- **Mochi** રિવ્યૂના ઇતિહાસ સાથે `.apkg` ફાઇલો ઇમ્પોર્ટ કરે છે. તે HTMLને Markdownમાં ફેરવે છે, CSS અને JavaScript કાઢે છે અને Ankiનાં ચાર રિવ્યૂ બટનને બદલે Remembered અથવા Forgot આપે છે.
- **RemNote** `.apkg` ફાઇલો, મોટા ભાગના નોટ પ્રકારો અને રિવ્યૂનો ઇતિહાસ ઇમ્પોર્ટ કરે છે. તેની હાલની માર્ગદર્શિકા એમ પણ કહે છે કે ઇમ્પોર્ટ કરેલાં કાર્ડ અલગ **Need to Learn** કતારમાં જાય છે. એટલે “રિવ્યૂનો ઇતિહાસ ઇમ્પોર્ટ થયો”નો અર્થ “આજની Anki કતાર બરાબર નકલ થઈ” એવો ન કરશો.

બાકીના ચારમાં સામગ્રી ફરી બનાવવી પડે છે; આખો સંગ્રહ સ્થળાંતર થતો નથી:

- **Quizlet** જાહેર સેટ, વર્ગો, રમતો અને માર્ગદર્શનવાળી પ્રેક્ટિસ માટે ઉપયોગી છે.
- **Brainscape** જૂથને જવાબ આવડતો હોવાની ખાતરી માટે 1–5નું રેટિંગ આપવાની સરળ રિવ્યૂ પદ્ધતિ આપે છે.
- **SuperMemo** અપનાવવું એટલે તેની માલિકીની પદ્ધતિ અને કોર્સ કૅટલૉગ તરફ જવું.
- **Nibomo** તમને MIT લાઇસન્સવાળા વેબ અને નેટિવ ક્લાયન્ટ, સેલ્ફ-હોસ્ટેડ બૅકએન્ડ, API અને MCP ઍક્સેસ આપે છે. સમીક્ષા સાથેના તેના TXT અથવા CSV વર્કફ્લોમાં Ankiની શીખવાની સ્થિતિ જળવાતી નથી.

તમારાં કાર્ડ ચોક્કસ દેખાવ, ઍડ-ઑન્સ કે હાલની રિવ્યૂ કતાર પર આધારિત હોય, તો Ankiમાં રહેવું અનિર્ણય નથી. એ જ જવાબ છે.

## પહેલાં તમારા Anki સંગ્રહમાં ખરેખર શું છે તે ગણો

“ડેક” એક જ સરળતાથી ખસેડી શકાય તેવી વસ્તુ નથી. ઉત્પાદનો સરખાવતાં પહેલાં, તમે ખસેડવા માગતા હો તે દરેક પ્રકારની સામગ્રી અને ડેટાને અલગ સમજો.

| સંગ્રહનો ભાગ | Anki પૅકેજમાં શું મૂકી શકે | નવી એપે શેનો સ્પષ્ટ સપોર્ટ આપવો જોઈએ |
| --- | --- | --- |
| **નોટની સામગ્રી** | ટેક્સ્ટ ફીલ્ડ અને સંગ્રહિત HTML | ફીલ્ડનું મૅપિંગ, ખાલી જગ્યા પૂરવાનાં cloze કાર્ડ, બિન-લેટિન લખાણ, કોડ અને લાઇન બ્રેક |
| **કાર્ડ બનાવવાની રીત** | નોટ પ્રકારો અને કાર્ડ ટેમ્પ્લેટ | આગળ/ઉલટી દિશાનાં કાર્ડ, કસ્ટમ ફીલ્ડ, CSS અને JavaScriptનું વર્તન |
| **મીડિયા** | **Include media** ચાલુ હોય ત્યારે સ્થાનિક ચિત્રો, ઑડિયો અને બીજી ફાઇલો | ફાઇલો કાઢવી, તેમનાં સંદર્ભો, સપોર્ટેડ ફૉર્મેટ અને ઉપકરણો વચ્ચે સિંક |
| **ગોઠવણી** | ડેક, ઉપડેક, ટૅગ અને વૈકલ્પિક ડેક પ્રીસેટ | સ્તરબદ્ધ ગોઠવણી, ટૅગનો અર્થ, પ્રીસેટ અને અભ્યાસમાં સમાવવાની સામગ્રીની હદ |
| **શીખવાની સ્થિતિ** | સામેલ કર્યા હોય ત્યારે શેડ્યૂલિંગની માહિતી અને રિવ્યૂનો ઇતિહાસ | નિયત તારીખો, અંતરાલ, ભૂલી જવાની ઘટનાઓ અને નવી એપના શેડ્યૂલરમાં રૂપાંતર |
| **વર્કફ્લોનો કોડ** | ઍડ-ઑન્સ ડેક પૅકેજના ભાગ તરીકે સામેલ થતા નથી | બ્રાઉઝર ટૂલ્સ, સામૂહિક ફેરફારો, નોટ બનાવવાની રીત અને ઍડ-ઑન્સનાં અન્ય વર્તનનો વિકલ્પ |

[Ankiની એક્સપોર્ટ માર્ગદર્શિકા](https://docs.ankiweb.net/exporting.html) પૅકેજના આ બધા વિકલ્પો સમજાવે છે. ટેક્સ્ટ ઇમ્પોર્ટરને માત્ર પહેલી હરોળ અને કદાચ ટૅગ દેખાય છે. સીધું `.apkg` ઇમ્પોર્ટ કરનાર વધુ જોઈ શકે છે, પણ શું રૂપાંતર કરવું અને શું કાઢી નાખવું તે દરેક ઉત્પાદન નક્કી કરે છે.

એટલે એપ બદલવાનો નિર્ણય લેવા માટે “Anki ઇમ્પોર્ટ કરે છે” બહુ અસ્પષ્ટ છે. ત્રણ અલગ પ્રશ્નો પૂછો:

1. **શું કાર્ડનો અર્થ હજી એ જ છે?** ફીલ્ડ, બનતાં કાર્ડની દિશાઓ, cloze, મીડિયા અને દેખાવ તપાસો.
2. **શું નવી એપ જાણે છે કે મેં શું શીખ્યું છે?** રિવ્યૂની ઘટનાઓ, હાલની સ્થિતિ, નિયત તારીખો અને પહેલી વાસ્તવિક કતાર તપાસો.
3. **શું હું ફરી બહાર નીકળી શકું?** નવી એપમાંથી એક્સપોર્ટ કરો અને બહાર નીકળવાના ફૉર્મેટમાં ખરેખર શું છે તે તપાસો.

ઇમ્પોર્ટર પહેલા પ્રશ્નમાં પાસ થઈ શકે અને બીજા બેમાં નિષ્ફળ જઈ શકે.

## RemNote: કાર્ડને પરસ્પર જોડાયેલી નોટમાં ખસેડો

RemNote કાર્ડ ક્યાંથી આવે છે તે બદલે છે. લેક્ચરની નોટની સાથે અલગ ડેક જાળવવાને બદલે તમે આઉટલાઇન, દસ્તાવેજ કે PDFના વર્કફ્લોમાં જ કાર્ડ બનાવો છો. નોટની એપ અને ફ્લૅશકાર્ડ એપ વચ્ચે સામગ્રીની નકલ કરવામાં જ વધુ સમય અને મહેનત જતાં હોય તો Anki છોડવાનું આ ખરેખર યોગ્ય કારણ છે.

તેના ઇમ્પોર્ટમાં ઘણું જળવાય છે, પણ રિવ્યૂ કતાર સાથે શું થાય છે તે ધ્યાનથી સમજવું જરૂરી છે. RemNoteની [હાલની Anki ઇમ્પોર્ટ માર્ગદર્શિકા](https://help.remnote.com/en/articles/6751471-importing-from-anki) શેડ્યૂલિંગની માહિતી, ડેક પ્રીસેટ અને મીડિયા સાથે `.apkg` એક્સપોર્ટ કરવા કહે છે. તે રિવ્યૂનો ઇતિહાસ અને basic, cloze તથા સામાન્ય image-occlusion કાર્ડ સહિત મોટા ભાગના નોટ પ્રકારો ઇમ્પોર્ટ કરે છે.

એ જ માર્ગદર્શિકા કહે છે કે નવા ઇમ્પોર્ટ કરેલાં કાર્ડ અલગ **Need to Learn** કતારમાં જાય છે. એટલે ઇતિહાસ RemNoteને ઉપલબ્ધ છે, પરંતુ તમારી હાલની Anki રિવ્યૂ કતાર જરાય બદલાયા વિના ફરી દેખાશે એવી ખાતરી દસ્તાવેજો આપતા નથી. વધુ જટિલ CSS પણ કાઢી નાખવામાં આવે છે, કસ્ટમ JavaScript સપોર્ટેડ નથી, જરૂર પડ્યે બનતું અમુક text-to-speech કામ કરતું નથી અને image-occlusion ઇમ્પોર્ટ અપેક્ષિત નોટ અને ફીલ્ડનાં નામ પર આધાર રાખે છે.

તમારા સંગ્રહનું પ્રતિનિધિત્વ કરતો એક ડેક અજમાવો અને કાર્ડ તથા પહેલી કતાર બંને તપાસો. ઇમ્પોર્ટ પછી દેખાવ સારો હોવો એ અડધી જ કસોટી છે.

ઇન્સ્ટૉલ કરેલી ડેસ્કટૉપ અને મોબાઇલ એપ્સ ઇન્સ્ટૉલેશન અને લૉગિન પછી ઑફલાઇન કામ કરે છે. [ઑફલાઇન માર્ગદર્શિકા](https://help.remnote.com/en/articles/6752029-offline-mode) મીડિયાની મહત્ત્વની મર્યાદા જણાવે છે: ડેસ્કટૉપ નૉલેજ બેઝનાં બધાં ચિત્રો અને PDF રાખે છે, જ્યારે મોબાઇલ તાજેતરનાં અમુક ચિત્રો જ કૅશ કરે છે. વેબ એપ પહેલેથી ખુલ્લા ટૅબમાં ચાલુ રહી શકે છે, પરંતુ ઑફલાઇન સ્થિતિમાં નવેસરથી ખોલી શકાતી નથી.

પરસ્પર જોડાયેલી નોટ માટે સંગ્રહનું માળખું બદલવું યોગ્ય લાગતું હોય ત્યારે RemNote વાપરો. કાર્ડ ટેમ્પ્લેટ અને ઍડ-ઑન્સ તમારી વ્યવસ્થાનો પાયો હોય, માત્ર શણગાર નહીં, તો Anki સાથે રહો.

## Mochi: સંપૂર્ણ નેટિવ એક્સપોર્ટ સાથે સ્થાનિક Markdown

સ્થાનિક ડેટા, Markdown સ્વરૂપનાં કાર્ડ અને સ્ક્રીન પર ઓછાં નિયંત્રણો ઇચ્છતા લોકો માટે Mochi વધુ સાદો વિકલ્પ છે. તેની ઇન્સ્ટૉલ કરેલી એપ્સ દરેક મુખ્ય ડેસ્કટૉપ અને મોબાઇલ પ્લૅટફૉર્મ પર ચાલે છે અને [ખાતા વિના સંપૂર્ણ ઑફલાઇન વાપરી શકાય છે](https://mochi.cards/docs/getting-started/download-and-install/). સિંક માટે દર મહિને $5 ચૂકવવા પડે છે.

સીધો Anki ઇમ્પોર્ટર રિવ્યૂનો ઇતિહાસ પણ લાવે છે, એટલે માત્ર ટેક્સ્ટ સ્વીકારતા વિકલ્પો કરતાં Mochi ઘણું આગળ છે. રૂપાંતરમાં શું થાય છે તે પણ ખાસ સ્પષ્ટ છે: Mochi CSS અને JavaScript કાઢે છે અને HTMLને Markdownમાં ફેરવે છે. કાર્ડનો અર્થ લખાણ અને સામાન્ય જોડેલી ફાઇલોમાંથી સ્પષ્ટ થતો હોય ત્યારે આ ચાલે છે. અર્થ ટેમ્પ્લેટમાં રહેલો હોય તો આ સાવચેત થવાનો સંકેત છે.

Mochi હવે બે શેડ્યૂલર આપે છે. તેનું પોતાનું અલ્ગોરિધમ ડિફૉલ્ટ રહે છે, જ્યારે Mochiમાં થયેલી પ્રગતિ રીસેટ કર્યા વિના [FSRS ચાલુ કરી શકાય છે](https://mochi.cards/docs/reviewing/fsrs/). Mochi પાસે જે રિવ્યૂ ઇતિહાસ છે તેના પરથી FSRS કાર્ડની સ્થિતિ નક્કી કરે છે. FSRSમાં પણ રિવ્યૂ રેટિંગ બે જ વિકલ્પનું રહે છે: Remembered અથવા Forgot. એટલે Hard અને Easyને અલગ સંકેત તરીકે વાપરતા Anki વપરાશકર્તાઓએ રોજના અભ્યાસની લય બદલાવાની અપેક્ષા રાખવી જોઈએ.

મોટા ભાગની માલિકીની એપ્સની સરખામણીમાં અહીંથી ડેટા બહાર કાઢવાની રીત વધુ સ્પષ્ટ છે. નેટિવ [`.mochi` એક્સપોર્ટ](https://mochi.cards/docs/import-and-export/exporting/)માં કાર્ડ, ટેમ્પ્લેટ, જોડેલી ફાઇલો, ટૅગ, ડેકની ગોઠવણી અને રિવ્યૂનો ઇતિહાસ આવે છે. Markdown અને CSV અન્યત્ર તપાસવા સરળ છે, પરંતુ તેમાં રિવ્યૂનો ઇતિહાસ અને બીજો મેટાડેટા આવતો નથી.

Mochiની જાહેર GitHub રિપૉઝિટરીમાં [ઇન્ટિગ્રેશન અને સંબંધિત ટૂલ્સ](https://github.com/mochi-cards/open-source) છે, મુખ્ય એપ કે સપોર્ટેડ સિંક સર્વર નથી. તેને ઑફલાઇન ઉપયોગ અને ડેટાની પોર્ટેબિલિટી માટે પસંદ કરો, સોર્સ કોડ પર નિયંત્રણ માટે નહીં.

## Mnemosyne: ઓપન સોર્સ ડેસ્કટૉપનો રસ્તો

Mnemosyne પરંપરાગત “પ્રોગ્રામ અને સ્થાનિક ડેટાબેઝ”ના સ્વરૂપની સૌથી નજીક છે. હાલની રિલીઝ Windows, macOS અને Linux સપોર્ટ કરે છે; ઑફલાઇન રિવ્યૂ માટે Android ક્લાયન્ટ છે. તેના સુવિધાઓના પેજ પર સમૃદ્ધ સામગ્રીવાળાં કાર્ડ, સ્તરબદ્ધ ટૅગ, પ્લગઇન, 0–5 રિવ્યૂ સ્કેલ અને કસ્ટમ કાર્ડ પ્રકારો તથા શીખવાના ડેટા સાથે સંપૂર્ણ Anki ઇમ્પોર્ટ દર્શાવેલો છે.

મોટી નોટ વ્યવસ્થા કે ક્લાઉડ સેવામાં ગયા વિના Anki છોડવું હોય, તો અહીં ઓપન સોર્સ સ્થળાંતરનો આ સૌથી સીધો રસ્તો છે. તેમાં [બિલ્ટ-ઇન સિંક સર્વર](https://mnemosyne-proj.org/help/syncing) પણ છે, જે ડેસ્કટૉપ કે હેડલેસ મશીન પર ચાલી શકે છે અને ઘણા ક્લાયન્ટનો શીખવાનો ડેટા ભેગો કરી શકે છે.

તેની મર્યાદાઓ પણ નિર્ણય લેતી વખતે ધ્યાનમાં રાખવી પડે. Android ક્લાયન્ટમાં [કાર્ડમાં ફેરફાર કરી શકાતા નથી](https://mnemosyne-proj.org/help/android-client). iOS વપરાશકર્તાઓએ બીજા મશીન પર ચાલતા બ્રાઉઝર સર્વર દ્વારા રિવ્યૂ કરવો પડે છે, અને તે સર્વરના સત્તાવાર સુવિધા પેજ પર ચેતવણી છે કે તેમાં સુરક્ષાની સુવિધાઓ નથી. જાતે સિંક ચલાવવાનો અર્થ સર્વર ઍક્સેસ કરી શકાય તેમ રાખવું, નેટવર્ક ગોઠવવું અને ડેટા ડિરેક્ટરીનો બૅકઅપ લેવો પણ થાય છે.

લાઇસન્સિંગ માત્ર “GPL” કહેવા કરતાં વધુ ચોક્કસ છે: [પ્રોજેક્ટની લાઇસન્સ ફાઇલ](https://raw.githubusercontent.com/mnemosyne-proj/mnemosyne/master/LICENSE) દરેક ઘટક માટે જુદી શરતો બતાવે છે. [મુખ્ય ભાગનું લાઇસન્સ](https://raw.githubusercontent.com/mnemosyne-proj/mnemosyne/master/mnemosyne/LICENSE) નામ/શ્રેયની વધારાની જોગવાઈ સાથે AGPL v3 વાપરે છે, જ્યારે [openSM2sync](https://raw.githubusercontent.com/mnemosyne-proj/mnemosyne/master/openSM2sync/LICENSE) LGPL v3 વાપરે છે. ફેરફાર કે પુનઃવિતરણ કરવાની યોજના હોય તો આ ફાઇલો વાંચો.

## Quizlet: વર્ગખંડ માટે બદલો, સંગ્રહ યથાવત્ રાખવા માટે નહીં

Quizlet જુદું કામ વધુ સારી રીતે કરે છે. જાહેર અભ્યાસ સેટ, શિક્ષકના વર્ગો, શેરિંગ, Match, Test, Learn અને જૂથ પ્રવૃત્તિઓ કસ્ટમાઇઝ કરેલી Anki પ્રોફાઇલ કરતાં વર્ગને આપવી સરળ છે.

સ્થળાંતરની હદ સાદું લખાણ છે. Quizlet પેસ્ટ કરેલી હરોળોમાંથી શબ્દો અને વ્યાખ્યાઓ બનાવી શકે છે, પરંતુ `.apkg` વાંચીને નોટ પ્રકારો, ટેમ્પ્લેટ, શેડ્યૂલિંગ કે રિવ્યૂનો ઇતિહાસ ફરી બનાવતું નથી. સર્જકો [પોતાના સેટ નકલ કરેલા લખાણ તરીકે એક્સપોર્ટ કરી શકે છે](https://help.quizlet.com/hc/en-us/articles/360034345672-Exporting-your-sets), ચિત્રો વિના; બીજા વપરાશકર્તા પાસેથી નકલ કરેલા સેટ એક્સપોર્ટ કરી શકાતા નથી. આ સામગ્રીની પોર્ટેબિલિટી છે, આખા સંગ્રહની નહીં.

Quizletનું શેડ્યૂલિંગ બદલાઈ રહ્યું છે. તેનો નવો [Spaced Repetition](https://quizlet.com/features/spaced-repetition) વર્કફ્લો ઓછામાં ઓછા 100 શબ્દોવાળા સેટ માટે વેબ પર આપમેળે ચાલુ થાય છે અને Repeat, Hard, Okay તથા Easy રેટિંગ વાપરે છે. Quizlet હજી મોબાઇલ સપોર્ટ ટૂંક સમયમાં આવશે એમ દર્શાવે છે. Learn ચૂકવણી આધારિત ઉપયોગ મર્યાદાઓ સાથે અલગ અનુકૂલનશીલ પ્રેક્ટિસનો રસ્તો રહે છે.

ઑફલાઇન ઉપયોગ પણ મોબાઇલ એપ્સમાં જ છે, વેબસાઇટ પર નહીં. Quizlet તાજેતરના આઠ સેટ આપમેળે સાચવે છે અને વધુ ડાઉનલોડ કરવા દે છે; [Flashcards અને Match ઑફલાઇન ચાલે છે](https://help.quizlet.com/hc/en-us/articles/360030565412-Studying-offline-with-Quizlet-mobile-apps), પછી ફરી કનેક્શન થતાં પ્રગતિ સિંક થાય છે.

સામગ્રી વહેંચવી અને વર્ગખંડની પ્રવૃત્તિઓ ધ્યેય હોય ત્યારે અહીં આવો. માત્ર આ સુવિધાઓ મેળવવા માટે વર્ષોથી ગોઠવાયેલું વ્યક્તિગત અભ્યાસ શેડ્યૂલ ફરી બનાવવું સામાન્ય રીતે યોગ્ય સોદો નથી.

## Brainscape: શેડ્યૂલર વિશે ઓછા નિર્ણયો, સ્થળાંતરમાં ઓછું જળવાય

Brainscape જવાબ આવડતો હોવાની કેટલી ખાતરી છે તે માટે 1થી 5નું રેટિંગ માંગે છે અને તેના આધારે ઓછાં આવડતાં કાર્ડ વહેલાં ફરી બતાવે છે. સંપૂર્ણ સૂત્ર જાહેર નથી, પણ સાથે અભ્યાસ કરતા વર્ગને આ રીત શીખવવી સરળ છે.

તે CSV, TXT, XLSX અને ODS ફાઇલો સ્વીકારે છે. આગળ-પાછળ લખાણવાળાં કાર્ડ માટે આ અનુકૂળ છે, પરંતુ તેનો અર્થ એ કે ટેમ્પ્લેટ, ઍડ-ઑન્સ, મીડિયાના નિયમો અને Ankiનો શીખવાનો ડેટા પાછળ રહી જાય છે. વ્યક્તિગત બૅકઅપ એક્સપોર્ટ કરવો Pro સુવિધા છે અને તે એવી ફાઇલો બનાવે છે જે સ્પ્રેડશીટમાં ખોલીને પછી ફરી ઇમ્પોર્ટ કરી શકાય.

Brainscapeનું હાલનું મદદ કેન્દ્ર કહે છે કે તેની વેબસાઇટ અને મોબાઇલ એપ્સમાં હવે શોધવા, બનાવવા, શેર કરવા અને અભ્યાસ કરવાની મુખ્ય સુવિધાઓ સમાન છે. તે ઑફલાઇન મોબાઇલ ઉપયોગ, જાતે ફરી સિંક કરવું અને ઉપકરણ પર પહેલેથી ડાઉનલોડ કરેલા વર્ગોમાં અપડેટ વિશે પણ સમજાવે છે. એટલે ઑફલાઇન કરેલું કામ ફરી કનેક્શન મળતાં સિંક કરવાની વ્યવસ્થા છે, પરંતુ આખું ખાતું સંપૂર્ણ સ્થાનિક લાઇબ્રેરી બને એવી ખાતરી નથી.

વ્યક્તિગત ડેક એક્સપોર્ટ કરવો હજી [Pro સુવિધા](https://brainscape.zendesk.com/hc/en-us/articles/115002383872-How-can-I-export-a-backup-of-my-flashcards) છે. સત્તાવાર સોર્સ કોડ રિલીઝ કે સેલ્ફ-હોસ્ટિંગનો રસ્તો નથી.

અભ્યાસ કરવાના લોકોને Ankiમાં બહુ ગોઠવણી કરવી પડે એવું લાગતું હોય તો Brainscape વિચારવા યોગ્ય છે. જે વ્યક્તિ એ ગોઠવણીનો પહેલેથી સારો ઉપયોગ કરે છે તેના માટે તે બહાર નીકળવાનો સારો રસ્તો નથી.

## SuperMemo: પદ્ધતિ પસંદ કરો, નવી શરૂઆત સ્વીકારો

હાલની SuperMemo.com સેવા SuperMemoની માલિકીની શેડ્યૂલિંગ પદ્ધતિ પર આધારિત વેબ, iOS અને Android ભાષા શીખવાનું પ્લૅટફૉર્મ છે. લાંબા સમયથી SuperMemo વાપરતા લોકો જે જૂના Windows ઉત્પાદનને જાણતા હોય તેનાથી આ અલગ છે.

આ પદ્ધતિ અને કૅટલૉગ પસંદ કરવાનો નિર્ણય છે, Ankiમાંથી સરળતાથી બધું ખસેડવાનો નહીં. SuperMemo [વિભાજકથી અલગ કરેલી પ્રશ્ન-જવાબની હરોળો પેસ્ટ કરીને એકસાથે કાર્ડ બનાવવાનો સપોર્ટ આપે છે](https://www.supermemo.com/en/blog/how-to-create-flashcards-for-learning), દરેક ઇમ્પોર્ટમાં 100 કાર્ડની મર્યાદા સાથે. મને હોસ્ટેડ સેવા માટે હાલનો સત્તાવાર `.apkg` ઇમ્પોર્ટર કે વપરાશકર્તાનો ડેટા એક્સપોર્ટ કરવાનો રસ્તો મળ્યો નથી. એટલે આ દસ્તાવેજિત રસ્તાથી ટેમ્પ્લેટ, ઍડ-ઑન્સ, મીડિયાની ગોઠવણી અને રિવ્યૂનો ઇતિહાસ ખસેડાતા નથી.

ડાઉનલોડ કરેલા કોર્સનો મોબાઇલ એપ્સમાં ઑફલાઇન અભ્યાસ કરી શકાય છે. [ઑફલાઇન માર્ગદર્શિકા](https://www.supermemo.com/en/faq/can-i-use-supermemo-offline) મુજબ AI સુવિધાઓ, MemoCards ઉમેરવાં, શોધ, રેકૉર્ડિંગ, આંકડા અને કોર્સ એડિટર ઑફલાઇન ઉપલબ્ધ નથી. એટલે કનેક્શન બંધ કરતાં પહેલાં સામગ્રી તૈયાર કરો અને સિંક કરો.

SuperMemoની પોતાની પદ્ધતિ કે કોર્સ કૅટલૉગ માટે નવું શેડ્યૂલ શરૂ કરવા તૈયાર હો ત્યારે તેને પસંદ કરો. હાલનું શેડ્યૂલ જાળવવું પ્રાથમિકતા હોય તો તે તમારી સમસ્યાનો ઉકેલ નથી.

## Nibomo: આખા સ્ટૅકનો સોર્સ કોડ, પણ સૌથી નબળો Anki ઇમ્પોર્ટ

Nibomoમાં એપથી લઈને બૅકએન્ડ સુધીનો મોટો હિસ્સો તમારા નિયંત્રણમાં રાખી શકો છો. [MIT લાઇસન્સવાળી રિપૉઝિટરી](https://github.com/kirill-markin/flashcards-open-source-app)માં વેબ એપ, iOS અને Android ક્લાયન્ટ, બૅકએન્ડ, ઑફલાઇન સિંક, ઇન્ફ્રાસ્ટ્રક્ચર, [જાહેર API](/docs/api/) અને [MCP સર્વર](/docs/mcp-connector/) છે. રિવ્યૂમાં [FSRS](/docs/architecture/#scheduling) વપરાય છે. વેબ, iOS અને Android પર ડેટા પહેલાં સ્થાનિક રીતે સચવાય છે, ફેરફારો outboxમાં ઉમેરાય છે અને ફરી કનેક્શન મળતાં સિંક થાય છે.

તેનો અર્થ Anki સાથે સુસંગતતા નથી. Nibomo `.apkg` કે `.colpkg` વાંચી શકતું નથી. સપોર્ટેડ [Anki TXT સ્થળાંતર](/blog/migrate-from-anki-txt-export-open-source-flashcards/) મુખ્યત્વે લખાણવાળાં કાર્ડ માટે AIની મદદથી ડ્રાફ્ટ બનાવી તેની સમીક્ષા કરવાનો વર્કફ્લો છે. તેમાં ટેમ્પ્લેટ, ઍડ-ઑન્સ, ડેકની સ્તરબદ્ધ ગોઠવણી, નિયત તારીખો, અંતરાલ કે રિવ્યૂની ઘટનાઓ જળવાતી નથી. TXT ફાઇલમાં મીડિયાના સંદર્ભો હોય એટલે મીડિયા ફાઇલો હોય એવું નથી. એટલે વધુ મીડિયાવાળા ડેક માટે અલગથી ફરી બનાવવું અને ચકાસવું પડે છે.

Nibomoનું પોતાનું `flashcards.zip` પૅકેજ પણ બૅકઅપ કરતાં મર્યાદિત છે. તે Nibomo વર્કસ્પેસ વચ્ચે કાર્ડ, ટૅગ અને સંબંધિત મીડિયા ખસેડે છે. તે રિવ્યૂનો ઇતિહાસ, FSRS સ્થિતિ, ડેકની સંપૂર્ણ ગોઠવણી, વર્કસ્પેસ સેટિંગ કે ખાતાં ખસેડતું નથી.

હોસ્ટેડ મૂળભૂત સુવિધાઓ [બીટા દરમિયાન મફત છે](/gu/pricing/). પ્રોડક્શન સ્ટૅક સેલ્ફ-હોસ્ટ કરવો એટલે એક કમાન્ડથી Docker ઇન્સ્ટૉલ કરવું નહીં: [સેલ્ફ-હોસ્ટિંગ માર્ગદર્શિકા](/docs/self-hosting/) AWS CDK વાપરે છે અને તેમાં AWS સેવાઓ ઉપરાંત Cloudflare, Resend, Sentry, સિક્રેટ્સ, માઇગ્રેશન, બૅકઅપ, રિસ્ટોર અને અપગ્રેડ જરૂરી છે. Docker Compose ડેવલપમેન્ટનો રસ્તો છે, સપોર્ટેડ પ્રોડક્શન ડિપ્લૉયમેન્ટ નહીં.

સંપૂર્ણ સોર્સ કોડ અને સંચાલકના નિયંત્રણવાળું બૅકએન્ડ એપ બદલવાનું કારણ હોય અને તમારાં કાર્ડ સુરક્ષિત રીતે ફરી બનાવી શકાય એટલાં સરળ હોય ત્યારે Nibomo વાપરો. નાનો કામચલાઉ ડેક અજમાવવા [હોસ્ટેડ એપ ખોલો](https://app.nibomo.com/). શીખવાની સ્થિતિ યથાવત્ રાખવી સૌથી મહત્ત્વની હોય ત્યારે Anki સાથે રહો અથવા RemNote, Mochi કે Mnemosyne અજમાવો.

## સ્થળાંતરમાં અણધાર્યું નુકસાન થયા વિના Ankiનો કયો વિકલ્પ iOS પર ચાલે છે?

“iOS માટે Ankiનો વિકલ્પ”ના બે જુદા અર્થ હોઈ શકે: નેટિવ iPhone એપ અથવા [AnkiMobileની $24.99ની એક વખતની ખરીદી](https://apps.apple.com/us/app/ankimobile-flashcards/id373493387)નો વિકલ્પ.

RemNote, Mochi, Quizlet, Brainscape, SuperMemo અને Nibomo બધાની iOS એપ્સ છે. Mnemosyneની નથી. છતાં સ્થળાંતરનો પ્રશ્ન રહે જ છે:

- **Mochi** માત્ર ટેક્સ્ટવાળા iOS વિકલ્પો કરતાં વધુ જાળવે છે: તે Markdown રૂપાંતર અને બે વિકલ્પના રેટિંગ સાથે `.apkg`નો રિવ્યૂ ઇતિહાસ ઇમ્પોર્ટ કરે છે.
- **RemNote** પણ `.apkg`નો રિવ્યૂ ઇતિહાસ ઇમ્પોર્ટ કરે છે, પરંતુ આજનું Anki શેડ્યૂલ જળવાશે એવું માની લેવાને બદલે તેની **Need to Learn** કતાર તપાસો.
- **Quizlet** વર્ગમાં સામગ્રી વહેંચવા યોગ્ય છે, પરંતુ તેનો Anki રસ્તો માત્ર ટેક્સ્ટનો છે અને તેનો નવો સ્પેસ્ડ રિપિટિશન વર્કફ્લો હજી મોબાઇલ પર નથી.
- **Nibomo** નેટિવ iOS ક્લાયન્ટ સાથે સોર્સ કોડ ઉપલબ્ધ કરાવતો વિકલ્પ છે, પણ Ankiમાંથી સ્થળાંતરમાં શીખવાની સ્થિતિ રીસેટ થાય છે.
- **Brainscape** અને **SuperMemo**ની રિવ્યૂ પદ્ધતિ માટે કાર્ડ અને શેડ્યૂલ ફરી બનાવવાં યોગ્ય લાગતાં હોય તો જ તે અર્થપૂર્ણ વિકલ્પો છે.

કિંમતને કારણે AnkiMobile છોડતાં પહેલાં સબ્સ્ક્રિપ્શનના ખર્ચ અને સ્થળાંતર સુધારવામાં લાગતા કલાકો સાથે સરખામણી કરો. લાંબા સમયથી વાપરતા સંગ્રહને જાતે ફરી ગોઠવવાની ફરજ પાડતી મફત એપ કરતાં એક વખત ખરીદેલી એપ સસ્તી પડી શકે છે.

## Anki સાથે રહેવું ક્યારે વધુ સુરક્ષિત છે

જ્યાં છો ત્યાં રહેવું પણ નિર્ણય છે; નવી વસ્તુ પસંદ કરવામાં નિષ્ફળતા નથી. નીચેમાંથી કંઈ પણ સાચું હોય તો Anki સાથે રહો:

- તમારો સંગ્રહ કસ્ટમ ટેમ્પ્લેટ, CSS, JavaScript કે ઍડ-ઑન્સ પર આધાર રાખે છે;
- કાર્ડનો અર્થ સમજવા માટે Image Occlusion, ઑડિયો કે અન્ય મીડિયા અનિવાર્ય છે;
- એક નોટમાંથી જુદી દિશાનાં અનેક કાર્ડ બને છે, જે પરસ્પર જોડાયેલાં રહેવા જોઈએ;
- વર્ષોનો રિવ્યૂ ઇતિહાસ અને હાલની નિયત તારીખો નવા એડિટર કરતાં વધુ મૂલ્યવાન છે;
- તમે એવા ડેસ્કટૉપ વર્કફ્લો કે પ્લૅટફૉર્મના સંયોજન પર આધાર રાખો છો જે વિકલ્પ આપી શકતો નથી;
- નવી એપનો ઑફલાઇન મોડ માત્ર એવા માધ્યમ પર ચાલે છે જે તમે વાપરવાના નથી;
- સેલ્ફ-હોસ્ટિંગનો વિચાર ગમે છે, પણ સર્વર ચલાવવું, સુરક્ષિત રાખવું, બૅકઅપ લેવો અને અપગ્રેડ કરવું નથી ગમતું;
- વધુ સ્વચ્છ દેખાવ સિવાય વિકલ્પ કોઈ વારંવાર નડતી સમસ્યા હલ કરતો નથી.

Anki હજી પણ પરિપક્વ ઍડ-ઑન ઇકોસિસ્ટમ, લવચીક નોટ અને કાર્ડ ટેમ્પ્લેટ, FSRS અને જૂના શેડ્યૂલિંગનાં નિયંત્રણો, સ્થાનિક રીતે ઇન્સ્ટૉલ કરેલા ક્લાયન્ટ અને સંગ્રહ સમાવી શકતા પૅકેજ ફૉર્મેટ આપે છે. ઉપરનાં ઉત્પાદનોમાંથી કોઈ આ બધું પુનઃસર્જિત કરતું નથી.

માલિકી અને નિયંત્રણની હદો વિશે વધુ કેન્દ્રિત સરખામણી માટે [ઓપન સોર્સ ફ્લૅશકાર્ડ એપ માર્ગદર્શિકા](/blog/best-open-source-flashcard-apps-2026/) વાંચો. ઑફલાઇન વર્તન નિર્ણાયક હોય તો [ઑફલાઇન ફ્લૅશકાર્ડની સરખામણી](/blog/best-offline-flashcards-app/) ઇન્સ્ટૉલ કરેલી એપ્સ, કૅશ થયેલી સામગ્રી અને બ્રાઉઝર ટૅબ વચ્ચેનો ભેદ સમજાવે છે.

## સ્થળાંતરની એવી ચેકલિસ્ટ જેનો જવાબ હજી પણ “ના” હોઈ શકે

તમારા આખા સંગ્રહથી શરૂઆત ન કરો. એવી કસોટી ગોઠવો જેને નિષ્ફળ જવાની છૂટ હોય.

1. **પુનઃપ્રાપ્તિ માટે પૅકેજ બનાવો.** મીડિયા સાથે `.colpkg` એક્સપોર્ટ કરો, Anki પ્રોફાઇલની બહાર રાખો અને બીજી નકલ અન્ય જગ્યાએ રાખો.
2. **અઘરો ડેક પસંદ કરો.** તેમાં cloze, કસ્ટમ ફીલ્ડ, આગળ અને ઉલટી દિશાનાં કાર્ડ, અંદર ગોઠવાયેલા ઉપડેક, ટૅગ, ચિત્રો, ઑડિયો અને શેડ્યૂલનું રૂપાંતર સમજાય એટલો રિવ્યૂ ઇતિહાસ સામેલ કરો.
3. **નવી એપ ખરેખર સપોર્ટ કરતી હોય તે ફૉર્મેટ એક્સપોર્ટ કરો.** સીધા ઇમ્પોર્ટર માટે શેડ્યૂલિંગ, પ્રીસેટ અને મીડિયા સાથે `.apkg` વાપરો. માત્ર સામગ્રી ફરી બનાવવાનું સ્વીકારતા હો ત્યારે જ Notes in Plain Text વાપરો.
4. **સરખામણી માટે મૂળ સ્થિતિ નોંધો.** નોટની સંખ્યા, કાર્ડની સંખ્યા, ટૅગ અને ડેકનાં નામ, મીડિયાની સંખ્યા, થોડી નિયત તારીખો અને અંતરાલ તથા દરેક નોટ પ્રકારમાંથી બનતાં કાર્ડની અપેક્ષિત સંખ્યા લખો.
5. **કામચલાઉ જગ્યામાં ઇમ્પોર્ટ કરો.** મૂળ પ્રોફાઇલ પર લખી ન નાખો અને પહેલી કસોટીને નવી એપની કાયમી લાઇબ્રેરીમાં ભેળવી ન દો.
6. **સામગ્રી અને શીખવાની સ્થિતિ અલગ તપાસો.** આગળ અને પાછળનું લખાણ સાચું હોય એટલે cloze, મીડિયા, એક જ નોટનાં સંબંધિત કાર્ડ, રિવ્યૂનો ઇતિહાસ કે આગામી નિયત તારીખ બચ્યાં છે એવું સાબિત થતું નથી.
7. **ખરેખર વાપરવાના દરેક ઉપકરણ પર ઑફલાઇન નવેસરથી ખોલો.** રિવ્યૂ કરો, ફેરફાર કરો, એપ સંપૂર્ણ બંધ કરો, કનેક્શન વિના ફરી ખોલો, પછી ફરી કનેક્ટ કરો અને બીજા ઉપકરણ પર તપાસો.
8. **બંને કતારમાં ફેર પડવાનું શરૂ થાય તે પહેલાં સરખામણી કરો.** બંને એપ્સમાં એ જ વાસ્તવિક કાર્ડને રેટિંગ આપતાં પહેલાં રિવ્યૂ માટે નિયત પહેલો સમૂહ અને કેટલાક અંતરાલ સરખાવો. બીજી એપમાં પહેલા રિવ્યૂ પછી બંને શેડ્યૂલ સ્વતંત્ર છે.
9. **નક્કી કરતાં પહેલાં બહાર નીકળવાનો રસ્તો અજમાવો.** નવી એપમાંથી એક્સપોર્ટ કરો અને આવતા વર્ષે તેને છોડો તો શું પાછું મેળવી શકશો તે તપાસો.
10. **Anki અને અસ્પર્શિત બૅકઅપ રાખો.** નવી એપ સામાન્ય ઉપયોગમાં સફળ નીવડે અને તમે દરેક નુકસાન સમજીને સ્વીકારો ત્યાં સુધી બંનેમાંથી કંઈ કાઢી ન નાખો.

નવી એપ માત્ર ટેક્સ્ટ સ્વીકારતી હોય તો સંપૂર્ણ [સુરક્ષિત TXT એક્સપોર્ટ વર્કફ્લો](/blog/migrate-from-anki-txt-export-open-source-flashcards/) અનુસરો. તે પુનઃપ્રાપ્તિ માટેની `.colpkg`ને ખસેડી શકાય તેવી કામની ફાઇલથી અલગ રાખે છે અને રીસેટ થવાની વાત સ્પષ્ટ કરે છે.

## આ ક્રમમાં નિર્ણય લો

જે ગુમાવવું તમને પરવડે નહીં ત્યાંથી શરૂ કરો:

1. ચોક્કસ ટેમ્પ્લેટ, ઍડ-ઑન્સ કે હાલની કતાર અનિવાર્ય હોય તો પ્રતિનિધિ `.apkg`ની કસોટી વિપરીત સાબિત ન કરે ત્યાં સુધી Anki સાથે રહો.
2. નોટ અને કાર્ડ એક જ વ્યવસ્થા બનવાં જોઈએ તો RemNote અજમાવો. માત્ર ઇમ્પોર્ટ થયેલાં પેજ નહીં, **Need to Learn** કતાર પણ તપાસો.
3. Ankiના દેખાવ કરતાં સ્થાનિક Markdown અને તપાસી શકાય એવા એક્સપોર્ટ વધુ મહત્ત્વના હોય તો Mochi અજમાવો.
4. સીધા Anki ઇમ્પોર્ટ સાથે કેન્દ્રિત ઓપન સોર્સ ડેસ્કટૉપ એપ જોઈએ તો Mnemosyne અજમાવો અને તેની મોબાઇલ મર્યાદાઓ તમારી દિનચર્યાને અનુકૂળ છે તેની ખાતરી કરો.
5. વર્ગમાં સામગ્રી વહેંચવી કે જૂથ માટે સરળ રિવ્યૂ પદ્ધતિની જ ખરેખર જરૂર હોય તો Quizlet અથવા Brainscapeમાં નાનો સેટ ફરી બનાવો.
6. ખાસ SuperMemoની પદ્ધતિ જ જોઈએ તો નવું શેડ્યૂલ સ્વીકારો. ખાસ આખા સ્ટૅકનો સોર્સ કોડ, સેલ્ફ-હોસ્ટિંગ, API અને MCP ઍક્સેસ જોઈએ તો Nibomoમાં કેટલીક માહિતી ગુમાવીને સામગ્રી ફરી બનાવવાનું અને સંચાલનનું કામ સ્વીકારો.

ત્રણ ખૂબ જુદાં મોડેલની સુવિધાવાર સરખામણી માટે [Anki વિરુદ્ધ Quizlet વિરુદ્ધ Nibomo](/blog/anki-vs-quizlet-vs-open-source-flashcards-app/) જુઓ.

ઉપયોગી નિયમ સરળ છે: લાભ ચોક્કસ હોય અને વાસ્તવિક કસોટી પછી નુકસાન સ્વીકાર્ય લાગ્યું હોય ત્યારે બદલો. તમારા સંગ્રહનું પ્રતિનિધિત્વ કરતો ડેક આ સીમા સારી રીતે પાર ન કરી શકે તો Anki સાથે રહેવું માત્ર સાવચેતીભર્યો બીજો રસ્તો નથી. એ સરખામણીનું પરિણામ છે.
