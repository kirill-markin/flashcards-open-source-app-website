## Claude ଡିରେକ୍ଟୋରିରୁ ଯୋଡ଼ନ୍ତୁ

[Claude ଡିରେକ୍ଟୋରିରେ Nibomo](https://claude.ai/directory/nibomo) ଖୋଲି କନେକ୍ଟର୍ ଯୋଡ଼ନ୍ତୁ। ନିଜ Nibomo ଆକାଉଣ୍ଟରେ ସାଇନ୍ ଇନ୍ କରି ଆକ୍ସେସ୍ ଅନୁମତି ଦିଅନ୍ତୁ। ଡିରେକ୍ଟୋରିରେ Nibomo ଏକ Community କନେକ୍ଟର୍ ଭାବେ ତାଲିକାଭୁକ୍ତ।

Claude Code ପାଇଁ ସେହି Claude ସବ୍‌ସ୍କ୍ରିପ୍‌ସନ୍ ଆକାଉଣ୍ଟ ବ୍ୟବହାର କରନ୍ତୁ ଓ ଯୋଡ଼ିବା ପରେ `/mcp` ଯାଞ୍ଚ କରନ୍ତୁ। API କୀ କିମ୍ବା ତୃତୀୟ ପକ୍ଷ ପ୍ରଦାନକାରୀ ମାଧ୍ୟମରେ ଲଗ୍‌ଇନ୍ କଲେ claude.ai ର କନେକ୍ଟର୍‌ଗୁଡ଼ିକ ଆପେଆପେ ଲୋଡ୍ ହୁଏ ନାହିଁ।

Claude Code କୁ ସିଧାସଳଖ ବିନ୍ୟାସ ମଧ୍ୟ କରିପାରିବେ। ତଳର କମାଣ୍ଡ ଚଲାଇ Claude Code ରେ `/mcp` ଖୋଲନ୍ତୁ ଓ ବ୍ରାଉଜର୍‌ରେ ଅନୁମତି ଦେବା ପ୍ରକ୍ରିୟା ସମ୍ପୂର୍ଣ୍ଣ କରନ୍ତୁ।

```bash
claude mcp add --transport http nibomo https://mcp.nibomo.com/mcp
```

[Claude Code ର MCP ଡକ୍ୟୁମେଣ୍ଟେସନ୍](https://code.claude.com/docs/en/mcp#use-mcp-servers-from-claudeai)।

## ସଂକ୍ଷିପ୍ତ ପରିଚୟ

Nibomo ଏକ ରିମୋଟ୍ MCP (Model Context Protocol) ସର୍ଭର୍ ଚଲାଏ। ଏହା ମାଧ୍ୟମରେ MCP କ୍ଲାଏଣ୍ଟ ଓ AI ଏଜେଣ୍ଟ ଅଭ୍ୟାସ ପାଇଁ ଥିବା ଆପଣଙ୍କ କାର୍ଡ ପଢ଼ିପାରନ୍ତି, ଗୋଟିଏ ପରେ ଗୋଟିଏ ପ୍ରଶ୍ନରେ ଆପଣଙ୍କ ସହ ଅଭ୍ୟାସ କରିପାରନ୍ତି, ଏବଂ ଆପଣଙ୍କ ପାଇଁ କାର୍ଡ ଓ ଡେକ୍ ତିଆରି କିମ୍ବା ସମ୍ପାଦନା କରିପାରନ୍ତି।

ଏଜେଣ୍ଟ ଦୁଇଟି ଉପାୟରେ ଯୋଡ଼ି ହୋଇପାରେ। Claude ବା Cursor ପରି MCP କ୍ଲାଏଣ୍ଟ ପାଇଁ ଏହି MCP ସର୍ଭର୍ ଉପଯୁକ୍ତ। CLI ଏଜେଣ୍ଟ ପାଇଁ [Agents API ଡିସ୍‌କଭରି URL](/docs/api/) ଅଛି। ଉଭୟ ଉପାୟରେ ଜଣେ ବ୍ୟବହାରକାରୀଙ୍କ ସେହି ଏକା ତଥ୍ୟ ଆକ୍ସେସ୍ କରିହୁଏ। ଏହି ପୃଷ୍ଠାରେ MCP ସର୍ଭର୍ ବିଷୟରେ ଦିଆଯାଇଛି।

ଯୋଡ଼ିବା ପାଇଁ ଏହି ଠିକଣା ବ୍ୟବହାର କରନ୍ତୁ।

```text
https://mcp.nibomo.com/mcp
```

ଯୋଗାଯୋଗ ପାଇଁ Streamable HTTP ବ୍ୟବହୃତ ହୁଏ। ସର୍ଭର୍ ଆଠଟି ଟୁଲ୍ ଦିଏ। ଏଗୁଡ଼ିକ ଦ୍ୱାରା ୱର୍କସ୍ପେସ୍ ଖୋଜିବା, କାର୍ଡ ଓ ଡେକ୍ ପଢ଼ିବା ଓ ବଦଳାଇବା, ସନ୍ଦର୍ଭ ଗାଇଡ୍ ଦେଖିବା, ଅଭ୍ୟାସ କରିବା ଏବଂ ଆକାଉଣ୍ଟର ବ୍ୟବହାର ଦେଖିବା ସମ୍ଭବ।

## ନିଜ କ୍ଲାଏଣ୍ଟରେ କିପରି ଯୋଡ଼ିବେ

ଅଧିକାଂଶ କ୍ଲାଏଣ୍ଟରେ ରିମୋଟ୍ MCP ସର୍ଭର୍‌କୁ କଷ୍ଟମ୍ କନେକ୍ଟର୍ ଭାବେ ଯୋଡ଼ାଯାଏ।

1. ନିଜ କ୍ଲାଏଣ୍ଟର କନେକ୍ଟର୍ କିମ୍ବା MCP ସର୍ଭର୍ ସେଟିଂସ୍ ଖୋଲନ୍ତୁ।
2. ଏକ କଷ୍ଟମ୍ କନେକ୍ଟର୍ ଯୋଡ଼ି ସର୍ଭର୍ URL `https://mcp.nibomo.com/mcp` ପେଷ୍ଟ୍ କରନ୍ତୁ।
3. ଇଣ୍ଟରାକ୍ଟିଭ୍ କ୍ଲାଏଣ୍ଟରେ ଅନୁମତି ମଗାଗଲେ ବ୍ରାଉଜର୍‌ରେ ଅନୁମତି ଦିଅନ୍ତୁ। ସର୍ଭର୍ Dynamic Client Registration ସହ OAuth 2.1 ବ୍ୟବହାର କରେ। ତେଣୁ କ୍ଲାଏଣ୍ଟ ସିକ୍ରେଟ୍ ପେଷ୍ଟ୍ କରିବା କିମ୍ବା ଆଗରୁ ଆପ୍ ପଞ୍ଜୀକରଣ କରିବା ଦରକାର ନାହିଁ।
4. ହେଡ୍‌ଲେସ୍ କିମ୍ବା CLI ବ୍ୟବହାର ପାଇଁ ବ୍ରାଉଜର୍‌ରେ ଅନୁମତି ଦେବା ବଦଳରେ ନିଜ ଏଜେଣ୍ଟ API କୀ ଦେଇ `Authorization: Bearer fca_…` ହେଡର୍ ସେଟ୍ କରନ୍ତୁ।

ଅନୁମତି ଦେବା ପରେ ୱର୍କସ୍ପେସ୍ ବାଛିବାକୁ ଥରେ `list_workspaces` କଲ୍ କରନ୍ତୁ। ତା’ପରେ ପଢ଼ିବାକୁ `sql_query` ଏବଂ କାର୍ଡ ବା ଡେକ୍ ବଦଳାଇବାକୁ `sql_execute` ବ୍ୟବହାର କରନ୍ତୁ। ଅଭ୍ୟାସ ପାଇଁ କ୍ରମରେ `next_review_card`, `reveal_answer` ଓ `submit_review` କଲ୍ କରନ୍ତୁ।

## ଟୁଲ୍‌ଗୁଡ଼ିକ

ସର୍ଭର୍‌ରେ ଆଠଟି ଟୁଲ୍ ଅଛି। ପଢ଼ିବା ଓ ଲେଖିବା କାମ ଅଲଗା ଟୁଲ୍‌ରେ ହୁଏ, ଯାହା ଫଳରେ ସୁରକ୍ଷିତ ଓ ତଥ୍ୟ ବଦଳାଇପାରୁଥିବା କାମ ଗୋଟିଏ ଟୁଲ୍‌ରେ ମିଶେ ନାହିଁ।

- `get_usage_limits` — ଆକାଉଣ୍ଟର ପ୍ଲାନ୍, ସୀମା ଓ ଚାଲୁ ମାସର AI ବ୍ୟବହାର କେବଳ ପଢ଼େ। କାର୍ଡ ପଢ଼େ ନାହିଁ କି ବଦଳାଏ ନାହିଁ।
- `sql_query` — ଆପଣଙ୍କ କାର୍ଡ ଓ ଡେକ୍ କେବଳ ପଢ଼ିବାକୁ ଦିଏ (`SHOW TABLES`, `DESCRIBE`, `SHOW COLUMNS`, `SELECT`)।
- `sql_execute` — ଆପଣଙ୍କ କାର୍ଡ ଓ ଡେକ୍‌ରେ ଲେଖିବାକୁ ଦିଏ (`INSERT`, `UPDATE`, `DELETE`)। ଏକ ବ୍ୟାଚ୍‌ର ସବୁ ପରିବର୍ତ୍ତନ ଏକାଠି ଲାଗୁ ହୁଏ କିମ୍ବା କିଛି ଲାଗୁ ହୁଏ ନାହିଁ।
- `list_workspaces` — ଆପଣ ଆକ୍ସେସ୍ କରିପାରୁଥିବା ୱର୍କସ୍ପେସ୍‌ର କେବଳ ପଠନଯୋଗ୍ୟ ତାଲିକା ଦିଏ। ପ୍ରତି ୱର୍କସ୍ପେସ୍ ପାଇଁ `workspaceId`, ନାମ, ସକ୍ରିୟ କାର୍ଡ ସଂଖ୍ୟା, ଶେଷ କାର୍ଯ୍ୟକଳାପ ଏବଂ ତାହା ଆପଣଙ୍କ ବର୍ତ୍ତମାନର ଡିଫଲ୍ଟ କି ନାହିଁ, ତାହା ଥାଏ। SQL ଓ ଅଭ୍ୟାସ ଟୁଲ୍‌ର ଇଚ୍ଛାଧୀନ `workspaceId` ଆର୍ଗୁମେଣ୍ଟ୍ ପାଇଁ ତାଲିକାରୁ ମିଳିଥିବା `workspaceId` ବ୍ୟବହାର କରନ୍ତୁ।
- `get_guide` — `sql_dialect`, `card_authoring`, `bulk_authoring` କିମ୍ବା `review_flow` ମଧ୍ୟରୁ ଗୋଟିଏ ବିଷୟର କେବଳ ପଠନଯୋଗ୍ୟ ସନ୍ଦର୍ଭ ଗାଇଡ୍ ଦିଏ। କୌଣସି ୱର୍କସ୍ପେସ୍ ତଥ୍ୟ ପଢ଼େ ନାହିଁ।
- `next_review_card` — କେବଳ ପଢ଼େ ଏବଂ ଆପ୍‌ରେ ଥିବା ସେହି କ୍ରମରେ ଅଭ୍ୟାସ ପାଇଁ ପରବର୍ତ୍ତୀ କାର୍ଡର କେବଳ ସାମ୍ନା ପଟ ଦିଏ। ଚାହିଁଲେ `tags` କିମ୍ବା `deckId` ଦେଇ ତାଲିକାକୁ ସୀମିତ କରିପାରିବେ।
- `reveal_answer` — କେବଳ ପଢ଼େ ଏବଂ ଶିକ୍ଷାର୍ଥୀ କାର୍ଡର ସାମ୍ନା ପଟର ପ୍ରଶ୍ନର ଉତ୍ତର ଦେବାକୁ ଚେଷ୍ଟା କଲା ପରେ ସେହି କାର୍ଡର ପଛ ପଟ ଦିଏ।
- `submit_review` — `Again`, `Hard`, `Good` ବା `Easy` ମଧ୍ୟରୁ ଗୋଟିଏ ରେଟିଂ ରେକର୍ଡ କରେ ଏବଂ କାର୍ଡର FSRS ସୂଚୀ ଅଦ୍ୟତନ କରେ।

SQL ଇଣ୍ଟରଫେସ୍ ଜାଣିଶୁଣି ସୀମିତ ରଖାଯାଇଛି। ଏହି ଡକ୍ୟୁମେଣ୍ଟେସନ୍ କେବଳ ସମର୍ଥିତ SQL ରୂପ ବିଷୟରେ ତଥ୍ୟ ଦିଏ। ପୂରା PostgreSQL କିମ୍ବା ତାହା ସହ ସୁସଙ୍ଗତି ଏହାର ପରିସର ବାହାରେ। ଷ୍ଟେଟ୍‌ମେଣ୍ଟ କେବଳ `workspace`, `cards`, `decks` ଓ `review_events` ରିସୋର୍ସରେ କାମ କରେ। ପ୍ରତି ଷ୍ଟେଟ୍‌ମେଣ୍ଟ ନିଜ ୱର୍କସ୍ପେସ୍‌ରେ ସୀମିତ, ଏବଂ ପଢ଼ିବା ଓ ଲେଖିବାର ସୀମା ପ୍ରତି ଷ୍ଟେଟ୍‌ମେଣ୍ଟ ପାଇଁ `100` ଧାଡ଼ି।

## ଅଭ୍ୟାସ

ଅଭ୍ୟାସ ଟୁଲ୍ ମାଧ୍ୟମରେ ଏଜେଣ୍ଟ ଶିକ୍ଷାର୍ଥୀଙ୍କୁ ଗୋଟିଏ ପରେ ଗୋଟିଏ କାର୍ଡର ପ୍ରଶ୍ନ ପଚାରିପାରେ ଓ ପ୍ରତିଟି ରେଟିଂ କାର୍ଡର FSRS ସୂଚୀରେ ସେଭ୍ କରିପାରେ।

1. `next_review_card` ଏକ `cardId` ଓ `frontText` ଦିଏ। ଅଭ୍ୟାସ ପାଇଁ କାର୍ଡ ନଥିଲେ `card: null` ଦିଏ।
2. ଶିକ୍ଷାର୍ଥୀ ଉତ୍ତର ଦେଲା ପରେ `reveal_answer` ସେହି କାର୍ଡର `backText` ଦିଏ।
3. `submit_review` ରେ `cardId`, କ୍ଲାଏଣ୍ଟ ତିଆରି କରିଥିବା `reviewId` UUID, `rating` ଏବଂ ଶିକ୍ଷାର୍ଥୀଙ୍କ IANA `reviewedTimeZone` ଦିଆଯାଏ। ସର୍ଭର୍ ଅଭ୍ୟାସର ସମୟ ଦର୍ଜ କରି କାର୍ଡର ନୂଆ ସୂଚୀ ଫେରାଏ।

ରେଟିଂ ଦାଖଲ ହୋଇଛି କି ନାହିଁ ଜଣା ନପଡ଼ିଲେ ସେହି `reviewId` ଦେଇ ପୁଣି ଚେଷ୍ଟା କରନ୍ତୁ। ଏଥିରେ ଅଭ୍ୟାସ ଦ୍ୱିତୀୟ ଥର ରେକର୍ଡ ହୁଏ ନାହିଁ। ଦାଖଲ ପରେ ଏହି ଉତ୍ତରଗୁଡ଼ିକ ମଧ୍ୟ ମିଳିପାରେ।

- `409 REVIEW_EVENT_CONFLICT` — ଅଭ୍ୟାସ ଆଗରୁ ରେକର୍ଡ ହୋଇଛି। ତ୍ରୁଟି ବିବରଣୀରେ କାର୍ଡର ବର୍ତ୍ତମାନର ସୂଚୀ ଥାଏ।
- `409 REVIEW_ID_CARD_MISMATCH` — ସେହି `reviewId` ଆଗରୁ ଅନ୍ୟ ଏକ କାର୍ଡର ଅଭ୍ୟାସ ପାଇଁ ବ୍ୟବହୃତ ହୋଇଛି। ତେଣୁ କିଛି ସେଭ୍ ହୋଇନାହିଁ। ନୂଆ `reviewId` ଦେଇ ପୁଣି ଦାଖଲ କରନ୍ତୁ।
- `409 REVIEW_STALE` — କାର୍ଡ ପାଇଁ ସେଭ୍ ହୋଇଥିବା ଅଭ୍ୟାସ ସମୟ ବର୍ତ୍ତମାନର ସର୍ଭର୍ ସମୟ ସହ ସମାନ କିମ୍ବା ତାହାଠାରୁ ପରର। ଅନ୍ୟ ଏକ କାର୍ଡ ଅଭ୍ୟାସ କରନ୍ତୁ।

ଅଭ୍ୟାସ କେବଳ `submit_review` ମାଧ୍ୟମରେ ରେକର୍ଡ ହୁଏ। SQL ଦ୍ୱାରା `review_events` କିମ୍ବା FSRS ସୂଚୀର ଅବସ୍ଥା ଲେଖିହେବ ନାହିଁ। ଅଭ୍ୟାସ ଓ ରେଟିଂର ସମସ୍ତ ନିୟମ ପାଇଁ `review_flow` ବିଷୟ ଦେଇ `get_guide` କଲ୍ କରନ୍ତୁ।

## କାର୍ଡର ଗଠନ ନିୟମ

ଟୁଲ୍‌ଗୁଡ଼ିକ ପ୍ରତିଟି କାର୍ଡ ପାଇଁ ଏହି ନିୟମ ଉପରେ ନିର୍ଭର କରେ।

- `front_text` ରେ କେବଳ ପ୍ରଶ୍ନ କିମ୍ବା ଉତ୍ତର ମନେ ପକାଇବାକୁ କହୁଥିବା ଏକ ନିର୍ଦ୍ଦେଶ ଥାଏ। ସେଥିରେ ଉତ୍ତର ରହେ ନାହିଁ।
- `back_text` ରେ ଉତ୍ତର ଥାଏ। ଚାହିଁଲେ ଏକ ନିର୍ଦ୍ଦିଷ୍ଟ ଉଦାହରଣ ମଧ୍ୟ ଦେଇପାରିବେ।

`sql_execute` ମାଧ୍ୟମରେ କାର୍ଡ ତିଆରି କରୁଥିବା ଏଜେଣ୍ଟ ଏହି ନିୟମ ମାନନ୍ତି। ତେଣୁ ସେମାନଙ୍କ କାର୍ଡ ତିଆରି ହେବା ମାତ୍ରେ ସ୍ପେସ୍ଡ ରିପିଟିସନ୍ ପାଇଁ ପ୍ରସ୍ତୁତ ଥାଏ।

## ପ୍ରାମାଣିକରଣ

ପ୍ରତି ବ୍ୟବହାରକାରୀଙ୍କ ସେହି ଏକା ତଥ୍ୟ ଆକ୍ସେସ୍ କରିବାକୁ ଦୁଇଟି ଅନୁମତି ପ୍ରକ୍ରିୟା ଅଛି।

### OAuth 2.1 (ଇଣ୍ଟରାକ୍ଟିଭ୍ କନେକ୍ଟର୍ କ୍ଲାଏଣ୍ଟ)

ସର୍ଭର୍ PKCE ଓ Dynamic Client Registration ସହ ଅଥରାଇଜେସନ୍ କୋଡ୍ ପ୍ରକ୍ରିୟା ବ୍ୟବହାର କରେ। MCP URL କୁ କଷ୍ଟମ୍ କନେକ୍ଟର୍ ଭାବେ ଯୋଡ଼ି ବ୍ରାଉଜର୍‌ରେ ଅନୁମତି ଦିଅନ୍ତୁ। କ୍ଲାଏଣ୍ଟ ସିକ୍ରେଟ୍ ଆଗରୁ ସେୟାର୍ କରିବା ଦରକାର ନାହିଁ। ମାନକ ଡିସ୍‌କଭରି ଠିକଣାଗୁଡ଼ିକ ଏଠାରେ ଅଛି।

- ସୁରକ୍ଷିତ ରିସୋର୍ସର ମେଟାଡାଟା — `https://mcp.nibomo.com/.well-known/oauth-protected-resource`
- ଅଥରାଇଜେସନ୍ ସର୍ଭର୍‌ର ମେଟାଡାଟା — `https://auth.flashcards-open-source-app.com/.well-known/oauth-authorization-server`

### API କୀ (ହେଡ୍‌ଲେସ୍ ଓ CLI)

[API ସନ୍ଦର୍ଭ](/docs/api/) ରେ ବର୍ଣ୍ଣିତ ଇମେଲ୍ OTP ଲଗ୍‌ଇନ୍ ପ୍ରକ୍ରିୟା ମାଧ୍ୟମରେ ଦୀର୍ଘ ସମୟ କାର୍ଯ୍ୟକ୍ଷମ `fca_` ଏଜେଣ୍ଟ API କୀ ନିଅନ୍ତୁ। ତା’ପରେ ସେହି କୀକୁ Bearer ଟୋକେନ୍ ଭାବେ ପଠାନ୍ତୁ।

```text
Authorization: Bearer fca_ABCDEFGH_0123456789ABCDEFGHJKMNPQRS
```

REST ଏଜେଣ୍ଟ ଇଣ୍ଟରଫେସ୍‌ରେ ମଧ୍ୟ ଏହି କୀ ଚାଲେ। ବ୍ରାଉଜର୍ କିମ୍ବା OAuth ପ୍ରକ୍ରିୟା ଦରକାର ହୁଏ ନାହିଁ।

ଦୁଇଟିଯାକ ପ୍ରକ୍ରିୟାର ମେସିନ୍‌ରେ ପଢ଼ିହେବା ଭଳି ମୁଖ୍ୟ ବିବରଣୀ `https://api.nibomo.com/v1/` ର ଡିସ୍‌କଭରି ରେସପନ୍ସରେ ଅଛି। `/v1/agent` ରେ ମଧ୍ୟ ସେହି ବିବରଣୀ ମିଳେ।

## ସୁରକ୍ଷା ଓ ପରିସର

SQL ଟୁଲ୍‌କୁ ଅନୁମତି ଦେବା ସୁରକ୍ଷିତ। ପାର୍ସର୍ କେବଳ ସୀମିତ SQL ରୂପକୁ ଅନୁମତି ଦିଏ ଏବଂ ଡାଟାବେସ୍‌ରେ ମନଇଚ୍ଛା ଆକ୍ସେସ୍ ଦିଏ ନାହିଁ।

- **ଅନୁମୋଦିତ ଷ୍ଟେଟ୍‌ମେଣ୍ଟର ନିର୍ଦ୍ଦିଷ୍ଟ ତାଲିକା** — `sql_query` କେବଳ `SHOW TABLES`, `DESCRIBE`, `SHOW COLUMNS` ଓ `SELECT` ଗ୍ରହଣ କରେ। `sql_execute` କେବଳ `INSERT`, `UPDATE` ଓ `DELETE` ଗ୍ରହଣ କରେ। ଅନ୍ୟ ସବୁ ଷ୍ଟେଟ୍‌ମେଣ୍ଟ ପାର୍ସିଂ ସମୟରେ ପ୍ରତ୍ୟାଖ୍ୟାନ ହୁଏ।
- **ସୀମିତ ରିସୋର୍ସ** — ଷ୍ଟେଟ୍‌ମେଣ୍ଟ କେବଳ `workspace`, `cards`, `decks` ଓ `review_events` ରିସୋର୍ସକୁ ଆକ୍ସେସ୍ କରିପାରେ।
- **ଗୋଟିଏ ୱର୍କସ୍ପେସ୍‌ରେ ସୀମିତ** — ପ୍ରତି SQL ଷ୍ଟେଟ୍‌ମେଣ୍ଟ ଓ ଅଭ୍ୟାସ ଆପଣ ଆକ୍ସେସ୍ କରିପାରୁଥିବା ଗୋଟିଏ ୱର୍କସ୍ପେସ୍‌ରେ ସୀମିତ। ଏହା ଆପଣ ଦେଇଥିବା `workspaceId` ର ୱର୍କସ୍ପେସ୍ କିମ୍ବା ଆପଣ ବାଛିଥିବା ଡିଫଲ୍ଟ ୱର୍କସ୍ପେସ୍। ଗୋଟିଏ ଟେନାଣ୍ଟରୁ ଅନ୍ୟ ଟେନାଣ୍ଟର ତଥ୍ୟ ଆକ୍ସେସ୍ କରିହୁଏ ନାହିଁ।
- **ଆର୍ଗୁମେଣ୍ଟ୍‌ର କଡ଼ା ଯାଞ୍ଚ** — ପ୍ରତି ଟୁଲ୍ ଅଜଣା ଆର୍ଗୁମେଣ୍ଟ୍ ପ୍ରତ୍ୟାଖ୍ୟାନ କରେ। `workspaceId` ଭୁଲ୍ ବନାନରେ ଦେଲେ ଟୁଲ୍ ଏକ ତ୍ରୁଟି ଫେରାଏ ଏବଂ ଡିଫଲ୍ଟ ୱର୍କସ୍ପେସ୍‌ରେ ଚାଲେ ନାହିଁ।
- **ସୀମା** — ପ୍ରତି ଷ୍ଟେଟ୍‌ମେଣ୍ଟ ପାଇଁ ସର୍ବାଧିକ `100` ଧାଡ଼ି, ପ୍ରତି ବ୍ୟାଚ୍ ପାଇଁ ସର୍ବାଧିକ `50` ଷ୍ଟେଟ୍‌ମେଣ୍ଟ ଓ ଫଳାଫଳ ପାଇଁ ପ୍ରାୟ `12k` ଟୋକେନ୍‌ର ସୀମା। ପରିବର୍ତ୍ତନର ଏକ ବ୍ୟାଚ୍‌ରେ ସବୁ କାମ ଏକାଠି ଲାଗୁ ହୁଏ କିମ୍ବା କିଛି ଲାଗୁ ହୁଏ ନାହିଁ।
- **ପଢ଼ିବା ଓ ଲେଖିବା ପାଇଁ ଅଲଗା ଟୁଲ୍** — `get_usage_limits`, `sql_query`, `list_workspaces`, `get_guide`, `next_review_card` ଓ `reveal_answer` କେବଳ ପଢ଼ନ୍ତି (`readOnlyHint`)। ଏଗୁଡ଼ିକ ତଥ୍ୟ ମରାମତି, ଅଭ୍ୟାସ ସୂଚୀର ପୁନଃଗଣନା କିମ୍ବା କାର୍ଡର ଅବସ୍ଥା ପରିବର୍ତ୍ତନ କରନ୍ତି ନାହିଁ। କେବଳ `sql_execute` ଓ `submit_review` ଲେଖିବା ଟୁଲ୍ (`destructiveHint`)। `sql_execute` କାର୍ଡ ଓ ଡେକ୍‌ରେ ଲେଖେ। `submit_review` ଅଭ୍ୟାସ ରେକର୍ଡ କରି କାର୍ଡର ସୂଚୀ ଅଦ୍ୟତନ କରେ।

ଆପ୍, ବ୍ୟାକ୍‌ଏଣ୍ଡ ଓ ଭିତ୍ତିଭୂମି ସବୁ ଓପନ୍‌ ସୋର୍ସ ଏବଂ [ନିଜେ ହୋଷ୍ଟ୍ କରିପାରିବେ](/docs/self-hosting/)। ତେଣୁ ନିଜେ ଡିପ୍ଲୟ କରିଥିବା ସେବା ସହ ସେହି କନେକ୍ଟର୍ ଚଲାଇପାରିବେ।
