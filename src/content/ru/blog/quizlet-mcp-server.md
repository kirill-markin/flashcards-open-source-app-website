По состоянию на 12 сентября 2026 года в публичной документации Quizlet не описаны ни MCP-сервер, ни публичный API для разработчиков с открытой регистрацией. Если вы искали адрес MCP-сервера Quizlet, который можно добавить в Claude, Codex или другой MCP-клиент, официальной инструкции по такому подключению сейчас нет.

При этом у Quizlet есть официальное приложение в ChatGPT. Оно превращает разговор с ChatGPT в новый набор Quizlet, но этот отдельный сценарий не заменяет полноценный MCP-сервер для регулярной работы. Если агенту нужен постоянный доступ к существующим карточкам, практический путь такой: экспортировать текст из созданного вами набора, сохранить исходник, проверить результат переноса и выбрать систему карточек, которая прямо поддерживает чтение и запись через агентов.

**Факты проверены:** 12 сентября 2026 года.

> **Раскрытие интересов:** меня зовут Кирилл Маркин, и я разрабатываю Flashcards Open Source App. Ниже его MCP-сервер и Agent API рассматриваются как альтернативы. Flashcards не подключается к аккаунту Quizlet и не импортирует набор по URL Quizlet.

## У приложения ChatGPT, экспорта и MCP разные задачи

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/getting-started/intro) — открытый стандарт для подключения ИИ-приложений к внешним системам. Обычно MCP-сервер предоставляет совместимым клиентам известный адрес и определённый набор инструментов, которые те могут вызывать.

В [официальном анонсе приложения для ChatGPT](https://quizlet.com/blog/quizlet-comes-to-chat-gpt) Quizlet описан другой сценарий. Вы устанавливаете приложение Quizlet в ChatGPT, начинаете запрос с `@Quizlet`, просматриваете созданные карточки прямо в ChatGPT, а затем открываете набор в Quizlet, чтобы настроить его под себя и приступить к занятиям.

Это удобно, если нужно превратить конкретный разговор с ChatGPT в набор Quizlet. Но в анонсе нет универсального MCP-эндпоинта Quizlet, доступа Claude или Codex к вашей библиотеке и учётных данных разработчика для повторного использования.

Это не утверждение о частной или внутренней инфраструктуре Quizlet. Речь только об интерфейсах, которые компания описывает в открытой документации. Подробнее о границах доступа для разработчиков — в статье [«Есть ли у Quizlet публичный API в 2026 году?»](/blog/quizlet-api/).

Вот в чём разница:

| Что вам нужно | Лучший из поддерживаемых способов сейчас | Что вы получите |
| --- | --- | --- |
| Создать новый набор Quizlet из разговора с ChatGPT | Официальное приложение Quizlet для ChatGPT | Сценарий с `@Quizlet` внутри ChatGPT, затем переход в Quizlet для редактирования и занятий |
| Перенести термины и определения из созданного вами набора | Экспорт на сайте Quizlet | Разовую текстовую копию, которую нужно сохранить и проверить |
| Дать Claude, Codex или другому агенту постоянный доступ к карточкам на чтение и редактирование | Система карточек с документированным MCP-сервером или Agent API | Аутентифицированный доступ к целевому рабочему пространству, но не к Quizlet |
| Разработать программу для работы с данными аккаунта Quizlet | Дождаться официальной документации для разработчиков или работать через авторизованную партнёрскую интеграцию | Сейчас публичный API Quizlet с открытой регистрацией и контракт MCP не документированы |

Приложение Quizlet для ChatGPT решает одну задачу создания набора. Экспорт подходит для разового переноса. MCP даёт повторяемый доступ к системе, которая намеренно открывает свои инструменты. Эти способы не взаимозаменяемы.

## Выбирайте самый простой поддерживаемый способ

Если официальное приложение для ChatGPT уже решает задачу, используйте его. Нет смысла подключать вторую систему только ради одного набора Quizlet из одного разговора.

Для резервной копии или разового переноса достаточно экспорта Quizlet. Но если агент должен и завтра найти колоду, добавить карточки или исправить их, на стороне целевой системы нужен документированный интерфейс чтения и записи. Пока Quizlet не опубликует такой интерфейс, организовать эту регулярную работу через поддерживаемое прямое подключение к аккаунту Quizlet нельзя.

Для собственного ПО, построенного вокруг данных Quizlet, граница проходит там же. Запрос из браузера, старая библиотека-обёртка или интеграция, созданная с помощью обратного проектирования, не заменяют актуальную документацию для разработчиков.

## При переносе своего набора сохраните исходник

В [официальной инструкции по экспорту](https://help.quizlet.com/hc/en-us/articles/360034345672-Exporting-your-sets) Quizlet сказано, что экспортировать набор может только его создатель и только на сайте. Порядок действий: **More → Export → Copy text**. Экспорт включает термины и определения; изображения экспортировать нельзя, а копии наборов не поддерживаются.

Аккуратный перенос созданного вами набора займёт несколько шагов:

1. Экспортируйте набор на сайте Quizlet и вставьте результат в обычный текстовый файл.
2. Прежде чем менять разделители, переносы строк или формулировки, сохраните нетронутую копию в UTF-8.
3. Редактируйте дубликат, а исходный экспорт оставьте без изменений.
4. Проверьте фрагменты из начала, середины и конца файла, а также многострочные определения и символы нелатинских письменностей.
5. Импортируйте или приложите рабочую копию, просмотрите несколько лицевых и обратных сторон и только затем сохраняйте карточки.
6. Не удаляйте набор Quizlet и исходный файл, пока не откроете и не протестируете колоду в целевой системе.

Подробная проверка разделителей, CSV и файлов описана в статье [«Как экспортировать набор Quizlet в 2026 году»](/blog/how-to-export-quizlet-sets-and-turn-them-into-fsrs-flashcards/). Главное ограничение легко упустить: экспорт переносит текст карточек, но не изображения Quizlet, папки, историю занятий, прогресс освоения или расписание повторений.

Поэтому важно сохранить возможность вернуться к исходнику. Если многострочное определение превратится в две карточки или разделитель сдвинет поля, нетронутый файл останется надёжным эталоном.

## Что смогут использовать Claude и Codex после экспорта

Flashcards Open Source App публикует удалённый MCP-эндпоинт по адресу:

`https://mcp.flashcards-open-source-app.com/mcp`

В [документации MCP-коннектора](/docs/mcp-connector/) описаны три инструмента: `list_workspaces`, `sql_query` для чтения и `sql_execute` для записи. Интерактивные MCP-клиенты могут авторизоваться через OAuth. Терминальные агенты вместо этого могут начать с [документации Agent API](/docs/api/) и использовать опубликованный HTTP-сценарий.

Это не превращает Flashcards в коннектор для Quizlet. Поддерживаемый процесс выглядит так:

1. экспортируйте текст из набора Quizlet, который создали сами;
2. сохраните исходный файл и проверьте рабочую копию;
3. проверьте карточки после сопоставления полей, прежде чем сохранять их во Flashcards;
4. подключите получившееся рабочее пространство Flashcards к совместимому клиенту для дальнейшего чтения и записи.

Инструкции для Claude есть в статье [«Как подключить Flashcards к Claude через MCP»](/blog/how-to-connect-flashcards-to-claude-with-mcp/). Codex и другие агенты могут использовать документированный вариант с MCP или Agent API, который поддерживает их среда.

Flashcards не умеет читать URL Quizlet, зеркалировать аккаунт Quizlet, синхронизировать последующие изменения из Quizlet или восстанавливать изображения и историю занятий, которых нет в экспорте. Из материалов, которые вы решите перенести, система создаёт собственные карточки и новое расписание повторений.

Если вы оцениваете такой переход не только с точки зрения доступа для агентов, посмотрите [сравнение альтернативы Quizlet с открытым исходным кодом](/blog/quizlet-alternative/).

## Давайте агенту только необходимые права

Публичный контракт снимает часть вопросов при интеграции, но не делает любое действие через MCP безопасным. OAuth подтверждает, кто подключается. Однако он не гарантирует, что созданная ИИ карточка верна, не удерживает полученные данные внутри сервиса карточек и не определяет, соответствует ли правка вашему намерению.

Flashcards отделяет операции чтения от инструмента записи `sql_execute`. При этом учётные данные OAuth дают доступ ко всему интерфейсу коннектора, поэтому запрет отдельных инструментов и порядок подтверждения вызовов зависят от клиента. Начните с небольшого рабочего пространства без конфиденциальных данных. Разрешите агенту читать только нужные для задачи данные, оставьте подтверждение каждой операции записи, если клиент это поддерживает, и до принятия изменений проверьте рабочее пространство и предложенную правку.

Не подключайте приватные учебные материалы, пока не проверите условия ИИ-клиента по хранению и обработке данных. Подробная модель угроз описана в статье [«Безопасен ли MCP для Flashcards?»](/blog/is-mcp-safe-for-flashcards/). Для первого переноса достаточно простого правила: сохраните исходный экспорт, просмотрите несколько карточек, одобрите одну узкую операцию записи и проверьте результат в целевом приложении, прежде чем продолжать.

## Не выдавайте закрытые запросы браузера за API

Запрос, который виден в инструментах разработчика браузера, не становится от этого публичным API Quizlet. Закрытые эндпоинты могут зависеть от сессионных cookie, внутренних форматов и поведения, которое меняется без предупреждения. Любая автоматизация также должна соответствовать [Условиям использования Quizlet](https://quizlet.com/tos) и вашим правам на материалы.

В этой статье нет инструкций по скрейпингу или эндпоинтов, найденных с помощью обратного проектирования. Если официальное приложение для ChatGPT решает задачу, используйте его. Если вы создали набор и хотите перенести его один раз, воспользуйтесь экспортом. Если агенту нужен регулярный доступ на чтение и запись, перенесите проверенные материалы в систему с документированным интерфейсом, а с Quizlet продолжайте работать вручную, пока компания не опубликует новый способ.
