Открыт ли исходный код Quizlet? **Нет — по крайней мере, не у основного веб- и мобильного продукта целиком.** По состоянию на 29 августа 2026 года Quizlet не публикует его полную собираемую версию под лицензией открытого ПО.

У Quizlet есть публичные учебные наборы, официальная организация на GitHub и экспорт наборов, которые вы создали сами. Всё это даёт определённый доступ, но к разным вещам. Ни одна из этих возможностей не открывает полный исходный код Quizlet, документированный публичный API общего назначения или поддерживаемую версию продукта для развёртывания на собственной инфраструктуре.

Вывод основан на актуальных официальных репозиториях, справочных материалах и условиях использования Quizlet. О недокументированном закрытом коде и внутренних системах он ничего не говорит.

**Факты проверены:** 29 августа 2026 года.

## Сначала разберитесь, какой контроль вам нужен

Путаница вокруг **открытого исходного кода Quizlet** обычно начинается с того, что пять разных вопросов смешивают в один:

| Что вас интересует | Что даёт Quizlet | Где заканчивается ваш контроль |
| --- | --- | --- |
| **Публичные учебные наборы** | Можно просматривать учебные материалы, которые автор сделал публичными. | Публичность набора не открывает доступ к программе, которая его показывает. |
| **Права на содержимое набора** | Создатели оригинальных материалов обычно сохраняют авторские права на них, если такие материалы охраняются законом. Quizlet при этом получает лицензию на контент, загруженный в сервис. | Права на слова или изображения из набора не дают прав на приложение Quizlet. Публичный набор нельзя автоматически считать свободным для копирования. |
| **Исходный код и лицензии** | Quizlet публикует на GitHub отдельные инструменты, компоненты, actions и форки. | Эти репозитории не содержат полный сайт, мобильные приложения, бэкенд и инфраструктуру Quizlet. |
| **Экспорт и доступ к API** | Автор набора может экспортировать его термины и определения с сайта в виде текста. | Такой экспорт нельзя восстановить обратно как резервную копию Quizlet, и он не заменяет документированный API для чтения и записи. |
| **Самостоятельный хостинг** | Quizlet управляет облачным сервисом и выпускает официальные приложения. | Поддерживаемого способа самостоятельно развернуть весь продукт компания не публикует. |

Нужный ответ зависит от задачи. Студенту, который хочет сохранить текст карточек, достаточно экспорта. Преподавателю перед повторным использованием чужого материала нужно проверить права на контент. Разработчику для постоянной автоматизации нужен документированный API. Организации, которая хочет сама управлять приложением, понадобятся исходный код, подходящая лицензия и инструкции по развёртыванию.

## Что опубликовано на GitHub Quizlet?

В [официальной организации Quizlet на GitHub](https://github.com/quizlet) сейчас 28 публичных репозиториев. В них лежат компоненты, инженерные инструменты, actions и форки — но не открытая версия всего продукта Quizlet.

Например:

- `argocd-diff-action` — GitHub Action, который создаёт diff для Argo CD;
- `ts-migration` — инструменты для переноса кода с Flow на TypeScript;
- `pinyin-converter` — утилита для преобразования нумерованного пиньиня в запись со знаками тонов;
- `Hammock` — самостоятельная библиотека моков для Hack.

У отдельных репозиториев может быть собственная лицензия открытого ПО, а их код может пригодиться далеко за пределами Quizlet. Но такая лицензия распространяется только на конкретный репозиторий. Она не охватывает программное обеспечение, которое Quizlet там не публиковал.

Я не нашёл официального репозитория, из которого можно собрать полный сайт и мобильные приложения Quizlet вместе с облачным бэкендом и рабочей инфраструктурой. Поиск на GitHub по запросу «Quizlet source code» также находит неофициальные обёртки, загрузчики, клоны и старые интеграции. Они не подтверждают, что Quizlet открыл исходный код своего основного продукта.

Точный вывод такой: полного основного продукта Quizlet нет в актуальных официальных публичных репозиториях под лицензией открытого ПО.

## Публичный набор — это вопрос прав на контент, а не на программу

Публичный набор Quizlet и приложение, которое его показывает, относятся к разным уровням. Термины, определения и загруженные изображения — пользовательский контент. Учётные записи, режимы обучения, планировщик, мобильные клиенты, сайт и бэкенд — программное обеспечение самого продукта.

В материале Quizlet [об основах авторского права](https://help.quizlet.com/hc/en-us/articles/360029925172-Copyright-basics) сказано, что автор произведения обычно сохраняет права на него, если оно охраняется авторским правом. Для использования чужой работы могут потребоваться разрешение или лицензия; в других случаях она должна находиться в общественном достоянии, подпадать под добросовестное использование или другое исключение. Одна лишь публичность набора этого вопроса не решает.

[Условия использования Quizlet](https://quizlet.com/tos), обновлённые 28 мая 2026 года, регулируют доступ к облачному сервису и лицензию, которую пользователи предоставляют Quizlet на загруженный контент. Это не лицензия открытого ПО на код приложения Quizlet.

Здесь важно не смешивать три разных соглашения:

- **лицензия на контент** относится к материалам — например, к набору карточек, ответу, изображению или документу;
- **лицензия на программное обеспечение** относится к исходному коду и правам использовать, изучать, изменять и распространять его;
- условия использования сервиса регулируют доступ к программе, которой управляет кто-то другой.

В одной учётной записи Quizlet могут одновременно действовать все три уровня, и права на каждом будут разными. Это практическая схема опубликованных Quizlet ограничений, а не юридическая консультация.

## Что на самом деле даёт экспорт Quizlet

Экспорт Quizlet — ограниченный, но полезный способ перенести данные. По [официальной инструкции](https://help.quizlet.com/hc/en-us/articles/360034345672-Exporting-your-sets) автор набора может выбрать порядок терминов и определений, нажать **Copy text** и вставить полученный текст в другое приложение.

Ограничения описаны вполне конкретно:

- экспорт доступен на сайте, но не в мобильных приложениях;
- экспортировать можно набор, который создали вы;
- скопированные наборы экспортировать нельзя;
- в результат попадают термины и определения в виде обычного скопированного текста;
- изображения не экспортируются.

Этого хватит, чтобы сохранить читаемую копию текста собственных карточек или аккуратно перенести его в другой инструмент. Но экспорт не сохраняет изображения Quizlet, историю обучения, игры, учебные процессы для классов, структуру учётной записи или копию продукта, которую можно восстановить.

Если вам нужен именно такой уровень контроля, воспользуйтесь [пошаговым руководством по экспорту Quizlet](/ru/blog/how-to-export-quizlet-sets-and-turn-them-into-fsrs-flashcards/). Там разобраны разделители, кодировка UTF-8, многострочные определения, исходные резервные копии и пробный импорт. Не удаляйте исходный набор, пока не проверите скопированный текст в новом приложении.

## Есть ли у Quizlet публичный API?

В актуальной публичной документации Quizlet нет портала, где сторонний разработчик может самостоятельно зарегистрироваться, получить API-ключ и начать работать с документированным API общего назначения. Это не значит, что у Quizlet нет внутренних API или закрытых партнёрских интеграций. Речь только о том, что сейчас независимому разработчику не предлагают опубликованный интерфейс с понятными условиями подключения.

Поддерживаемый публичный API обычно объясняет, как зарегистрироваться и пройти аутентификацию, читать и записывать данные, обрабатывать ошибки и соблюдать лимиты. Ручной экспорт текста ничего этого не даёт. Сетевые запросы, которые отправляет собственный сайт Quizlet, тоже не становятся от этого публичным интерфейсом для разработчиков.

В [руководстве по состоянию Quizlet API](/ru/blog/quizlet-api/) разобраны поддерживаемые варианты: экспорт для разового копирования собственного набора, официальный embed для показа задания Quizlet и отдельные интеграции для тех сценариев, которые они прямо поддерживают. Ни один из вариантов не выдаёт стороннему приложению универсальные учётные данные для постоянной синхронизации данных с Quizlet.

Для разработчика выбор довольно простой:

- используйте экспорт, если перенос нужен один раз;
- выбирайте продукт с документированным API, если программа должна регулярно создавать, читать или обновлять карточки;
- требуйте опубликованный исходный код и подходящую лицензию, если хотите менять сам продукт.

## Можно ли развернуть Quizlet у себя?

Ни в официальной организации на GitHub, ни в публичной документации Quizlet нет поддерживаемой версии полного сервиса **для самостоятельного хостинга**. Нет и официального способа собрать основной продукт, настроить бэкенд, развернуть всё на своей инфраструктуре и подключить совместимые веб- и мобильные клиенты.

Хранить экспортированный текст на своём компьютере — это локальное хранение, а не самостоятельный хостинг. Самостоятельный хостинг означает, что вы сами управляете программой: серверами или полным стеком, конфигурацией, хранилищем данных, обновлениями и резервными копиями. И у вас есть лицензия, разрешающая запускать эту систему.

Публичные компоненты этого пробела не закрывают. Утилита для пиньиня, инструмент миграции или action для инфраструктуры могут быть частью большой системы, но не раскрывают её целиком и не делают пригодной для развёртывания.

Если самостоятельный хостинг обязателен, сравнивайте проекты, которые точно описывают, что именно можно запустить у себя. [Сравнение приложений для карточек с открытым исходным кодом](/ru/blog/best-open-source-flashcard-apps-2026/) разделяет полные веб-развёртывания, серверы только для синхронизации, локальные клиенты и хостинг всего стека. За общей формулировкой «открытый исходный код» здесь стоят совсем разные возможности.

## Раскрытие информации: я создаю альтернативу с открытым исходным кодом

> **Раскрытие информации:** меня зовут Кирилл Маркин, и я разрабатываю [Flashcards Open Source App](/ru/features/). В его [репозитории под лицензией MIT](https://github.com/kirill-markin/flashcards-open-source-app) опубликован весь стек: веб-приложение, клиенты для iOS и Android, аутентификация, бэкенд, синхронизация и инфраструктура. Граница открытого исходного кода здесь проходит иначе, чем у Quizlet, но полноценной заменой Quizlet это Flashcards не делает.

Для Flashcards есть [руководство по самостоятельному хостингу в AWS](/ru/docs/self-hosting/), а не локальный установщик в один клик. Оператор сам отвечает за облачные учётные записи, аутентификацию, доставку электронной почты, мониторинг, резервные копии, обновления и сборку нативных приложений.

Flashcards несовместим с Quizlet. Импортировать данные из Quizlet одним кликом нельзя, а вся экосистема игр и учебных процессов Quizlet для классов не воспроизводится. Проверенный текстовый экспорт из Quizlet можно взять за основу для новых карточек, но это обычный перенос данных — совместимости с наборами Quizlet и историей обучения он не даёт.

Присмотритесь к Flashcards, если открытый исходный код всего стека, лицензия MIT, API и развёртывание под вашим контролем достаточно важны, чтобы принять эти ограничения. Если важнее зрелая экосистема настольных приложений, прямой импорт или более простой самостоятельный хостинг, сравните другие [приложения для карточек с открытым исходным кодом](/ru/blog/best-open-source-flashcard-apps-2026/).

## Короткий ответ

Открыт ли исходный код Quizlet в 2026 году? **Нет — если речь о полном основном продукте.** Quizlet публикует на GitHub полезные инструменты и компоненты, но не выпускает полную собираемую версию веб- и мобильного сервиса под лицензией открытого ПО.

Публичность набора касается видимости контента и разрешения на его использование. Экспорт даёт автору текстовую копию терминов и определений. Актуальная публичная документация Quizlet не предлагает ни API общего назначения с самостоятельной регистрацией, ни поддерживаемого способа полностью развернуть продукт у себя.

Если вам нужен текст собственных карточек, экспортируйте его и проверьте результат. Для регулярной автоматизации выбирайте документированный API. А если вы хотите изучать, изменять или самостоятельно запускать продукт, ищите ПО, чья лицензия на исходный код и документация по развёртыванию явно это разрешают.
