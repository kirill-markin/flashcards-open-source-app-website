Mochiಯಲ್ಲಿ ಆರಂಭವಾಗುವುದು Markdown ದಾಖಲೆಯಿಂದ; ಸಾಂಪ್ರದಾಯಿಕ ಮುಂಭಾಗ ಮತ್ತು ಹಿಂಭಾಗದ ಫಾರ್ಮ್‌ನಿಂದಲ್ಲ. ಮೂರು ಡ್ಯಾಶ್‌ಗಳಿರುವ ಒಂದು ಸಾಲು ಸೇರಿಸಿದರೆ, ಆ ದಾಖಲೆಯಲ್ಲಿ ರಿವ್ಯೂ ಮಾಡಬಹುದಾದ ಬದಿಗಳು ರೂಪುಗೊಳ್ಳುತ್ತವೆ. ಅದನ್ನು ನೋಟ್ ಆಗಿಯೇ ಇಟ್ಟುಕೊಳ್ಳಬಹುದು, ಮತ್ತೊಂದು ಕಾರ್ಡ್‌ಗೆ ಲಿಂಕ್ ಮಾಡಬಹುದು, ಅಥವಾ ಆರ್ಕೈವ್ ಮಾಡಬಹುದು; ಆಗ ಅದು ರಿವ್ಯೂ ಸರದಿಗೆ ಬರುವುದಿಲ್ಲ, ಆದರೆ ಹುಡುಕಾಟದಲ್ಲಿ ಸಿಗುತ್ತದೆ.

ಆ ಚಿಕ್ಕ ವಿಭಾಜಕವೇ **Mochi ಫ್ಲ್ಯಾಶ್‌ಕಾರ್ಡ್‌ಗಳು** ಯಾರಿಗೆ ಹೊಂದುತ್ತವೆ ಎಂಬುದನ್ನು ವಿವರಿಸುತ್ತದೆ. ಸ್ಥಳೀಯ ಡೇಟಾಗೆ ಆದ್ಯತೆ ನೀಡುವ ಒಂದೇ ಆ್ಯಪ್‌ನಲ್ಲಿ ನೋಟ್‌ಗಳು ಮತ್ತು ಸ್ಪೇಸ್ಡ್ ರಿಪಿಟಿಷನ್ ಬೇಕಾದವರಿಗೆ Mochi ಚೆನ್ನಾಗಿ ಹೊಂದುತ್ತದೆ. ವಿಶೇಷವಾಗಿ Markdown, ಬ್ಯಾಕ್‌ಲಿಂಕ್‌ಗಳು ಮತ್ತು ಸರಳವಾದ Remembered/Forgot ರಿವ್ಯೂ ವಿಧಾನ ಸಹಜವೆನಿಸಿದರೆ. ಈಗಾಗಲೇ Anki ಬಳಸುತ್ತಿದ್ದು, ಸ್ವಯಂಚಾಲಿತವಾಗಿ ರಚನೆಯಾಗುವ ಕಾರ್ಡ್ ರೂಪಾಂತರಗಳು, ಕಸ್ಟಮ್ HTML/CSS, JavaScript, ಆ್ಯಡ್-ಆನ್‌ಗಳು ಅಥವಾ ವಿವರವಾದ ವೇಳಾಪಟ್ಟಿ ನಿಯಂತ್ರಣಗಳನ್ನು ಅವಲಂಬಿಸಿರುವ ಸಂಗ್ರಹವಿದ್ದರೆ, Mochiಗೆ ಬದಲಿಸುವುದರಿಂದ ಅಷ್ಟೊಂದು ಪ್ರಯೋಜನವಾಗದಿರಬಹುದು.

ಒಂದೇ ಸಾಧನದಲ್ಲಿ ಬಳಸುವುದಾದರೆ, ಉಚಿತ ಪ್ಲಾನ್ ಕೇವಲ ಪ್ರಯೋಗಕ್ಕೆ ಸೀಮಿತವಾಗಿಲ್ಲ: ನೋಂದಣಿ ಬೇಕಿಲ್ಲ, ಮತ್ತು ಅನಿಯಮಿತ ಆಫ್‌ಲೈನ್ ಬಳಕೆ ಇದೆ ಎಂದು Mochi ತಿಳಿಸುತ್ತದೆ. ಆದರೆ ಸಾಧನಗಳ ನಡುವಿನ ಸಿಂಕ್ **ತಿಂಗಳಿಗೆ US$5 ಇರುವ Pro ಪ್ಲಾನ್‌ಗೆ** ಸೇರಿದೆ. Anki ಬಳಕೆದಾರರಿಗೆ ವರ್ಗಾವಣೆಯಲ್ಲಿ ಕಳೆದುಕೊಳ್ಳುವ ಅಂಶಗಳೇ ದೊಡ್ಡ ಬೆಲೆ. Mochi, Anki ಪ್ಯಾಕೇಜ್ ಮತ್ತು ಅದರ ರಿವ್ಯೂ ಇತಿಹಾಸವನ್ನು ಇಂಪೋರ್ಟ್ ಮಾಡಬಲ್ಲದು. ಆದರೆ ಪ್ರತಿಯೊಂದು ಟೆಂಪ್ಲೇಟ್, ಶೈಲಿ, ಸ್ಕ್ರಿಪ್ಟ್, ವೇಳಾಪಟ್ಟಿ ಸೆಟ್ಟಿಂಗ್ ಅಥವಾ ಆ್ಯಡ್-ಆನ್ ವರ್ತನೆಯನ್ನು ಉಳಿಸಿಕೊಳ್ಳಲಾರದು.

> **ಪಾರದರ್ಶಕತೆಗಾಗಿ:** ನಾನು Kirill Markin, [Nibomo](/kn/) ಅನ್ನು ನಿರ್ಮಿಸುತ್ತಿದ್ದೇನೆ. ಇದು ಮೂಲಗಳನ್ನು ಪರಿಶೀಲಿಸಿ ಬರೆದ ಕೆಲಸದ ವಿಧಾನಗಳ ವಿಮರ್ಶೆ; ಉತ್ಪನ್ನವನ್ನು ನಾನೇ ನೇರವಾಗಿ ಬಳಸಿ ಪರೀಕ್ಷಿಸಿದ್ದೇನೆ ಎಂಬ ಹೇಳಿಕೆಯಲ್ಲ. ಇಲ್ಲಿ ಅಫಿಲಿಯೇಟ್ ಲಿಂಕ್‌ಗಳಿಲ್ಲ. ಮುಖ್ಯ ಹೋಲಿಕೆ Mochi ಮತ್ತು Anki ನಡುವೆಯೇ ಇದೆ; ಕೊನೆಯಲ್ಲಿ ಮಾತ್ರ ನನ್ನ ಉತ್ಪನ್ನವನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಗುರುತಿಸಿದ ಪರ್ಯಾಯವಾಗಿ ಉಲ್ಲೇಖಿಸಿದ್ದೇನೆ.

**ಮಾಹಿತಿ ಪರಿಶೀಲಿಸಿದ ದಿನಾಂಕ:** ಸೆಪ್ಟೆಂಬರ್ 7, 2026. ಆ ದಿನ ಕಾಣಿಸುತ್ತಿದ್ದ ಅತ್ಯಂತ ಇತ್ತೀಚಿನ [Mochi ಬಿಡುಗಡೆ](https://mochi.cards/changelog/) ಆಗಸ್ಟ್ 10, 2026ರ ಆವೃತ್ತಿ 26.8.2 ಆಗಿತ್ತು. ಬೆಲೆಗಳು ಮತ್ತು ಆ್ಯಪ್ ಸ್ಟೋರ್ ವಿವರಗಳು ಬದಲಾಗಬಹುದು.

## ಸಂಕ್ಷಿಪ್ತ ವಿಮರ್ಶೆ

- **Mochi ಆಯ್ಕೆಮಾಡಿ:** Markdown ನೋಟ್‌ಗಳು ಮತ್ತು ಕಾರ್ಡ್‌ಗಳು ಒಟ್ಟಿಗೆ ಬೇಕಿದ್ದರೆ, ಒಂದೇ ಸಾಧನದಲ್ಲಿ ಖಾತೆಯಿಲ್ಲದೆ ಆಫ್‌ಲೈನ್ ಬಳಕೆ, ಬ್ಯಾಕ್‌ಲಿಂಕ್‌ಗಳು ಮತ್ತು ಎರಡು ಆಯ್ಕೆಗಳ ರಿವ್ಯೂ ನಿರ್ಧಾರ ಬೇಕಿದ್ದರೆ.
- **Anki ಆಯ್ಕೆಮಾಡಿ:** ಬಹುಕಾಲದಿಂದ ಅಭಿವೃದ್ಧಿಗೊಂಡ ನೋಟ್ ಪ್ರಕಾರಗಳು, HTML/CSS ಟೆಂಪ್ಲೇಟ್‌ಗಳು, ಆ್ಯಡ್-ಆನ್‌ಗಳು, ಉಚಿತ ಹೋಸ್ಟೆಡ್ ಸಿಂಕ್, ನಾಲ್ಕು ರಿವ್ಯೂ ಗ್ರೇಡ್‌ಗಳು ಅಥವಾ ಇನ್ನಷ್ಟು FSRS ನಿಯಂತ್ರಣಗಳು ಬೇಕಿದ್ದರೆ.
- **ಈಗಲೇ ಬದಲಿಸಬೇಡಿ:** ನೀವು ಈಗಾಗಲೇ ನಿಯಮಿತವಾಗಿ ರಿವ್ಯೂ ಮಾಡುತ್ತಿದ್ದು, Mochi ಪರಿಹರಿಸಬೇಕಾದ ಕೆಲಸದ ವಿಧಾನದಲ್ಲಿನ ಸಮಸ್ಯೆ ಯಾವುದು ಎಂದು ಹೇಳಲಾಗದಿದ್ದರೆ. ಹಲವು ವರ್ಷಗಳ ವೇಳಾಪಟ್ಟಿ ಡೇಟಾ ಮತ್ತು ಕಸ್ಟಮ್ ಕಾರ್ಡ್‌ಗಳನ್ನು ಅಪಾಯಕ್ಕೆ ಒಡ್ಡಲು ಹೊಸ ಇಂಟರ್‌ಫೇಸ್ ಒಂದೇ ಸಾಕಾದ ಕಾರಣವಲ್ಲ.
- **ವರ್ಗಾಯಿಸುವ ಮೊದಲು ಪರೀಕ್ಷಿಸಿ:** Ankiಯಲ್ಲಿ ಈಗಾಗಲೇ ದೀರ್ಘಕಾಲದ ಸಂಗ್ರಹವಿದ್ದರೆ. Mochi `.apkg` ಫೈಲ್‌ಗಳನ್ನು ಸ್ವೀಕರಿಸಿ ರಿವ್ಯೂ ಇತಿಹಾಸವನ್ನೂ ತರಬಲ್ಲದು. ಆದರೆ HTML ಅನ್ನು Markdownಗೆ ಪರಿವರ್ತಿಸಿ, CSS ಮತ್ತು JavaScript ತೆಗೆದುಹಾಕುತ್ತದೆ.

## Mochi ಇಂಟರ್‌ಫೇಸ್ ಯಾವುದರ ಸುತ್ತ ರೂಪುಗೊಂಡಿದೆ

ಒಂದು ಕಾರ್ಡ್ Mochiಯಲ್ಲಿ ಹೇಗೆ ಸಾಗುತ್ತದೆ ಎಂಬುದನ್ನು ನೋಡಿದರೆ ಅದರ ಇಂಟರ್‌ಫೇಸ್ ಹೆಚ್ಚು ಸ್ಪಷ್ಟವಾಗುತ್ತದೆ.

ಪ್ರತಿ ಕಾರ್ಡ್ ಒಂದು ಡೆಕ್‌ಗೆ ಸೇರಿರುತ್ತದೆ. **New Card** (ಹೊಸ ಕಾರ್ಡ್) ಕ್ಲಿಕ್ ಮಾಡಿದರೆ, ನಿಗದಿತ ಪ್ರಶ್ನೆ ಮತ್ತು ಉತ್ತರದ ಬಾಕ್ಸ್‌ಗಳ ಬದಲು Markdown ಬರೆಯುವ ಜಾಗ ಸಿಗುತ್ತದೆ. ಒಂದೇ ಕಾರ್ಡ್‌ನಲ್ಲಿ ಶೀರ್ಷಿಕೆಗಳು, ಪಟ್ಟಿಗಳು, ಕೋಡ್, ಚಿತ್ರಗಳು, ನಿಗದಿತ ರಚನೆಯ ಫೀಲ್ಡ್‌ಗಳು ಮತ್ತು ಲಿಂಕ್‌ಗಳನ್ನು ಇಡಬಹುದು. ಭಾಗಗಳ ನಡುವೆ `---` ಸೇರಿಸಿ ರಿವ್ಯೂಗಾಗಿ ಎರಡು ಅಥವಾ ಹೆಚ್ಚು ಬದಿಗಳನ್ನು ರಚಿಸಬಹುದು. ಮತ್ತೊಂದು ಕಾರ್ಡ್ ಅನ್ನು ಉಲ್ಲೇಖಿಸಲು `[[double brackets]]` ಸೇರಿಸಿ; Mochi ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಬ್ಯಾಕ್‌ಲಿಂಕ್ ರಚಿಸುತ್ತದೆ. ನಿಗದಿತ ರಚನೆಯ ಫೀಲ್ಡ್‌ಗಳ ಮೌಲ್ಯಗಳನ್ನು ಪ್ಲೇಸ್‌ಹೋಲ್ಡರ್‌ಗಳ ಮೂಲಕ ತೋರಿಸುವ ಟೆಂಪ್ಲೇಟ್‌ಗಳನ್ನೂ ಅಧಿಕೃತ [ಕಾರ್ಡ್‌ಗಳ ಪರಿಚಯ](https://mochi.cards/docs/cards/) ವಿವರಿಸುತ್ತದೆ.

ಪ್ರತ್ಯೇಕ ವ್ಯವಸ್ಥೆಗಳಲ್ಲಿ ಇಡದೆ ಕಾರ್ಡ್‌ಗಳನ್ನು ಎರಡು ಕೆಲಸಗಳಿಗೆ ಬಳಸಬಹುದು:

- ರಿವ್ಯೂ ಕಾರ್ಡ್ ಬದಿಗಳನ್ನು ಬಳಸಿಕೊಂಡು ಸ್ಪೇಸ್ಡ್ ರಿಪಿಟಿಷನ್‌ಗೆ ಸೇರುತ್ತದೆ;
- ಉಲ್ಲೇಖಕ್ಕಾಗಿ ಇಟ್ಟ ನೋಟ್ ಅದೇ ಡೆಕ್‌ನಲ್ಲಿ ಉಳಿದು ಆರ್ಕೈವ್ ಆಗಬಹುದು. ಹೀಗೆ ಮಾಡಿದಾಗ ಅದರ ವಿಷಯ, ಟ್ಯಾಗ್‌ಗಳು, ಲಿಂಕ್‌ಗಳು ಅಥವಾ ಇತಿಹಾಸವನ್ನು ಅಳಿಸದೆ, ಹೊಸ ಕಾರ್ಡ್‌ಗಳು ಮತ್ತು ರಿವ್ಯೂಗೆ ಬಾಕಿಯಿರುವ ಕಾರ್ಡ್‌ಗಳ ಸರದಿಗಳಿಂದ ಹೊರಗಿಡಲಾಗುತ್ತದೆ.

[ಡೆಕ್ ವೀಕ್ಷಣೆಗಳು](https://mochi.cards/docs/decks/custom-views/) ಎಂದರೆ ಫಿಲ್ಟರ್‌ಗಳು, ವಿಂಗಡಣೆ ಮತ್ತು ವಿನ್ಯಾಸದ ಉಳಿಸಿದ ಸಂಯೋಜನೆಗಳು. ಸಾಮಾನ್ಯವಾಗಿ ನೋಡಲು ಗ್ರಿಡ್ ಇಟ್ಟುಕೊಂಡು, ನಿರ್ದಿಷ್ಟ ಟ್ಯಾಗ್, ರಿವ್ಯೂ ಬಾಕಿ ಇರುವ ಸ್ಥಿತಿ, ಕಡಿಮೆ ನೆನಪಿಡುವ ಪ್ರಮಾಣ ಅಥವಾ ಇತ್ತೀಚಿನ ರಿವ್ಯೂಗಾಗಿ ಮತ್ತೊಂದು ವೀಕ್ಷಣೆಯನ್ನು ರಚಿಸಬಹುದು. ಸಾಮಾನ್ಯ ವೇಳಾಪಟ್ಟಿ ಅಥವಾ ರಿವ್ಯೂ ಇತಿಹಾಸ ಬದಲಾಗದಂತೆ ವೀಕ್ಷಣೆಯಲ್ಲಿರುವ ಕಾರ್ಡ್‌ಗಳನ್ನು ಒಂದೇ ಅವಧಿಯಲ್ಲಿ ತೀವ್ರವಾಗಿ ಅಭ್ಯಾಸ ಮಾಡುವ cram ಸೆಷನ್ ಆಗಿಯೂ Mochi ಬಳಸಲು ಬಿಡುತ್ತದೆ. ಇಂಟರ್‌ಫೇಸ್ “ಸ್ವಚ್ಛವಾಗಿದೆ” ಎನ್ನುವುದಕ್ಕಿಂತ ಇದು ಹೆಚ್ಚು ಸ್ಪಷ್ಟ: ಅದೇ ಡೆಕ್ ನೋಟ್‌ಬುಕ್, ಫಿಲ್ಟರ್ ಮಾಡಿದ ಡೇಟಾಬೇಸ್ ಮತ್ತು ಅಧ್ಯಯನ ಸರದಿಯಾಗಿ ಕೆಲಸ ಮಾಡಬಹುದು.

[ದೈನಂದಿನ ರಿವ್ಯೂ](https://mochi.cards/docs/getting-started/reviewing-cards/) ಎರಡು ಹಂತಗಳಲ್ಲಿದೆ. **New cards** (ಹೊಸ ಕಾರ್ಡ್‌ಗಳು) ಹಂತದಲ್ಲಿ ಕಾರ್ಡ್ ಅನ್ನು ರಿವ್ಯೂ ವೇಳಾಪಟ್ಟಿಗೆ ಸೇರಿಸಬಹುದು, ಅಥವಾ ಸ್ವಲ್ಪ ಹೊತ್ತಿನಲ್ಲಿ ಮತ್ತೆ ನೋಡಲು Again ಆಯ್ಕೆಮಾಡಬಹುದು. ಕಾರ್ಡ್ ಕಲಿತ ನಂತರ, ಅದರ ರಿವ್ಯೂ ಸಮಯ ಬಂದಾಗ ಮುಂದಿನ ಬದಿಯನ್ನು ತೋರಿಸಿ **Forgot** (ಮರೆತಿದ್ದೆ) ಅಥವಾ **Remembered** (ನೆನಪಿತ್ತು) ಎಂದು ಕೇಳುತ್ತದೆ. ಮರೆತಿದ್ದರೆ, ಪ್ರಗತಿಯನ್ನು ಮರುಹೊಂದಿಸುವ ಮೊದಲು Mochi ಮರುರಿವ್ಯೂ ಸರದಿಯನ್ನು ಬಳಸುತ್ತದೆ. ಹೀಗಾಗಿ ರಿವ್ಯೂ ಸಮಯದಲ್ಲಿ ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಸೀಮಿತವಾದ ನಿರ್ಧಾರವಷ್ಟೇ ಬೇಕಾಗುತ್ತದೆ.

## Mochi ಆಯ್ಕೆಮಾಡಲು ನಿಜವಾದ ಕಾರಣ Markdown ಫ್ಲ್ಯಾಶ್‌ಕಾರ್ಡ್‌ಗಳು

ನೀವು ನಿರ್ವಹಿಸುವ ಮೂಲ ವಿಷಯವನ್ನು Markdown ಹೇಗೆ ಬದಲಿಸುತ್ತದೆ ಎಂಬುದೇ Mochiಯ ನಿಜವಾದ ಪ್ರಯೋಜನ.

Mochi ಕಾರ್ಡ್ ಪಠ್ಯವಾಗಿಯೂ ಓದಲು ಸುಲಭವಾಗಿರುತ್ತದೆ. ಅದೇ ದಾಖಲೆಯಲ್ಲಿ ಚಿಕ್ಕ ವಿವರಣೆ, ಕೋಡ್ ಬ್ಲಾಕ್, ಸಂಬಂಧಿತ ವಿಚಾರಗಳ ಲಿಂಕ್‌ಗಳು ಮತ್ತು ರಿವ್ಯೂ ಬದಿಗಳ ನಡುವಿನ ವಿಭಾಜಕಗಳು ಇರಬಹುದು. ಒಂದೇ ರಚನೆ ಮತ್ತೆ ಮತ್ತೆ ಬೇಕಾದಾಗ ಕಾರ್ಡ್‌ಗಳಲ್ಲಿ ಫೀಲ್ಡ್‌ಗಳು ಮತ್ತು ಟೆಂಪ್ಲೇಟ್‌ಗಳನ್ನೂ ಬಳಸಬಹುದು. ಟೆಂಪ್ಲೇಟ್ ಅನ್ವಯಿಸಿದಾಗ, Mochi ಫೀಲ್ಡ್ ಪ್ಲೇಸ್‌ಹೋಲ್ಡರ್‌ಗಳಿರುವ ಟೆಂಪ್ಲೇಟ್‌ನ Markdown ಅನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ. ಕಾರ್ಡ್‌ನ ಸ್ವಂತ Markdown ಅನ್ನು ಅಳಿಸದೆ, ಪ್ರದರ್ಶನದ ಸಮಯದಲ್ಲಿ ಕಡೆಗಣಿಸುತ್ತದೆ.

Anki ಬೇರೆ ಮಾದರಿಯಿಂದ ಆರಂಭವಾಗುತ್ತದೆ. ಒಂದು ನೋಟ್‌ನಲ್ಲಿ ಫೀಲ್ಡ್‌ಗಳ ಮೌಲ್ಯಗಳು ಉಳಿಯುತ್ತವೆ; ಯಾವ ಫೀಲ್ಡ್‌ಗಳು ಕಾಣಿಸಬೇಕು ಮತ್ತು ಯಾವ ಕಾರ್ಡ್‌ಗಳು ರಚನೆಯಾಗಬೇಕು ಎಂಬುದನ್ನು [ಕಾರ್ಡ್ ಟೆಂಪ್ಲೇಟ್‌ಗಳು](https://docs.ankiweb.net/templates/intro.html) ನಿರ್ಧರಿಸುತ್ತವೆ. ಟೆಂಪ್ಲೇಟ್‌ಗಳು HTML ಬಳಸುತ್ತವೆ, ಶೈಲಿಗಾಗಿ CSS ಇರುತ್ತದೆ. ಆದ್ದರಿಂದ ಒಂದು ಶಬ್ದಸಂಪತ್ತಿನ ನೋಟ್‌ನಿಂದ ಪದವನ್ನು ಗುರುತಿಸುವ ಕಾರ್ಡ್ ಮತ್ತು ಅದನ್ನು ಸ್ವತಃ ನೆನಪಿನಿಂದ ಹೇಳುವ ಕಾರ್ಡ್ ರಚಿಸಬಹುದು; ಮೂಲ ಡೇಟಾ ಒಂದೇ ಕಡೆ ಉಳಿಯುತ್ತದೆ.

ಈ ರಚನೆಯಿಂದ ಷರತ್ತುಬದ್ಧ ವಿನ್ಯಾಸಗಳು, ಸ್ವಯಂಚಾಲಿತ ಕಾರ್ಡ್ ರೂಪಾಂತರಗಳು, ಟೈಪ್ ಮಾಡಿ ನೀಡುವ ಉತ್ತರಗಳು, ಕಸ್ಟಮ್ ಶೈಲಿ ಮತ್ತು ಆ್ಯಡ್-ಆನ್‌ಗಳಿಂದ ವಿಸ್ತರಿಸಿದ ಕೆಲಸದ ವಿಧಾನಗಳಲ್ಲಿ Ankiಗೆ ಹೆಚ್ಚು ಅವಕಾಶವಿದೆ. ಜೊತೆಗೆ Anki ಮೂಲತಃ Markdown ಫ್ಲ್ಯಾಶ್‌ಕಾರ್ಡ್ ಆ್ಯಪ್ ಅಲ್ಲ ಎಂಬುದೂ ಇದರ ಅರ್ಥ. Markdown ಆಧಾರಿತ Anki ಕೆಲಸದ ವಿಧಾನಕ್ಕೆ ಹೆಚ್ಚುವರಿ ಪರಿವರ್ತನೆ ಅಥವಾ ಆ್ಯಡ್-ಆನ್ ಪದರ ಬೇಕಾಗುತ್ತದೆ.

ಪ್ರಾಯೋಗಿಕ ಪ್ರಶ್ನೆ ಸರಳವಾಗಿದೆ: ಕಾರ್ಡ್ ಆಗಬಹುದಾದ ನೋಟ್ ಬೇಕೇ, ಅಥವಾ ಹಲವು ಕಾರ್ಡ್‌ಗಳನ್ನು ರಚಿಸಬಲ್ಲ ನಿಗದಿತ ರಚನೆಯ ನೋಟ್ ಪ್ರಕಾರ ಬೇಕೇ? ಮೊದಲನೆಯದಕ್ಕೆ Mochi ಹೆಚ್ಚು ಸೂಕ್ತ. ಎರಡನೆಯದಕ್ಕೆ Anki ಹೆಚ್ಚು ಸೂಕ್ತ.

## Mochi ಸ್ಪೇಸ್ಡ್ ರಿಪಿಟಿಷನ್‌ನಲ್ಲಿ ಈಗ FSRS ಕೂಡ ಇದೆ

Mochiಯಲ್ಲಿ FSRS ಇಲ್ಲ ಎನ್ನುವ ಹೋಲಿಕೆಗಳು ಹಳೆಯದಾಗಿವೆ. Mochi 2025ರಲ್ಲಿ FSRS ಪೂರ್ವವೀಕ್ಷಣೆ ಸೇರಿಸಿತು ಮತ್ತು ಅದರ ವೇಳಾಪಟ್ಟಿ ವ್ಯವಸ್ಥೆಗೆ ಸಂಬಂಧಿಸಿದ ದೋಷ ಪರಿಹಾರಗಳನ್ನು ಬಿಡುಗಡೆ ಮಾಡುತ್ತಲೇ ಬಂದಿದೆ. ಆದರೂ [Mochiಯ ಸ್ವಂತ ಅಲ್ಗಾರಿದಮ್ ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ ಉಳಿದಿದೆ](https://mochi.cards/docs/reviewing/fsrs/).

ಪ್ರತಿ ರಿವ್ಯೂನಲ್ಲಿ ನೆನಪಿದ್ದರೆ ಅಥವಾ ಮರೆತಿದ್ದರೆ, ಪೂರ್ವನಿಯೋಜಿತ ಅಲ್ಗಾರಿದಮ್ ನಿಗದಿತ ಗುಣಕಗಳಿಂದ ಅಂತರಗಳನ್ನು ಬದಲಿಸುತ್ತದೆ. Review Settings (ರಿವ್ಯೂ ಸೆಟ್ಟಿಂಗ್‌ಗಳು)ನಲ್ಲಿ FSRSಗೆ ಬದಲಿಸಿದರೆ, ಈಗಾಗಲೇ ಕಲಿತ ಕಾರ್ಡ್‌ಗಳು ಇತಿಹಾಸ ಕಳೆದುಕೊಳ್ಳದೆ FSRSಗೆ ಹೋಗುತ್ತವೆ. ಗುರಿಯಾಗಿಟ್ಟ ನೆನಪಿಡುವ ಪ್ರಮಾಣವನ್ನು ಹೊಂದಿಸಬಹುದು, ಕಸ್ಟಮ್ ಪ್ಯಾರಾಮೀಟರ್‌ಗಳನ್ನು ನಮೂದಿಸಬಹುದು ಮತ್ತು ನಂತರ ಹಿಂದಿನ ವಿಧಾನಕ್ಕೆ ಮರಳಬಹುದು.

ಎರಡೂ ವೇಳಾಪಟ್ಟಿ ವ್ಯವಸ್ಥೆಗಳಲ್ಲಿ Mochi ತನ್ನ ಎರಡು ಗ್ರೇಡ್‌ಗಳನ್ನು ಉಳಿಸಿಕೊಳ್ಳುತ್ತದೆ:

- **Forgot** ಎಂಬುದು FSRSನ Againಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ.
- **Remembered** ಎಂಬುದು FSRSನ Goodಗೆ ಹೊಂದಿಕೆಯಾಗುತ್ತದೆ.

Mochi ಮಾರ್ಗದರ್ಶಿಯ ಪ್ರಕಾರ ಎರಡು ಗ್ರೇಡ್‌ಗಳ ವಿಧಾನ FSRS ಜೊತೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ. ಆದರೆ Hard ಮತ್ತು Easy ನೀಡಬಹುದಾದ ಕೆಲವು ಮಾಹಿತಿ ಇದರಲ್ಲಿ ಸಿಗುವುದಿಲ್ಲ. ಆಪ್ಟಿಮೈಸ್ ಮಾಡಿದ ಕಸ್ಟಮ್ ಪ್ಯಾರಾಮೀಟರ್‌ಗಳನ್ನು ಅದು ಸ್ವೀಕರಿಸುತ್ತದೆ, ಆದರೆ ಒಳಗೇ ಆಪ್ಟಿಮೈಸರ್ ಇಲ್ಲ. ವೈಯಕ್ತಿಕ ಪ್ಯಾರಾಮೀಟರ್‌ಗಳನ್ನು ರಚಿಸಲು ಹೊರಗಿನ FSRS ಆಪ್ಟಿಮೈಸರ್ ಮತ್ತು Mochi ರಿವ್ಯೂ ಇತಿಹಾಸ ಬೇಕಾಗುತ್ತದೆ.

[Ankiಯ FSRS ಸೆಟ್ಟಿಂಗ್‌ಗಳು](https://docs.ankiweb.net/deck-options.html#fsrs) ಇನ್ನೂ ಹೆಚ್ಚಿನ ನಿಯಂತ್ರಣ ನೀಡುತ್ತವೆ. ಬಯಸಿದ ನೆನಪಿಡುವ ಪ್ರಮಾಣ ಮತ್ತು ಪ್ಯಾರಾಮೀಟರ್‌ಗಳನ್ನು ಪೂರ್ವನಿಗದಿಗಳಿಗೆ ಜೋಡಿಸಬಹುದು. ಒಳಗಿರುವ ಆಪ್ಟಿಮೈಸರ್ ರಿವ್ಯೂ ಇತಿಹಾಸಕ್ಕೆ ತಕ್ಕಂತೆ ಪ್ಯಾರಾಮೀಟರ್‌ಗಳನ್ನು ಹೊಂದಿಸಬಲ್ಲದು. ಬೇರೆ ಬೇರೆ ಸೆಟ್ಟಿಂಗ್‌ಗಳಲ್ಲಿ ಎಷ್ಟು ರಿವ್ಯೂಗಳು ಅಥವಾ ಅಧ್ಯಯನ ನಿಮಿಷಗಳು ಬೇಕಾಗಬಹುದು ಎಂದು ಸಿಮ್ಯುಲೇಟರ್ ಅಂದಾಜಿಸುತ್ತದೆ. Anki ನಾಲ್ಕು ಫಲಿತಾಂಶಗಳನ್ನೂ ದಾಖಲಿಸುತ್ತದೆ: Again, Hard, Good ಮತ್ತು Easy.

ಹೆಚ್ಚುವರಿ ಬಟನ್‌ಗಳನ್ನು ಪ್ರತಿ ಬಾರಿಯೂ ಅವುಗಳ ಅರ್ಥಕ್ಕೆ ತಕ್ಕಂತೆ ಬಳಸಿದರೆ ಮಾತ್ರ ಅವು ನೆರವಾಗುತ್ತವೆ. Anki ಕೈಪಿಡಿ Hard ಅನ್ನು ಯಶಸ್ವಿಯಾಗಿ ನೆನಪಿಸಿಕೊಂಡ ಫಲಿತಾಂಶವೆಂದು ಪರಿಗಣಿಸುತ್ತದೆ. ಉತ್ತರ ಮರೆತಿದ್ದಾಗ Hard ಒತ್ತಿದರೆ FSRSಗೆ ತಪ್ಪು ಮಾಹಿತಿ ಕೊಟ್ಟಂತಾಗುತ್ತದೆ, ಮತ್ತು ರಿವ್ಯೂ ನಡುವಿನ ಅಂತರಗಳು ಅತಿಯಾಗಿ ಉದ್ದವಾಗಬಹುದು.

ನೆನಪಿತ್ತು/ಮರೆತಿದ್ದೆ ಎಂಬ ನಿರ್ಧಾರದಿಂದ ಸೆಷನ್ ಸರಳವಾಗಿದ್ದರೆ Mochiಯ ಎರಡು ಆಯ್ಕೆಗಳ ರಿವ್ಯೂ ಆರಿಸಿ. ಹೆಚ್ಚುವರಿ ಗ್ರೇಡ್ ಮಾಹಿತಿ ಬೇಕಿದ್ದರೆ ಮತ್ತು ಆಪ್ಟಿಮೈಸರ್, ನೆನಪಿಡುವ ಪ್ರಮಾಣದ ನಿಯಂತ್ರಣಗಳು, ಪೂರ್ವನಿಗದಿಗಳು ಅಥವಾ ಅಧ್ಯಯನದ ಹೊರೆ ಸಿಮ್ಯುಲೇಟರ್ ಬಳಸುವುದಾದರೆ Anki ಆರಿಸಿ. ಆ್ಯಪ್‌ಗಳ ಬದಲು ವೇಳಾಪಟ್ಟಿ ಅಲ್ಗಾರಿದಮ್‌ಗಳ ಹೋಲಿಕೆಗಾಗಿ [FSRS ಮತ್ತು SM-2](/blog/fsrs-vs-sm-2/) ನೋಡಿ.

## Mochi ಹೋಸ್ಟಿಂಗ್ ಮತ್ತು ಸ್ಥಳೀಯ ಡೇಟಾಗೆ ಆದ್ಯತೆ ನೀಡುವ ಬಳಕೆ ಒಂದೇ ಅಲ್ಲ

ಮೂರು ಪದಗಳನ್ನು ಹೆಚ್ಚಾಗಿ ಒಂದೇ ಅರ್ಥದಲ್ಲಿ ಬಳಸಲಾಗುತ್ತದೆ:

- **ಸ್ಥಳೀಯ ಡೇಟಾಗೆ ಆದ್ಯತೆ (Local-first)** ಎಂದರೆ ಕೆಲಸಕ್ಕೆ ಬಳಸುವ ಪ್ರತಿ ನಿಮ್ಮ ಸಾಧನದಲ್ಲಿರುತ್ತದೆ ಮತ್ತು ಆ್ಯಪ್ ತನ್ನ ಕ್ಲೌಡ್ ಸೇವೆಯಿಲ್ಲದೆಯೂ ಮುಂದುವರಿಯಬಲ್ಲದು.
- **ಓಪನ್ ಸೋರ್ಸ್** ಎಂದರೆ ಪರಿಶೀಲನೆ ಮತ್ತು ಬದಲಾವಣೆಗೆ ಅನುಮತಿ ನೀಡುವ ಪರವಾನಗಿಯಡಿ ಸೋರ್ಸ್ ಕೋಡ್ ಲಭ್ಯವಿರುತ್ತದೆ.
- **ಸ್ವಂತ ಹೋಸ್ಟಿಂಗ್** ಎಂದರೆ ಸಂಬಂಧಿತ ಸೇವೆಯನ್ನು ನಿಮ್ಮದೇ ಮೂಲಸೌಕರ್ಯದಲ್ಲಿ ನಡೆಸಲು ಬೆಂಬಲಿತ ವಿಧಾನವನ್ನು ಉತ್ಪನ್ನದ ಮಾರ್ಗದರ್ಶಿ ವಿವರಿಸುತ್ತದೆ.

Mochi ಸ್ಥಳೀಯ ಡೇಟಾಗೆ ಆದ್ಯತೆ ನೀಡುವ ವರ್ತನೆಯನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ದಾಖಲಿಸಿದೆ. ಅದು ತನ್ನ ಮೂಲ ಆ್ಯಪ್ ಅನ್ನು ಓಪನ್ ಸೋರ್ಸ್ ಎಂದು ಪರಿಚಯಿಸುವುದಿಲ್ಲ: ಸಾರ್ವಜನಿಕ ತಾಣದ ಅಡಿಭಾಗದಲ್ಲಿರುವ “Open source” ಲಿಂಕ್ [ಸಂಪರ್ಕ ಸಾಧನಗಳ ಸಂಗ್ರಹಕ್ಕೆ](https://github.com/mochi-cards/open-source) ಹೋಗುತ್ತದೆ, ಮೂಲ ಆ್ಯಪ್‌ಗೆ ಅಲ್ಲ. ಅದರ ಅಧಿಕೃತ ತಾಣದಲ್ಲಿ Pro ಸಿಂಕ್‌ಗೆ ಬದಲಾಗಿ ಸ್ವಂತವಾಗಿ ಹೋಸ್ಟ್ ಮಾಡಬಹುದಾದ ಬೆಂಬಲಿತ ಸೇವೆಯ ಮಾರ್ಗದರ್ಶಿಯೂ ಇಲ್ಲ.

ನಿಮ್ಮದೇ ಸರ್ವರ್ ಬೇಕೆಂದು **Mochi ಹೋಸ್ಟಿಂಗ್** ಹುಡುಕುತ್ತಿದ್ದರೆ, ಮಿತಿ ಇದು: ಸ್ಥಳೀಯ ಡೇಟಾ ಮತ್ತು ನೇಟಿವ್ ಬ್ಯಾಕಪ್‌ಗಳನ್ನು ಇಟ್ಟುಕೊಳ್ಳಬಹುದು, ಆದರೆ ಸಾಧನಗಳ ನಡುವಿನ ಬಳಕೆಗೆ ದಾಖಲಿಸಿರುವ ದಾರಿ Mochi Pro. ಸ್ಥಳೀಯ ಡೇಟಾಗೆ ಆದ್ಯತೆ ನೀಡುವುದು ಉಪಯುಕ್ತ ಡೇಟಾ ನಿಯಂತ್ರಣ; ಅದು ಸ್ವಂತ ಹೋಸ್ಟಿಂಗ್ ಆಗುವುದಿಲ್ಲ.

Ankiಯ ಮುಖ್ಯ ರೆಪೊಸಿಟರಿಗೆ [AGPL ಆವೃತ್ತಿ 3 ಅಥವಾ ನಂತರದ ಆವೃತ್ತಿಯ ಪರವಾನಗಿ](https://github.com/ankitects/anki/blob/main/LICENSE) ಇದೆ; ಕೆಲವು ಘಟಕಗಳಿಗೆ ನಮೂದಿಸಿದ ವಿನಾಯಿತಿಗಳಿವೆ. ಅನುಭವಿ ಬಳಕೆದಾರರಿಗೆ [ಸ್ವಂತವಾಗಿ ಹೋಸ್ಟ್ ಮಾಡಬಹುದಾದ ಸಿಂಕ್ ಸರ್ವರ್](https://docs.ankiweb.net/sync-server.html) ಅನ್ನು ಅಧಿಕೃತ ಕೈಪಿಡಿಯೂ ವಿವರಿಸುತ್ತದೆ. ಹೊಂದಿಕೆಯಾಗುವ ಕ್ಲೈಂಟ್‌ಗಳಿಗೆ ಆ ಸರ್ವರ್ AnkiWeb ಸಿಂಕ್‌ಗೆ ಪರ್ಯಾಯವಾಗುತ್ತದೆ. ಅದು AnkiWeb ತಾಣದ ಸ್ವಂತ ಹೋಸ್ಟಿಂಗ್ ಪ್ರತಿಯಲ್ಲ. ಅದನ್ನು ನಡೆಸುವವರು ಕಮಾಂಡ್ ಲೈನ್, ನೆಟ್‌ವರ್ಕಿಂಗ್, ಫೈರ್‌ವಾಲ್, ಪ್ರೋಟೋಕಾಲ್ ಮತ್ತು ಅಪ್‌ಡೇಟ್ ಸಮಸ್ಯೆಗಳನ್ನು ನಿಭಾಯಿಸಬೇಕು ಎಂದು Anki ನಿರೀಕ್ಷಿಸುತ್ತದೆ.

## Anki ಇಂಪೋರ್ಟ್ ಏನನ್ನು ಉಳಿಸುತ್ತದೆ, ಏನನ್ನು ಬದಲಿಸುತ್ತದೆ

Mochiಯ [ಇಂಪೋರ್ಟ್ ಮಾರ್ಗದರ್ಶಿ](https://mochi.cards/docs/import-and-export/importing/) ರಿವ್ಯೂ ಇತಿಹಾಸ ಸೇರಿದಂತೆ Anki `.apkg` ಫೈಲ್‌ಗಳನ್ನು ಸ್ವೀಕರಿಸುವುದಾಗಿ ಹೇಳುತ್ತದೆ. ಆದರೆ “ಇಂಪೋರ್ಟ್ ಆಗಿದೆ” ಮತ್ತು “ಸಮಾನವಾಗಿ ಕೆಲಸ ಮಾಡುತ್ತದೆ” ಎಂಬುದು ಒಂದೇ ಫಲಿತಾಂಶವಲ್ಲ.

ಇಂಪೋರ್ಟ್ ಮಾಡುವಾಗ Mochi HTML ಅನ್ನು Markdownಗೆ ಪರಿವರ್ತಿಸಿ, CSS ಮತ್ತು JavaScript ತೆಗೆದುಹಾಕುತ್ತದೆ. ಇದು ಎರಡು ಬೇರೆ ಕಾರ್ಡ್ ಮಾದರಿಗಳ ನಡುವಿನ ಫಾರ್ಮ್ಯಾಟ್ ಪರಿವರ್ತನೆ. ಸರಳ ಮುಂಭಾಗ/ಹಿಂಭಾಗದ ವಿಷಯ ಸುಲಭವಾದ ಸಂದರ್ಭ. ಶೈಲಿ, ಟೆಂಪ್ಲೇಟ್ ಲಾಜಿಕ್, ಟೈಪ್ ಮಾಡುವ ಮೂಲಕ ನಡೆಯುವ ಸಂವಹನ ಅಥವಾ JavaScript ಅವಲಂಬಿಸಿರುವ ಕಾರ್ಡ್ ಅನ್ನು ಇಂಪೋರ್ಟ್ ನಂತರ ಪರಿಶೀಲಿಸಬೇಕು.

ರಿವ್ಯೂ ಇತಿಹಾಸಕ್ಕೂ ಎಕ್ಸ್‌ಪೋರ್ಟ್‌ನಲ್ಲಿ ಸ್ಪಷ್ಟ ಆಯ್ಕೆ ಬೇಕು. Ankiಯ [ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಕೈಪಿಡಿ](https://docs.ankiweb.net/exporting.html) ಪ್ರಕಾರ **Include Scheduling Information** (ವೇಳಾಪಟ್ಟಿ ಮಾಹಿತಿ ಸೇರಿಸಿ) ಆಯ್ಕೆಯು ರಿವ್ಯೂ ಇತಿಹಾಸ ಪ್ಯಾಕೇಜ್‌ಗೆ ಸೇರುತ್ತದೆಯೇ ಎಂಬುದನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ. ಅದನ್ನು ಆರಿಸದಿದ್ದರೆ, `.apkg`ಯಲ್ಲಿ ಇಲ್ಲದ ಇತಿಹಾಸವನ್ನು Mochi ಮರಳಿ ಪಡೆಯಲಾರದು.

ಇತಿಹಾಸ ಬಂದರೂ ಮುಂದಿನ ರಿವ್ಯೂ ದಿನಾಂಕಗಳು ಒಂದೇ ಆಗಿರುತ್ತವೆ ಎಂದು ನಿರೀಕ್ಷಿಸಬೇಡಿ. ಎರಡು ಆ್ಯಪ್‌ಗಳು ಬೇರೆ ವೇಳಾಪಟ್ಟಿ ವ್ಯವಸ್ಥೆಗಳು, ಗ್ರೇಡ್‌ಗಳು, ಗುರಿಯಾಗಿಟ್ಟ ನೆನಪಿಡುವ ಪ್ರಮಾಣ, ಪ್ಯಾರಾಮೀಟರ್‌ಗಳು, ಕಲಿಕೆಯ ಹಂತಗಳು ಮತ್ತು ಡೆಕ್ ಸೆಟ್ಟಿಂಗ್‌ಗಳನ್ನು ಬಳಸಬಹುದು. ಉಳಿಸಿದ ಘಟನೆಗಳು ಹೊಸ ವೇಳಾಪಟ್ಟಿ ವ್ಯವಸ್ಥೆಗೆ ಆಧಾರ ನೀಡುತ್ತವೆ; ಎರಡೂ ವ್ಯವಸ್ಥೆಗಳನ್ನು ಒಂದೇ ಆಗಿಸುವುದಿಲ್ಲ.

## ನೇಟಿವ್ ಬ್ಯಾಕಪ್‌ಗಳು ಮತ್ತು ವರ್ಗಾಯಿಸಬಹುದಾದ ಪಠ್ಯದ ಕೆಲಸ ಬೇರೆ

ಏನನ್ನಾದರೂ ವರ್ಗಾಯಿಸುವ ಮೊದಲು ಮೂಲ ವ್ಯವಸ್ಥೆಯನ್ನು ಮರುಸ್ಥಾಪಿಸಬಲ್ಲ ಬ್ಯಾಕಪ್ ಇಟ್ಟುಕೊಳ್ಳಿ. ಓದಬಹುದಾದ ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಉಪಯುಕ್ತ, ಆದರೆ ಅದರಿಂದ ಯಾವಾಗಲೂ ಮರುಸ್ಥಾಪಿಸಲು ಆಗುವುದಿಲ್ಲ.

Mochiಯ [ಬ್ಯಾಕಪ್ ಮಾರ್ಗದರ್ಶಿ](https://mochi.cards/docs/getting-started/backing-up/) ಎರಡು ನೇಟಿವ್ ಸುರಕ್ಷತಾ ಆಯ್ಕೆಗಳನ್ನು ವಿವರಿಸುತ್ತದೆ:

- ಸಂಪೂರ್ಣ ಬಳಕೆದಾರ ಡೈರೆಕ್ಟರಿಯನ್ನು ನಕಲಿಸುವುದು ವಿಷಯ, ರಿವ್ಯೂ ಇತಿಹಾಸ, ಲಗತ್ತುಗಳು, ಆ್ಯಪ್ ಸೆಟ್ಟಿಂಗ್‌ಗಳು ಮತ್ತು ಲಾಗಿನ್ ಸ್ಥಿತಿಯನ್ನು ಉಳಿಸುತ್ತದೆ.
- `.mochi` ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಡೆಕ್‌ಗಳು, ಕಾರ್ಡ್‌ಗಳು, ಟೆಂಪ್ಲೇಟ್‌ಗಳು ಮತ್ತು ಫೀಲ್ಡ್‌ಗಳು, ಲಗತ್ತುಗಳು, ಟ್ಯಾಗ್‌ಗಳು ಮತ್ತು ಮೆಟಾಡೇಟಾ, ರಿವ್ಯೂ ಇತಿಹಾಸ, ಕಾರ್ಡ್ ಕ್ರಮ ಮತ್ತು ಡೆಕ್ ರಚನೆಯನ್ನು ಉಳಿಸುತ್ತದೆ.

Mochiಯ [Markdown ಮತ್ತು CSV ಎಕ್ಸ್‌ಪೋರ್ಟ್‌ಗಳು](https://mochi.cards/docs/import-and-export/exporting/) ವಿಷಯವನ್ನು ವರ್ಗಾಯಿಸಲು ಇರುವ ಫಾರ್ಮ್ಯಾಟ್‌ಗಳು. Markdown ಪ್ರತಿ ಕಾರ್ಡ್‌ಗೆ ಒಂದು ಫೈಲ್ ಮತ್ತು ಉಪಡೆಕ್‌ಗಳಿಗೆ ಫೋಲ್ಡರ್‌ಗಳನ್ನು ರಚಿಸುತ್ತದೆ. ಆದರೆ ರಿವ್ಯೂ ಇತಿಹಾಸ, ಕಾರ್ಡ್ ಕ್ರಮ, ಟೆಂಪ್ಲೇಟ್‌ಗಳು ಮತ್ತು ಮೆಟಾಡೇಟಾ ಟ್ಯಾಗ್‌ಗಳನ್ನು ಕೈಬಿಡುತ್ತದೆ; ಟ್ಯಾಗ್‌ಗಳು Markdown ಒಳಗಿದ್ದರೆ ಮಾತ್ರ ಉಳಿಯುತ್ತವೆ. CSV ಟೆಂಪ್ಲೇಟ್ ಫೀಲ್ಡ್‌ಗಳನ್ನು ಅಥವಾ ಪ್ರದರ್ಶಿತ ಮುಂಭಾಗ/ಹಿಂಭಾಗವನ್ನು ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಮಾಡಬಲ್ಲದು. ಆದರೆ ರಿವ್ಯೂ ಇತಿಹಾಸ, ಟೆಂಪ್ಲೇಟ್‌ಗಳು ಅಥವಾ ಮೆಟಾಡೇಟಾ ಟ್ಯಾಗ್‌ಗಳನ್ನು ಉಳಿಸುವುದಿಲ್ಲ; ಟ್ಯಾಗ್‌ಗಳು ವಿಷಯದೊಳಗೆ ಸೇರಿದ್ದರೆ ಮಾತ್ರ ಉಳಿಯುತ್ತವೆ.

Ankiಯಲ್ಲೂ ಇದೇ ರೀತಿಯ ವ್ಯತ್ಯಾಸವಿದೆ:

- `.colpkg` ವೇಳಾಪಟ್ಟಿಯೊಂದಿಗೆ ಸಂಪೂರ್ಣ ಸಂಗ್ರಹವನ್ನು ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಮಾಡುತ್ತದೆ ಮತ್ತು ಮೀಡಿಯಾವನ್ನೂ ಸೇರಿಸಬಹುದು. ಅದನ್ನು ಇಂಪೋರ್ಟ್ ಮಾಡಿದರೆ ಗುರಿಯಾದ Anki ಸಂಗ್ರಹದಲ್ಲಿನ ಕಾರ್ಡ್‌ಗಳ ಸ್ಥಾನದಲ್ಲಿ ಪ್ಯಾಕೇಜ್‌ನಲ್ಲಿರುವ ಕಾರ್ಡ್‌ಗಳು ಬರುತ್ತವೆ.
- `.apkg` ಒಂದು ಡೆಕ್ ಮತ್ತು ಅದರ ಉಪಡೆಕ್‌ಗಳನ್ನು ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಮಾಡುತ್ತದೆ. ವೇಳಾಪಟ್ಟಿ ಮಾಹಿತಿ, ಪೂರ್ವನಿಗದಿಗಳು ಮತ್ತು ಮೀಡಿಯಾ ಸೇರಿಸುವ ಆಯ್ಕೆಗಳಿವೆ.
- ಸರಳ ಪಠ್ಯದಲ್ಲಿನ ನೋಟ್‌ಗಳು ಒಳಗೇ ಸೇರಿಸಿದ HTML ಫಾರ್ಮ್ಯಾಟಿಂಗ್‌ನೊಂದಿಗೆ ಟ್ಯಾಬ್‌ಗಳಿಂದ ಬೇರ್ಪಡಿಸಿದ ಫೀಲ್ಡ್‌ಗಳನ್ನು ಬಳಸುತ್ತವೆ. ಅವು ತಿದ್ದಬಹುದಾದ ವಿಷಯವನ್ನು ಉಳಿಸುತ್ತವೆ, ಸಂಪೂರ್ಣ ಸಂಗ್ರಹದ ವರ್ತನೆಯನ್ನಲ್ಲ.

Mochiಯಿಂದ ಮತ್ತೆ Ankiಗೆ ಹೋಗಲು ಸಾಮಾನ್ಯವಾಗಿ CSV ಬಳಸಲಾಗುತ್ತದೆ. Anki [ಪಠ್ಯದ ಕಾಲಮ್‌ಗಳನ್ನು ನೋಟ್ ಫೀಲ್ಡ್‌ಗಳಿಗೆ ಹೊಂದಿಸಬಲ್ಲದು](https://docs.ankiweb.net/importing/text-files.html). ಆದರೆ ಆ ಫೈಲ್ ಮೂಲಕ Mochi ಲಿಂಕ್‌ಗಳು, ಹಲವು ಬದಿಗಳ ವರ್ತನೆ, ಟೆಂಪ್ಲೇಟ್‌ಗಳು ಮತ್ತು ರಿವ್ಯೂ ಇತಿಹಾಸ ಸಮಾನ Anki ವಸ್ತುಗಳಾಗುವುದಿಲ್ಲ. Ankiಯಲ್ಲಿನ ಪ್ರತಿ ಸರಿಯಾಗಿ ಕಾಣಿಸಿಕೊಂಡ ನಂತರವೂ `.mochi` ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಇಟ್ಟುಕೊಳ್ಳಿ.

## ಹಿಂದಕ್ಕೆ ಮರಳಲು ಅವಕಾಶವಿರುವ ಪ್ರಾತಿನಿಧಿಕ ಡೆಕ್ ಪರೀಕ್ಷೆ ಮಾಡಿ

ವರ್ಗಾವಣೆಯ ಸಂವಾದಪೆಟ್ಟಿಗೆ ಒಂದು ಫೈಲ್ ಸ್ವೀಕರಿಸಲಾಗಿದೆ ಎಂಬುದನ್ನು ಮಾತ್ರ ತೋರಿಸುತ್ತದೆ. ನಿಮ್ಮ ನಿಜವಾದ ಸಂಗ್ರಹ ಇನ್ನೂ ಸರಿಯಾಗಿ ಕೆಲಸ ಮಾಡುತ್ತದೆ ಅಥವಾ ಉಪಯೋಗಿಸಬಹುದಾದ ವಿಷಯವನ್ನು ಮರಳಿ ತರಬಹುದು ಎಂಬುದನ್ನು ಅದು ಸಾಬೀತುಪಡಿಸುವುದಿಲ್ಲ. ನಿಮ್ಮ ಸಾಮಾನ್ಯ Anki ಪ್ರೊಫೈಲ್‌ಗೆ ಬದಲಾವಣೆ ಮಾಡದೆ ಎರಡೂ ದಿಕ್ಕುಗಳಲ್ಲಿ ಪರೀಕ್ಷಿಸಿ.

1. **ಸಂಪೂರ್ಣ Anki ಬ್ಯಾಕಪ್ ಮಾಡಿ.** ಮೀಡಿಯಾದೊಂದಿಗೆ `.colpkg` ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಮಾಡಿ, ಕೆಲಸಕ್ಕೆ ಬಳಸುವ ಪ್ರೊಫೈಲ್‌ನ ಹೊರಗೆ ಉಳಿಸಿ.
2. **ಬ್ಯಾಕಪ್ ತೆರೆಯುತ್ತದೆ ಎಂದು ಖಚಿತಪಡಿಸಿಕೊಳ್ಳಿ.** ಖಾಲಿ ತಾತ್ಕಾಲಿಕ Anki ಪ್ರೊಫೈಲ್ ರಚಿಸಿ, ಅಲ್ಲಿ `.colpkg` ಇಂಪೋರ್ಟ್ ಮಾಡಿ. ಸಂಗ್ರಹ ಪ್ಯಾಕೇಜ್ ಇಂಪೋರ್ಟ್ ಮಾಡಿದಾಗ ಗುರಿಯಲ್ಲಿರುವ ಸಂಗ್ರಹದ ಸ್ಥಾನದಲ್ಲಿ ಪ್ಯಾಕೇಜ್‌ನ ಸಂಗ್ರಹ ಬರುತ್ತದೆ; ಅದಕ್ಕೇ ತಾತ್ಕಾಲಿಕ ಪ್ರೊಫೈಲ್ ಮುಖ್ಯ.
3. **ಆ ತಾತ್ಕಾಲಿಕ ಪ್ರೊಫೈಲ್‌ನಲ್ಲಿ ನಿಮ್ಮ ಬಳಕೆಯನ್ನು ಪ್ರತಿನಿಧಿಸುವ ಡೆಕ್ ರಚಿಸಿ.** ಪ್ರತಿ ಕಾರ್ಡ್ ಪರಿಶೀಲಿಸಲು ಸಾಧ್ಯವಾಗುವಷ್ಟು ಚಿಕ್ಕದಾಗಿರಲಿ. ಆದರೆ ನೀವು ಅವಲಂಬಿಸಿರುವ ವರ್ತನೆಗಳನ್ನು ಸೇರಿಸಿ: ಸರಳ ಮತ್ತು ಹಿಮ್ಮುಖ ಕಾರ್ಡ್‌ಗಳು, ಖಾಲಿ ಜಾಗ ತುಂಬುವ cloze, ಕಸ್ಟಮ್ ಟೆಂಪ್ಲೇಟ್‌ಗಳು, CSS, JavaScript, ಚಿತ್ರಗಳು, ಆಡಿಯೊ, ಸಮೀಕರಣಗಳು, ಟ್ಯಾಗ್‌ಗಳು, ಒಂದರೊಳಗೊಂದು ಇರುವ ಡೆಕ್‌ಗಳು ಮತ್ತು ರಿವ್ಯೂ ಇತಿಹಾಸ.
4. **ಆ ಡೆಕ್ ಅನ್ನು `.apkg` ಆಗಿ ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಮಾಡಿ.** ಅಗತ್ಯವಿದ್ದಾಗ ವೇಳಾಪಟ್ಟಿ ಮಾಹಿತಿ, ಪೂರ್ವನಿಗದಿಗಳು ಮತ್ತು ಮೀಡಿಯಾ ಸೇರಿಸಿ. ಈ ಆಯ್ಕೆಗಳು ಡೇಟಾವನ್ನು Anki ಪ್ಯಾಕೇಜ್‌ಗೆ ಸೇರಿಸುತ್ತವೆ; Mochi ಪ್ರತಿಯೊಂದು ಸೆಟ್ಟಿಂಗ್ ಮರುಸೃಷ್ಟಿಸುತ್ತದೆ ಎಂಬ ಭರವಸೆ ನೀಡುವುದಿಲ್ಲ.
5. **ಹೊಸ Mochi ಡೆಕ್‌ಗೆ ಇಂಪೋರ್ಟ್ ಮಾಡಿ.** ನಿಮ್ಮ ದಿನನಿತ್ಯದ Anki ಪ್ರೊಫೈಲ್ ಮತ್ತು ರಿವ್ಯೂಗೆ ಬಾಕಿಯಿರುವ ಅದರ ಸರದಿಯನ್ನು ಬದಲಿಸಬೇಡಿ.
6. **ರಿವ್ಯೂ ಮಾಡುವ ಮೊದಲು ಪರಿಶೀಲಿಸಿ.** ವಿಷಯ, ಫಾರ್ಮ್ಯಾಟಿಂಗ್, ಫೀಲ್ಡ್‌ಗಳು, ಮೀಡಿಯಾ, ಟ್ಯಾಗ್‌ಗಳು, ಡೆಕ್ ರಚನೆ ಮತ್ತು ಇತಿಹಾಸವನ್ನು ಹೋಲಿಸಿ. HTML, CSS, JavaScript ಅಥವಾ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ರಚನೆಯಾಗುವ ಕಾರ್ಡ್ ರೂಪಾಂತರಗಳನ್ನು ಅವಲಂಬಿಸಿದ್ದ ಅಂಶಗಳಿಗೆ ವಿಶೇಷ ಗಮನ ಕೊಡಿ.
7. **ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ವೇಳಾಪಟ್ಟಿ ವ್ಯವಸ್ಥೆ ಆರಿಸಿ.** Mochi ತನ್ನ ಸ್ವಂತ ಅಲ್ಗಾರಿದಮ್‌ನಿಂದ ಆರಂಭಿಸುತ್ತದೆ. ಪ್ರಯೋಗದ ನಂತರವೂ FSRS ಬಳಸುವ ಉದ್ದೇಶವಿದ್ದರೆ ಮಾತ್ರ ಅದನ್ನು ಆನ್ ಮಾಡಿ.
8. **ಆ ಪ್ರತಿಯನ್ನು ಒಂದು ವಾರ ನಿಮ್ಮ ಎಂದಿನ ಕ್ರಮದಲ್ಲಿ ರಿವ್ಯೂ ಮಾಡಿ.** Markdown ತಿದ್ದುವ ವಿಧಾನ, New cards ಹಂತ, Remembered/Forgot ನಿರ್ಧಾರ, ಆಫ್‌ಲೈನ್ ವರ್ತನೆ ಮತ್ತು ಸಿಂಕ್‌ಗೆ ಹಣ ಕೊಟ್ಟಿದ್ದರೆ ನೀವು ನಿಜವಾಗಿ ಜೊತೆಯಲ್ಲಿ ಕೊಂಡೊಯ್ಯುವ ಸಾಧನಗಳಲ್ಲಿನ ಸಿಂಕ್ ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ ಎಂಬುದನ್ನು ಗಮನಿಸಿ.
9. **ಹಿಂದಕ್ಕೆ ಬರುವ ದಾರಿಯನ್ನೂ ಪರೀಕ್ಷಿಸಿ.** Mochi ಪರೀಕ್ಷಾ ಡೆಕ್ ಅನ್ನು ನೇಟಿವ್ ಬ್ಯಾಕಪ್‌ಗಾಗಿ `.mochi` ಆಗಿ ಮತ್ತು Ankiಗಾಗಿ CSV ಆಗಿ ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಮಾಡಿ. ಮರುಬಳಕೆ ಮಾಡಬಹುದಾದ ಫೀಲ್ಡ್‌ಗಳು ಮುಖ್ಯವಾಗಿದ್ದರೆ ಫೀಲ್ಡ್ ಮೌಲ್ಯಗಳ CSV ಬಳಸಿ. ಕಾಣಿಸುವ ಮುಂಭಾಗ/ಹಿಂಭಾಗದ ವಿಷಯವೇ ಮುಖ್ಯವಾಗಿದ್ದರೆ ಪ್ರದರ್ಶಿತ ಬದಿಗಳ CSV ಬಳಸಿ. ಆ CSVಯನ್ನು ಮತ್ತೊಂದು ಖಾಲಿ Anki ಪ್ರೊಫೈಲ್‌ಗೆ ಇಂಪೋರ್ಟ್ ಮಾಡಿ, ಅದರ ಕಾಲಮ್‌ಗಳನ್ನು ಸೂಕ್ತ ನೋಟ್ ಪ್ರಕಾರಕ್ಕೆ ಹೊಂದಿಸಿ.
10. **ಒಪ್ಪಿಕೊಂಡ ಪ್ರತಿಯೊಂದು ನಷ್ಟವನ್ನೂ ಬರೆದಿಡಿ.** ಹೋಗುವ ಮತ್ತು ಮರಳುವ ದಾರಿಗಳನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ ಪರಿಶೀಲಿಸಿ. ನಿಖರ ಶೈಲಿ, ಹಲವು ಬದಿಗಳ ವರ್ತನೆ, ಆ್ಯಡ್-ಆನ್ ವರ್ತನೆ, ರಚನೆಯಾಗುವ ರೂಪಾಂತರಗಳು, ರಿವ್ಯೂ ಗ್ರೇಡ್‌ಗಳು, ಇತಿಹಾಸ ಅಥವಾ ಮುಂದಿನ ರಿವ್ಯೂ ದಿನಾಂಕಗಳು ಹೋಲಿಕೆ ಪಟ್ಟಿಯಲ್ಲಿ ಕಂಡದ್ದಕ್ಕಿಂತ ದಿನನಿತ್ಯದ ಬಳಕೆಯಲ್ಲಿ ಹೆಚ್ಚು ಮುಖ್ಯವಾಗಬಹುದು.

CSV ಮೂಲಕ ಹಿಂದಕ್ಕೆ ತರುವುದು ವಿಷಯದ ವರ್ಗಾವಣೆ; ಸಂಪೂರ್ಣ Mochi ಮರುಸ್ಥಾಪನೆ ಅಲ್ಲ. ಅದರಲ್ಲಿ ರಿವ್ಯೂ ಇತಿಹಾಸ, ಟೆಂಪ್ಲೇಟ್‌ಗಳು ಅಥವಾ ಮೆಟಾಡೇಟಾ ಟ್ಯಾಗ್‌ಗಳು ಬರುವುದಿಲ್ಲ; ಟ್ಯಾಗ್‌ಗಳು ವಿಷಯದೊಳಗೆ ಇದ್ದರೆ ಮಾತ್ರ ಬರುತ್ತವೆ. ನೀವು ಗುರುತಿಸಿದ ಸಮಸ್ಯೆಯನ್ನು Mochi ಪರಿಹರಿಸದಿದ್ದರೆ, ಪರೀಕ್ಷಾ ಡೆಕ್ ಅಳಿಸಿ ಮೂಲ Anki ಪ್ರೊಫೈಲ್‌ನೊಂದಿಗೆ ಮುಂದುವರಿಯಿರಿ. ಪರಿಹರಿಸಿದರೆ, ಒಂದೊಂದೇ ನಿಜವಾದ ಡೆಕ್ ವರ್ಗಾಯಿಸಿ. ಹಲವು ಸಾಮಾನ್ಯ ರಿವ್ಯೂ ಚಕ್ರಗಳು ಮುಗಿಯುವವರೆಗೆ Anki `.colpkg` ಮತ್ತು Mochi `.mochi` ಬ್ಯಾಕಪ್‌ಗಳನ್ನು ಇಟ್ಟುಕೊಳ್ಳಿ.

## Mochi ಫ್ಲ್ಯಾಶ್‌ಕಾರ್ಡ್‌ಗಳು ಯಾರಿಗೆ ಸೂಕ್ತ?

ಈ ಸಂದರ್ಭಗಳಲ್ಲಿ Mochi ಚೆನ್ನಾಗಿ ಹೊಂದುತ್ತದೆ:

- ಈಗಾಗಲೇ Markdownನಲ್ಲಿ ಬರೆಯುವುದು ಮತ್ತು ವಿಚಾರಗಳನ್ನು ರೂಪಿಸುವುದು ನಿಮಗೆ ಸಹಜವಾಗಿದ್ದರೆ;
- ನೋಟ್‌ಗಳು ಮತ್ತು ರಿವ್ಯೂ ಕಾರ್ಡ್‌ಗಳು ಒಂದೇ ಸಂಪರ್ಕಿತ ಕೆಲಸದ ಜಾಗದಲ್ಲಿ ಇರಬೇಕಿದ್ದರೆ;
- ನಾಲ್ಕು ಗ್ರೇಡ್‌ಗಳ ಬದಲಿಗೆ ಸರಳ Remembered/Forgot ನಿರ್ಧಾರ ಬೇಕಿದ್ದರೆ;
- ಒಂದೇ ಸಾಧನದ ಆಫ್‌ಲೈನ್ ಬಳಕೆ ನಿಮ್ಮ ಉಚಿತ ಕೆಲಸದ ವಿಧಾನಕ್ಕೆ ಸಾಕಾದರೆ, ಅಥವಾ Pro ಸಿಂಕ್‌ಗೆ ತಿಂಗಳಿಗೆ US$5 ಕೊಡುವುದು ಸಮಂಜಸವೆನಿಸಿದರೆ;
- ನಿಮ್ಮ ಸಂಗ್ರಹ ಹೊಸದಾಗಿದ್ದರೆ, ಅಥವಾ Ankiಯಿಂದ ಪರಿವರ್ತಿಸುವ ಅಪಾಯ ಕಡಿಮೆ ಇರುವಷ್ಟು ಸರಳವಾಗಿದ್ದರೆ.

ಈ ಸಂದರ್ಭಗಳಲ್ಲಿ Ankiಯಲ್ಲೇ ಉಳಿಯಿರಿ:

- ನಿಮ್ಮ ನೋಟ್ ಪ್ರಕಾರಗಳು ಹಲವು ಮುಖ್ಯ ಕಾರ್ಡ್ ರೂಪಾಂತರಗಳನ್ನು ರಚಿಸುತ್ತಿದ್ದರೆ;
- HTML/CSS ಟೆಂಪ್ಲೇಟ್‌ಗಳು, JavaScript, ಆ್ಯಡ್-ಆನ್‌ಗಳು ಅಥವಾ ಹಂಚಿದ ಡೆಕ್‌ಗಳು ನಿಮ್ಮ ವ್ಯವಸ್ಥೆಯ ಭಾಗವಾಗಿದ್ದರೆ;
- Markdownನಲ್ಲಿ ಬರೆಯುವುದಕ್ಕಿಂತ ಸಾಧನಗಳ ನಡುವಿನ ಉಚಿತ ಸಿಂಕ್ ಮುಖ್ಯವಾಗಿದ್ದರೆ;
- Ankiಯ FSRS ಆಪ್ಟಿಮೈಸರ್, ಪೂರ್ವನಿಗದಿ ನಿಯಂತ್ರಣಗಳು, ನಾಲ್ಕು ಗ್ರೇಡ್‌ಗಳು ಮತ್ತು ಅಧ್ಯಯನದ ಹೊರೆ ಸಿಮ್ಯುಲೇಟರ್ ಬೇಕಿದ್ದರೆ;
- ಹಲವು ವರ್ಷಗಳ ರಿವ್ಯೂ ಡೇಟಾ ಮತ್ತು ಕಸ್ಟಮ್ ವರ್ತನೆ ಈಗಾಗಲೇ ಚೆನ್ನಾಗಿ ಕೆಲಸ ಮಾಡುತ್ತಿದ್ದರೆ.

ಇವೆರಡೂ ನಿಮಗೆ ಏಕೆ ಹೊಂದುವುದಿಲ್ಲ ಎಂಬುದನ್ನು ಅವಲಂಬಿಸಿ ಸೂಕ್ತ Mochi ಪರ್ಯಾಯ ಬದಲಾಗುತ್ತದೆ. ಹೊಸ, ಸರಳ ಸಂಗ್ರಹಕ್ಕಾಗಿ [Nibomo ವೈಶಿಷ್ಟ್ಯಗಳಲ್ಲಿ](/kn/features/) FSRS ರಿವ್ಯೂಗಳು, ಆಫ್‌ಲೈನ್ ಅಧ್ಯಯನ ಮತ್ತು ಸಿಂಕ್, ಕಾರ್ಡ್/ಟ್ಯಾಗ್/ಮೀಡಿಯಾ ವರ್ಗಾವಣೆ, ಏಜೆಂಟ್ ಪ್ರವೇಶ ಮತ್ತು ಮಾರ್ಗದರ್ಶಿಯಲ್ಲಿ ವಿವರಿಸಿದ ಸ್ವಂತ ಹೋಸ್ಟಿಂಗ್ ದಾರಿ ಇವೆ. ಅದನ್ನು ನಾನು ನಿರ್ಮಿಸುತ್ತಿದ್ದೇನೆ, ಮತ್ತು ಅದರ ಮಿತಿಗಳೂ ಇಲ್ಲಿ ಮುಖ್ಯ: ಅದು Mochiಯ ಸಂಪರ್ಕಿತ Markdown ನೋಟ್‌ಬುಕ್ ಅಥವಾ Ankiಯ ಬಹುಕಾಲದಿಂದ ಅಭಿವೃದ್ಧಿಗೊಂಡ ಟೆಂಪ್ಲೇಟ್ ಮತ್ತು ಆ್ಯಡ್-ಆನ್ ವ್ಯವಸ್ಥೆಗೆ ಪರ್ಯಾಯವಾಗುವುದಿಲ್ಲ. [ಆರಂಭಿಸುವ ಮಾರ್ಗದರ್ಶಿ](/docs/getting-started/) ಈಗ ಲಭ್ಯವಿರುವ ಹೋಸ್ಟೆಡ್, ಮೊಬೈಲ್, ಏಜೆಂಟ್ ಮತ್ತು ಸ್ವಂತ ಹೋಸ್ಟಿಂಗ್ ದಾರಿಗಳನ್ನು ತೋರಿಸುತ್ತದೆ.

## ಅಂತಿಮ ನಿರ್ಧಾರ

Mochi ಕೇವಲ ಹೆಚ್ಚು ಆಕರ್ಷಕವಾದ Anki ಇಂಟರ್‌ಫೇಸ್ ಅಲ್ಲ. Markdown ನೋಟ್, ಸಂಪರ್ಕಿತ ಜ್ಞಾನದ ದಾಖಲೆ ಮತ್ತು ಸ್ಪೇಸ್ಡ್ ರಿಪಿಟಿಷನ್ ಕಾರ್ಡ್ ಒಂದೇ ವಸ್ತುವಾಗಿರಬಹುದು ಎನ್ನುವುದೇ ಅದರ ನಿಜವಾದ ಕಲ್ಪನೆ. ಉಚಿತ ಪ್ಲಾನ್ ಖಾತೆಯಿಲ್ಲದ ಆಫ್‌ಲೈನ್ ಕೆಲಸಕ್ಕೆ ಸಾಕಾಗುತ್ತದೆ; Pro ಸಾಧನಗಳ ನಡುವಿನ ಸಿಂಕ್ ಸೇರಿದಂತೆ ಹೋಸ್ಟೆಡ್ ವೈಶಿಷ್ಟ್ಯಗಳನ್ನು ಸೇರಿಸುತ್ತದೆ.

Markdown ಕೇಂದ್ರಿತ ಹೊಸ ಸಂಗ್ರಹ ಆರಂಭಿಸುವ ಕಲಿಯುವವರಿಗೆ ಇದು ಒಳ್ಳೆಯ ಆಯ್ಕೆ. ಪ್ರಾತಿನಿಧಿಕ ಡೆಕ್ ಪರೀಕ್ಷೆಯಲ್ಲಿ ನೇರ Markdown ಬಳಕೆ ಮತ್ತು ಎರಡು ಆಯ್ಕೆಗಳ ರಿವ್ಯೂ ನಿಜವಾದ ತೊಡಕುಗಳನ್ನು ನಿವಾರಿಸುತ್ತವೆ ಎಂದು ಕಂಡರೆ, Ankiಯಿಂದ ಬದಲಿಸುವುದೂ ಸಮಂಜಸವಾಗಬಹುದು.

ಈಗಾಗಲೇ ಸ್ಥಿರವಾದ Anki ಸಂಗ್ರಹವಿರುವವರಿಗೆ, ಬದಲಾವಣೆ ಉಪಯುಕ್ತವೆಂದು ಸಾಬೀತಾಗಬೇಕು. ಸಂಗ್ರಹದ ಬ್ಯಾಕಪ್ ಮಾಡಿ, ಹೆಚ್ಚು ಕಸ್ಟಮ್ ವರ್ತನೆ ಹೊಂದಿರುವ ಕಾರ್ಡ್‌ಗಳನ್ನು ಪರೀಕ್ಷಿಸಿ. ನಿರ್ದಿಷ್ಟ ಫಾರ್ಮ್ಯಾಟಿಂಗ್, ಟೆಂಪ್ಲೇಟ್, ವೇಳಾಪಟ್ಟಿ ಮತ್ತು ಪೂರಕ ವ್ಯವಸ್ಥೆಯ ವೈಶಿಷ್ಟ್ಯಗಳನ್ನು ಬಿಟ್ಟುಕೊಡಬೇಕಾಗುತ್ತದೆ. ಆ ನಷ್ಟವನ್ನು ಒಪ್ಪಿಕೊಳ್ಳುವಷ್ಟು ನಿಮ್ಮ ವಾರದ ಅಧ್ಯಯನ ಕ್ರಮವನ್ನು Mochi ಸುಧಾರಿಸದಿದ್ದರೆ, Ankiಯನ್ನೇ ಉಳಿಸಿಕೊಳ್ಳಿ.
