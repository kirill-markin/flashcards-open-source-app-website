2026ರ ಆಗಸ್ಟ್ 18ರ ವೇಳೆಗೆ, ಡೆವಲಪರ್‌ಗಳು ಸ್ವತಃ ನೋಂದಾಯಿಸಿಕೊಂಡು ಬಳಸಬಹುದಾದ ಸಾರ್ವಜನಿಕ API ಅಥವಾ ಸಾರ್ವಜನಿಕ ಡೆವಲಪರ್ ಪೋರ್ಟಲ್ ಬಗ್ಗೆ Quizlet ಯಾವುದೇ ದಾಖಲೆಗಳನ್ನು ಪ್ರಕಟಿಸಿಲ್ಲ. ಸ್ವತಂತ್ರ ಡೆವಲಪರ್‌ಗೆ ಆ್ಯಪ್ ನೋಂದಾಯಿಸಲು, Quizlet API ಕೀ ಪಡೆಯಲು ಮತ್ತು ದಾಖಲೆಗಳಲ್ಲಿ ವಿವರಿಸಿದ ಎಂಡ್‌ಪಾಯಿಂಟ್‌ಗಳ ಮೂಲಕ ಫ್ಲ್ಯಾಶ್‌ಕಾರ್ಡ್ ಡೇಟಾವನ್ನು ಓದಲು ಅಥವಾ ಬರೆಯಲು ಸದ್ಯ ಅಧಿಕೃತ ಮಾರ್ಗವಿಲ್ಲ.

ಈ ನಿರ್ಣಯಕ್ಕೆ ಆಧಾರ Quizlet ಪ್ರಕಟಿಸಿರುವ ಸಾರ್ವಜನಿಕ ದಾಖಲೆಗಳು; ಅದರ ಆಂತರಿಕ ವ್ಯವಸ್ಥೆಗಳ ಬಗ್ಗೆ ಇಲ್ಲಿ ಹೇಳುತ್ತಿಲ್ಲ. Quizlet ಇತರ ಉತ್ಪನ್ನಗಳು ಮತ್ತು ಪಾಲುದಾರರೊಂದಿಗೆ ಏಕೀಕರಣಗಳನ್ನು ಹೊಂದಿದೆ. ಅದರ ChatGPT ಆ್ಯಪ್ ಮತ್ತು Google Classroom ಆ್ಯಡ್-ಆನ್ ಈಗಿನ ಎರಡು ಉದಾಹರಣೆಗಳು. ಇವೆರಡೂ ಇತರ ಆ್ಯಪ್‌ಗಳಿಗೆ ಸಾಮಾನ್ಯ ಉದ್ದೇಶದ Quizlet ಡೆವಲಪರ್ API ಪ್ರವೇಶವನ್ನು ನೀಡುವುದಿಲ್ಲ.

**ಮಾಹಿತಿ ಪರಿಶೀಲಿಸಿದ ದಿನಾಂಕ:** ಆಗಸ್ಟ್ 18, 2026.

> **ನನ್ನ ಸಂಬಂಧದ ಬಗ್ಗೆ:** ನಾನು Kirill Markin, Nibomoವನ್ನು ನಿರ್ಮಿಸುತ್ತಿದ್ದೇನೆ. ಅದರ Agent API ಮತ್ತು MCP ಸರ್ವರ್‌ಗಳನ್ನು ಕೆಳಗೆ ಪರ್ಯಾಯಗಳಾಗಿ ವಿವರಿಸಿದ್ದೇನೆ. Nibomo Quizletಗೆ ಹೊಂದಿಕೆಯಾಗುವುದಿಲ್ಲ ಮತ್ತು Quizlet ಸೆಟ್‌ಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಆಮದು ಮಾಡುವುದಿಲ್ಲ.

## ಸಂಕ್ಷಿಪ್ತ ಉತ್ತರ: ಸ್ವತಃ ಪ್ರವೇಶ ಪಡೆಯಬಹುದಾದ ಸಾರ್ವಜನಿಕ Quizlet APIಗೆ ದಾಖಲೆಗಳಿಲ್ಲ

Quizletನಲ್ಲೇ ಕೆಲಸಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತಗೊಳಿಸಲು “Quizletಗೆ API ಇದೆಯೇ?” ಎಂದು ಹುಡುಕಿದ್ದರೆ, ಸದ್ಯದ ಪ್ರಾಯೋಗಿಕ ಉತ್ತರ ಹೀಗಿದೆ: **ಸ್ವತಃ ನೋಂದಾಯಿಸಿಕೊಂಡು ಬಳಸಬಹುದಾದ ಸಾರ್ವಜನಿಕ APIಗೆ ಯಾವುದೇ ದಾಖಲೆಗಳಿಲ್ಲ**.

ವ್ಯತ್ಯಾಸ ಸರಳವಾಗಿದೆ: ನಿಮ್ಮದೇ ಕಾರ್ಡ್ ಪಠ್ಯವನ್ನು ಒಮ್ಮೆ ನಕಲಿಸುವುದು ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಕೆಲಸ. ಇನ್ನೊಂದು ಪುಟದಲ್ಲಿ Quizlet ತೋರಿಸುವುದು ಎಂಬೆಡ್ ಕೆಲಸ. ನಿರ್ದಿಷ್ಟ ಉತ್ಪನ್ನದ ಏಕೀಕರಣ ಆ ಉತ್ಪನ್ನದ ಪ್ರಕ್ರಿಯೆಯೊಳಗೆ ಮಾತ್ರ ಕೆಲಸ ಮಾಡುತ್ತದೆ. ಪದೇಪದೇ ಕಾರ್ಡ್‌ಗಳನ್ನು ರಚಿಸುವ, ಓದುವ ಮತ್ತು ಸಂಪಾದಿಸುವ ಸಾಫ್ಟ್‌ವೇರ್‌ಗೆ ದಾಖಲೆಗಳಿರುವ ಓದುವ/ಬರೆಯುವ API ಬೇಕು.

## ಎಕ್ಸ್‌ಪೋರ್ಟ್, ಎಂಬೆಡ್ ಮತ್ತು ಪಾಲುದಾರರ ಪ್ರವೇಶ ಸಾರ್ವಜನಿಕ APIಗಳಲ್ಲ

ಸಾರ್ವಜನಿಕ API ಹೊರಗಿನ ಡೆವಲಪರ್‌ಗಳಿಗೆ ಅದನ್ನು ಹೇಗೆ ಬಳಸಬೇಕೆಂಬ ಸ್ಪಷ್ಟ ಆಧಾರ ನೀಡುತ್ತದೆ: ತಾಂತ್ರಿಕ ದಾಖಲೆಗಳು, ಗುರುತಿನ ದೃಢೀಕರಣ, ಬೆಂಬಲಿತ ಕಾರ್ಯಾಚರಣೆಗಳು, ಬಳಕೆಯ ನಿಯಮಗಳು ಮತ್ತು ಪ್ರವೇಶಕ್ಕೆ ಬೇಕಾದ ವಿವರಗಳನ್ನು ಪಡೆಯುವ ವಿಧಾನ. Quizletನ ಈಗಿನ ಸಾರ್ವಜನಿಕ ಸೌಲಭ್ಯಗಳಲ್ಲಿ ಯಾವುದೂ ಸ್ವತಃ ಪ್ರಾರಂಭಿಸಿ ಬಳಸಲು ಅಗತ್ಯವಿರುವ ಈ ಸಂಪೂರ್ಣ ಮಾರ್ಗವನ್ನು ನೀಡುವುದಿಲ್ಲ.

Quizletನ **ಎಕ್ಸ್‌ಪೋರ್ಟ್** ಕೈಯಾರೆ ಮಾಡುವ ವರ್ಗಾವಣೆ. ಸೆಟ್‌ನ ರಚನೆಕಾರರು ವೆಬ್‌ಸೈಟ್‌ನಲ್ಲಿ ಪದಗಳು ಮತ್ತು ವ್ಯಾಖ್ಯಾನಗಳನ್ನು ಜೋಡಿಸಿ, “ಪಠ್ಯವನ್ನು ನಕಲಿಸಿ” (**Copy text**) ಆಯ್ಕೆಯನ್ನು ಬಳಸಿ, ನಕಲಿಸಿದ ಪಠ್ಯವನ್ನು ಬೇರೆಡೆ ಅಂಟಿಸಬಹುದು. ಚಿತ್ರಗಳನ್ನು ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ, ನಕಲು ಮಾಡಿದ ಸೆಟ್‌ಗಳನ್ನು ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ ಮತ್ತು ಈ ಸೌಲಭ್ಯ ವೆಬ್‌ಸೈಟ್‌ನಲ್ಲಿ ಮಾತ್ರ ಲಭ್ಯ ಎಂದು Quizlet ಹೇಳುತ್ತದೆ. ಎಚ್ಚರಿಕೆಯಿಂದ ಒಮ್ಮೆ ಡೇಟಾ ವರ್ಗಾಯಿಸಲು ಈ ವಿಧಾನ ಸೂಕ್ತ. ಎರಡು ವ್ಯವಸ್ಥೆಗಳನ್ನು ಸಾಫ್ಟ್‌ವೇರ್ ಮೂಲಕ ನಿರಂತರವಾಗಿ ಸಿಂಕ್ ಮಾಡಲು ಇದು ಅವಕಾಶ ನೀಡುವುದಿಲ್ಲ.

**ಎಂಬೆಡ್** ವಿಷಯವನ್ನು ಪ್ರದರ್ಶಿಸುತ್ತದೆ; ಡೇಟಾಗೆ ಪ್ರವೇಶ ನೀಡುವುದಿಲ್ಲ. ಸಾರ್ವಜನಿಕ ಸೆಟ್ ಅನ್ನು ಜೋಡಿಸಿ (Match), ಕಲಿಯಿರಿ (Learn), ಪರೀಕ್ಷೆ (Test), ಫ್ಲ್ಯಾಶ್‌ಕಾರ್ಡ್‌ಗಳು (Flashcards) ಅಥವಾ ಕಾಗುಣಿತ (Spell) ಮೋಡ್‌ನಲ್ಲಿ ತೋರಿಸಲು Quizlet HTML ನಕಲಿಸಲು ಅವಕಾಶ ನೀಡುತ್ತದೆ. ಎಂಬೆಡ್ ಮಾಡಿದ ಚಟುವಟಿಕೆಯಲ್ಲಿ Quizlet ಲೋಗೋ ಉಳಿಯುತ್ತದೆ ಮತ್ತು ಕಲಿಯುವವರು Quizletನ ಇಂಟರ್‌ಫೇಸ್ ಬಳಸುತ್ತಾರೆ. ನಿಮ್ಮ ಆ್ಯಪ್‌ಗೆ ಸಂಪಾದಿಸಬಹುದಾದ ಕಾರ್ಡ್ ದಾಖಲೆಗಳಾಗಿ ಸೆಟ್ ಸಿಗುವುದಿಲ್ಲ.

**ನಿರ್ದಿಷ್ಟ ಉತ್ಪನ್ನದೊಂದಿಗಿನ ಏಕೀಕರಣ** ಆ ಪಾಲುದಾರರು ಒಪ್ಪಿಕೊಂಡ ಬಳಕೆಯ ವಿಧಾನಕ್ಕೆ ಅನುಗುಣವಾಗಿ ಕೆಲಸ ಮಾಡುತ್ತದೆ. ಎಲ್ಲ ಡೆವಲಪರ್‌ಗಳಿಗೂ ಅದೇ ಇಂಟರ್‌ಫೇಸ್ ನೀಡದೆ Quizlet, ChatGPT ಅಥವಾ Google Classroom ಜೊತೆಗೆ ಕೆಲಸ ಮಾಡಬಹುದು. ಆ ಬಿಡುಗಡೆಗಳು ನಿರ್ದಿಷ್ಟ ಏಕೀಕರಣಗಳು ಇವೆ ಎಂಬುದನ್ನು ತೋರಿಸುತ್ತವೆ; ಅವುಗಳ ಹಿಂದೆ ಎಲ್ಲರೂ ಬಳಸಬಹುದಾದ ಸಾರ್ವಜನಿಕ Quizlet API ಇದೆ ಎಂಬುದನ್ನು ತೋರಿಸುವುದಿಲ್ಲ.

ಅದಕ್ಕಾಗಿಯೇ ಹಳೆಯ ರ್ಯಾಪರ್ ಅಥವಾ ಬ್ರೌಸರ್ ಡೆವಲಪರ್ ಟೂಲ್‌ಗಳಲ್ಲಿ ಕಾಣಿಸುವ ರಿಕ್ವೆಸ್ಟ್ ಬೆಂಬಲಿತ Quizlet API ಆಗುವುದಿಲ್ಲ. ಇಲ್ಲಿ ಕೊರತೆಯಿರುವುದು ಸಾರ್ವಜನಿಕ ದಾಖಲೆಗಳು ಮತ್ತು ಡೆವಲಪರ್‌ಗಳು ಅವಲಂಬಿಸಬಹುದಾದ ಸ್ಥಿರ ಬಳಕೆಯ ವಿಧಾನ.

## ಕೆಲಸಕ್ಕೆ ಹೊಂದುವ ಮಾರ್ಗವನ್ನು ಆರಿಸಿ

### ಒಮ್ಮೆ ಬ್ಯಾಕಪ್ ಮಾಡಲು ಅಥವಾ ವರ್ಗಾಯಿಸಲು ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಬಳಸಿ

ನೀವು ರಚಿಸಿದ ಸೆಟ್‌ಗಾಗಿ Quizletನ ಅಧಿಕೃತ ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಪ್ರಕ್ರಿಯೆ ಬಳಸಿ. ಈ ಪ್ರಕ್ರಿಯೆ “ಪಠ್ಯವನ್ನು ನಕಲಿಸಿ” (**Copy text**) ಆಯ್ಕೆಯೊಂದಿಗೆ ಮುಗಿಯುತ್ತದೆ. ಹೀಗಾಗಿ ವಿಭಾಜಕಗಳನ್ನು ಸರಿಪಡಿಸುವ ಅಥವಾ ಫೀಲ್ಡ್‌ಗಳನ್ನು ಹೊಂದಿಸುವ ಮೊದಲು, ಮೊಟ್ಟಮೊದಲು ಅಂಟಿಸಿದ ಪಠ್ಯದ ನಕಲನ್ನು ಬದಲಾಯಿಸದೆ ಉಳಿಸಿಕೊಳ್ಳಿ. ನೀವು ಪದಗಳು ಮತ್ತು ವ್ಯಾಖ್ಯಾನಗಳನ್ನು ಉಳಿಸುತ್ತಿದ್ದೀರಿ; ಮರುಸ್ಥಾಪಿಸಬಹುದಾದ ಡೆಕ್ ಪ್ಯಾಕೇಜ್ ಡೌನ್‌ಲೋಡ್ ಮಾಡುತ್ತಿಲ್ಲ. ಚಿತ್ರಗಳು ಮತ್ತು ಅಧ್ಯಯನ ಇತಿಹಾಸ ವರ್ಗಾವಣೆಯಾಗುವುದಿಲ್ಲ.

ಪ್ರಾಯೋಗಿಕ ಪರಿಶೀಲನಾ ಪಟ್ಟಿ [2026ರಲ್ಲಿ Quizlet ಸೆಟ್‌ಗಳನ್ನು ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಮಾಡುವುದು ಹೇಗೆ](/kn/blog/how-to-export-quizlet-sets-and-turn-them-into-fsrs-flashcards/) ಲೇಖನದಲ್ಲಿದೆ. ಅದರಲ್ಲಿ ಮೂಲ ನಕಲು ಮತ್ತು ಸಂಪಾದನೆಗಾಗಿ ಬಳಸುವ ನಕಲು, UTF-8, ಟ್ಯಾಬ್‌ಗಳು, ಹಲವು ಸಾಲುಗಳ ವ್ಯಾಖ್ಯಾನಗಳು ಹಾಗೂ ಕಾರ್ಡ್ ವಿಷಯವನ್ನು ವರ್ಗಾಯಿಸುವುದಕ್ಕೂ ಅಧ್ಯಯನ ವೇಳಾಪಟ್ಟಿಯ ಸ್ಥಿತಿಯನ್ನು ವರ್ಗಾಯಿಸುವುದಕ್ಕೂ ಇರುವ ವ್ಯತ್ಯಾಸವನ್ನು ವಿವರಿಸಲಾಗಿದೆ.

ಒಮ್ಮೆ ಡೇಟಾ ವರ್ಗಾಯಿಸಿ ಮುಗಿಸಲು ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಸೂಕ್ತ. ಸಾಫ್ಟ್‌ವೇರ್ ಮೂಲಕ ಪ್ರತಿದಿನ ಕಾರ್ಡ್‌ಗಳನ್ನು ರಚಿಸಲು, ಸಿಂಕ್ ಮಾಡಲು ಅಥವಾ ಪದೇಪದೇ ಸಂಪಾದಿಸಲು ಇದು ಹೊಂದುವುದಿಲ್ಲ.

### ಪ್ರದರ್ಶಿಸಲು ಅಧಿಕೃತ ಎಂಬೆಡ್ ಬಳಸಿ

ತರಗತಿಯ ವೆಬ್‌ಸೈಟ್ ಅಥವಾ LMS ಪುಟದಿಂದ ಕಲಿಯುವವರು ಸಾರ್ವಜನಿಕ Quizlet ಸೆಟ್ ಅಧ್ಯಯನ ಮಾಡಬೇಕಿದ್ದರೆ, Quizlet ತನ್ನ ವೆಬ್‌ಸೈಟ್‌ನಲ್ಲಿ ನೀಡುವ ಎಂಬೆಡ್ ಕೋಡ್ ಬಳಸಿ. ಚಟುವಟಿಕೆಯನ್ನು ಆರಿಸಿ, “HTML ನಕಲಿಸಿ” (**Copy HTML**) ಆಯ್ಕೆಯನ್ನು ಬಳಸಿ, ನಕಲಿಸಿದ ಕೋಡ್ ಅನ್ನು ಪುಟಕ್ಕೆ ಸೇರಿಸಿ. ಕಲಿಯುವವರಿಗೆ ಸಂವಾದಾತ್ಮಕ Quizlet ಚಟುವಟಿಕೆ ಸಿಗುತ್ತದೆ; ಅದನ್ನು ತೋರಿಸುವ ವೆಬ್‌ಸೈಟ್‌ಗೆ ಮೂಲ ಕಾರ್ಡ್ ಡೇಟಾ ಸಿಗುವುದಿಲ್ಲ.

ಅನೇಕ ಸಂದರ್ಭಗಳಲ್ಲಿ ಶಿಕ್ಷಕರಿಗೆ ಬೇಕಿರುವುದು ಇಷ್ಟೇ. ಇದನ್ನು API ಎಂದು ಕರೆದರೆ, ಸರಳವಾದ ಅಗತ್ಯವೂ ಅನಗತ್ಯವಾಗಿ ಜಟಿಲವೆನಿಸುತ್ತದೆ.

### ChatGPT ಅಥವಾ Google Classroomಗಾಗಿ ಅವುಗಳ ನಿರ್ದಿಷ್ಟ ಏಕೀಕರಣ ಬಳಸಿ

ಮಾರ್ಚ್ 10, 2026ರ Quizletನ ChatGPT ಪ್ರಕಟಣೆ ಒಂದು ನಿರ್ದಿಷ್ಟ ಪ್ರಕ್ರಿಯೆಯನ್ನು ವಿವರಿಸುತ್ತದೆ: Quizlet ಆ್ಯಪ್ ಸಂಪರ್ಕಿಸಿ, ಪ್ರಾಂಪ್ಟ್ ಅನ್ನು `@Quizlet`ನಿಂದ ಪ್ರಾರಂಭಿಸಿ, ರಚನೆಯಾದ ಸೆಟ್‌ನ ಪೂರ್ವವೀಕ್ಷಣೆಯನ್ನು ChatGPTಯಲ್ಲಿ ನೋಡಿ, ನಂತರ ಅದನ್ನು Quizletನಲ್ಲಿ ತೆರೆದು ನಿಮಗೆ ತಕ್ಕಂತೆ ಬದಲಾಯಿಸಿ ಅಧ್ಯಯನ ಮಾಡಿ. ಆ ಸಂಭಾಷಣೆಯಿಂದ Quizlet ಸೆಟ್ ರಚಿಸಲು ಇದು ಬೆಂಬಲಿತ ಮಾರ್ಗ. ನಿಮ್ಮ ಬಾಟ್, ಸ್ಕ್ರಿಪ್ಟ್ ಅಥವಾ ವೆಬ್‌ಸೈಟ್ ಮರುಬಳಕೆ ಮಾಡಬಹುದಾದ Quizlet API ಪ್ರವೇಶ ವಿವರಗಳನ್ನು ಇದು ನೀಡುವುದಿಲ್ಲ.

ಜೂನ್ 30, 2026ರ Quizletನ Google Classroom ಪ್ರಕಟಣೆಯೂ ಇದೇ ರೀತಿ ನಿರ್ದಿಷ್ಟವಾಗಿದೆ. ಅಭ್ಯಾಸದ ಪ್ರಶ್ನೆಗಳು, ಫ್ಲ್ಯಾಶ್‌ಕಾರ್ಡ್‌ಗಳು ಮತ್ತು ಆಟಗಳಂತಹ ಚಟುವಟಿಕೆಗಳನ್ನು ಹುಡುಕಿ ವಿದ್ಯಾರ್ಥಿಗಳಿಗೆ ನೀಡಲು ಹಾಗೂ Classroom ಪ್ರಕ್ರಿಯೆಯಲ್ಲೇ ಅವರ ಪಾಲ್ಗೊಳ್ಳುವಿಕೆ ಮತ್ತು ಪ್ರಗತಿಯನ್ನು ಗಮನಿಸಲು ಆ್ಯಡ್-ಆನ್ ಶಿಕ್ಷಕರಿಗೆ ಅವಕಾಶ ನೀಡುತ್ತದೆ. ಇದಕ್ಕೆ Google Workspace for Education Plus ಅಗತ್ಯ ಎಂದು Quizlet ಹೇಳುತ್ತದೆ; ಅನುಮತಿ ನೀಡಲು ಅಥವಾ ಆ್ಯಡ್-ಆನ್ ಲಭ್ಯಗೊಳಿಸಲು ಶಿಕ್ಷಕರು ತಮ್ಮ IT ನಿರ್ವಾಹಕರನ್ನು ಸಂಪರ್ಕಿಸಬೇಕಾಗಬಹುದು.

ಈ ನಿರ್ದಿಷ್ಟ ಪ್ರಕ್ರಿಯೆಗಳಲ್ಲಿ ಯಾವುದಾದರೂ ನಿಮ್ಮ ಗುರಿಗೆ ಈಗಾಗಲೇ ಹೊಂದಿದರೆ, ಅದನ್ನು ಬಳಸಿ. ನಿಮ್ಮದೇ ಆ್ಯಪ್ ಬೇಕಿದ್ದರೆ, ಈ ಎರಡೂ ಏಕೀಕರಣಗಳು ಸಾರ್ವಜನಿಕ ಡೆವಲಪರ್ ಪ್ರವೇಶಕ್ಕೆ ಪರ್ಯಾಯವಾಗುವುದಿಲ್ಲ.

### ಕೆಲಸಗಳನ್ನು ಪದೇಪದೇ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಮಾಡಲು, ಬಳಕೆಯ ದಾಖಲೆಗಳಿರುವ ಓದುವ/ಬರೆಯುವ ಇಂಟರ್‌ಫೇಸ್ ಆರಿಸಿ

ನಿರಂತರ ಸ್ವಯಂಚಾಲನೆ ಎಂದರೆ ನಿಮ್ಮ ಸಾಫ್ಟ್‌ವೇರ್ ಒಂದೇ ಕೆಲಸವನ್ನು ಹಲವು ಬಾರಿ ವಿಶ್ವಾಸಾರ್ಹವಾಗಿ ಮಾಡಬೇಕು: ಟಿಪ್ಪಣಿಗಳಿಂದ ಕಾರ್ಡ್ ರಚಿಸುವುದು, ಡೆಕ್‌ಗಳ ಪಟ್ಟಿ ಪಡೆಯುವುದು, ಉತ್ತರಗಳನ್ನು ನವೀಕರಿಸುವುದು ಅಥವಾ ಕಾಲಕ್ರಮೇಣ ಕಾರ್ಯಸ್ಥಳವನ್ನು ನಿರ್ವಹಿಸುವುದು. ಕ್ಲಿಪ್‌ಬೋರ್ಡ್‌ಗೆ ಪಠ್ಯ ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಮಾಡುವ ಸೌಲಭ್ಯ ಇಂಥ ನಿರಂತರ ಕಾರ್ಯಾಚರಣೆಗಳಿಗೆ ಆಧಾರವಾಗಲಾರದು.

ಹೊರಗಿನ ಸಾಫ್ಟ್‌ವೇರ್ ತನ್ನ ಗುರುತನ್ನು ಹೇಗೆ ದೃಢೀಕರಿಸಬೇಕು ಮತ್ತು ಯಾವ ಓದುವ/ಬರೆಯುವ ಕಾರ್ಯಾಚರಣೆಗಳನ್ನು ಬಳಸಬಹುದು ಎಂಬುದನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ದಾಖಲಿಸಿರುವ ಫ್ಲ್ಯಾಶ್‌ಕಾರ್ಡ್ ವ್ಯವಸ್ಥೆಯನ್ನು ಆರಿಸುವುದು ಸುರಕ್ಷಿತ ಮಾರ್ಗ. ಸ್ವಯಂಚಾಲಿತ ಕೆಲಸಗಳಿಗೆ Quizlet API ಪರ್ಯಾಯವನ್ನು ಆರಿಸಿ, Quizletನ ಸಾರ್ವಜನಿಕ ಉತ್ಪನ್ನ ಬೆಂಬಲಿಸುವ ಅಧ್ಯಯನ ಕೆಲಸಗಳಿಗೆ Quizlet ಉಳಿಸಿಕೊಳ್ಳಬಹುದು.

## Nibomo API ಪರ್ಯಾಯ ನಿಜವಾಗಿ ಏನು ನೀಡುತ್ತದೆ

ಪ್ರತಿ ಬಳಕೆದಾರರ ಸೀಮಿತ ವ್ಯಾಪ್ತಿಯ ಡೇಟಾವನ್ನು ಬಳಸಲು Nibomo ಎರಡು ಮಾರ್ಗಗಳನ್ನು ಪ್ರಕಟಿಸಿದೆ. ಎರಡರಲ್ಲೂ ಲಭ್ಯವಾಗುವುದು ಅದೇ ಡೇಟಾ:

- [ಬಾಹ್ಯ Agent API](/kn/docs/api/) `GET https://api.nibomo.com/v1/`ನಲ್ಲಿ ಪ್ರಾರಂಭವಾಗುತ್ತದೆ. ಈ ಆರಂಭಿಕ ವಿನಂತಿಗೆ ಸಿಗುವ ಡಿಸ್ಕವರಿ ಪ್ರತಿಕ್ರಿಯೆ, ಇಮೇಲ್ OTP ಮೂಲಕ ಲಾಗಿನ್ ಮಾಡಲು, API ಕೀ ರಚಿಸಲು ಮತ್ತು ಕಾರ್ಯಸ್ಥಳ ಆರಿಸಲು ಏಜೆಂಟ್‌ಗೆ ಮಾರ್ಗದರ್ಶನ ನೀಡುತ್ತದೆ. ಓದಲು SQL ಶೈಲಿಯ query ಮಾರ್ಗ ಬಳಸಲಾಗುತ್ತದೆ; ಬರೆಯಲು ಪ್ರತ್ಯೇಕ execute ಮಾರ್ಗವಿದೆ.
- [ರಿಮೋಟ್ MCP ಸರ್ವರ್](/kn/docs/mcp-connector/) `https://mcp.nibomo.com/mcp`ನಲ್ಲಿ ಲಭ್ಯವಿದೆ. MCP ಕ್ಲೈಂಟ್‌ಗಳಿಗೆ ಎಂಟು ಟೂಲ್‌ಗಳು ಸಿಗುತ್ತವೆ: `list_workspaces`, `sql_query`, `sql_execute`, `get_guide` ಹಾಗೂ ಪುನರವಲೋಕನದ ಟೂಲ್‌ಗಳಾದ `next_review_card`, `reveal_answer` ಮತ್ತು `submit_review`.

ಎಂಟನೆಯ ಟೂಲ್ `get_usage_limits`, ಖಾತೆಯ ಪ್ಲಾನ್, ಮಿತಿಗಳು ಮತ್ತು ಪ್ರಸಕ್ತ ತಿಂಗಳ AI ಬಳಕೆಯ ಮಾಹಿತಿಯನ್ನು ಓದಲು ಮಾತ್ರ ಅವಕಾಶ ನೀಡುತ್ತದೆ. ಇದು ಕಾರ್ಡ್‌ಗಳನ್ನು ಓದುವುದಿಲ್ಲ ಅಥವಾ ಬದಲಾಯಿಸುವುದಿಲ್ಲ.

ಎರಡೂ ಮಾರ್ಗಗಳು ಆಯ್ದ ಕಾರ್ಯಸ್ಥಳದ ವ್ಯಾಪ್ತಿಗೆ ಸೀಮಿತವಾಗಿವೆ. ಪ್ರಕಟಿಸಿದ ರಿಸೋರ್ಸ್‌ಗಳು `workspace`, `cards`, `decks` ಮತ್ತು `review_events`; ಪ್ರತಿ ಸ್ಟೇಟ್‌ಮೆಂಟ್‌ನ ಫಲಿತಾಂಶಕ್ಕೆ 100 ಸಾಲುಗಳ ಮಿತಿ ಇದೆ. SQL ಶೈಲಿಯ ಈ ಇಂಟರ್‌ಫೇಸ್, SQLನ ಸೀಮಿತ ರೂಪವನ್ನು ಬಳಸುತ್ತದೆ; ಇದು ನೇರ PostgreSQL ಪ್ರವೇಶವಲ್ಲ. OpenAPI ಸ್ಕೀಮಾ ಇಲ್ಲದಿರುವುದರಿಂದ, OpenAPI ಸ್ಕೀಮಾದಿಂದ ಸ್ವಯಂಚಾಲಿತವಾಗಿ ರಚಿಸಿದ ಕ್ಲೈಂಟ್‌ಗಳನ್ನು ಅವಲಂಬಿಸುವ ಪ್ರಕ್ರಿಯೆಗಳಿಗೆ ಬೇರೆ ಇಂಟರ್‌ಫೇಸ್ ಬೇಕಾಗುತ್ತದೆ.

ಇದು ಡೆವಲಪರ್ ಅಥವಾ AI ಏಜೆಂಟ್‌ಗೆ ತಮ್ಮದೇ ಫ್ಲ್ಯಾಶ್‌ಕಾರ್ಡ್‌ಗಳ ಕೆಲಸಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತಗೊಳಿಸಲು ಸಹಾಯ ಮಾಡಬಹುದು. Quizlet URL ಓದಲು, Quizlet ಖಾತೆಯ ಪ್ರತಿರೂಪವನ್ನು ಸಿಂಕ್ ಮಾಡಲು ಅಥವಾ ದಾಖಲೆಗಳಿಲ್ಲದ Quizlet ಕ್ಲೈಂಟ್ ಆಗಿ ಕೆಲಸ ಮಾಡಲು ಇದಕ್ಕೆ ಸಾಧ್ಯವಿಲ್ಲ. ಸ್ವಯಂಚಾಲಿತ Quizlet ಆಮದು ಸೌಲಭ್ಯ ಇಲ್ಲ. ವರ್ಗಾಯಿಸಲು, ಮೊದಲು ನಿಮ್ಮದೇ ಸೆಟ್‌ನ ಪದಗಳು ಮತ್ತು ವ್ಯಾಖ್ಯಾನಗಳನ್ನು ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಮಾಡಿ, ಪಠ್ಯ ಪರಿಶೀಲಿಸಿ, ನಂತರ ಅದನ್ನು ಹೊಸ ವ್ಯವಸ್ಥೆಯ ಕಾರ್ಡ್ ಫೀಲ್ಡ್‌ಗಳಿಗೆ ಹೊಂದಿಸಿ. ಹೊಸ ವ್ಯವಸ್ಥೆ ತನ್ನದೇ ಅಧ್ಯಯನ ಸ್ಥಿತಿಯನ್ನು ರಚಿಸುತ್ತದೆ; Quizlet ಇತಿಹಾಸ ವರ್ಗಾವಣೆಯಾಗುವುದಿಲ್ಲ.

API ಪ್ರವೇಶದ ಹೊರತಾಗಿ ಉತ್ಪನ್ನಗಳ ವ್ಯತ್ಯಾಸಗಳಿಗಾಗಿ, [ಓಪನ್ ಸೋರ್ಸ್ Quizlet ಪರ್ಯಾಯದ ಹೋಲಿಕೆ](/blog/quizlet-alternative/) ನೋಡಿ.

## ಖಾಸಗಿ ಬ್ರೌಸರ್ ರಿಕ್ವೆಸ್ಟ್‌ಗಳು ಸುರಕ್ಷಿತ ಅಡ್ಡದಾರಿಯಲ್ಲ

ಎಲ್ಲ ಆಧುನಿಕ ವೆಬ್ ಆ್ಯಪ್‌ಗಳಂತೆ Quizletನ ವೆಬ್ ಇಂಟರ್‌ಫೇಸ್ ಕೂಡ ನೆಟ್‌ವರ್ಕ್ ರಿಕ್ವೆಸ್ಟ್‌ಗಳನ್ನು ಮಾಡುತ್ತದೆ. ಆ ರಿಕ್ವೆಸ್ಟ್‌ಗಳಲ್ಲಿ ಒಂದನ್ನು ಕಂಡುಹಿಡಿದ ಮಾತ್ರಕ್ಕೆ ಅದು ನಿಮ್ಮ ಪ್ರೋಗ್ರಾಂಗೆ ಬೆಂಬಲಿತ ಎಂಡ್‌ಪಾಯಿಂಟ್ ಆಗುವುದಿಲ್ಲ.

ಖಾಸಗಿ ಬ್ರೌಸರ್ ಎಂಡ್‌ಪಾಯಿಂಟ್‌ಗಳು ಸೆಷನ್ ಕುಕೀಗಳು, ಆಂತರಿಕ ಫಾರ್ಮ್ಯಾಟ್‌ಗಳು, ದುರ್ಬಳಕೆ ತಡೆಯುವ ನಿಯಂತ್ರಣಗಳು ಮತ್ತು ಈಗಿನ ಇಂಟರ್‌ಫೇಸ್‌ಗೆ ಸಂಬಂಧಿಸಿದ ಊಹೆಗಳನ್ನು ಅವಲಂಬಿಸಿರಬಹುದು. ಆವೃತ್ತಿಗಳ ಬಗ್ಗೆ ಸಾರ್ವಜನಿಕ ಮಾಹಿತಿ ಅಥವಾ ಹೊಸ ಆವೃತ್ತಿಗೆ ಬದಲಾಗುವ ಮಾರ್ಗದರ್ಶನ ನೀಡದೆಯೇ ಅವು ಬದಲಾಗಬಹುದು. ಇದಲ್ಲದೆ, ಮೇ 28, 2026ರಂದು ಕೊನೆಯದಾಗಿ ನವೀಕರಿಸಿದ [Quizletನ ಸೇವಾ ನಿಯಮಗಳು](https://quizlet.com/tos) ಸ್ಕ್ರೇಪಿಂಗ್ ಮತ್ತು ಇತರ ಸ್ವಯಂಚಾಲಿತ ಡೇಟಾ ಸಂಗ್ರಹಣೆಯನ್ನು ಹಾಗೂ ಅನುಮತಿಯಿಲ್ಲದೆ ಸೇವೆಯನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಬಳಸುವುದನ್ನು ನಿಷೇಧಿಸುತ್ತವೆ.

ವೈಯಕ್ತಿಕ ಸ್ಕ್ರಿಪ್ಟ್‌ಗೇ ಇದು ಅಸ್ಥಿರವಾದ, ಅಪಾಯವಿರುವ ಆಧಾರ. ಇದನ್ನು ಆಧರಿಸಿ ಉತ್ಪನ್ನ ನಿರ್ಮಿಸಿದರೆ ಅಪಾಯ ಇನ್ನೂ ಹೆಚ್ಚು. ಇಲ್ಲಿ ನಾನು ಊಹಿಸಿದ ಎಂಡ್‌ಪಾಯಿಂಟ್‌ಗಳನ್ನಾಗಲಿ, ರಿವರ್ಸ್ ಎಂಜಿನಿಯರಿಂಗ್ ಹಂತಗಳನ್ನಾಗಲಿ ನೀಡುವುದಿಲ್ಲ.

ನಿಮ್ಮದೇ ಸೆಟ್ ಅನ್ನು ಒಮ್ಮೆ ವರ್ಗಾಯಿಸಲು ಎಕ್ಸ್‌ಪೋರ್ಟ್ ಮಾಡಿ. ಕಲಿಯುವವರಿಗೆ ಇನ್ನೊಂದು ಪುಟದಲ್ಲಿ ಸಾರ್ವಜನಿಕ ಸೆಟ್ ಬೇಕಿದ್ದರೆ ಎಂಬೆಡ್ ಮಾಡಿ. ನಿರ್ದಿಷ್ಟ ChatGPT ಅಥವಾ Google Classroom ಪ್ರಕ್ರಿಯೆಗಳಿಗೆ ಅವುಗಳ ಏಕೀಕರಣ ಬಳಸಿ. ಪದೇಪದೇ ಓದಲು ಮತ್ತು ಬರೆಯಲು ಸ್ವಯಂಚಾಲಿತ ಬಳಕೆಯ ವಿಧಾನವನ್ನು ದಾಖಲಿಸಿರುವ ಸಾಫ್ಟ್‌ವೇರ್ ಆರಿಸಿ, ಅಥವಾ Quizlet ಅಂತಹ ದಾಖಲೆಗಳನ್ನು ಪ್ರಕಟಿಸುವವರೆಗೆ Quizletನ ಭಾಗವನ್ನು ಕೈಯಾರೆ ನಿರ್ವಹಿಸಿ.

## ಸ್ಥಿತಿ ಬದಲಾಗಿದೆಯೇ ಎಂದು ತಿಳಿಯುವುದು ಹೇಗೆ

ಈ ಲೇಖನದ ಮಾಹಿತಿ ಪರಿಶೀಲಿಸಿದ ದಿನಾಂಕದ ನಂತರ Quizlet ಡೆವಲಪರ್ ಕಾರ್ಯಕ್ರಮವನ್ನು ಆರಂಭಿಸಬಹುದು. ಯಾರು ನೋಂದಾಯಿಸಬಹುದು, ಗುರುತಿನ ದೃಢೀಕರಣ ಹೇಗೆ ನಡೆಯುತ್ತದೆ, ಯಾವ ಕಾರ್ಡ್ ಕಾರ್ಯಾಚರಣೆಗಳಿಗೆ ಬೆಂಬಲವಿದೆ ಮತ್ತು ಯಾವ ಬಳಕೆಯ ನಿಯಮಗಳು ಅನ್ವಯಿಸುತ್ತವೆ ಎಂಬುದನ್ನು ವಿವರಿಸುವ ಅಧಿಕೃತ ಡೆವಲಪರ್ ಪೋರ್ಟಲ್ ಅಥವಾ ದಾಖಲೆಗಳನ್ನು ಗಮನಿಸಿ.

ಇನ್ನೊಂದು ಮೂರನೇ ಪಕ್ಷದ ರ್ಯಾಪರ್ ಬಂದರೆ ಉತ್ತರ ಬದಲಾಗುವುದಿಲ್ಲ. ಹೊಸ ನಿರ್ದಿಷ್ಟ ಪಾಲುದಾರಿಕೆ ಬಂದರೂ ಬದಲಾಗುವುದಿಲ್ಲ. ಡೆವಲಪರ್‌ಗಳು ಸ್ವತಃ ಪ್ರವೇಶ ಪಡೆಯುವ ವಿಧಾನವನ್ನು Quizlet ದಾಖಲಿಸುವವರೆಗೆ, Quizlet API ಈಗ ಲಭ್ಯವಿದೆ ಎಂಬ ಹೇಳಿಕೆಗಳನ್ನು ಎಚ್ಚರಿಕೆಯಿಂದ ಪರಿಶೀಲಿಸಿ ಮತ್ತು ನಿಜವಾದ ಕೆಲಸಕ್ಕೆ ಹೊಂದುವ ಬೆಂಬಲಿತ ಮಾರ್ಗವನ್ನು ಆರಿಸಿ.
