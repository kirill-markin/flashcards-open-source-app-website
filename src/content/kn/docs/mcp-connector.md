## Claude ಡೈರೆಕ್ಟರಿ ಮೂಲಕ ಸಂಪರ್ಕಿಸಿ

[Claude ಡೈರೆಕ್ಟರಿಯಲ್ಲಿ Nibomo](https://claude.ai/directory/nibomo) ತೆರೆಯಿರಿ, ಅದನ್ನು ಸಂಪರ್ಕಿಸಿ, ನಿಮ್ಮ Nibomo ಖಾತೆಗೆ ಸೈನ್ ಇನ್ ಮಾಡಿ ಮತ್ತು ಪ್ರವೇಶಕ್ಕೆ ಅಧಿಕಾರ ನೀಡಿ. Nibomo ಸಮುದಾಯ ಕನೆಕ್ಟರ್ ಆಗಿ ಪಟ್ಟಿಯಾಗಿದೆ.

Claude Code ಗಾಗಿ ಅದೇ Claude ಚಂದಾದಾರಿಕೆ ಖಾತೆಯನ್ನು ಬಳಸಿ ಮತ್ತು ಸಂಪರ್ಕಿಸಿದ ನಂತರ `/mcp` ಪರಿಶೀಲಿಸಿ. API ಕೀ ಅಥವಾ ಮೂರನೇ ವ್ಯಕ್ತಿಯ ಪೂರೈಕೆದಾರರ ಮೂಲಕ ಲಾಗಿನ್ ಆದಾಗ ನಿಮ್ಮ claude.ai ಕನೆಕ್ಟರ್‌ಗಳು ತಾನಾಗಿಯೇ ಲೋಡ್ ಆಗುವುದಿಲ್ಲ.

ನೀವು Claude Code ಅನ್ನು ನೇರವಾಗಿಯೂ ಕಾನ್ಫಿಗರ್ ಮಾಡಬಹುದು. ಕೆಳಗಿನ ಕಮಾಂಡ್ ಚಲಾಯಿಸಿ, ನಂತರ Claude Code ನಲ್ಲಿ `/mcp` ತೆರೆದು ಬ್ರೌಸರ್‌ನಲ್ಲಿ ಅಧಿಕಾರ ನೀಡುವಿಕೆಯನ್ನು ಪೂರ್ಣಗೊಳಿಸಿ:

```bash
claude mcp add --transport http nibomo https://mcp.nibomo.com/mcp
```

[Claude Code MCP ದಾಖಲೆಗಳು](https://code.claude.com/docs/en/mcp#use-mcp-servers-from-claudeai).

## ಸಮಗ್ರ ನೋಟ

Nibomo ಒಂದು ರಿಮೋಟ್ MCP (Model Context Protocol) ಸರ್ವರ್ ಅನ್ನು ನಡೆಸುತ್ತದೆ, ಇದರಿಂದ MCP ಕ್ಲೈಂಟ್‌ಗಳು ಮತ್ತು
AI ಏಜೆಂಟ್‌ಗಳು ನಿಮ್ಮ ಬಾಕಿ ಇರುವ ಕಾರ್ಡ್‌ಗಳನ್ನು ಓದಬಹುದು, ಒಂದು ಬಾರಿಗೆ ಒಂದು ಪ್ರಶ್ನೆಯಂತೆ ನಿಮ್ಮೊಂದಿಗೆ ಅವುಗಳನ್ನು ಪುನರಾವರ್ತಿಸಬಹುದು,
ಮತ್ತು ನಿಮಗಾಗಿ ಕಾರ್ಡ್‌ಗಳು ಹಾಗೂ ಡೆಕ್‌ಗಳನ್ನು ರಚಿಸಬಹುದು ಅಥವಾ ಸಂಪಾದಿಸಬಹುದು.

ಏಜೆಂಟ್‌ಗಳು ಎರಡು ರೀತಿಯಲ್ಲಿ ಸಂಪರ್ಕಗೊಳ್ಳಬಹುದು: ಈ MCP ಸರ್ವರ್ ಮೂಲಕ (Claude ಅಥವಾ Cursor ನಂತಹ MCP ಕ್ಲೈಂಟ್‌ಗಳಿಗೆ
ಉತ್ತಮ), ಅಥವಾ CLI ಏಜೆಂಟ್‌ಗಳಿಗಾಗಿ [Agents API ಡಿಸ್ಕವರಿ URL](/docs/api/) ಮೂಲಕ. ಎರಡೂ ಪ್ರತಿ ಬಳಕೆದಾರರ
ಒಂದೇ ಡೇಟಾ ಇಂಟರ್ಫೇಸ್ ಅನ್ನು ತಲುಪುತ್ತವೆ; ಈ ಪುಟ MCP ಸರ್ವರ್ ಬಗ್ಗೆ ವಿವರಿಸುತ್ತದೆ.

ಇದಕ್ಕೆ ಇಲ್ಲಿ ಸಂಪರ್ಕಿಸಿ:

```text
https://mcp.nibomo.com/mcp
```

ಟ್ರಾನ್ಸ್‌ಪೋರ್ಟ್ Streamable HTTP. ಕಾರ್ಯಸ್ಥಳ ಡಿಸ್ಕವರಿ, ಕಾರ್ಡ್ ಮತ್ತು ಡೆಕ್‌ಗಳ ಓದು ಹಾಗೂ ಬರಹ, ಉಲ್ಲೇಖ ಮಾರ್ಗದರ್ಶಿಗಳು, ಪುನರಾವರ್ತನೆಗಳು ಮತ್ತು ಖಾತೆಯ ಬಳಕೆಗಾಗಿ ಸರ್ವರ್ ಎಂಟು ಟೂಲ್‌ಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ.

## ನಿಮ್ಮ ಕ್ಲೈಂಟ್‌ನಲ್ಲಿ ಇದನ್ನು ಸೇರಿಸುವುದು ಹೇಗೆ

ಹೆಚ್ಚಿನ ಕ್ಲೈಂಟ್‌ಗಳು ರಿಮೋಟ್ MCP ಸರ್ವರ್ ಅನ್ನು ಕಸ್ಟಮ್ ಕನೆಕ್ಟರ್ ಆಗಿ ಸೇರಿಸುತ್ತವೆ:

1. ನಿಮ್ಮ ಕ್ಲೈಂಟ್‌ನ ಕನೆಕ್ಟರ್ ಅಥವಾ MCP ಸರ್ವರ್ ಸೆಟ್ಟಿಂಗ್‌ಗಳನ್ನು ತೆರೆಯಿರಿ.
2. ಕಸ್ಟಮ್ ಕನೆಕ್ಟರ್ ಸೇರಿಸಿ ಮತ್ತು ಸರ್ವರ್ URL `https://mcp.nibomo.com/mcp` ಅನ್ನು ಅಂಟಿಸಿ.
3. ಇಂಟರ್ಯಾಕ್ಟಿವ್ ಕ್ಲೈಂಟ್‌ಗಳಲ್ಲಿ, ಕೇಳಿದಾಗ ಬ್ರೌಸರ್‌ನಲ್ಲಿ ಅಧಿಕಾರ ನೀಡಿ. ಸರ್ವರ್
   Dynamic Client Registration ಜೊತೆಗೆ OAuth 2.1 ಬಳಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಅಂಟಿಸಬೇಕಾದ ಕ್ಲೈಂಟ್ ಸೀಕ್ರೆಟ್ ಇಲ್ಲ
   ಮತ್ತು ಮೊದಲೇ ನೋಂದಾಯಿಸಬೇಕಾದ ಆ್ಯಪ್ ಇಲ್ಲ.
4. ಹೆಡ್‌ಲೆಸ್ ಅಥವಾ CLI ಬಳಕೆಗಾಗಿ, ಬ್ರೌಸರ್ ಫ್ಲೋ ಬದಲು ನಿಮ್ಮ ಏಜೆಂಟ್ API ಕೀಯೊಂದಿಗೆ
   `Authorization: Bearer fca_…` ಹೆಡರ್ ಹೊಂದಿಸಿ.

ಅಧಿಕಾರ ನೀಡಿದ ನಂತರ, ಕಾರ್ಯಸ್ಥಳವನ್ನು ಆಯ್ಕೆ ಮಾಡಲು ಒಮ್ಮೆ `list_workspaces` ಕರೆ ಮಾಡಿ, ನಂತರ ಓದುವಿಕೆಗೆ
`sql_query` ಮತ್ತು ಕಾರ್ಡ್ ಹಾಗೂ ಡೆಕ್ ಬರೆಯುವಿಕೆಗೆ `sql_execute` ಬಳಸಿ. ಪುನರಾವರ್ತಿಸಲು,
`next_review_card`, ನಂತರ `reveal_answer`, ನಂತರ `submit_review` ಕರೆ ಮಾಡಿ.

## ಟೂಲ್‌ಗಳು

ಸರ್ವರ್ ಎಂಟು ಟೂಲ್‌ಗಳನ್ನು ಒದಗಿಸುತ್ತದೆ. ಓದು ಮತ್ತು ಬರಹವನ್ನು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಬೇರ್ಪಡಿಸಲಾಗಿದೆ, ಇದರಿಂದ ಯಾವುದೇ ಒಂದು
ಟೂಲ್ ಸುರಕ್ಷಿತ ಮತ್ತು ವಿನಾಶಕಾರಿ ಕಾರ್ಯಾಚರಣೆಗಳನ್ನು ಎಂದಿಗೂ ಬೆರೆಸುವುದಿಲ್ಲ.

- `get_usage_limits` — ಖಾತೆಯ ಯೋಜನೆ, ಮಿತಿಗಳು ಮತ್ತು ಪ್ರಸ್ತುತ ತಿಂಗಳ AI ಬಳಕೆಯನ್ನು ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಓದಲು ಮಾತ್ರ ನೀಡುತ್ತದೆ; ಇದು ಕಾರ್ಡ್‌ಗಳನ್ನು ಓದುವುದಿಲ್ಲ ಅಥವಾ ಬದಲಾಯಿಸುವುದಿಲ್ಲ.
- `sql_query` — ನಿಮ್ಮ ಕಾರ್ಡ್‌ಗಳು ಮತ್ತು ಡೆಕ್‌ಗಳಿಗೆ ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಓದಲು ಮಾತ್ರ ಪ್ರವೇಶ (`SHOW TABLES`,
  `DESCRIBE`, `SHOW COLUMNS`, `SELECT`).
- `sql_execute` — ನಿಮ್ಮ ಕಾರ್ಡ್‌ಗಳು ಮತ್ತು ಡೆಕ್‌ಗಳಿಗೆ ಅಟಾಮಿಕ್ ಬ್ಯಾಚ್ ಆಗಿ ಬರೆಯುವ ಪ್ರವೇಶ (`INSERT`, `UPDATE`,
  `DELETE`).
- `list_workspaces` — ನಿಮಗೆ ಪ್ರವೇಶವಿರುವ ಕಾರ್ಯಸ್ಥಳಗಳ ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಓದಲು ಮಾತ್ರ ಇರುವ ಪಟ್ಟಿ,
  ಪ್ರತಿಯೊಂದರ ಜೊತೆಗೆ
  `workspaceId`, ಹೆಸರು, ಸಕ್ರಿಯ ಕಾರ್ಡ್‌ಗಳ ಸಂಖ್ಯೆ, ಕೊನೆಯ ಚಟುವಟಿಕೆ, ಮತ್ತು ಅದು ನೀವು ಪ್ರಸ್ತುತ
  ಆಯ್ಕೆ ಮಾಡಿರುವ ಡೀಫಾಲ್ಟ್ ಹೌದೇ ಎಂಬುದು. SQL ಮತ್ತು ಪುನರಾವರ್ತನೆಯ ಟೂಲ್‌ಗಳ ಐಚ್ಛಿಕ
  `workspaceId` ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಾಗಿ ಹಿಂದಿರುಗಿದ `workspaceId` ಬಳಸಿ.
- `get_guide` — ಒಂದು ವಿಷಯಕ್ಕೆ ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಓದಲು ಮಾತ್ರ ಇರುವ ಉಲ್ಲೇಖ ಮಾರ್ಗದರ್ಶಿ: `sql_dialect`,
  `card_authoring`, `bulk_authoring` ಅಥವಾ `review_flow`. ಇದು ಯಾವುದೇ ಕಾರ್ಯಸ್ಥಳದ ಡೇಟಾವನ್ನು ಓದುವುದಿಲ್ಲ.
- `next_review_card` — ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಓದಲು ಮಾತ್ರ: ಆ್ಯಪ್‌ಗಳಲ್ಲಿರುವ ಅದೇ ಸರದಿ ಕ್ರಮದಲ್ಲಿ ಪುನರಾವರ್ತಿಸಬೇಕಾದ ಮುಂದಿನ ಕಾರ್ಡ್‌ನ
  ಮುಂಭಾಗವನ್ನು ಮಾತ್ರ ಹಿಂದಿರುಗಿಸುತ್ತದೆ. ಐಚ್ಛಿಕ `tags` ಅಥವಾ `deckId` ಸರದಿಯನ್ನು
  ಕಿರಿದಾಗಿಸುತ್ತದೆ.
- `reveal_answer` — ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಓದಲು ಮಾತ್ರ: ಕಲಿಕಾರ್ಥಿ ಕಾರ್ಡ್‌ನ ಮುಂಭಾಗಕ್ಕೆ ಉತ್ತರಿಸಲು ಪ್ರಯತ್ನಿಸಿದ ನಂತರ
  ಆ ಕಾರ್ಡ್‌ನ ಹಿಂಭಾಗವನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ.
- `submit_review` — `Again`, `Hard`, `Good` ಅಥವಾ `Easy` ಇವುಗಳಲ್ಲಿ ಒಂದು ರೇಟಿಂಗ್ ಅನ್ನು ದಾಖಲಿಸಿ
  ಕಾರ್ಡ್‌ನ FSRS ವೇಳಾಪಟ್ಟಿಯನ್ನು ಮುಂದುವರಿಸುತ್ತದೆ.

SQL ಇಂಟರ್ಫೇಸ್ ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಸೀಮಿತವಾದ ಡಯಲೆಕ್ಟ್ ಮತ್ತು ಪೂರ್ಣ PostgreSQL ಅಲ್ಲ.
ಈ ದಾಖಲೆಗಳು ಬೆಂಬಲಿತ ಡಯಲೆಕ್ಟ್ ಅನ್ನು ಮಾತ್ರ ಒಳಗೊಂಡಿವೆ, PostgreSQL ಹೊಂದಾಣಿಕೆಯ
ಉಲ್ಲೇಖವಲ್ಲ. ಸ್ಟೇಟ್‌ಮೆಂಟ್‌ಗಳು `workspace`, `cards`, `decks` ಮತ್ತು
`review_events` ಸಂಪನ್ಮೂಲಗಳನ್ನು ಮಾತ್ರ ಉದ್ದೇಶಿಸಬಹುದು, ಪ್ರತಿಯೊಂದು ಸ್ಟೇಟ್‌ಮೆಂಟ್ ನಿಮ್ಮದೇ ಕಾರ್ಯಸ್ಥಳಕ್ಕೆ ಸೀಮಿತ, ಮತ್ತು
ಓದು ಹಾಗೂ ಬರಹಗಳಿಗೆ ಪ್ರತಿ ಸ್ಟೇಟ್‌ಮೆಂಟ್‌ಗೆ `100` ಸಾಲುಗಳ ಮಿತಿ ಇದೆ.

## ಪುನರಾವರ್ತನೆಗಳು

ಪುನರಾವರ್ತನೆಯ ಟೂಲ್‌ಗಳು ಏಜೆಂಟ್‌ಗೆ ಕಲಿಕಾರ್ಥಿಯನ್ನು ಒಂದು ಬಾರಿಗೆ ಒಂದು ಕಾರ್ಡ್‌ನಂತೆ ಪ್ರಶ್ನಿಸಲು ಮತ್ತು ಪ್ರತಿಯೊಂದು
ರೇಟಿಂಗ್ ಅನ್ನು ಕಾರ್ಡ್‌ನ FSRS ವೇಳಾಪಟ್ಟಿಗೆ ಉಳಿಸಲು ಅವಕಾಶ ನೀಡುತ್ತವೆ:

1. `next_review_card` `cardId` ಮತ್ತು `frontText` ಅನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ, ಅಥವಾ ಯಾವುದೂ ಬಾಕಿ ಇಲ್ಲದಿದ್ದಾಗ
   `card: null` ಹಿಂದಿರುಗಿಸುತ್ತದೆ.
2. ಕಲಿಕಾರ್ಥಿ ಉತ್ತರಿಸಿದ ನಂತರ, `reveal_answer` ಆ ಕಾರ್ಡ್‌ನ `backText` ಹಿಂದಿರುಗಿಸುತ್ತದೆ.
3. `submit_review` `cardId`, ಕ್ಲೈಂಟ್ ರಚಿಸಿದ `reviewId` UUID, ಒಂದು
   `rating`, ಮತ್ತು ಕಲಿಕಾರ್ಥಿಯ IANA `reviewedTimeZone` ಅನ್ನು ಸ್ವೀಕರಿಸುತ್ತದೆ. ಸರ್ವರ್
   ಪುನರಾವರ್ತನೆಯ ಸಮಯವನ್ನು ದಾಖಲಿಸಿ ಕಾರ್ಡ್‌ನ ಹೊಸ ವೇಳಾಪಟ್ಟಿಯನ್ನು ಹಿಂದಿರುಗಿಸುತ್ತದೆ.

ಫಲಿತಾಂಶ ಖಚಿತವಿಲ್ಲದ ಸಲ್ಲಿಕೆಯನ್ನು ಅದೇ `reviewId` ಜೊತೆಗೆ ಮತ್ತೆ ಪ್ರಯತ್ನಿಸಿ; ಅದು ಎಂದಿಗೂ ಎರಡನೇ
ಪುನರಾವರ್ತನೆಯನ್ನು ದಾಖಲಿಸುವುದಿಲ್ಲ. ಸಲ್ಲಿಕೆಗೆ ಈ ಉತ್ತರಗಳೂ ಬರಬಹುದು:

- `409 REVIEW_EVENT_CONFLICT` — ಪುನರಾವರ್ತನೆ ಈಗಾಗಲೇ ದಾಖಲಾಗಿದೆ, ಮತ್ತು ದೋಷದ
  ವಿವರಗಳು ಕಾರ್ಡ್‌ನ ಪ್ರಸ್ತುತ ವೇಳಾಪಟ್ಟಿಯನ್ನು ಒಳಗೊಂಡಿರುತ್ತವೆ.
- `409 REVIEW_ID_CARD_MISMATCH` — `reviewId` ಈಗಾಗಲೇ ಬೇರೊಂದು ಕಾರ್ಡ್‌ನ
  ಪುನರಾವರ್ತನೆಯನ್ನು ಗುರುತಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ಏನನ್ನೂ ಉಳಿಸಲಾಗಿಲ್ಲ; ಹೊಸ `reviewId` ಜೊತೆಗೆ ಮತ್ತೆ ಸಲ್ಲಿಸಿ.
- `409 REVIEW_STALE` — ಕಾರ್ಡ್‌ನಲ್ಲಿ ಉಳಿಸಿರುವ ಪುನರಾವರ್ತನೆಯ ಸಮಯ ಪ್ರಸ್ತುತ
  ಸರ್ವರ್ ಸಮಯಕ್ಕೆ ಸಮ ಅಥವಾ ಅದರ ನಂತರದ್ದು; ಬೇರೊಂದು ಕಾರ್ಡ್ ಪುನರಾವರ್ತಿಸಿ.

ಪುನರಾವರ್ತನೆಗಳನ್ನು `submit_review` ಮೂಲಕ ಮಾತ್ರ ದಾಖಲಿಸಲಾಗುತ್ತದೆ: SQL
`review_events` ಅಥವಾ FSRS ವೇಳಾಪಟ್ಟಿಯ ಸ್ಥಿತಿಯನ್ನು ಬರೆಯಲು ಸಾಧ್ಯವಿಲ್ಲ. ಸಂಪೂರ್ಣ ಪುನರಾವರ್ತನೆ ಮತ್ತು ರೇಟಿಂಗ್ ನಿಯಮಗಳಿಗಾಗಿ
`review_flow` ವಿಷಯದೊಂದಿಗೆ `get_guide` ಕರೆ ಮಾಡಿ.

## ಕಾರ್ಡ್ ಕಾಂಟ್ರ್ಯಾಕ್ಟ್

ಪ್ರತಿಯೊಂದು ಕಾರ್ಡ್ ಒಂದೇ ಕಾಂಟ್ರ್ಯಾಕ್ಟ್ ಅನುಸರಿಸುತ್ತದೆ, ಮತ್ತು ಟೂಲ್‌ಗಳು ಅದನ್ನೇ ಅವಲಂಬಿಸಿವೆ:

- `front_text` ಕೇವಲ ಪ್ರಶ್ನೆ ಅಥವಾ ಪುನರಾವರ್ತನೆಯ ಪ್ರಾಂಪ್ಟ್, ಮತ್ತು ಅದರಲ್ಲಿ ಎಂದಿಗೂ ಉತ್ತರ ಇರುವುದಿಲ್ಲ.
- `back_text` ಉತ್ತರವನ್ನು ಹೊಂದಿರುತ್ತದೆ, ಬೇಕಿದ್ದರೆ ಒಂದು ನಿರ್ದಿಷ್ಟ ಉದಾಹರಣೆಯೊಂದಿಗೆ.

`sql_execute` ಮೂಲಕ ಕಾರ್ಡ್‌ಗಳನ್ನು ರಚಿಸುವ ಏಜೆಂಟ್‌ಗಳು ಈ ಕಾಂಟ್ರ್ಯಾಕ್ಟ್ ಅನುಸರಿಸುತ್ತವೆ, ಆದ್ದರಿಂದ
ಅವು ರಚಿಸುವ ಕಾರ್ಡ್‌ಗಳನ್ನು ತಕ್ಷಣವೇ ಸ್ಪೇಸ್ಡ್ ರಿಪಿಟಿಶನ್ ಮೂಲಕ ಪುನರಾವರ್ತಿಸಬಹುದು.

## ದೃಢೀಕರಣ

ಎರಡು ಅಧಿಕಾರ ಮಾರ್ಗಗಳು ಪ್ರತಿ ಬಳಕೆದಾರರ ಒಂದೇ ಡೇಟಾ ಇಂಟರ್ಫೇಸ್ ಅನ್ನು ತಲುಪುತ್ತವೆ.

### OAuth 2.1 (ಇಂಟರ್ಯಾಕ್ಟಿವ್ ಕನೆಕ್ಟರ್ ಕ್ಲೈಂಟ್‌ಗಳು)

ಸರ್ವರ್ PKCE ಮತ್ತು Dynamic Client Registration ಜೊತೆಗೆ
authorization-code ಫ್ಲೋ ಅನ್ನು ಅನುಷ್ಠಾನಗೊಳಿಸುತ್ತದೆ. MCP URL ಅನ್ನು ಕಸ್ಟಮ್ ಕನೆಕ್ಟರ್ ಆಗಿ ಸೇರಿಸಿ ಬ್ರೌಸರ್‌ನಲ್ಲಿ ಅಧಿಕಾರ ನೀಡಿ;
ಯಾವುದೇ ಕ್ಲೈಂಟ್ ಸೀಕ್ರೆಟ್ ಅನ್ನು ಮೊದಲೇ ಹಂಚಿಕೊಳ್ಳಬೇಕಿಲ್ಲ. ಡಿಸ್ಕವರಿ ಪ್ರಮಾಣಿತವಾಗಿದೆ:

- ಸಂರಕ್ಷಿತ ಸಂಪನ್ಮೂಲದ ಮೆಟಾಡೇಟಾ:
  `https://mcp.nibomo.com/.well-known/oauth-protected-resource`
- ಅಧಿಕಾರ ಸರ್ವರ್‌ನ ಮೆಟಾಡೇಟಾ:
  `https://auth.flashcards-open-source-app.com/.well-known/oauth-authorization-server`

### API ಕೀ (ಹೆಡ್‌ಲೆಸ್ ಮತ್ತು CLI)

[API ಉಲ್ಲೇಖ](/docs/api/) ದಲ್ಲಿ ದಾಖಲಿಸಿರುವ ಇಮೇಲ್ OTP ಲಾಗಿನ್ ಫ್ಲೋ ಮೂಲಕ ದೀರ್ಘಾವಧಿಯ `fca_` ಏಜೆಂಟ್ API ಕೀ
ಪಡೆಯಿರಿ, ನಂತರ ಅದನ್ನು Bearer ಟೋಕನ್ ಆಗಿ ಕಳುಹಿಸಿ:

```text
Authorization: Bearer fca_ABCDEFGH_0123456789ABCDEFGHJKMNPQRS
```

REST ಏಜೆಂಟ್ ಇಂಟರ್ಫೇಸ್ ಸ್ವೀಕರಿಸುವುದೂ ಇದೇ ಕೀ, ಮತ್ತು ಇದಕ್ಕೆ ಬ್ರೌಸರ್ ಅಥವಾ
OAuth ಪ್ರಕ್ರಿಯೆ ಬೇಕಿಲ್ಲ.

ಎರಡೂ ಮಾರ್ಗಗಳ ಅಧಿಕೃತ, ಯಂತ್ರ ಓದಬಲ್ಲ ವಿವರಣೆ `https://api.nibomo.com/v1/` ನಲ್ಲಿರುವ
ಡಿಸ್ಕವರಿ ಪೇಲೋಡ್ (`/v1/agent` ನಲ್ಲಿ ಪ್ರತಿರೂಪವಿದೆ).

## ಸುರಕ್ಷತೆ ಮತ್ತು ವ್ಯಾಪ್ತಿ

SQL ಟೂಲ್‌ಗಳಿಗೆ ಅನುಮೋದನೆ ನೀಡುವುದು ಸುರಕ್ಷಿತ, ಏಕೆಂದರೆ ಈ ಇಂಟರ್ಫೇಸ್ ಯಾವುದೇ ಡೇಟಾಬೇಸ್‌ಗೆ ಮುಕ್ತ ಪ್ರವೇಶವಲ್ಲ,
ಬದಲಿಗೆ ಪಾರ್ಸರ್ ಜಾರಿಗೊಳಿಸುವ, ನಿರ್ಬಂಧಿತ ಡಯಲೆಕ್ಟ್:

- **ಮುಚ್ಚಿದ ಸ್ಟೇಟ್‌ಮೆಂಟ್ ಅನುಮತಿ ಪಟ್ಟಿ**: `sql_query` `SHOW TABLES`,
  `DESCRIBE`, `SHOW COLUMNS` ಮತ್ತು `SELECT` ಅನ್ನು ಮಾತ್ರ ಸ್ವೀಕರಿಸುತ್ತದೆ; `sql_execute` `INSERT`,
  `UPDATE` ಮತ್ತು `DELETE` ಅನ್ನು ಮಾತ್ರ ಸ್ವೀಕರಿಸುತ್ತದೆ. ಉಳಿದ ಎಲ್ಲವನ್ನೂ ಪಾರ್ಸ್ ಸಮಯದಲ್ಲೇ ತಿರಸ್ಕರಿಸಲಾಗುತ್ತದೆ.
- **ಸೀಮಿತ ಸಂಪನ್ಮೂಲಗಳು**: ಸ್ಟೇಟ್‌ಮೆಂಟ್‌ಗಳು `workspace`, `cards`, `decks`
  ಮತ್ತು `review_events` ಅನ್ನು ಮಾತ್ರ ಮುಟ್ಟಬಹುದು.
- **ಪ್ರತಿ ಕಾರ್ಯಸ್ಥಳದ ವ್ಯಾಪ್ತಿ**: ಪ್ರತಿಯೊಂದು SQL ಸ್ಟೇಟ್‌ಮೆಂಟ್ ಮತ್ತು ಪುನರಾವರ್ತನೆ ನಿಮಗೆ ಪ್ರವೇಶವಿರುವ
  ಒಂದೇ ಕಾರ್ಯಸ್ಥಳಕ್ಕೆ ಸೀಮಿತ, ಅಂದರೆ ನೀವು ನೀಡುವ `workspaceId` ಅಥವಾ ನೀವು ಆಯ್ಕೆ ಮಾಡಿದ
  ಡೀಫಾಲ್ಟ್; ಬೇರೆ ಟೆನೆಂಟ್‌ಗಳ ಡೇಟಾಗೆ ಪ್ರವೇಶವಿಲ್ಲ.
- **ಕಟ್ಟುನಿಟ್ಟಾದ ಆರ್ಗ್ಯುಮೆಂಟ್‌ಗಳು**: ಪ್ರತಿಯೊಂದು ಟೂಲ್ ಅಪರಿಚಿತ ಆರ್ಗ್ಯುಮೆಂಟ್ ಅನ್ನು ತಿರಸ್ಕರಿಸುತ್ತದೆ, ಆದ್ದರಿಂದ ತಪ್ಪಾಗಿ ಬರೆದ
  `workspaceId` ನಿಮ್ಮ ಡೀಫಾಲ್ಟ್ ಕಾರ್ಯಸ್ಥಳದ ಮೇಲೆ ಚಲಿಸುವ ಬದಲು ವಿಫಲವಾಗುತ್ತದೆ.
- **ಮಿತಿಗಳು**: ಪ್ರತಿ ಸ್ಟೇಟ್‌ಮೆಂಟ್‌ಗೆ ಗರಿಷ್ಠ `100` ಸಾಲುಗಳು, ಪ್ರತಿ ಬ್ಯಾಚ್‌ಗೆ ಗರಿಷ್ಠ `50` ಸ್ಟೇಟ್‌ಮೆಂಟ್‌ಗಳು, ಮತ್ತು
  ಫಲಿತಾಂಶಕ್ಕೆ ಸುಮಾರು `12k` ಟೋಕನ್‌ಗಳ ಮಿತಿ. ಬದಲಾವಣೆಯ ಬ್ಯಾಚ್‌ಗಳು ಅಟಾಮಿಕ್ ಆಗಿ ಅನ್ವಯವಾಗುತ್ತವೆ.
- **ಓದು/ಬರಹ ವಿಭಜನೆ**: `get_usage_limits`, `sql_query`, `list_workspaces`, `get_guide`,
  `next_review_card` ಮತ್ತು `reveal_answer` ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಓದಲು ಮಾತ್ರ (`readOnlyHint`),
  ಮತ್ತು ಅವು ಎಂದಿಗೂ ಡೇಟಾ ದುರಸ್ತಿ ಮಾಡುವುದಿಲ್ಲ, ವೇಳಾಪಟ್ಟಿಯನ್ನು ಮರುಲೆಕ್ಕ ಮಾಡುವುದಿಲ್ಲ ಅಥವಾ ಕಾರ್ಡ್‌ನ ಸ್ಥಿತಿಯನ್ನು ಬದಲಾಯಿಸುವುದಿಲ್ಲ.
  `sql_execute` ಮತ್ತು `submit_review` ಮಾತ್ರ ಬರೆಯುವ ಟೂಲ್‌ಗಳು (`destructiveHint`):
  `sql_execute` ಕಾರ್ಡ್‌ಗಳು ಮತ್ತು ಡೆಕ್‌ಗಳನ್ನು ಬರೆಯುತ್ತದೆ, ಮತ್ತು `submit_review` ಒಂದು ಪುನರಾವರ್ತನೆಯನ್ನು ದಾಖಲಿಸಿ
  ಅದರ ಕಾರ್ಡ್‌ನ ವೇಳಾಪಟ್ಟಿಯನ್ನು ಮುಂದುವರಿಸುತ್ತದೆ.

ಸಂಪೂರ್ಣ ಸ್ಟ್ಯಾಕ್ — ಆ್ಯಪ್, ಬ್ಯಾಕೆಂಡ್ ಮತ್ತು ಇನ್‌ಫ್ರಾಸ್ಟ್ರಕ್ಚರ್ — ಓಪನ್ ಸೋರ್ಸ್ ಆಗಿದೆ ಮತ್ತು ಅದನ್ನು
[ಸ್ವಂತವಾಗಿ ಹೋಸ್ಟ್ ಮಾಡಬಹುದು](/docs/self-hosting/), ಆದ್ದರಿಂದ ನೀವು ಇದೇ ಕನೆಕ್ಟರ್ ಅನ್ನು ನಿಮ್ಮದೇ
ಡಿಪ್ಲಾಯ್‌ಮೆಂಟ್‌ನೊಂದಿಗೆ ಬಳಸಬಹುದು.
