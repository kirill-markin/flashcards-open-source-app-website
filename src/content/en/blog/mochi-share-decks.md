Suppose you send a three-card Mochi deck to a study group. Later, you correct one answer and replace an outdated question. The new release still has three cards. Someone checking only the total could keep studying the old answer.

Mochi lets you share a native `.mochi` file or publish a public link. Either way, give recipients a recognizable release and a way to identify later corrections. Below is a small publisher-and-recipient rehearsal, with exact card changes, a copyable bulletin, and a worksheet for checking what arrived.

**How this guide was made:** Substantially AI-assisted writing and editing based on Mochi's official documentation, checked October 15, 2026. This is documentation research, not a hands-on Mochi test. The fictional rehearsal has blank result fields for readers to complete.

## Send a file or publish a link

| Delivery | What recipients get | When it fits |
| --- | --- | --- |
| A native `.mochi` file | A portable deck file to import into Mochi; exporting doesn't require Pro | You want to send a named release that recipients can keep. |
| A published link | A public, read-only deck that anyone with the link can access; publishing requires Pro | You want people to browse the material before taking a copy. |

Viewers can clone a published deck into their own Mochi workspace. That clone is a separate deck, and their edits don't affect your original. Unpublishing disables the shared link while keeping your deck. [Mochi sharing documentation](https://www.mochi.cards/docs/decks/sharing/)

Plan correction delivery separately. The sharing documentation doesn't promise that publisher corrections reach older clones, and it doesn't establish that unpublishing retrieves copies already taken.

For broader app and plan details, see the [Mochi flashcards review](/blog/mochi-alternative/).

## Prepare the release before sending it

Create a share-only deck containing the material intended for recipients. Inspect every card and side, including fields, template text, tags, images, audio, and any included review history. Remove private examples and your personal annotations from this release copy. Publish a link only for material you intend to make public.

Native exports can preserve cards, templates and fields, attachments, tags, history, order, and deck structure. Markdown and CSV omit information, so they aren't equivalent copies for native distribution. [Mochi export formats](https://mochi.cards/docs/import-and-export/exporting/)

Name the file clearly, for example `paper-kite-volunteers-v1.mochi`. Keep a release list with the exact prompts beside it; someone may rename the imported deck. For a public page, record the release name and the date you checked its contents.

### Export one deck

1. Open the share-only deck.
2. Open its deck menu and choose **Export deck**.
3. Save the native file with the release name, then send it with the prompt list.
4. Have the recipient import it into Mochi and compare the received cards with that list before studying.

**Settings → Export everything** has a wider scope. A copy of the Mochi user directory also includes login state and is a different backup method; use a single-deck export for this sharing workflow. [Mochi single-deck export instructions](https://mochi.cards/docs/getting-started/backing-up/)

### Check a published deck

Use Mochi's publishing controls for the prepared deck. Before sending the link, inspect the public page against your release list, including the answers and media. Put the release name in the accompanying message.

If the recipient takes a clone, check that copy too. The public page and the recipient's study deck are two separate things to inspect.

## Rehearse a three-card correction

**Paper Kite** is a fictional event. All rules below are invented demonstration content, not instructions for a real volunteer program. The `VOL-01` through `VOL-04` labels are human worksheet references, **not Mochi card IDs**. Match the cards by their exact prompts.

| Worksheet label | Exact prompt | Version 1 answer | Version 2 answer or disposition |
| --- | --- | --- | --- |
| VOL-01 | At Paper Kite, where do unused badge clips go? | The green tray. | The green tray. Unchanged. |
| VOL-02 | At Paper Kite, which envelope holds the attendance slips? | The blue envelope. | The amber envelope. Corrected. |
| VOL-03 | At Paper Kite, what does a star sticker on a box mean? | Ready to unpack. | Withdrawn: this sticker convention has been retired. |
| VOL-04 | At Paper Kite, where do empty display boxes go? | Absent from version 1. | The folding table. New card. |

**Version 1 contains VOL-01, VOL-02, and VOL-03. Version 2 contains VOL-01, VOL-02, and VOL-04.** Both have three cards. The replacement tests a different fact, so it gets a new worksheet label.

Keep the publisher's demonstration collection separate from the recipient's demonstration collection, with no real study data in either. Work through these two roles:

1. **Publisher:** Create version 1 from the first three rows. Deliver it by file or link with its prompt list.
2. **Recipient:** Obtain a copy and check its three questions and answers. Beneath the answer on VOL-02, add a separate line: **“Recipient note: I mix this up with the badge tray.”** This is ordinary card text for the exercise.
3. **Publisher:** Prepare version 2. Leave VOL-01 unchanged, correct VOL-02, withdraw VOL-03, and add VOL-04. Export a named version 2 file, or inspect the public page against the version 2 list.
4. **Recipient:** Apply the bulletin below to your existing demonstration copy. Change VOL-02's answer line while preserving the note below it. Save any notes you want from VOL-03 before removing that retired question from the study copy. Add VOL-04 and leave VOL-01 alone.
5. Record your app version and delivery method, then complete the acceptance worksheet.

This is a manual content correction. Mochi documents native imports and an external-data update mechanism, but its [import guide](https://mochi.cards/docs/import-and-export/importing/) doesn't establish how a new publisher release reconciles a recipient's edits and reviews. Matching filenames or card totals don't establish a safe merge procedure.

Before correcting real study material, preserve the recipient's current work; the [Mochi backup and restore guide](/blog/mochi-backup-restore/) covers that task. This rehearsal makes no claim about combining review histories or preserving scheduling after edits.

## Send the correction bulletin

“Updated the deck” leaves recipients guessing. Give them the old release, the new release, the exact affected prompts, and the work they should keep.

Copy this bulletin for the fictional rehearsal. Attach `paper-kite-volunteers-v2.mochi`, or replace the delivery line with the public link you've inspected. That file or page is the version 2 reference; the steps are for someone maintaining an existing version 1 copy.

```text
Paper Kite volunteer deck — version 2
Replaces: version 1
Delivery: paper-kite-volunteers-v2.mochi

Already studying version 1? Apply these changes to your existing copy:

KEEP VOL-01
Prompt: At Paper Kite, where do unused badge clips go?
Answer stays: The green tray.

CORRECT VOL-02
Prompt: At Paper Kite, which envelope holds the attendance slips?
Old answer: The blue envelope.
New answer: The amber envelope.
Change the answer line only. Keep your personal note below it:
Recipient note: I mix this up with the badge tray.

WITHDRAW VOL-03
Prompt: At Paper Kite, what does a star sticker on a box mean?
Old answer: Ready to unpack.
The sticker convention has been retired. Save any personal notes you want,
then remove this question from your study copy.

ADD VOL-04
Prompt: At Paper Kite, where do empty display boxes go?
Answer: The folding table.
This is a new card, replacing the withdrawn item in the release.

Final membership: VOL-01, VOL-02, VOL-04 — three cards.
Check all three prompts and answers, and confirm your VOL-02 note remains.
These instructions don't rely on reimporting the attached file.
```

## Check the cards, then the total

Copy this worksheet and fill in the observed results after your rehearsal. The intended results are acceptance criteria, not reported test outcomes.

| Check | Intended result after the correction | Observed result |
| --- | --- | --- |
| Recipient membership | Exactly VOL-01, VOL-02, and VOL-04 in the study copy | __________ |
| VOL-01 | Same prompt and “The green tray.” answer | __________ |
| VOL-02 | Same prompt; answer is “The amber envelope.” | __________ |
| Recipient note on VOL-02 | “Recipient note: I mix this up with the badge tray.” remains | __________ |
| VOL-03 | Retired prompt is absent from the study copy | __________ |
| VOL-04 | New prompt is present with “The folding table.” answer | __________ |
| Total | Three cards, after the checks above pass | __________ |
| Public page, if using a link | Contents match the release named in the message | __________ |

If a row fails, record the discrepancy before continuing. A three-card total can hide a surviving retired question, a duplicate corrected card, or a lost personal note.

For a real release, add checks for the fields, templates, and attachments recipients need. Identify a specific image or audio card and confirm that its media opens or plays in the received copy. If history is part of the intended delivery, check it separately from readable card text.

A larger revision may be easier to distribute as a new copy. Before asking existing learners to switch, decide how they'll keep their annotations and study work. Leave the correction list beside the new release so someone returning next month can still see exactly what changed.
