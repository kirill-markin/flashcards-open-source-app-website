Two tools can belong in the same gray box. A question asking where to put either tool has a clear answer. Turn that relationship around, and “Which tool belongs in the gray box?” suddenly has two correct answers. A useful comparison table can contain a poor reverse flashcard.

When making RemNote table flashcards, choose the questions before enabling whole columns. The small exercise below gives you a complete list of intended prompts, including a deliberately ambiguous direction to catch. Compare it with the cards you can actually inspect.

This is a documentation-based worked example. It hasn't been tested in a live RemNote account. The tools and rules are fictional, and the questions express the intended recall task rather than RemNote's exact screen wording.

## Start with four rows you can inspect completely

Tables are a **RemNote Pro feature**. Free users can try up to **three tables total**, combining Simple and Advanced Tables within that allowance. See the [official table overview](https://help.remnote.com/en/articles/8118336-tables).

Create a Simple Table with `/simple table`. Put the tool names in its left gray header column, with Code, Storage, and Reference across the top. The [Simple Tables guide](https://help.remnote.com/en/articles/13867819-simple-tables) documents creation and header controls.

| Tool | Code | Storage | Reference |
| --- | --- | --- | --- |
| Arlo clamp | A17 | Gray box | Workshop sheet 1 |
| Mira jig | B26 | Gray box | Workshop sheet 2 |
| Tavi gauge | C38 | Blue drawer | Workshop sheet 3 |
| Nelo guide | D49 | Blue drawer | Workshop sheet 4 |

Use plain, populated cells without nested bullets. This keeps the exercise about column directions rather than empty values or additional card content.

The learning task is narrow: recall each tool's code, identify a tool from its unique code, and remember where to put it away. The Reference column helps you find a sheet later. Remembering sheet numbers is outside the task.

## Give each column a reason to generate cards

A forward property question asks for a value belonging to a named thing. A backward question asks which thing has that value. It doesn't ask you to name the property. RemNote's [concept and descriptor documentation](https://help.remnote.com/en/articles/6751778-creating-concept-descriptor-flashcards) explains that reverse target; our [outline example](/blog/remnote-concept-descriptor-cards/) explores it outside tables.

Apply that distinction to this grid:

| Column | Intended setting | Why it belongs in the exercise |
| --- | --- | --- |
| Code | Both directions | Each tool has one code, and each code identifies one tool |
| Storage | Forward only | A tool identifies its location; a shared location doesn't identify one tool |
| Reference | Disabled | Keep the source pointer available without rehearsing it |

To enable a column, click its header, open **Flashcards Configuration**, and choose **Enable For This Column**. Select the direction you want. RemNote also documents a preview when you hover over the header arrow. See [Generating Flashcards from Tables](https://help.remnote.com/en/articles/13869879-generating-flashcards-from-tables).

Leave Reference disabled. If you're adapting an existing table, inspect its settings before proceeding. A table you already use for studying may have other directions enabled.

## Keep a list of the questions you mean to create

This design has **12 intended prompt–answer pairs**: four Code cells in two directions, plus four Storage cells in one direction. Reference contributes none. That's arithmetic for this fully populated example and the chosen directions. It isn't an observed card count, a due count, or a universal formula for every table.

Copy the checklist into a temporary note. For each front you inspect, record what appears and whether its answer matches the intended task. Leave unseen pairs marked as unchecked.

| ID | Intended question | Required answer | Observed front and answer |
| --- | --- | --- | --- |
| C1 | What is Arlo clamp's code? | A17 | — |
| C2 | Which tool has code A17? | Arlo clamp | — |
| C3 | What is Mira jig's code? | B26 | — |
| C4 | Which tool has code B26? | Mira jig | — |
| C5 | What is Tavi gauge's code? | C38 | — |
| C6 | Which tool has code C38? | Tavi gauge | — |
| C7 | What is Nelo guide's code? | D49 | — |
| C8 | Which tool has code D49? | Nelo guide | — |
| S1 | Where is Arlo clamp stored? | Gray box | — |
| S2 | Where is Mira jig stored? | Gray box | — |
| S3 | Where is Tavi gauge stored? | Blue drawer | — |
| S4 | Where is Nelo guide stored? | Blue drawer | — |

Check which questions exist, not just how many. An unwanted Reference question and a missing reverse Code question could cancel out in a total. Record unexpected questions separately so they don't disappear into the count.

The header preview is a starting point. Seeing one correct example there doesn't establish that you've inspected every row and direction. Fill the checklist from the actual fronts and answers available to inspect, including cards you encounter in a trial practice session. If a pair hasn't appeared, it remains unverified; don't infer its contents from a neighboring row.

For C2, the front needs to give you A17 and ask for **Arlo clamp**. “Code” is the property label, not the answer. Read the surrounding context too: the tool's name shouldn't already be supplying the answer.

## Catch the shared-location trap

Temporarily enable the backward direction for Storage to examine what that change asks you to recall. These trial questions sit outside the twelve-pair plan above.

Suppose a front supplies only the workshop context, the Storage label, and **Gray box**. Both Arlo clamp and Mira jig satisfy that cue. A stored answer of Arlo clamp doesn't make Mira jig wrong. Remembering which row you recently edited doesn't resolve the question either.

Blue drawer has the same problem: both Tavi gauge and Nelo guide belong there. Evaluate the full front of each trial card you inspect. Additional context might distinguish one tool, or it might simply give its name away. The duplicate value alone tells you to investigate; the information shown determines whether that particular question is ambiguous.

Restore Storage to forward-only when finished. The task needs a location for a named tool, so this repairs the exercise without changing the underlying facts.

If your real task is to recall every tool in a location, write an explicit question such as “Which two tools are stored in the gray box?” Its answer would be Arlo clamp **and** Mira jig. That's a separate list-recall task. See [how to make better flashcards](/blog/how-to-make-better-flashcards/) for more on setting an answer boundary.

## Check whether table context gives the answer away

RemNote's **Show Entire Table** mode preserves table context during practice. The setting affects cards across that table, as explained in the [official configuration guide](https://help.remnote.com/en/articles/13869879-generating-flashcards-from-tables).

If you enable it, recheck the fronts for both Code directions and forward Storage. Can you read the target code elsewhere? Can a nearby row or a Reference entry identify the tool? Record what's visible instead of assuming every helpful value will be masked.

C2 should require recalling Arlo clamp from A17. If surrounding information supplies Arlo clamp, the activity becomes finding a visible answer. Decide whether that serves your learning task, adjust the view, and inspect it again. Changing the view can also change which of your earlier observations still apply.

## Take one real table through the same check

Repeat the exercise with a small section of your own notes. Choose the useful directions, list the intended pairs, and compare them with actual questions before settling into regular review. Keep unresolved entries visible until you've checked them.

Generated cards, cards due now, and cards included in a document practice session are different things. In an Advanced Table, a filtered view limits that document's practice to visible rows. The [table flashcard guide](https://help.remnote.com/en/articles/13869879-generating-flashcards-from-tables) documents that scope. Absence from one session therefore doesn't establish that a card wasn't generated. For questions that don't appear where expected, use the [RemNote cards-not-showing guide](/blog/remnote-cards-not-showing/).

For the workshop example, you should be able to account for both Code directions for each tool, one Storage question per tool, and no Reference questions. The useful result is a checked set of questions with defensible answers—not a particular number in today's queue.
