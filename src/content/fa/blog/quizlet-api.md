تا 18 اوت 2026، Quizlet هیچ API عمومی با امکان دسترسی مستقل یا درگاه عمومی‌ای برای توسعه‌دهندگان مستند نکرده است. در حال حاضر، توسعه‌دهندگان مستقل راه رسمی‌ای برای ثبت برنامه، دریافت کلید API Quizlet و خواندن یا نوشتن داده‌های فلش‌کارت از طریق مسیرهای مستند ندارند.

این نتیجه از بررسی مستندات عمومی Quizlet به دست آمده و دربارهٔ سیستم‌های داخلی آن ادعایی نمی‌کند. Quizlet با محصولات دیگر و شرکای تجاری خود ارتباط دارد؛ اپ Quizlet در ChatGPT و افزونهٔ آن برای Google Classroom دو نمونهٔ فعلی‌اند. هیچ‌کدام API همه‌منظوره‌ای برای توسعه‌دهندگان سایر برنامه‌ها فراهم نمی‌کنند.

**تاریخ بررسی اطلاعات:** 18 اوت 2026.

> **شفاف‌سازی:** من کیریل مارکین هستم و Nibomo را می‌سازم؛ Agent API و سرور MCP آن در ادامه به‌عنوان جایگزین معرفی شده‌اند. Nibomo با Quizlet سازگار نیست و مجموعه‌های Quizlet را به‌صورت خودکار وارد نمی‌کند.

## پاسخ کوتاه: API مستندی برای دسترسی مستقل به Quizlet وجود ندارد

اگر برای خودکارسازی کارها در Quizlet عبارت «آیا Quizlet API دارد؟» را جست‌وجو کرده‌اید، پاسخ فعلی در عمل این است: **هیچ API عمومی با امکان دسترسی مستقل مستند نشده است**.

برخی قابلیت‌های رسمی ممکن است در نگاه اول شبیه API به نظر برسند، اما هرکدام برای کار مشخص و محدودتری طراحی شده‌اند:

| نیاز شما | روش پشتیبانی‌شده | کاربرد | آنچه در اختیارتان نمی‌گذارد |
|---|---|---|---|
| انتقال متن از مجموعه‌ای که خودتان ساخته‌اید | [خروجی گرفتن از وب‌سایت Quizlet](https://help.quizlet.com/hc/en-us/articles/360034345672-Exporting-your-sets) | کپی کردن اصطلاح‌ها و تعریف‌ها برای انتقال یک‌باره | تصاویر، خروجی مجموعه‌های کپی‌شده، تاریخچهٔ مطالعه یا دسترسی به API |
| قرار دادن یک مجموعهٔ عمومی در وب‌سایت یا صفحهٔ سامانهٔ مدیریت یادگیری (LMS) | [جاسازی Quizlet](https://help.quizlet.com/hc/en-us/articles/360032935851-Embedding-sets) | فعالیت آموزشی با نشان Quizlet در صفحهٔ شما | داده‌های ساختاریافتهٔ کارت‌ها یا دسترسی برای خواندن و نوشتن |
| تبدیل گفت‌وگوی ChatGPT به مجموعهٔ Quizlet | [اپ Quizlet در ChatGPT](https://quizlet.com/blog/quizlet-comes-to-chat-gpt) | ساخت و پیش‌نمایش مجموعه از طریق `@Quizlet` | اطلاعات احراز هویت یا مسیرهای API برای اپ خودتان |
| تعیین فعالیت‌های Quizlet به‌عنوان تکلیف در Google Classroom | [افزونهٔ Quizlet برای Google Classroom](https://quizlet.com/blog/quizlet-google-classroom-add-on) | یافتن فعالیت‌ها، تعیین آن‌ها به‌عنوان تکلیف و پیگیری‌شان در Classroom | یک API همه‌منظوره برای نرم‌افزار آموزشی سفارشی |
| اتصال برنامهٔ خودتان به Quizlet | در حال حاضر راهی برای دسترسی مستقل مستند نشده است | ممکن است دسترسی از طریق توافق با یک شریک مشخص فراهم باشد | ثبت‌نام عمومی، کلیدهای API یا مشخصات مستند کار با کارت‌ها |
| خودکارسازی فضای کاری فلش‌کارت خودتان | [Nibomo Agent API](/fa/docs/api/) یا [رابط MCP](/fa/docs/mcp-connector/) | خواندن و نوشتن مکرر کارت‌ها و دسته‌ها در محدودهٔ فضای کاری | سازگاری با Quizlet یا وارد کردن خودکار داده‌ها از Quizlet |

در عمل، هر نیاز راه خودش را دارد: برای کپی یک‌بارهٔ متن کارت‌های خودتان خروجی می‌گیرید و برای نمایش Quizlet در صفحه‌ای دیگر از جاسازی استفاده می‌کنید. اتصال به یک محصول مشخص هم فقط در همان فرایند تعریف‌شده کاربرد دارد. نرم‌افزاری که مرتب کارت می‌سازد، می‌خواند و ویرایش می‌کند، به API مستندی برای خواندن و نوشتن نیاز دارد.

## خروجی گرفتن، جاسازی و دسترسی شرکا API عمومی نیستند

یک API عمومی، چارچوب کار را برای توسعه‌دهندگان خارج از شرکت مشخص می‌کند: مستندات، روش احراز هویت، عملیات پشتیبانی‌شده، قواعد استفاده و نحوهٔ دریافت اطلاعات لازم برای دسترسی. هیچ‌کدام از امکانات عمومی فعلی Quizlet این مسیر را به‌طور کامل و مستقل در اختیار توسعه‌دهنده نمی‌گذارند.

**خروجی گرفتن (Export)** در Quizlet روشی برای انتقال دستی است. سازندهٔ مجموعه می‌تواند در وب‌سایت، چیدمان اصطلاح‌ها و تعریف‌ها را تنظیم کند، **کپی متن (Copy text)** را بزند و نتیجه را جای دیگری جای‌گذاری کند. به گفتهٔ Quizlet، نمی‌توان از تصاویر یا مجموعه‌های کپی‌شده خروجی گرفت و این قابلیت فقط در وب‌سایت در دسترس است. این روش برای انتقال یک‌باره با بررسی دقیق مناسب است، اما نرم‌افزار نمی‌تواند با آن دو سیستم را همگام نگه دارد.

**جاسازی (Embed)** امکان نمایش مجموعه را می‌دهد، نه دسترسی به داده‌های آن. در Quizlet می‌توانید کد HTML یک مجموعهٔ عمومی را در حالت تطبیق (Match)، یادگیری (Learn)، آزمون (Test)، فلش‌کارت (Flashcards) یا املا (Spell) کپی کنید. فعالیت جاسازی‌شده همچنان نشان Quizlet را دارد و کاربران با رابط کاربری خود Quizlet مطالعه می‌کنند. برنامهٔ شما داده‌های کارت‌های مجموعه را برای ویرایش دریافت نمی‌کند.

**اتصال به یک محصول مشخص** بر اساس توافق و برای کاربرد معینی انجام می‌شود. Quizlet می‌تواند با ChatGPT یا Google Classroom کار کند، بی‌آنکه همان رابط را در اختیار همهٔ توسعه‌دهندگان بگذارد. عرضهٔ این قابلیت‌ها فقط وجود همین اتصال‌ها را نشان می‌دهد و به معنای وجود API عمومی Quizlet برای استفادهٔ همگان نیست.

به همین دلیل، یک کتابخانهٔ واسط قدیمی یا درخواستی که در ابزارهای توسعه‌دهندهٔ مرورگر دیده می‌شود هم API پشتیبانی‌شدهٔ Quizlet محسوب نمی‌شود. این موارد فاقد مستندات عمومی و چارچوب فنی پایداری هستند که توسعه‌دهنده بتواند به آن تکیه کند.

## راهی را انتخاب کنید که با کار شما تناسب دارد

### برای پشتیبان‌گیری یا انتقال یک‌باره، خروجی بگیرید

برای مجموعه‌ای که خودتان ساخته‌اید، از روش رسمی خروجی گرفتن Quizlet استفاده کنید. آخرین مرحلهٔ این کار **کپی متن (Copy text)** است؛ پس اولین نسخهٔ متنی را که جای‌گذاری می‌کنید، دست‌نخورده نگه دارید و اصلاح جداکننده‌ها یا تطبیق فیلدها را روی نسخهٔ دیگری انجام دهید. با این کار اصطلاح‌ها و تعریف‌ها را حفظ می‌کنید، اما بسته‌ای برای بازیابی کامل دسته دانلود نمی‌کنید. تصاویر و تاریخچهٔ مطالعه منتقل نمی‌شوند.

چک‌لیست عملی این کار در [چطور در سال 2026 از مجموعه‌های Quizlet خروجی بگیریم](/fa/blog/how-to-export-quizlet-sets-and-turn-them-into-fsrs-flashcards/) آمده است. این راهنما نگهداری نسخهٔ خام و نسخهٔ کاری، UTF-8، نویسه‌های تب، تعریف‌های چندخطی و تفاوت انتقال محتوای کارت با انتقال وضعیت زمان‌بندی مرور را توضیح می‌دهد.

خروجی گرفتن برای انتقالی مناسب است که یک بار انجام می‌شود و به پایان می‌رسد. ساخت روزانهٔ کارت، همگام‌سازی یا ویرایش مکرر با نرم‌افزار به روش دیگری نیاز دارد.

### برای نمایش، از جاسازی رسمی استفاده کنید

اگر می‌خواهید کاربران یک مجموعهٔ عمومی Quizlet را در وب‌سایت کلاس یا صفحهٔ LMS مطالعه کنند، از کد جاسازی موجود در وب‌سایت Quizlet استفاده کنید. فعالیت را انتخاب کنید، **کپی HTML (Copy HTML)** را بزنید و کد را به صفحه اضافه کنید. کاربران به یک فعالیت تعاملی Quizlet دسترسی پیدا می‌کنند، اما وب‌سایت میزبان داده‌های خام کارت‌ها را دریافت نمی‌کند.

اغلب همین قابلیت نیاز معلم را برطرف می‌کند. نامیدن آن به‌عنوان API فقط مسئله را پیچیده‌تر از آنچه هست نشان می‌دهد.

### برای ChatGPT یا Google Classroom، از اتصال رسمی همان محصول استفاده کنید

Quizlet در اطلاعیهٔ 10 مارس 2026 دربارهٔ ChatGPT مراحل مشخصی را شرح می‌دهد: اپ Quizlet را متصل کنید، درخواست را با `@Quizlet` شروع کنید، پیش‌نمایش مجموعهٔ ساخته‌شده را در ChatGPT ببینید و سپس آن را برای شخصی‌سازی و مطالعه در Quizlet باز کنید. این روش پشتیبانی‌شده‌ای برای ساخت مجموعهٔ Quizlet از همان گفت‌وگو است، اما اطلاعات دسترسی به API Quizlet را در اختیار بات، اسکریپت یا وب‌سایت شما نمی‌گذارد تا بتوانید دوباره از آن استفاده کنید.

اطلاعیهٔ 30 ژوئن 2026 Quizlet دربارهٔ Google Classroom هم کاربرد مشخصی را توضیح می‌دهد. این افزونه به معلمان امکان می‌دهد فعالیت‌هایی مثل سؤال‌های تمرینی، فلش‌کارت‌ها و بازی‌ها را پیدا کنند و به‌عنوان تکلیف بدهند، سپس میزان مشارکت و پیشرفت را در Classroom پیگیری کنند. به گفتهٔ Quizlet، استفاده از آن به Google Workspace for Education Plus نیاز دارد؛ ممکن است معلمان برای دریافت مجوز یا دسترسی به افزونه به کمک مدیر فناوری اطلاعات نیاز داشته باشند.

اگر یکی از این دو روش نیازتان را برطرف می‌کند، از همان استفاده کنید. برای ساخت برنامهٔ سفارشی، هیچ‌کدام جای دسترسی عمومی توسعه‌دهندگان را نمی‌گیرد.

### برای خودکارسازی مداوم، رابط مستند خواندن و نوشتن انتخاب کنید

خودکارسازی مداوم یعنی نرم‌افزار شما بتواند کارها را بارها و به‌شکل قابل اعتماد انجام دهد: از یادداشت‌ها کارت بسازد، دسته‌ها را فهرست کند، پاسخ‌ها را به‌روزرسانی کند یا در طول زمان فضای کاری را مدیریت کند. کپی کردن خروجی در کلیپ‌بورد، رابط لازم برای چنین کاری را فراهم نمی‌کند.

راه امن این است که سیستم فلش‌کارتی انتخاب کنید که روش احراز هویت نرم‌افزارهای بیرونی و عملیات خواندن و نوشتن پشتیبانی‌شده را به‌روشنی مستند کرده باشد. شاید لازم باشد بخش خودکار کار را به جایگزینی برای API Quizlet بسپارید و برای مطالعه با امکانات موجود Quizlet، همچنان از خود آن استفاده کنید.

## جایگزین API در Nibomo دقیقاً چه امکاناتی می‌دهد؟

Nibomo دو راه مستند برای دسترسی به مجموعهٔ محدودی از داده‌های هر کاربر دارد. هر دو راه به همان داده‌ها دسترسی می‌دهند:

- نقطهٔ شروع [Agent API برای برنامه‌های بیرونی](/fa/docs/api/)، `GET https://api.nibomo.com/v1/` است. پاسخ معرفی API، عامل را در مراحل ورود با رمز یک‌بارمصرف ایمیلی، ساخت کلید API و انتخاب فضای کاری راهنمایی می‌کند. خواندن داده‌ها از مسیر پرس‌وجو با ساختاری شبیه SQL انجام می‌شود و نوشتن آن‌ها مسیر اجرای جداگانه‌ای دارد.
- [سرور MCP راه‌دور](/fa/docs/mcp-connector/) در `https://mcp.nibomo.com/mcp` در دسترس است. کلاینت‌های MCP هشت ابزار دریافت می‌کنند: `list_workspaces`، `sql_query`، `sql_execute`، `get_guide` و ابزارهای مرور `next_review_card`، `reveal_answer` و `submit_review`.

ابزار `get_usage_limits` فقط اطلاعات طرح حساب، محدودیت‌ها و میزان مصرف هوش مصنوعی در ماه جاری را می‌خواند؛ کارت‌ها را نمی‌خواند و تغییر نمی‌دهد.

دسترسی در هر دو مسیر به فضای کاری انتخاب‌شده محدود است. منابع مستندشده شامل `workspace`، `cards`، `decks` و `review_events` هستند و هر دستور حداکثر 100 ردیف برمی‌گرداند. این رابط از گونه‌ای محدود از SQL استفاده می‌کند و دسترسی مستقیم به PostgreSQL نیست. شِمای OpenAPI هم ندارد؛ بنابراین اگر فرایند شما به کلاینت‌های تولیدشده از OpenAPI وابسته است، به رابط دیگری نیاز دارید.

این امکانات به توسعه‌دهنده یا عامل هوش مصنوعی کمک می‌کند کار با فلش‌کارت‌های خودش را خودکار کند. با آن نمی‌توان محتوای یک نشانی Quizlet را خواند، نسخه‌ای همگام از حساب Quizlet ساخت یا به‌عنوان کلاینت غیرمستند Quizlet عمل کرد. ابزاری برای وارد کردن خودکار مجموعه‌ها از Quizlet وجود ندارد. برای انتقال، ابتدا از اصطلاح‌ها و تعریف‌های مجموعهٔ خودتان خروجی بگیرید، متن را بررسی کنید و سپس آن را با فیلدهای کارت در مقصد تطبیق دهید. مقصد وضعیت مطالعهٔ تازه‌ای برای خودش می‌سازد؛ تاریخچهٔ Quizlet منتقل نمی‌شود.

برای آشنایی با تفاوت‌های این محصولات، فراتر از دسترسی به API، [مقایسهٔ جایگزین متن‌باز Quizlet](/blog/quizlet-alternative/) را ببینید.

## درخواست‌های خصوصی مرورگر میان‌بر امنی نیستند

رابط وب Quizlet مثل هر اپلیکیشن وب امروزی درخواست‌های شبکه ارسال می‌کند. پیدا کردن یکی از این درخواست‌ها، آن را به مسیر پشتیبانی‌شده‌ای برای برنامهٔ شما تبدیل نمی‌کند.

مسیرهای خصوصی‌ای که مرورگر از آن‌ها استفاده می‌کند ممکن است به کوکی‌های نشست، قالب‌های داخلی، سازوکارهای جلوگیری از سوءاستفاده و پیش‌فرض‌های رابط کاربری فعلی وابسته باشند. این مسیرها ممکن است بدون نسخه‌بندی عمومی یا راهنمای مهاجرت تغییر کنند. گذشته از این، [شرایط استفادهٔ Quizlet](https://quizlet.com/tos)، با آخرین به‌روزرسانی در 28 مه 2026، اسکرپینگ و دیگر روش‌های استخراج خودکار داده و همچنین استفادهٔ خودکار بدون مجوز از سرویس را ممنوع می‌کند.

حتی برای یک اسکریپت شخصی هم تکیه کردن به چنین مسیری ناپایدار و پرریسک است، چه برسد به یک محصول. در اینجا نشانی‌های حدسی API یا مراحل مهندسی معکوس ارائه نمی‌کنم.

برای انتقال یک‌بارهٔ مجموعهٔ خودتان، خروجی بگیرید. برای مطالعهٔ یک مجموعهٔ عمومی در صفحه‌ای دیگر، آن را جاسازی کنید. برای کارهای مشخص در ChatGPT یا Google Classroom، از اتصال رسمی همان محصول استفاده کنید. اگر به خواندن و نوشتن مکرر نیاز دارید، نرم‌افزاری انتخاب کنید که رابط خودکارسازی مستندی داشته باشد؛ یا تا زمانی که Quizlet چنین رابطی منتشر کند، بخش مربوط به Quizlet را دستی انجام دهید.

## چطور متوجه تغییر وضعیت شوید؟

ممکن است Quizlet پس از تاریخ بررسی اطلاعات این مقاله، برنامه‌ای برای توسعه‌دهندگان راه‌اندازی کند. نشانهٔ چنین تغییری، درگاه رسمی توسعه‌دهندگان یا مستنداتی است که توضیح دهد چه کسانی می‌توانند ثبت‌نام کنند، احراز هویت چگونه انجام می‌شود، چه عملیاتی روی کارت‌ها پشتیبانی می‌شود و چه قواعدی برای استفاده وجود دارد.

انتشار یک کتابخانهٔ واسط دیگر از سوی شخص ثالث یا آغاز همکاری با محصولی تازه، این پاسخ را تغییر نمی‌دهد. تا زمانی که Quizlet دسترسی مستقل توسعه‌دهندگان را مستند نکرده است، ادعاهای مربوط به وجود API فعلی Quizlet را با دقت بررسی کنید و روش پشتیبانی‌شده‌ای را انتخاب کنید که نیاز واقعی شما را برطرف کند.
