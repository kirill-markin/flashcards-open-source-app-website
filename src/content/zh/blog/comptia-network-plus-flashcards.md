CompTIA 给 N10-009 考生 90 分钟，最多完成 90 道题，其中还包括实操题。官方考试目标既要求你记住端口和协议，也要求你在具体场景中运用 IPv4 地址、配置交换功能、分析网络证据并排查故障。

这些内容需要不同的学习方式。实用的 **CompTIA Network+ 闪卡**适合帮你快速想起一个小知识点或判断：某项服务对应的端口、一个子网掩码、某条命令的用途，或指向下一步检查的线索。计算、配置、数据包捕获、完整的故障排除场景和 PBQ，则仍要在卡组之外动手练习。

**事实核查截至：**2026 年 8 月 26 日。

## 先看当前的 N10-009 考试目标

当前官方 [CompTIA Network+ N10-009 考试目标](https://assets.ctfassets.net/82ripq7fjls2/113XqW3JHT7AlIU33M63I0/af42da2af7383a38f318bad10aa9afbd/Network_Plus_N10-009_Exam_Objectives.pdf)标注为 **Exam Objectives Version 4.0**。文档说明，考试包含选择题和实操题，时限为 90 分钟，并建议考生至少具备 9–12 个月的 IT 网络工作经验。

| N10-009 考试领域 | 权重 |
| --- | ---: |
| 网络概念 | 23% |
| 网络实施 | 20% |
| 网络运维 | 19% |
| 网络安全 | 14% |
| 网络故障排除 | 24% |

这些百分比适合用来检查整体复习是否均衡，不适合直接换算成卡片数量。如果故障排除占考试近四分之一，而你的卡组里只有端口号，卡组反而会掩盖备考缺口。解决办法也不是再做几百张故障排除卡，而是增加场景练习，再用少量卡片补上你反复记错的具体知识点和判断。

CompTIA 还特别说明，各项目标下列出的示例并不涵盖全部考查内容。因此，可以把考试目标当作当前最可靠的范围依据，但不要假定每道题都会照搬其中某一条。给卡片保留 `n10-009-v4` 这样的来源标签，并在考试前对照官方 PDF 复查与版本有关的内容。

## 先分清：这项内容该用闪卡记，还是该动手练

最简单的判断标准，是看怎样才算真正掌握。如果只需给出一个简短、稳定的答案，闪卡通常很合适。如果需要计算、分析不断变化的证据、在多个合理操作中作出选择，或亲手配置设备，就该用实践练习。当答案取决于具体场景时，把可复用的线索或判断规则写进卡片，不要把整个场景都塞进去。

| 适合做成闪卡的内容 | 更适合完整练习的内容 |
| --- | --- |
| 服务与端口的对应关系 | 分析数据包捕获结果 |
| 缩略词及其实际作用 | 在时间压力下为陌生网络划分子网 |
| CIDR 前缀与掩码的转换 | 配置 VLAN、路由、无线网络或网络服务 |
| 命令或工具的用途 | 解读不熟悉的命令输出 |
| 一个症状，以及下一步该收集的证据 | 追踪跨越多个网络层的故障 |
| 故障排除流程中的一个步骤 | 完成一项 PBQ 或较长的场景题 |

有些主题会同时出现在两列。你可以用卡片记住 `/27` 对应 `255.255.255.224`，再拿一组新的 `/27` 地址在纸上计算。你可以先想起 `tcpdump` 是做什么的，再用它捕获并筛选真实流量。卡片减少不必要的迟疑，动手练习则检验你能不能把事情做对。

## 端口卡片要同时包含服务和实际线索

N10-009 考试目标明确列出了一组 **Network+ 端口与协议**。备考范围应以这张表为准。如果需要进一步查阅协议，可以参考 [IANA 服务名称与传输协议端口号注册表](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.xhtml)。它记录了官方的服务名称和传输端口分配，却仍不能告诉你某台主机实际运行着什么服务。

不要把任何一份来源直接做成一张“说出所有端口”的巨型卡片。把内容拆成短小、明确的问题；如果某组重要关联总让你出错，再从两个方向分别练习。

```text
正面：在 N10-009 中，哪项服务与端口 22 相关联，可用于加密的远程
命令行访问？

背面：SSH。端口 22 是标准关联；仍需确认主机上实际运行的服务和配置。
```

```text
正面：N10-009 考试目标把哪两项服务与端口 22 关联起来？

背面：SSH 和 SFTP。
```

```text
正面：客户端需要自动获取 IP 配置。根据 N10-009 考试目标，应该想到哪项
服务和哪组端口？

背面：DHCP，端口 67 和 68。
```

实际线索比孤立的数字更重要。`53 -> DNS` 值得记，但“名称解析失败，下一步检查 DNS”更容易用于排障。`161/162 -> SNMP` 也值得记，同时还要把 SNMP 与网络监控和管理联系起来。

下面这条边界值得单独做一张卡：

```text
正面：某段流量的目标端口是 443。仅凭端口号，你能确定它运行了什么应用吗？

背面：不能。端口 443 通常与 HTTPS 关联，但仍需结合配置、进程和流量证据
确认实际运行的应用或服务。
```

端口号是一种约定，也是一条线索，却不是身份验证。服务可以改端口，也可能经过隧道或代理，甚至配置错误。如果让人只凭一个数字就下定论，正好会把 **Network+ 故障排除**训练带偏。

刚开始时，不必为每组关联都制作正向和反向两张卡。先练一个方向；只有在回忆速度太慢，或两项服务总是互相混淆时，再补一张反向卡。[Security+ 闪卡指南](/zh/blog/how-to-use-flashcards-for-security-plus/)也用同样的方法学习协议和安全概念之间的区别。

## 子网划分：用闪卡记锚点，用新地址练计算

N10-009 目标 1.7 要求考生“在给定场景中使用适当的 IPv4 网络地址”。这比在选择题里认出一个掩码更进一步。**Network+ 子网划分闪卡**应该把常用锚点练成自动反应，然后把真正的计算留给新的题目。

实用的锚点卡很容易判断对错：

```text
正面：哪个子网掩码对应 /27？

背面：255.255.255.224。
```

```text
正面：普通的 IPv4 /27 子网共有多少个地址？按传统方式计算，其中多少个
可以分配给主机？

背面：共 32 个；排除网络地址和广播地址后，传统可用主机地址为 30 个。
```

```text
正面：192.0.2.77/27 属于哪个网络？

背面：192.0.2.64/27。地址块从 .64 到 .95；传统主机地址范围为 .65 到
.94，.95 是广播地址。
```

第三张卡可以作为最初的示例题。一旦你记住了这个固定答案，它考查的就不再是子网计算，而是对这张卡本身的记忆。把做过的例子当作临时检查或模板，接下来继续换用新地址、不同前缀长度、VLSM 规划和限时练习，而且不要让答案预先等在卡片背面。

一组均衡的子网划分练习可以这样安排：

1. 复习到期的前缀、掩码、块大小和主机数量卡片。
2. 不看答案，计算五个从未做过的子网。
3. 核对网络地址、广播地址和可用主机范围。
4. 只有同一条规则反复导致错误时，才补一张修正卡。

如果你总忘记 `/26` 的块大小是 64，这个知识点适合做成卡片。如果你已经理解块大小，却在时间压力下总找错边界，需要补的是计算练习。

## 命令卡片应该先帮你想起工具，再去练语法

考试目标列出的软件工具包括协议分析器、`ping`、`traceroute` 或 `tracert`、`nslookup`、`tcpdump`、`dig`、`netstat`、`ip`、`ifconfig`、`ipconfig`、`arp` 和 Nmap。文档还列出硬件工具，以及 `show route`、`show interface`、`show config`、`show arp` 和 `show vlan` 等基础设备命令。

这些内容很适合出卡，但单纯背命令很容易制造虚假的熟练感。卡片应该先问：为了拿到某项证据，该用哪个工具？

```text
正面：需要测试名称解析时，可以用哪个 N10-009 命令行工具查询 DNS？

背面：`nslookup` 或 `dig`，具体取决于系统和任务。
```

```text
正面：哪个命令行工具可以捕获数据包，供之后分析？

背面：`tcpdump`。
```

```text
正面：需要查看 VLAN 信息时，可以先考虑哪条基础设备命令？

背面：`show vlan`。具体语法和输出取决于设备平台。
```

```text
正面：与基础的 `ping` 测试相比，`traceroute` 还能提供什么证据？

背面：它会显示通往目标途中作出响应的各跳顺序，有助于定位路径从哪里开始
变化或中断。某一跳没有响应只是需要继续调查的证据，不能直接证明它已宕机。
```

复习完一张命令卡后，在实验环境或你获准测试的系统上实际运行一次。先预测结果，再查看真实输出，改变一个条件，然后重新运行。这个短循环会让你接触权限、参数、平台差异、筛选方法和杂乱输出——这些都不是卡片能够还原的。[终端命令闪卡指南](/zh/blog/how-to-learn-terminal-commands-with-flashcards/)更详细地介绍了这种练法。

## 故障排除卡片要保留不确定性

N10-009 权重最高的领域是网络故障排除，占 24%。考试目标涵盖故障排除方法、物理接口故障、交换和服务问题、性能问题、软件工具、硬件工具以及设备命令。

较弱的卡片会问“什么会导致丢包？”，然后期待一长串答案。更好的卡片会给出一项观察结果，再问这条证据足以支持你下一步做什么。

```text
正面：客户端拿到了 169.254.x.x IPv4 地址。这说明什么？下一步该调查什么？

背面：客户端获得的是 APIPA/链路本地地址，而不是预期的网络配置。检查本地
链路以及通往 DHCP 的路径。仅凭这个地址还不能确定具体哪个组件出了故障。
```

```text
正面：可以通过 IP 地址访问一台主机，却无法通过主机名访问。下一步检查哪项
服务比较合理？

背面：DNS 名称解析。先确认客户端配置并查询所需记录，再判断 DNS 在哪个
环节出现问题。
```

```text
正面：某个接口上的 CRC 错误持续增加。这条证据足以支持你做什么？

背面：调查物理链路和相关接口证据，包括线缆、收发器，以及速度或双工设置。
仅凭计数器还不能把问题锁定到某一个组件。
```

这里的措辞很重要。“这说明什么？”或“下一步该检查什么？”训练的是根据证据推理。“这是什么造成的？”则容易让人根据一个症状就武断地认定唯一原因。

官方故障排除方法也适合制作步骤顺序卡：

```text
正面：关于可能原因的第一个理论没有得到证实。按照 N10-009 故障排除方法，
下一步是什么？

背面：建立新的理论，或升级处理。
```

记住步骤只是起点。在实验中，你还要识别问题，提出并验证理论，规划解决方案并考虑影响，实施方案或升级处理，验证全部功能，考虑预防措施，最后记录发现、操作和结果。真实故障几乎不会附带对应的考试目标编号。

## PBQ 练习必须比一张卡片更完整

CompTIA 将[实操题](https://www.comptia.org/en-us/resources/test-policies/exam-development/performance-based-questions-explained/)描述为在模拟或虚拟环境中考查问题解决能力的题目。一项 PBQ 可能同时包含拓扑、配置、工具、症状和多项判断。只有正反两面的提示，无法还原这种完整的操作状态。

可以在 **Network+ PBQ 练习**前后使用闪卡：

1. 练习前，回忆可能用到的端口、命令、子网锚点和故障排除步骤。
2. 进行 PBQ 或实验时，不打开卡组，只根据现有证据完成任务。
3. 结束后，记下漏掉的线索、错误的假设，以及真正欠缺的技能。
4. 只有当一个明确的记忆问题导致失误时，才制作修正卡。
5. 换一个场景，检验这项修正是否真的有效。

如果你因为想不起哪条命令用于查询 DNS 而选错工具，这就适合补一张明确的卡。如果你知道该用什么工具，却看不懂响应，就该多分析真实输出。如果你在子网划分时找错网络边界，就多算几组陌生网络。如果你不会配置设备，就回到实验环境继续练。

不要把正规的练习题原样复制进卡组。用自己的话保留可复用的知识点，舍弃原题的故事、答案选项和独特措辞。[把练习题变成闪卡的指南](/zh/blog/how-to-turn-practice-questions-into-flashcards/)提供了完整流程。

官方考试目标还警告考生不要使用通常称为 brain dump 的未获授权第三方材料。请使用当前考试目标、获授权的培训和练习、自己的实验观察，以及自己写出的解释。背下泄露题目的措辞，不等于真正学习 Network+。

## 一套实用的 Network+ 学习循环

好的每周学习安排会在记忆复习和网络实践之间反复切换，而不是先把卡组做完，再把实验一直推到以后。

每次选一小组考试目标，可以按下面的顺序练习：

1. 阅读考试目标，并用当前有效的正规资料学习。
2. 针对无法顺利想起的事实、区别和工具选择，制作少量卡片。
3. 在动手练习前复习到期卡片。
4. 完成一组计算、配置任务、数据包练习或故障排除实验。
5. 完成一小组正规的场景题或 PBQ 练习。
6. 先判断每次失误属于哪一类，再选择补救方式。

| 问题出在哪里 | 最合适的下一步 |
| --- | --- |
| 忘记了一个端口、掩码、缩略词或命令用途 | 添加或重写一张范围明确的卡片 |
| 两个相关概念总是互相混淆 | 添加一张对比卡 |
| 子网划分速度慢或容易算错 | 继续计算新的网络 |
| 看错了命令输出或数据包捕获结果 | 分析更多真实输出，并标出漏看的线索 |
| 无法配置这项功能 | 从干净状态重新完成实验 |
| 在多步骤场景中理不清思路 | 再做一项故障排除练习或 PBQ |

当卡片本身确实值得排程时，FSRS 可以很好地融入 Network+ 学习计划。不过，制卡仍要有所选择。排程器能根据你的复习记录调整之后的复习时间，却无法把含糊的问题，或一项从未动手练过的网络技能，变成真正的能力。[FSRS 工作原理指南](/zh/blog/what-is-fsrs/)介绍了这个排程器及其局限。

最简单的组织方式，是建立一个 `N10-009` 卡组，再使用 `ports`、`subnetting`、`commands`、`operations`、`security`、`troubleshooting`、`practice-miss` 和 `lab-miss` 等标签。如果考试目标代码有助于之后复查，也可以把它加到与版本有关的卡片上。标签应该帮助你找到薄弱领域，而不是把整份 PDF 复制成一棵文件夹树。

## CompTIA Network+ 闪卡常见问题

### N10-009 闪卡里应该放哪些端口？

先看当前官方考试目标中的端口与服务表。把你无法顺利想起的关联拆成小卡片，再把每项关联与它的实际用途联系起来。考试目标中的示例并不涵盖全部考查内容，而且端口号也不能证明某项服务一定正在运行。

### 只用 Network+ 闪卡能学会子网划分吗？

不能。卡片适合记前缀与掩码的转换、块大小、主机数量，以及你反复忘记的规则。还要另外计算新的网络，确保自己无需记住某道固定题，也能找出网络地址、广播地址和可用主机范围。

### 闪卡能代替 Network+ 实验或 PBQ 吗？

不能。卡片可以让你更快想起前置知识。实验和正规的 PBQ 练习仍会考查配置、计算、界面操作、证据收集和多步骤判断。

### 每一条 N10-009 考试目标都要做成卡片吗？

不用。把考试目标当作覆盖范围图，而不是逐条誊写的任务清单。只有需要反复回忆的具体事实和区别才适合做卡。其余内容应通过实验、计算、数据包捕获、场景题和练习题来掌握。

### 做错的练习题该怎样改成卡片？

先找出真正导致失误的那个小知识点、线索或区别，再用自己的话写一个只考查这一点的新问题。不要复制原题、答案选项或独特场景。

## 从下一次真实失误开始建立卡组

打开官方 N10-009 考试目标，选择其中一个小节。学完后，去做一件有可能失败的事：计算子网、查询 DNS、检查路由、捕获流量、配置交换机，或排查一个故意设错的实验环境。

只把那些拖慢你回忆速度的具体知识点做成卡片。计算、设备、输出和完整场景都留在实践环节。这样的分工，才能让你的 **N10-009 闪卡**值得长期复习，也能让 Network+ 学习计划应对那些无法靠卡片背面一句答案解决的问题。
