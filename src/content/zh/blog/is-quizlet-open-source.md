Quizlet 开源吗？**不开源——至少完整的核心 Web 产品和移动应用不开源。** 截至 2026 年 8 月 29 日，Quizlet 没有以开源许可证发布一套可供构建的完整产品代码。

Quizlet 确实有公开学习集、官方 GitHub 组织，也允许用户导出自己创建的学习集。只是，这三者开放的东西并不相同：它们都不会让你获得完整的 Quizlet 源码、文档齐全的通用公共 API，或一套受官方支持、可以部署到自有基础设施上的完整服务。

本文结论来自 Quizlet 目前的官方仓库、帮助页面和服务条款，不涉及未公开的私有代码或内部系统。

**事实核查日期：** 2026 年 8 月 29 日。

## 先弄清楚你需要哪一种控制权

谈到 **Quizlet 是否开源**，最常见的误区是把五个不同问题混在一起：

| 边界 | Quizlet 提供什么 | 你的控制权止于哪里 |
| --- | --- | --- |
| **公开学习集** | 用户可以查看由创建者设为公开的学习材料。 | 能看到内容，不等于能看到背后的软件。 |
| **学习集内容的权利** | 对于符合版权保护条件的原创材料，原作者通常拥有版权；用户向 Quizlet 提交内容时，也会授予 Quizlet 相应许可。 | 拥有学习集里的文字或图片，不代表拥有 Quizlet 应用。学习集公开可见，也不等于任何人都能自由复制。 |
| **源代码与许可证** | Quizlet 在 GitHub 上发布了若干独立工具、组件、Action 和派生仓库。 | 这些仓库不包含完整的 Web 应用、移动应用、后端和基础设施。 |
| **导出与 API 访问** | 学习集创建者可以在网站上把术语和定义导出为文本。 | 导出的文本既不是可恢复的 Quizlet 备份，也不是有正式文档的读写 API。 |
| **自托管** | Quizlet 负责运营在线服务并发布官方应用。 | 官方没有给出自行部署完整产品的受支持方案。 |

该看哪一项，取决于你想做什么。学生要保留卡片文字，需要导出；教师要复用他人的材料，需要先弄清内容权利；开发者要持续自动化操作，需要有正式文档的 API；组织若必须自行运营整套应用，则需要源码、合适的许可证和部署文档。

## Quizlet 的 GitHub 上到底有什么？

[Quizlet 官方 GitHub 组织](https://github.com/quizlet)目前有 28 个公开仓库，主要是组件、工程工具、Action 和派生仓库，并不是完整 Quizlet 产品的公开版本。

例如：

- `argocd-diff-action`：生成 Argo CD 差异的 GitHub Action；
- `ts-migration`：把代码从 Flow 迁移到 TypeScript 的工具；
- `pinyin-converter`：把数字标调的拼音转换为声调符号；
- `Hammock`：供 Hack 使用的独立模拟库。

这些仓库各自可能采用开源许可证，其中一些在 Quizlet 之外也很实用。不过，许可证只覆盖对应仓库里的代码，不会自动延伸到 Quizlet 从未在该仓库发布的软件。

我没有找到任何一个官方仓库，能够构建完整的 Quizlet 网站和移动端产品，并包含其托管后端与运行基础设施。搜索“Quizlet source code”还会看到非官方封装、下载工具、仿制项目和旧版集成，但这些第三方项目不能证明 Quizlet 已经开放自己的核心产品。

因此，能够从现有证据得出的准确结论是：Quizlet 当前没有在官方公开仓库中，以开源许可证提供完整的核心产品。

## 公开学习集涉及内容权利，不是软件权利

公开的 Quizlet 学习集，与展示它的应用，属于两个不同层面。术语、定义和用户上传的图片属于用户内容；账户系统、学习模式、调度器、移动客户端、网站和后端，则属于产品软件。

Quizlet 的[版权基础知识](https://help.quizlet.com/hc/en-us/articles/360029925172-Copyright-basics)说明，对于符合条件的原创作品，原作者通常拥有版权。页面同时提醒，使用他人的作品可能需要获得许可、取得许可证、确认作品已进入公有领域、符合合理使用原则，或满足其他例外条件。学习集被设为公开，并不能替你解决这些权利问题。

Quizlet 于 2026 年 5 月 28 日更新的[服务条款](https://quizlet.com/tos)，规定了用户如何访问其托管服务，以及用户向 Quizlet 提交内容时授予了哪些许可。它并不是 Quizlet 应用代码的开源许可证。

可以把这三类规则分开理解：

- **内容许可**管的是闪卡学习集、答案、图片或文档等材料；
- **软件许可证**管的是源代码，以及使用、研究、修改和再分发代码的权利；
- 服务条款管的是如何访问由他人运营的软件服务。

同一个 Quizlet 账户可能同时涉及这三类规则，而你在每一层拥有的权利并不相同。这里梳理的是 Quizlet 已公开边界的实际含义，不构成法律建议。

## 从 Quizlet 导出后，你究竟能拿到什么？

Quizlet 提供了一种范围不大、但确实有用的数据迁移方式。按照[官方导出说明](https://help.quizlet.com/hc/en-us/articles/360034345672-Exporting-your-sets)，学习集创建者可以调整术语和定义的排列方式，点击 **Copy text**，再把复制出的内容粘贴到其他地方。

官方文档列出的限制很明确：

- 只能在网站上导出，移动应用不支持；
- 只能导出自己创建的学习集；
- 复制他人内容后创建的学习集不能导出；
- 得到的是包含术语和定义的纯文本；
- 图片不会随之导出。

这些内容足够为自己的卡片文字留下一份可读备份，也可以用来谨慎迁移到其他工具。但它不会保留 Quizlet 中的图片、学习历史、游戏、课堂工作流和账户结构，更不是一份能够恢复整个产品的备份。

如果你需要的正是这种控制权，可以参考[将 Quizlet 学习集导出并转换成 FSRS 闪卡的分步指南](/zh/blog/how-to-export-quizlet-sets-and-turn-them-into-fsrs-flashcards/)。其中介绍了分隔符、UTF-8、多行定义、原始备份和测试导入。确认复制出的文本在目标工具中无误之前，先别删除原始学习集。

## Quizlet 有公共 API 吗？

Quizlet 当前的公开文档中，没有供外部开发者自行注册的开发者门户、API 密钥申请流程，也没有一套有正式文档的通用 API。这不代表 Quizlet 没有内部 API 或私有合作伙伴集成，只能说明独立开发者目前没有一套公开、可自行申请使用的接口。

一套受支持的公共 API，通常会说明如何注册和认证、如何读写数据、如何处理错误，以及有哪些调用限制。手动导出文本不具备这些能力。Quizlet 网站自身发出的网络请求，也不能视为面向外部开发者的正式接口。

[Quizlet API 现状指南](/zh/blog/quizlet-api/)梳理了几条官方支持的路径：一次性复制自己创建的学习集，可以使用导出；要展示 Quizlet 活动，可以使用官方嵌入功能；特定工作流则可以使用官方明确列出的集成。这些方式都不会给自定义应用一套通用凭据，用来持续同步 Quizlet 数据。

对开发者来说，选择其实很直接：

- 只需要迁移一次，就使用导出；
- 软件需要反复创建、读取或更新卡片，就选择为这类操作提供正式 API 文档的产品；
- 需要修改产品本身，就要求产品公开源码，并采用合适的许可证。

## Quizlet 可以自托管吗？

Quizlet 的官方 GitHub 组织和公开文档都没有提供受支持的完整 **Quizlet 自托管**方案。官方没有给出一条完整路径，让你构建核心产品、配置后端、部署到自有基础设施，再运行与之兼容的 Web 和移动客户端。

把导出的文本存到自己的电脑上，只能算本地存储，不是自托管。自托管意味着由你来运营软件，包括服务器或整套技术栈、配置、数据存储、升级和备份；同时，你还需要一份允许这样运行软件的许可证。

那些公开组件也填不上这块缺口。拼音转换工具、迁移工具或基础设施 Action 可以成为大型系统中的一部分，但它们不会因此公开整个系统，更不会让整套产品变得可部署。

如果自托管是硬性要求，应该比较那些明确写清楚哪些部分能由你运行的项目。[开源闪卡应用对比](/zh/blog/best-open-source-flashcard-apps-2026/)区分了完整的浏览器端部署、仅自托管同步服务器、本地客户端和全栈托管。它们都可能被称为“开源”，实际给你的控制权却差别很大。

## 按实际需求做选择

只争取足以解决实际问题的那一层控制权：

| 你的需求 | 实用的下一步 |
| --- | --- |
| 保留自己创建的学习集中的术语和定义 | 导出文本，另存一份未经修改的原始副本，再到目标工具中测试。 |
| 复用他人创建的公开学习集 | 核对创建者、内容来源、授权、许可证或适用的例外条件；仅仅公开可见还不够。 |
| 完成一次性迁移 | 使用官方导出，不要围绕浏览器中的私有请求开发工具。 |
| 让卡片与你自己的软件持续同步 | 选择为这类工作流提供正式读写 API 文档的产品。 |
| 检查或修改学习应用 | 查看真正的源码仓库和许可证文件，而不只是项目介绍。 |
| 自行运营完整服务 | 要求项目提供持续维护的部署文档、备份与恢复流程，以及清晰的升级路径。 |

明确自己的需求后，可以再看[更全面的 Quizlet 替代方案指南](/zh/blog/quizlet-alternative/)了解产品取舍。熟悉的界面、一个公开的 GitHub 链接、离线使用和自托管，解决的是不同问题，不能相互替代。

## 披露：我在开发一款开源替代产品

> **披露：** 我是 Kirill Markin，也是 [Flashcards Open Source App](/zh/features/) 的开发者。它采用 [MIT 许可证的仓库](https://github.com/kirill-markin/flashcards-open-source-app)，包含完整的 Web、iOS、Android、身份验证、后端、同步和基础设施技术栈。它公开源码的范围与 Quizlet 不同，但并不因此成为可以直接替换 Quizlet 的产品。

Flashcards 提供了一套以 AWS 为核心的[自托管指南](/zh/docs/self-hosting/)，而不是一键运行的本地安装程序。部署者需要自行负责云账户、身份验证、邮件发送、监控、备份、升级和原生应用构建。

它与 Quizlet 并不兼容：没有一键式 Quizlet 导入器，也没有复刻 Quizlet 的全部游戏和课堂生态。经过检查的 Quizlet 文本导出可以作为新卡片的素材，但这只是一套迁移流程，不代表它兼容 Quizlet 学习集或学习历史。

如果你看重全栈源码、MIT 许可证、API 和由运营者掌控的部署，并且愿意接受上述限制，可以考虑 Flashcards。如果你更需要成熟的桌面生态、直接导入能力，或更轻量的自托管工作，则可以比较其他[开源闪卡应用](/zh/blog/best-open-source-flashcard-apps-2026/)。

## 简短答案

2026 年 Quizlet 开源吗？**不开源——至少完整的核心产品不开源。** Quizlet 在 GitHub 上发布了一些实用工具和组件，但没有以开源许可证发布可供构建的完整 Web 与移动端服务。

公开学习集涉及的是内容可见性和使用权限。导出功能只会让学习集创建者获得一份包含术语和定义的文本副本。Quizlet 当前的公开文档既没有自助式通用 API，也没有受官方支持的完整自托管方案。

如果你只需要自己的卡片文字，就导出并核对；如果需要持续自动化，就选择有正式文档的 API；如果需要检查、修改或自行运营产品，就选择源码许可证与部署文档明确覆盖这些需求的软件。
