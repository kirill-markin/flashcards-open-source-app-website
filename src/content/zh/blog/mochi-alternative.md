Mochi 从一份 Markdown 文档开始，而不是传统的正面/背面表单。单独写一行 `---`，文档就会多出可供复习的卡面。你也可以只把它当作笔记、将它链接到另一张卡片，或将它归档：内容仍可搜索，但不会进入复习队列。

这个小小的分隔符，几乎就划出了 **Mochi 闪卡**的适用人群。如果你想在同一款本地优先应用里兼顾笔记和间隔重复，而且用惯了 Markdown、反向链接和简单的 Remembered/Forgot 二选一，Mochi 会很合适。但如果你已长期使用 Anki，卡片库又依赖自动生成的卡片变体、自定义 HTML/CSS、JavaScript、插件或精细的调度器设置，换成 Mochi 的理由就没那么充分。

如果只在一台设备上使用，免费版远不止试用：无需注册，而且 Mochi 明确支持不限量离线使用。限制是跨设备同步属于**每月 US$5 的 Pro 方案**。对 Anki 用户来说，更棘手的成本其实是迁移中的损失。Mochi 可以导入 Anki 数据包及其中的复习历史，却无法原样保留每一种模板、样式、脚本、调度器设置或插件行为。

> **利益披露：** 我是 Kirill Markin，也是 [Flashcards Open Source App](/zh/) 的开发者。这是一篇依据资料撰写的工作流评测，并不表示我亲自做过产品实测。文中没有联盟营销链接。主要比较对象仍是 Mochi 和 Anki；我自己的产品只会在接近文末的位置，以明确标注的替代方案出现。

**事实核查日期：** 2026 年 9 月 7 日。当时 [Mochi 更新日志](https://mochi.cards/changelog/)中可见的最新版本是 26.8.2，发布于 2026 年 8 月 10 日。价格和应用商店信息可能会变化。

## 先看结论

- 如果你想把 Markdown 笔记和卡片放在一起，在单台设备上无需账号即可离线使用，还想要反向链接和简单的二元复习判断，适合选 **Mochi**。
- 如果你需要成熟的笔记类型、HTML/CSS 模板、插件、免费云同步、四档复习评分或更深入的 FSRS 设置，适合选 **Anki**。
- 如果你已经能稳定复习，却说不清 Mochi 究竟能解决哪个工作流问题，**先别切换**。只为换个界面，不值得拿多年的调度数据和自定义卡片冒险。
- 如果 Anki 已经承载了你的长期卡片库，迁移前务必**先做测试**。Mochi 接受 `.apkg` 文件，也能导入复习历史，但会把 HTML 转为 Markdown，并移除 CSS 和 JavaScript。

## Mochi 与 Anki 快速对比

| 决策维度 | Mochi | Anki |
|---|---|---|
| 最适合 | 想把关联笔记与复习卡片放在一起的 Markdown 用户 | 想要成熟、可配置闪卡系统的学习者 |
| 创建卡片 | 加入 `---` 后，Markdown 文档会变成多面卡片；也支持字段和模板 | 笔记保存字段；HTML/CSS 模板据此生成一张或多张卡片 |
| 复习流程 | 新卡片先进入学习阶段；学会后用 Forgot / Remembered 复习 | 用 Again / Hard / Good / Easy 四档评分复习 |
| 调度方式 | 默认使用 Mochi 自有算法；也可选择 FSRS | 支持 FSRS 或传统 SM-2，并提供更完整的 FSRS 调整工具 |
| 免费使用 | 无需注册，可不限量离线使用 | 桌面应用与 AnkiWeb 同步免费；官方 iOS 应用收费 |
| 跨设备同步 | Pro，每月 US$5 | 通过 AnkiWeb 免费同步 |
| 平台 | Web、macOS、Windows、Linux、iOS、Android | Windows、macOS、Linux、AnkiWeb、官方 AnkiMobile、独立开发的 AnkiDroid |
| 可移植格式 | 原生 `.mochi`、Markdown 和 CSV 导出 | 原生 `.colpkg` 和 `.apkg`，以及制表符分隔文本 |
| 数据与托管边界 | 本地优先；核心应用并未宣称开源，也没有官方支持的自托管同步服务文档 | 主代码库采用 AGPL 许可证；官方提供自托管同步服务器文档 |

真正有用的分界线在于：你要的是**以笔记为核心的简洁体验，还是对整个卡片库的深度控制**。

## Mochi 的界面逻辑

沿着一张卡片走完整个流程，就很容易理解 Mochi 的界面。

每张卡片都属于一个牌组。点击 **New Card** 后，打开的是 Markdown 编辑区，而不是固定的提问框和答案框。一张卡片可以包含标题、列表、代码、图片、结构化字段和链接。在内容块之间加入 `---`，就能创建两个或更多复习卡面；用 `[[双层方括号]]` 引用另一张卡片，Mochi 会自动生成反向链接。官方的[卡片概览](https://mochi.cards/docs/cards/)还介绍了模板：其中的占位符可以渲染结构化字段的值。

卡片可以承担两种角色，无须拆到不同系统中：

- 复习卡片拥有多个卡面，并进入间隔重复计划；
- 参考笔记可以留在同一牌组里并归档。归档后，它不会出现在新卡片和到期卡片队列中，但内容、标签、链接与历史都会保留。

[牌组视图](https://mochi.cards/docs/decks/custom-views/)可以保存筛选条件、排序方式和布局。你可以保留一个网格视图用于日常浏览，再针对某个标签、到期状态、低保留率或最近复习过的卡片建立其他视图。还可以直接把某个视图变成突击复习，而不影响正常的调度和复习历史。这比简单说界面“简洁”更准确：同一个牌组既可以当笔记本，也可以当筛选后的数据库和学习队列。

[每日复习](https://mochi.cards/docs/getting-started/reviewing-cards/)分为两个阶段。在 **New cards** 阶段，你可以把卡片加入复习计划，也可以选择 Again，过一会儿再看。卡片学会后，每次到期都会显示下一个卡面，让你选择 **Forgot** 或 **Remembered**。选择 Forgot 后，Mochi 会先把卡片放入再次复习队列，然后才重置进度。整个复习过程有意把判断收束成简单的二选一。

## Mochi 免费吗？哪些功能可以离线使用？

免费，也能离线，但“免费”和“离线”的具体含义取决于使用方式。[Mochi 当前的价格页面](https://mochi.cards/)列出：

- **Free：** 永久免费（US$0），无需注册，可不限量离线使用。
- **Pro：** 每月 US$5，包含跨设备同步、牌组发布、动态字段、AI 集成和电子邮件支持。

Mochi 支持 macOS、Windows、Linux、iOS、Android 和 Web。它的[下载与安装指南](https://mochi.cards/docs/getting-started/download-and-install/)把实际边界写得很清楚：

| 使用方式 | “免费”和“离线”的具体含义 |
|---|---|
| 已安装的桌面或移动应用 | 无需账号即可离线使用 Mochi。数据保存在设备上，因此只用一个已安装的应用，也能拥有完整的免费工作流。 |
| 未订阅 Pro 的 Web 应用 | 内容保存在浏览器的离线存储中。Mochi 提醒，浏览器可能不经提示就清除这些数据。 |
| 在多台设备上使用同一卡片库 | 自动跨设备同步属于 Pro 功能；不过，每台设备上已安装的应用仍能各自离线工作。 |

离线使用和同步是两回事。在下载并安装的应用里创建或复习卡片，并不需要 Pro；但如果希望同一份最新卡片库自动从笔记本电脑同步到手机，就需要 Pro。免费版里的重要数据应当保留原生备份，不要把一台设备——尤其是浏览器存储——当成唯一副本。

如果离线能力是决定因素，可以通过 [Anki 能否离线使用？](/zh/blog/does-anki-work-offline/)对比具体的设备工作流，也可以阅读更完整的[离线闪卡应用指南](/zh/blog/best-offline-flashcards-app/)。

## 真正值得选择 Mochi 的，是 Markdown 闪卡工作流

Mochi 真正的优势，在于 Markdown 改变了你日常维护的内容形态。

Mochi 卡片本身就是可读的文本。同一份文档里可以放一段简短说明、一个代码块、指向相关概念的链接，以及划分复习卡面的分隔符。如果需要反复使用固定结构，卡片也支持字段和模板。套用模板后，Mochi 会以字段占位符渲染模板中的 Markdown；渲染时不使用卡片自身的 Markdown，但也不会删除它。

Anki 的模型不同。笔记负责保存字段，[卡片模板](https://docs.ankiweb.net/templates/intro.html)决定显示哪些字段、生成哪些卡片。模板使用 HTML，再由 CSS 控制样式。因此，一条词汇笔记可以同时生成识别卡和输出卡，底层数据仍只需保存一份。

这套结构让 Anki 在条件布局、自动生成卡片变体、输入答案、自定义样式，以及用插件扩展工作流等方面拥有更高的上限。代价是 Anki 并非原生 Markdown 闪卡应用；想在 Anki 里使用 Markdown 工作流，还要加一层转换工具或插件。

实际要回答的问题很简单：你想要一则能变成卡片的笔记，还是一种能生成多张卡片的结构化笔记类型？Mochi 更擅长前者，Anki 更擅长后者。

## Mochi 的间隔重复如今也支持 FSRS

还在说 Mochi 不支持 FSRS 的对比文章已经过时。Mochi 在 2025 年加入了 FSRS 预览版，之后也持续修复与调度器有关的问题。不过，[Mochi 自有算法仍是默认选项](https://mochi.cards/docs/reviewing/fsrs/)。

在默认算法中，每次选择 Remembered 或 Forgot 后，复习间隔都会按固定倍数调整。在 Review Settings 中切换到 FSRS 后，已经学会的卡片会改用 FSRS，原有历史不会丢失。你可以设置目标保留率、输入自定义参数，也可以随时切换回来。

无论使用哪种调度器，Mochi 都只有两档评分：

- **Forgot** 对应 FSRS 的 Again。
- **Remembered** 对应 FSRS 的 Good。

Mochi 文档说明，两档评分可以配合 FSRS 使用，只是会少掉 Hard 和 Easy 本可提供的部分信息。Mochi 支持输入优化后的自定义参数，却没有内置优化器；要生成个人参数，需要把 Mochi 复习历史交给外部 FSRS 优化器。

[Anki 的 FSRS 设置](https://docs.ankiweb.net/deck-options.html#fsrs)更进一步。期望保留率和参数可以跟随预设，内置优化器能根据复习历史拟合参数，模拟器还能估算不同设置下的复习次数或学习时长。Anki 也会记录四种结果：Again、Hard、Good 和 Easy。

只有始终按同一标准使用，这些额外按钮才有帮助。Anki 手册把 Hard 视为成功回忆。如果明明忘记了答案却按下 Hard，就是在向 FSRS 提供错误信息，可能导致间隔过长。

如果“记住/忘记”能让复习过程更清晰，就选择 Mochi 的两档评分。如果你需要更多评分信号，也确实会使用优化器、保留率设置、预设或工作量模拟器，就选择 Anki。若只想比较调度器而不是应用本身，请参阅 [FSRS 与 SM-2 对比](/zh/blog/fsrs-vs-sm-2/)。

## Mochi 与 Anki：钱花在不同地方

只在一台桌面设备上学习时，两款应用都可以不花钱。设备一多，成本就会出现在不同地方。

Mochi Pro **每月 US$5**，除了同步，还包含牌组发布、动态字段、AI 集成和支持。[Anki 官方网站](https://apps.ankiweb.net/)则说明，Anki 桌面应用和 AnkiWeb 同步均免费。AnkiMobile 是面向 iPhone 和 iPad 的付费官方应用；AnkiDroid 是免费且独立开发的 Android 客户端。

因此，“哪个更便宜”取决于你用哪些设备：

- 一台电脑：两者都可以免费；
- 多台桌面设备或 Android 设备：Anki 提供免费的云同步，无须订阅；
- iPhone 或 iPad：Anki 需要一次性购买应用，而 Mochi 把跨设备同步放在持续付费的 Pro 方案中；
- 如果你本来就需要牌组发布、动态字段或 Mochi 的 AI 集成，同步可能只是整个功能包的一部分，而不是全部成本。

计算 iOS 端的确切总成本前，请先查看你所在地区的 App Store。应用价格可能因市场而异，因此本文不固定列出一个数字。

## Mochi 本地优先，不等于可以自托管

这三个概念经常被混在一起：

- **本地优先**是指工作副本保存在你的设备上，即使云服务不可用，应用仍能继续运行。
- **开源**是指源代码以允许查看和修改的许可证公开。
- **自托管**是指产品提供官方支持的方案和文档，让你能在自己的基础设施上运行相关服务。

Mochi 明确说明了本地优先的工作方式，但并未宣称核心应用开源。官网页脚的“Open source”链接指向[一组集成项目](https://github.com/mochi-cards/open-source)，而不是核心应用。Mochi 官方网站也没有提供能够替代 Pro 同步的自托管方案文档。

如果你搜索 **Mochi 托管**是因为想运行自己的服务器，边界就在这里：本地数据和原生备份可以自己保管，但官方文档提供的跨设备方案只有 Mochi Pro。本地优先确实能让你更好地掌控数据，却不等于自托管。

Anki 主代码库采用 [AGPL 第 3 版或更高版本许可证](https://github.com/ankitects/anki/blob/main/LICENSE)，部分组件另有明确列出的例外。官方手册还为高级用户提供了[自托管同步服务器](https://docs.ankiweb.net/sync-server.html)文档。该服务器可为兼容客户端替代 AnkiWeb 同步，但并不是 AnkiWeb 网站的自托管版本；服务器运营者还要自行处理命令行、网络、防火墙、协议和更新问题。

## 从 Anki 导入会保留什么，又会改变什么

Mochi 的[导入文档](https://mochi.cards/docs/import-and-export/importing/)说明，它可以导入 Anki `.apkg` 文件，包括复习历史。但“导入成功”不等于“完全等效”。

导入时，Mochi 会把 HTML 转为 Markdown，并移除 CSS 和 JavaScript。这是在两种不同的卡片模型之间转换格式。普通的正面/背面内容最容易迁移；依赖样式、模板逻辑、输入答案等交互或 JavaScript 的卡片，则要在导入后逐一检查。

能否带上复习历史，还取决于一个明确的导出选项。Anki 的[导出手册](https://docs.ankiweb.net/exporting.html)说明，**Include Scheduling Information** 决定复习历史是否写入数据包。如果导出时没有勾选，`.apkg` 从一开始就不包含这些历史，Mochi 自然无法恢复。

复习历史即使成功导入，也不要期待今后的到期日完全一致。两款应用可能使用不同的调度器、评分、目标保留率、参数、学习步骤和牌组设置。保留下来的复习记录能为新调度器提供依据，却不会让两个系统变得一模一样。

## 原生备份和可移植文本用途不同

迁移任何内容前，都要先留下一份能恢复原系统的备份。可读的导出文件很有用，但未必能完整还原。

Mochi 的[备份指南](https://mochi.cards/docs/getting-started/backing-up/)介绍了两种原生备份方式：

- 复制整个用户目录会保留内容、复习历史、附件、应用设置和登录状态。
- `.mochi` 导出会保留牌组、卡片、模板与字段、附件、标签与元数据、复习历史、卡片顺序和牌组结构。

Mochi 的 [Markdown 和 CSV 导出](https://mochi.cards/docs/import-and-export/exporting/)属于可移植格式。Markdown 会为每张卡片生成一个文件，并为子牌组建立文件夹，但不会保留复习历史、卡片顺序、模板和元数据标签；只有已经写进 Markdown 的标签例外。CSV 可以导出模板字段或渲染后的正面/背面，但同样不会保留复习历史、模板或元数据标签，除非这些内容本来就嵌在卡片正文中。

Anki 也有类似的区别：

- `.colpkg` 会导出带有调度信息的整个卡片库，并可包含媒体。导入时，它会替换目标 Anki 卡片库中的卡片。
- `.apkg` 会导出一个牌组及其子牌组，并可选择包含调度信息、预设和媒体。
- 纯文本笔记以制表符分隔字段，HTML 格式则嵌在字段中。它能保留可编辑内容，却不能保留完整的卡片库行为。

从 Mochi 迁回 Anki 通常要用 CSV。Anki 可以[将文本列映射到笔记字段](https://docs.ankiweb.net/importing/text-files.html)，但 Mochi 的链接、多面卡片行为、模板和复习历史，无法通过 CSV 变成完全对应的 Anki 对象。即使导入 Anki 后看起来一切正常，也要保留 `.mochi` 导出文件。

## 先用代表性牌组做一次可回退测试

迁移对话框只能证明文件被接受了，不能证明真实卡片库仍能正常工作，也不能证明内容还能顺利迁回来。请在不动日常 Anki 配置文件的前提下，把两个方向都测试一遍。

1. **备份整个 Anki 卡片库。** 导出一份包含媒体的 `.colpkg`，并将它存放在当前工作配置文件之外。
2. **确认备份确实能打开。** 新建一个空的临时 Anki 配置文件，把 `.colpkg` 导入其中。卡片库数据包会替换目标卡片库，这正是必须使用临时配置文件的原因。
3. **在临时配置文件中建立一个有代表性的牌组。** 规模要小到可以逐张检查，同时又要覆盖你依赖的特性：基础卡、反向卡、填空卡、自定义模板、CSS、JavaScript、图片、音频、公式、标签、嵌套牌组和复习历史。
4. **把这个牌组导出为 `.apkg`。** 如果调度信息、预设和媒体很重要，导出时就把它们包含在内。这些选项只负责把数据写入 Anki 数据包，并不保证 Mochi 能重现每项设置。
5. **导入到一个新的 Mochi 牌组。** 不要改动日常使用的 Anki 配置文件及其到期队列。
6. **先检查，再开始复习。** 对比内容、格式、字段、媒体、标签、牌组结构和历史。尤其要检查依赖 HTML、CSS、JavaScript 或自动生成卡片变体的内容。
7. **主动选择调度器。** Mochi 默认使用自有算法。只有当你确实打算在试用后继续使用 FSRS，才把它打开。
8. **用这份副本完成一个正常的复习周。** 评估 Markdown 编辑流程、New cards 阶段、Remembered/Forgot 判断、离线表现，以及——如果你付费订阅了——在平时随身设备上的同步效果。
9. **测试迁回 Anki 的路径。** 把 Mochi 测试牌组导出为 `.mochi`，留作原生备份；再导出一份 CSV，供 Anki 使用。如果可复用字段很重要，选择字段值 CSV；如果主要需要看得见的正面/背面内容，选择渲染卡面 CSV。把 CSV 导入另一个空的 Anki 配置文件，并将各列映射到合适的笔记类型。
10. **写下每一项你能接受的损失。** 去程和返程要分开检查。精确样式、多面卡片行为、插件行为、自动生成的变体、复习评分、历史或未来到期日，在日常使用中可能比在对比表里更重要。

通过 CSV 迁回 Anki，只能迁移内容，并不能完整还原 Mochi：复习历史、模板和元数据标签都不会随文件带回，除非标签已经嵌入正文。如果 Mochi 没有解决你一开始提出的问题，就删除测试牌组，继续使用原来的 Anki 配置文件。如果确实解决了问题，每次只迁移一个真实牌组，并在接下来的几个正常复习周期内一直保留 Anki `.colpkg` 和 Mochi `.mochi` 备份。

## Mochi 闪卡适合谁？

以下情况适合 Mochi：

- 你本来就用 Markdown 写作和整理思路；
- 你希望笔记和复习卡片都留在同一个相互链接的工作区；
- 相比四档评分，你更喜欢简单的 Remembered/Forgot 二选一；
- 单设备离线使用足以满足免费工作流，或者 Pro 同步值得每月 US$5；
- 你的卡片库刚开始建立，或结构足够简单，从 Anki 转换的风险较低。

以下情况更适合继续使用 Anki：

- 你的笔记类型会生成多种不可缺少的卡片变体；
- HTML/CSS 模板、JavaScript、插件或共享牌组是整个系统的一部分；
- 相比 Markdown 编辑体验，你更看重免费的跨设备同步；
- 你需要 Anki 的 FSRS 优化器、预设控制、四档评分和工作量模拟器；
- 多年的复习数据和自定义行为已经运行良好。

如果 Mochi 和 Anki 都不合适，应该选哪种替代方案，取决于这两款应用为什么都满足不了你。对于刚开始建立、结构较简单的卡片库，[Flashcards Open Source App 的功能](/zh/features/)包括 FSRS 复习、离线学习与同步、可移植的卡片/标签/媒体迁移、Agent 访问，以及有文档说明的自托管路径。我是它的开发者，它的局限也需要说清楚：它不能取代 Mochi 的关联式 Markdown 笔记本，也不能取代 Anki 成熟的模板和插件系统。[入门指南](/zh/docs/getting-started/)介绍了目前的托管版、移动端、Agent 和自托管使用方式。

## 最终结论

Mochi 并不是给 Anki 换了一个更漂亮的界面。它的核心思路，是让一则 Markdown 笔记、一条相互链接的知识记录和一张间隔重复卡片成为同一个对象。免费版支持无需账号的离线使用；Pro 则增加跨设备同步等托管功能。

对于刚开始建立 Markdown 卡片库的学习者，这种取舍很划算。如果代表性牌组测试证明，原生 Markdown 和两档评分确实让日常使用更顺畅，那么从 Anki 切换过去也可能值得。

但对已经拥有成熟 Anki 卡片库的用户，判断标准正好相反。先备份整个卡片库，再测试自定义行为最多的卡片。除非 Mochi 能明显改善你每周的实际工作流，足以弥补具体格式、模板、调度器和生态功能上的损失，否则就继续使用 Anki。
