RemNote 开源吗？**不开源——至少核心应用不开源。** 截至 2026 年 8 月 21 日，RemNote 并未以开源许可证发布其核心客户端或服务器，也没有把它们作为开源项目公开。

不过，RemNote 确实在 GitHub 上公开了一些代码，也通过纯本地知识库、离线应用、备份、导出、插件和本地 MCP 服务器，让用户能够掌控部分数据与工作流。但这些功能都不能让你拿到一套可完整构建的 RemNote 产品代码。RemNote 还承诺，如果公司停止运营，将发布全部代码；这项承诺有明确的触发条件，并未在今天授予任何源码访问权或自托管权利。

**事实核查日期：** 2026 年 8 月 21 日。

## 先分清七种不同的控制能力

讨论 **RemNote 是否开源**时，最容易混淆的是：下面几种实用属性看起来都像“用户拥有控制权”，实际指的却不是一回事。

- **免费**说的是价格。RemNote 提供[免费方案](https://www.remnote.com/pricing)，但免费使用的软件仍然可以是专有软件。
- **离线可用**说的是断网后应用能否继续工作。
- **本地存储**说的是某个知识库或文件保存在哪里。
- **可导出**意味着你能以文档列明的格式取出部分或全部数据副本。
- **可通过插件扩展**意味着开发者能借助 API 添加功能。
- **开源**意味着相关源码在某种许可证下公开，而且该许可证允许使用、研究、修改和再分发代码。
- **可自托管**意味着有一套能实际运行的部署方案，可以放在你掌控的基础设施上运营。

RemNote 以实用的方式具备前五项能力，但核心产品目前不具备最后两项。

## 一张表看清 RemNote 能让你掌控到哪里

| 能力 | 现在能掌控什么 | 做不到什么 |
| --- | --- | --- |
| **核心应用** | 可以使用官方 Web、桌面和移动应用。 | 官方客户端和服务器源码目前没有作为开源项目发布。 |
| **公开 GitHub 代码** | 可以查看公开的插件、模板、主题、翻译、支持代码和派生仓库。部分仓库采用开源许可证。 | 这些仓库不包含 RemNote 核心客户端、托管服务或完整部署方案。公开代码如果没有可确认的许可证，也不会自动成为开源软件。 |
| **本地知识库** | 在桌面端，知识库只保存在你的电脑上，不会经过 RemNote 的服务器。 | 它仍要由专有的桌面应用打开，不能同步到其他设备；可选的集成功能还可能产生各自的数据流。 |
| **离线使用** | 完成安装和登录后，桌面与移动应用可以离线编辑笔记、复习卡片；桌面端还会保存完整的本地媒体副本。 | 离线模式不提供源码。Web 端无法在断网时冷启动，移动端和 Web 端可能缺少未缓存的媒体，大多数 AI 功能和插件也有离线限制。 |
| **本地文件与备份** | 桌面应用会把工作数据库、上传文件和本地备份保存到磁盘。 | 有恢复文件不等于有一套可自托管的 RemNote 应用或同步服务器。 |
| **导出** | 可以导出 RemNote 原生数据、OPML、仅含卡片的 Anki 内容包、HTML、Markdown 和文本。 | 没有一种导出格式能复现整个产品。RemNote（完整）导出目前不包含图片和 PDF。 |
| **本地 MCP 服务器** | 桌面 AI 智能体可以读取当前知识库；授权读写模式后，也可以修改其中的数据。 | RemNote 必须保持打开；连接器不会提供应用源码、服务器部署、图片内容或待复习卡片队列。 |
| **托管同步** | 同步知识库可以跨设备使用，并获得云端备份。 | 服务由 RemNote 运营，官方文档没有提供可自托管的同步服务器。 |
| **停止运营后的承诺** | RemNote 表示，如果公司停止运营，将发布全部代码。 | 触发条件尚未发生，因此这既不是当前的开源发布，也不是当前生效的开源许可证。 |

这张表比简单贴一个“是”或“否”的标签更有用。想保护敏感笔记的学生，可能最在意本地存储；要审查应用行为的开发者，需要拿到源码；自托管用户则需要可部署的服务、文档和升级路径。满足其中一项，并不等于其余需求也随之满足。

## RemNote 的 GitHub 组织究竟公开了什么

[RemNote 官方 GitHub 组织](https://github.com/remnoteio)目前列出 17 个公开仓库，内容包括插件模板、主题与代码片段、翻译归档、插件、更新程序或支持代码，以及支持库的派生仓库。例如，[官方插件仓库](https://github.com/remnoteio/remnote-official-plugins)提供了基于 RemNote 插件 SDK 构建的示例和文档。

这些代码确实有价值：插件开发者可以参考示例，了解插件扩展能力覆盖到哪里，社区也能据此改进 RemNote 周边工具。

但核心应用不在这个公开范围内。我没有在这些官方公开仓库中找到任何一个，能够用来构建完整桌面客户端、复现托管 Web 应用、部署 RemNote 同步服务，或追踪完整的服务端数据路径。

各仓库的许可证也并不统一。GitHub 将 React 插件模板、游戏手柄插件等多个项目识别为 MIT 许可；但目前没有检测到 `remnote-official-plugins`、已归档的翻译仓库和其他一些公开仓库的许可证。这并不证明这些项目在任何条款下都绝对不能使用，却足以说明：不能把 RemNote 的所有公开仓库一概称为开源。复用代码前，应检查具体仓库和许可证。

以上结论仅依据 RemNote 目前公开的官方仓库与文档，不涉及该公司的私有代码或内部系统。

## 停止运营后的承诺有价值，但不是当前的许可证

2023 年 4 月，RemNote 发布了由三部分组成的产品延续承诺。其中的[访问保障条款](https://help.remnote.com/en/articles/6085006-can-i-trust-you-ll-be-around-for-the-long-haul)表示，如果 RemNote 有一天停止运营，公司会将全部代码作为开源项目发布，让人们能够继续运行桌面应用，或独立托管 RemNote。

理解这项承诺的关键，在于它描述的是一组未来才会触发的步骤：

1. RemNote 必须先停止运营。
2. 公司随后才会发布代码。
3. 社区届时才能基于这份代码继续开发。

在触发条件满足、代码真正附带许可证发布之前，这项承诺不等于今天就能访问源码。它不能让你审查当前的核心实现、维护当前版本的派生项目，也不能让你部署官方发布的 RemNote 服务器。

这项承诺或许能降低一种长期访问风险，但不能据此声称“RemNote 是开源的”。本文只是从实用角度分析源码与产品的开放范围，不构成法律建议。

## 本地知识库确实划出了一条隐私边界

[RemNote 本地知识库](https://help.remnote.com/en/articles/7867942-multiple-knowledge-bases)只能在桌面端使用，数据保存在你电脑的硬盘上。RemNote 表示，这类知识库不会同步到其他设备，也不会经过公司的服务器。对于必须与 RemNote 云端隔离的数据，这是一项实实在在的控制能力。

代价也很直接：同一个知识库无法通过 RemNote 同步到手机、平板或另一台电脑，你还要自己负责异地备份。它让你在本地保管数据，却不会给你一套私有的 RemNote 云服务。

这一区别可以直接概括为：

> RemNote 本地知识库可以完全不经过 RemNote 的服务器，但打开和编辑它仍然依赖专有的 RemNote 软件。

对于同步知识库，[隐私文档](https://help.remnote.com/en/articles/7974260-privacy-of-your-notes)描述了另一套数据处理方式。RemNote 表示，静态数据会加密存储，传输过程受 TLS 保护，但目前不提供端到端加密。工作人员只有在明确场景下才能访问笔记内容，例如你临时授权客服访问，或主动向客服发送一份副本。

本地存储也不代表任何功能都绝不会把数据发往其他地方。RemNote 的 AI 功能、插件和文件转换集成都可能产生单独的数据流。即使知识库本身保存在本地，也要检查这些功能的设置与权限。

因此，隐私和源码是否公开应该分开评估。闭源软件可以让本地文件不经过供应商服务器；开源软件如果配置为使用托管服务，同样可能把数据发送到云端。

## 离线可用更抗断网，但不等于自托管

RemNote 的[离线模式](https://help.remnote.com/en/articles/6752029-offline-mode)不只是靠浏览器标签页临时撑过断网。应用下载安装完毕、用户登录后，桌面端和移动端都可以长期离线编辑笔记、复习闪卡。对于同步知识库，离线期间的更改会在网络恢复后上传。

桌面应用的离线能力最完整，因为它会在本地保存图片和 PDF 的完整副本。移动端和 Web 端只有有限缓存，较早的媒体文件可能打不开。Web 应用如果断网前已经打开，还能继续工作；但关闭或刷新标签页后，断网状态下无法重新启动。大多数 AI 功能和插件在离线时也不可用。

因此，桌面端很适合旅行、网络不稳定或需要在本地访问完整媒体库的场景，但它不会让你的电脑变成一台 RemNote 服务器。同步知识库恢复联网后，仍会通过 RemNote 的托管服务同步。

如果你真正关心的是，RemNote 以笔记为核心的工作流和 PDF 阅读体验是否值得接受这些限制，可以阅读 [RemNote 替代方案对比](/zh/blog/remnote-alternative/)。那篇文章专门讨论产品取舍，这里不再重复。

## 备份和导出解决的是两类问题

[桌面应用](https://help.remnote.com/en/articles/6030835-desktop-app)会显示每个知识库在本机的存储位置。RemNote 的[备份文档](https://help.remnote.com/en/articles/6301627-remnote-backups)说明，该文件夹包含工作数据库、按日期保存的本地备份，以及图片、PDF、音频等上传文件。同步知识库和本地知识库都会在桌面端生成本地备份；同步知识库发生变化时，还会获得每日云端备份。

这些副本主要用于故障恢复。如果知识库很重要，请在另一块磁盘或异地再留一份备份，因为工作数据库和本地备份可能随同一块硬盘一起损坏。

[RemNote 导出](https://help.remnote.com/en/articles/7898019-exporting-notes)解决的则是数据迁移问题：

- **RemNote（完整）**保留原生结构，可重新导入 RemNote，但目前不包含图片和 PDF。
- **OPML** 可以把大纲迁移到支持该格式的工具。
- **Anki（.apkg）**只导出闪卡，不含卡片的条目会被省略。
- **HTML、Markdown 和文本**能让更多工具读取笔记内容，但保留的结构和格式会依次减少。

打算把 RemNote 导出作为退出方案时，先拿一份内容不多但结构复杂的文档测试：其中应包含嵌套条目、引用、闪卡、图片和 PDF。然后在目标工具中打开导出结果，逐项检查哪些内容保留下来。能成功下载文件，只能证明导出功能可用，不能证明完整的学习流程可以原样迁移。

## 本地 MCP 服务器提供的是集成接口

RemNote 的[内置 MCP 服务器](https://help.remnote.com/en/articles/16424066-connecting-ai-agents-to-remnote-with-mcp)允许桌面 AI 客户端访问 RemNote 当前打开的知识库。你可以只授予读取权限，也可以授予读写权限。请求会到达本地端点，不会经过 RemNote 的服务器。

这套接口有明确限制：RemNote 必须保持打开；智能体一次只能看到当前知识库；连接器不能通过 RemNote 的 Web 或移动应用使用。它既不能访问待复习卡片队列，也不能读取图片内容。连接设置所用的提示文本中含有访问令牌，应当像保护其他凭据一样保护它。智能体读取到的数据，还会受到相应 AI 客户端隐私政策的约束。

这是一项实用的本地自动化能力，但不能据此认定 RemNote 应用开源，也不能让智能体脱离专有桌面应用运行 RemNote。API 或连接器开放的是选定操作，源码开放的是具体实现；两者解决的问题不同。

## RemNote 能自托管吗？

当前官方文档中找不到受官方支持的 **RemNote 自托管**版本。RemNote 没有提供完整自托管部署的文档，也没有提供官方自托管同步服务器的文档。官方列出的使用方式只有：

- 仅保存在本地、不支持跨设备同步的桌面知识库；
- 通过 RemNote 托管服务同步的知识库；
- 供 AI 客户端使用的桌面应用本地 MCP 端点。

这三种方式都不是自托管的 RemNote 服务。本地知识库放弃了同步；MCP 依赖正在运行的桌面应用；同步知识库在离线编辑后重新联网，仍然会接入 RemNote 的托管同步服务。

这个结论仅依据官方文档和 RemNote 对外提供的产品范围，不代表对其内部运行的每项服务作出判断。一套受官方支持的自托管版本，至少需要正式的部署说明、服务器代码或软件包、许可条款、升级路径，以及明确的兼容客户端列表。我没有在 RemNote 当前的官方文档或 GitHub 组织中找到这样的产品。

## 你真正需要掌控到哪一层？

如果你更看重关联笔记、反向链接、PDF 阅读、原生桌面应用和成熟的学习流程，而不是核心源码访问权，RemNote 仍可能很合适。若有一个桌面知识库必须完全避开 RemNote 服务器，纯本地模式是明确可用的选择。对普通的多设备学习而言，托管同步配合离线应用可能更省事。

如果以下任何一项是不能妥协的硬性要求，就该考虑其他产品：

- 现在就能查看或修改完整的客户端与服务器源码；
- 在自己运营的基础设施上部署多设备同步；
- 供应商改变方向后，仍能维护自己的派生版本；
- 在公开文档描述的接口之外验证应用行为；
- 为同步知识库提供端到端加密。

如果你需要**开源 RemNote 替代方案**，先确定不可妥协的是笔记与 PDF 工作区，还是闪卡系统。[Anki 的源码开放范围](/zh/blog/is-anki-open-source/)包括开源的桌面与 Android 客户端，以及可自托管的同步服务器，但 Anki 并非所有组成部分都开源。[开源闪卡应用指南](/zh/blog/best-open-source-flashcard-apps-2026/)则用许可证和托管范围比较了其他几款产品。它们都不会自动成为 RemNote 关联知识库的完整替代品。

## 披露：我在开发 Flashcards

> **披露：** 我是 Kirill Markin，也是 [Flashcards](https://flashcards-open-source-app.com/) 的开发者。它采用 MIT 许可证的仓库包含 Web 应用、iOS 和 Android 客户端、身份验证、后端、同步、MCP 服务以及 AWS 基础设施。目前，这套源码的开放范围比 RemNote 更广，但这并不意味着 Flashcards 适合所有学习流程。

Flashcards 专注的学习流程更窄：它没有关联笔记知识库、PDF 阅读器、原生桌面应用，也不能直接导入 RemNote。当笔记、引用和原始文档处于学习流程的核心时，RemNote 更成熟，优势也明显得多。只为许可证而迁移，可能会丢掉原本让卡片集合发挥作用的整套流程。

Flashcards 提供一套有文档的 [AWS 全栈自托管方案](/zh/docs/self-hosting/)，但它不是一条命令就能运行起来的本地一体化服务。部署者需要自行负责 AWS、Cloudflare、身份验证、邮件发送、监控、升级、数据库恢复，以及单独构建原生应用。它的[远程 MCP 连接器](/zh/docs/mcp-connector/)不要求桌面应用保持打开，就能访问卡片和卡组；RemNote 的本地连接器可以访问当前知识库，却不能访问复习队列。两者的产品形态不同，不能简单排成一条孰优孰劣的阶梯。

如果隐私比品牌更重要，可以阅读[借助 AI 使用私密闪卡](/zh/blog/private-flashcards-with-ai/)。其中的检查清单会帮助你分别判断学习流程中的本地存储、同步、AI 服务商访问和自托管。

## 坦率的答案

2026 年 RemNote 开源吗？**不开源——至少核心应用不开源。** 官方公开仓库提供了实用的插件、模板和支持代码；本地知识库、离线使用、本地备份、导出和 MCP，也确实让用户能够掌控部分数据与工作流。

但这些功能不会授予你完整应用源码的当前访问权。RemNote 目前也没有受官方支持的自托管产品或同步服务器文档。公司未来停止运营后发布全部代码的承诺，是一项产品延续承诺，不是今天已经生效的开源许可证。

如果关联笔记、PDF、桌面应用和产品成熟度足以让你接受这套专有软件的限制，RemNote 值得选择。如果你不能放弃的是当下就能审查、修改、再分发源码，或自行运营完整服务的权利，就应选择开源替代方案。
